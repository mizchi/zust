## r1 の指摘の扱い

3 人とも、規則 A.1(ファイル内で一意なら解決)を最大の問題に挙げた。R3 / R8 が低いのは主にこれによる。

| 指摘 | 誰が | 扱い | 理由 / r2 での変更 |
|---|---|---|---|
| 規則 A.1 は非局所的: enum を足すと離れた場所の `None` が壊れる | 全員 (high) | **採用** | A.1 を廃止。期待する型で決め、決まらなければ関数の終わりまで遅らせ、それでも決まらなければ修飾を求める |
| 期待する型がどこまで伝わるかが書かれていない(`if` の両枝、ブロックの末尾、`return`、配列の要素、引数) | rust-dev, implementer (high) | **採用** | 伝わる場所を列挙する。then 側で決まらないものは、else 側や後の使い方で決まるよう、候補つきの型変数で遅らせる(整数リテラルと同じ仕組み) |
| `At(found)` のように引数のあるバリアントには期待する型が届かない(`EK::Call` が callee を `infer(f, None)` で推論する) | implementer (high) | **採用** | 呼び出しの期待する型を、バリアントの解決に渡す(実装の注意として書く) |
| effect の操作(`perform Ask(..)`、handler の arm)は型検査の前に名前だけで解決している | 全員 (high) | **採用** | effect の操作名は、effect の enum の間で一意のまま。`perform Console::Ask(..)` と、arm の `Console::Print(s), k` の修飾を書けるようにする |
| パターンに Id がなく、解決結果を emitter に渡せない | implementer (high) | **採用**(実装) | パターンに Id を付け、解決した enum を side table に記録する |
| 書き換えのたびに全フィールドを書き直す(`Label { at, text, size } => Label { at: add(at), text, size }`) | rust-dev | **採用(要確認)** | `c @ Circle { center, .. }` の束縛と、腕の中で絞り込んだ値からの更新を足す案を r2 に入れる。更新の書き方は 002 の決定(`...c` か `..c` か)に合わせる |
| `..` なしの書き漏らしをエラーにすると、TS の人が毎回引っかかる | ts-dev | 一部採用 | エラーのままにする(フィールドの追加に気づける利点を優先)。メッセージに `..` を足す直し方を出し、LSP のクイックフィックスにする |
| `let Vec2 { x, y } = p` の型名が必須で、TS の `const { x, y } = p` と揃わない | ts-dev | **採用** | `let { x, y } = p;` を許す(`p` の型は分かっている)。002 の引数の位置の分割代入と揃える |
| `.d.ts` にバリアントごとの型がない | ts-dev | **採用** | 型と同名の namespace で `Shape.Circle` を出す(TS では `Shape.Circle` と書ける)。表現(`TAG`)の決定とは独立 |
| 名前付きフィールドの `TAG` が判別キーと衝突する | implementer | **採用** | 判別キーと同じ名前のフィールドはエラー(`@tag` で変えたら検査も変える) |
| 同名のレコード型とバリアント | ts-dev, implementer | **採用** | バリアントと同じ規則で、期待する型で決める。決まらなければ修飾を求める |
| 位置引数と名前付きのバリアントの混在 | rust-dev | **採用** | enum の中での混在は許す。1 つのバリアントの中で混ぜることだけ禁止する(Rust と同じ) |
| f64 のリテラルパターン(NaN、-0.0) | rust-dev | **採用** | 浮動小数点のリテラルパターンはエラー。ガードを入れるまでは `if` で比べる |
| 全バリアントに共通するフィールドを `s.at` で読みたい | ts-dev | 保留 | 未決事項に残す(TS 風の絞り込みと一緒に考える) |
| 同名のコンポーネント関数がバリアントを隠す | implementer | **採用** | 期待する型が enum で、その名前がバリアントでもあるときは、バリアントを優先する |
| データなしの enum にデータつきのバリアントを足すと `.d.ts` の形が変わる | ts-dev | 移す | enum の表現の決定(docs/plan.md の「保留」)に移す |
