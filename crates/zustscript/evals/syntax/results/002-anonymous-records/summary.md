## r1 の指摘の扱い

R2(一貫性)が一番低い。書き方の混在(`->` と `=>`、旧式の `fn(..)`、名前付きと無名の 2 つの世界、`..t` の位置)が主な理由。

| 指摘 | 誰が | 扱い | 理由 / r2 での変更 |
|---|---|---|---|
| 「期待する型がレコードならレコードとして読む」(構文が型に依存する)は採れない | implementer, ts-dev (high) | **採用** | 構文だけで決める: `{` の次が `ident :` / `ident ,` / `...` ならレコード。`{ x }` だけはブロック(期待する型がレコードの所では did-you-mean を出す)。`{ todo, onToggle }` も書ける |
| `{ done: x, ..t }` は JS の `{ done: x, ...t }`(後が勝つ)と逆の意味に読める | ts-dev (high) | **採用(要確認)** | 更新は JS と同じ `{ ...t, done: x }`(`...` は先頭)に揃え、名前付きのレコードでも `Todo { ...t, done: x }` と書く。`...` を後ろに書いたら、JS との違いを説明するエラー。Rust 式の `..t` は廃止 |
| 無名の値が名前付きの型に渡せない(`let r = { .. }; f(r)`) | 全員 (high) | **採用(要確認)** | `type X = { .. }` を TS と同じく構造的な型の別名にする。名前は表示と `@wasm` の struct 名に使う。再帰する型だけは名前で区別する |
| `@wasm` で無名のレコードが使えない | rust-dev (high), ts-dev | **採用** | フィールドの集合から決まる名前の struct を作る(同じ形には同じ struct) |
| 関数型の書き方が 2 通り、`->` と `=>` が混ざる | 全員 | **採用(要確認)** | 型は TS 風の `(id: i32) => ()` に一本化し、旧式の `fn(i32) -> ()` は直し方つきのエラーにする。関数の宣言の `-> R` は残す(Rust と同じ。値のクロージャは `=>`、宣言は `->` という区別) |
| 引数名を持つ場所がない(`Ty::Fn` に名前がない) | implementer (high) | **採用**(実装) | `Ty::Fn` に引数名を持たせる(単一化では無視する) |
| props の分割代入(`fn TodoItem({ todo, onToggle }: { .. })`) | ts-dev | **採用** | 引数の位置にレコードのパターンを書ける。001 の `let { x, y } = p` と同じ規則 |
| 任意のフィールド `title?: String` | rust-dev, ts-dev | 移す | `Option` を標準にする提案(003)と一緒に入れる。`title?: T` は `title: Option<T>` の略記で、JSX では省略できる |
| 二重の波括弧 `if c { { .. } }` | 全員 | 一部採用 | 書き方はそのまま。ブロックの最初が `ident :` のときは「レコードの値はもう 1 組の波括弧で囲む」という専用のエラーにする。印(`#{ }`)は TS から離れるので採らない |
| 長い構造的な型の不一致が読めない | implementer | **採用**(実装) | 単一化で、レコード同士の差分(足りない、余分、型が違うフィールド)を返して表示する |
| `{}` の扱い | 全員 (questions) | **採用** | `{}` は常にブロック(値は `()`)。空のレコード型は書けない |
| `void` を `()` の別名に | ts-dev | 保留 | 評価で意見を聞く |
| `pub` な関数の無名の戻り値の型に名前がない | ts-dev (low) | 保留 | `.d.ts` で `type stats_Result = ..` のように名前を付けるかは、r2 の評価で聞く |

## r2 の指摘の扱い

mean は 3.08 → 3.54。R2(一貫性)は 2.3 → 3.0、R3(構文の曖昧さ)は 2.7 → 3.7。残る低い項目は R5(誤りが静かに通る)で、`{ x }`、newtype、spread の意味が理由。

| 指摘 | 誰が | 扱い | r3 での変更 |
|---|---|---|---|
| `{ x }` がブロックで `{ x, }` がレコード。`let r = { x };` が静かに `x` になる | ts-dev (high), rust-dev, implementer | **要確認** | 下の決定 3 |
| 構造的な `type` でレコードの newtype が作れない(`Meters` と `Celsius`) | rust-dev | **要確認** | 下の決定 4 |
| 同じ形の別名が 2 つあると `@wasm` の struct 名と表示名が決まらない | 全員 | **採用** | struct は形を鍵に 1 つ(名前は最初に宣言した別名)、他は Rust の `type ZsB = ZsA;`。表示名は注釈から来た名前、なければ形から逆に引く |
| spread の意味(フィールドを足す、型を変える、複数の spread) | 全員 | **採用** | 結果の型は `...t` の型と同じ。後のフィールドは t にあるものを同じ型で上書きするだけ。spread は 1 つ |
| TS から来た余分なプロパティが JS では残り、`@wasm` では落ちる | rust-dev, ts-dev | **要確認** | 下の決定 4 と一緒に |
| 再帰の定義、リテラルを再帰する型に渡せない | implementer, ts-dev, rust-dev | **採用** | 再帰は「enum の定義を通らない、別名と型引数の循環」。単一化で再帰する名前を 1 段だけ展開して、無名の値を受ける |
| 関数型を返す関数型の括弧に理由がない。`(T)` が 1 要素のタプルから括弧に変わる | ts-dev, implementer | **採用** | 型の `=>` は右結合、括弧は任意。1 要素のタプルの型は `(T,)` |
| 引数名を省いた `(i32) => ()` が TS では引数名に読める | ts-dev | **採用** | `pub` / `extern` のシグネチャの関数型では引数名がないと警告 |
| `type` がレコード専用 | implementer | **採用** | `type H = (id: i32) => ()` とタプルの別名も書ける |
| ブロック直下(if / fn の本体)の `{ done, x }` / `{ ...t }` に専用のエラーがない | implementer | **採用** | 判定を 1 関数にまとめ、block() の先頭でも 3 つの形すべてに専用のエラー |
| `Ty::Fn` の引数名が derive(PartialEq) に混ざる | implementer | **採用**(実装) | 等価性で無視する別のフィールドに持つ |
| 分割代入した引数の `.d.ts` での名前、jsx() が Ty::Rec を受けない | ts-dev, implementer | **採用** | コンポーネントは `props`、他は `arg0`。内部では `$p0` にして本体の先頭で展開 |
| props の型とパターンでフィールド名を 2 回書く | rust-dev | 保留 | 未決事項に残す |
| `void` を `()` の別名に | ts-dev | 保留 | 未決のまま(rust-dev は不要) |

### r2 の決定(ユーザー)

3. `{ x }`: **常に警告**。中身が識別子 1 つだけのブロックには、構文だけで警告を出す(直し方: レコードなら `{ x, }` か `{ x: x }`、値なら `x`)。判定は 2 トークンの先読みのまま
4. newtype: **`@nominal type Meters = { v: f64 }`** を入れる。名前で区別する型になる。余分なプロパティは JS の挙動のまま(spread でのフィールドの列挙はしない。未決事項に残す)

## r3 の指摘の扱い

mean は 3.54 → 3.83。R2、R3、R8 が 4.0 に上がった。低いのは R5(3.3)で、ほぼ `{ x }` の警告の範囲による。

| 指摘 | 誰が | 扱い | r4 での変更 |
|---|---|---|---|
| `{ x }` の警告が、if / else / fn の本体(`else { t }`、`{ None }`、`fn id(x) { x }`)にも出る | 全員 (high) | **採用** | 警告は、primary の `{` から読む式の位置のブロック(`let` の右辺、引数、フィールドの値、配列の要素、`=>` の後、match の腕、JSX の `{…}`)だけ。block() を直接呼ぶ本体には出さない。block() の先頭で見るのは 3 つの形の専用エラーだけ |
| `let` と引数のレコードのパターンでも `...` の書き漏らしがエラー(TS の一部だけの分割代入) | ts-dev | **要確認** | 下の決定 7 |
| 無名の struct 名 `ZsRec_done_total` が型の違う同名の形で衝突 | implementer | **採用** | 衝突したときだけ形の短いハッシュを付ける |
| 「最初に宣言した別名」で struct 名が決まる非局所性 | implementer, rust-dev | **採用** | struct 名は常に形から作り、別名はすべて Rust の `type` 別名にする。表示名は注釈から来た名前だけ(逆引きは hover の補足) |
| `.d.ts` が `interface` を出す | ts-dev | **採用** | `export type Todo = { … }` |
| `@nominal` の `.d.ts` | rust-dev | **採用** | 数値と同じ brand(`& { readonly __zsc_nominal: "Meters" }`)と、コンストラクタ `Meters({ v })` |
| `@nominal` をレコード以外に | implementer | **採用** | r4 ではレコードだけと明記。数値の newtype は別の提案 |
| 名前のある引数とない引数の混在 | implementer | **採用** | エラー |
| 余分なプロパティ(JS と wasm の差) | rust-dev | 保留 | 差分テストは型にあるフィールドだけを比べる、と明記。pub の入口で作り直す案を未決に |
| 複数の spread、`void`、`->` と `=>` の例 | ts-dev, rust-dev | 保留 | 未決のまま。`fn adder(n) -> (x: i32) => i32` の例を足す |
