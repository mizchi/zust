rustc tests/ui pass rate, by kind

Measured by CI on each push (bench/rust_ui.py against rust-lang/rust 1.100.0). The rate is over the tests zustc can be asked to handle: no nightly features, auxiliary crates or special flags. A compile-fail test passes only when zustc reports an error on a line its annotations point at. Each chart has its own scale.

Open pull requests, and the way to 90%

What each open pull request adds to bench/rust_ui_ratchet.txt (the passing tests a branch may not lose), against the base it was opened on: a PR stacked on another counts only its own part. Two PRs to main that pass the same test count it twice. The days to 90% are at the pace of the CI runs on main in the two days before the latest one: the same number of tests a day (linear), or the same share of the remaining tests a day (geometric, which slows down as the easier tests are taken). Speed KPIs against the first measurement

bench/kpi_log.tsv, one row per change, in instructions executed (lower is faster). The no-op build is left out: a stat-stamp short-circuit took it from —M to —M instructions. Rows whose commit was rebased away are placed between their neighbours.

Implementation and test code, without zustscript

Lines of .rs. Implementation: src/ and crates/*/ (without tests, benches, examples). Tests: tests/ and crates/*/tests/, plus each source file from its first #[cfg(test)] to its end. crates/zustscript (— lines now) is left out of both; cratebench, examples and formal are not counted.

How the numbers are made
  • All data comes from python3 scripts/retro/extract.py, which reads git history, bench/kpi_log.tsv and the benchmark history on the gh-pages branch. The Pages workflow reruns it after each benchmark run.
  • Commits: git log --no-merges without github-actions[bot]. Days and hours are cut in UTC.
  • KPI noise: the same binary measured again moves by about 0.01% (builds) and 0.1% (LSP).
  • Open pull requests: the Pages workflow lists them with the GitHub API when it builds the site; a PR's gain is its head's bench/rust_ui_ratchet.txt less the one at its merge base with its base branch, by kind (0 for a kind it has fewer of). The applicable tests are the last CI run's passing tests over its rate.
  • Code size is counted on one first-parent commit every 3 hours. The peak on 11-16 is when the old and the new driver both existed.
