What to fix, by importance

Every error, grouped by the fix it needs (cratebench/survey/issues.tsv names the fixes with a tracking issue; the rest are grouped by their text without names), ordered by what the fix holds back. Each surveyed crate that does not build shares its downloads equally among the fixes its graph needs; a fix's share is the sum. Alone: crates that need only this fix, as far as zustc shows (it stops a crate at its first item error, so another can come next). A bar without an issue is the next one to file.

Status by category

One bar per category, one segment per status (a crate's status is the first that applies: zurgo cannot plan its graph, its own code has errors, a dependency's code has errors, the build fails, it builds). Crates of one kind tend to stop zustc in the same places. Point at a segment for its crates.

Over time

One point per survey on main (cratebench/survey/history.tsv). A new crate list, or new versions in Cargo.lock, moves the numbers too: the list's date is in crates.tsv.

Packages with errors

Packages with errors, ordered by the downloads of the surveyed crates that only they keep from checking (alone: no other package of the crate's graph has errors), then by how many surveyed crates need them. The error count is what zustc reports now: a lower bound, since zustc stops reading a crate at a syntax or macro error and checks each function only up to its first error.

How it is measured
  • python3 cratebench/survey/survey.py run (cratebench/survey/README.md) writes, for each crate of crates.tsv, a probe package in a temporary directory, with the crate pinned with = and the versions of cratebench/survey/Cargo.lock. cargo fetches the sources from crates.io; nothing is vendored.
  • zurgo check gives each crate of the probe's graph its errors; when there are none, zurgo build compiles and links the crate and its dependencies.
  • Proc-macro crates run on the host, where rustc builds them; the crates that use them test them. Crates for other platforms (windows-*, wasm-bindgen, …) are listed, not probed.
  • The category comes from the crate's crates.io categories, corrected by name where they say little (survey.py's BY_NAME); a row of crates.tsv can be changed by hand.
  • CI runs the survey after each push to main that changes the compiler and commits the results; this page is rebuilt from them.
