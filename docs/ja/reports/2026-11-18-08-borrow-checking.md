# MIR なしの借用検査

Date: 2026-11-18

zustc には借用検査がなく、型検査を通るプログラムはすべて受け付けていた。この報告では、何を選んだか、AST から直接機械語にするコンパイラにどう合わせたか、rustc 自身の UI テスト（[報告 07](2026-11-18-07-rustc-ui-tests.md)）で何が起きたかをまとめる。

## 現在の手法

- rustc の既定の検査器は NLL である。liveness と outlives 制約から region を点の集合として推論し、まだ有効なローンと衝突するアクセスを報告する。
- 後継は Polonius である。2026 年のプロジェクト目標（[Rust project goals: borrow checker within](https://goals.rust-lang.org/2026/roadmap-borrow-checker-within.html)）は、"Polonius alpha" を 2026 年に安定化することである。Polonius alpha は条件付きの借用（NLL problem case 3）と lending iterator を扱える。フローを完全に区別する Polonius は今後の課題とされている。
- [Polonius の本](https://rust-lang.github.io/polonius/rules/loans.html) は、解析をローンと origin の規則として書いている。
  - ローンは、それが作る参照の origin に入る。その origin が生きている間、subset 関係と CFG の辺に沿って進む。
  - ある点でローンが生きているのは、それを含む origin が生きているときである。
  - 生きているローンを無効にするアクセスが誤りである。
  - 本は、位置を区別しない版を速い前処理として使うことも書いている。前処理が誤りの可能性を見つけなければ、完全な解析は省略する。
- [Wu, Wang, Chen (arXiv 2611.06319)](https://arxiv.org/html/2611.06319) は、遅延して検査すれば Polonius は前向きの抽象解釈になり、別の liveness パスが要らないことを示している。

## 設計

zustc には MIR がない。acg（型検査とコード生成を兼ねる）が関数本体を minclif に下ろす。借用検査は、acg がすでに作っている CFG を使う。

1. **記録。** acg は下ろしながら、minclif のブロックごとにイベントを記録する。
   - ローカル変数が束縛される（初期化あり・なし）、読まれる、ムーブされる、書かれる、借用される（`&`、`&mut`、自動参照のレシーバ、クロージャのキャプチャ、`ref` 束縛）。
   - ローカル変数がスコープを出る。

   `jump` と `brif` は CFG の辺も記録する。定数を条件とする brif は、取る辺だけを記録する。
2. **場所。** 場所はローカル変数と射影の列である。射影には、フィールド、Box を通る `*`、`&mut` を通る `*`、`&` を通る `*`、添字がある。フィールドと deref の射影は、自動 deref と同じく静的な型から決める。
3. **位置を区別しない前処理。** この前処理は制御フローを無視する。ムーブも未初期化の変数も、衝突するローンと重なるアクセスもなければ、データフローは回さない。フローに依らない可変性の誤りはここで報告する。
4. **データフロー。**
   - 後ろ向きのパスでローカル変数の生存を求める。
   - 前向きのパスを不動点まで回し、3 つを追う。ムーブ済み・未初期化かもしれないパス、代入済みかもしれない不変の変数、各変数が持ちうるローンである。
   - ローンが生きているのは、生きている変数がそれを持ちうる点である。これは Polonius の見方で、origin を変数ごとに 1 つとしたものにあたる。
5. **変数に何が流れるか。** 型に寿命がないので、次のように近似する。
   - 変数は、初期化式を評価する間に作られたローンと、そこで読んだ変数が持つローンを受け取る。
   - 呼び出しが引数の借用を戻り値に流すのは、シグネチャが「戻り値はその引数から借りうる」と言うときだけである。これは宣言の省略規則と名前付きの寿命から決める（`SigSyn::ret_from`）。
   - シグネチャの分からない呼び出しは何も流さない。クロージャ、関数ポインタ、`impl Trait` を返すものがこれにあたる。
   - prelude の反復子・ビューの型（`Iter`、`Chars`、`ChunksExact` など）は、反復する元のローンを持つ。

どの変数も持たないローンは、その式とともに終わる。これで two-phase borrow（`v.push(v.len())`）と、NLL が拒む条件付きの return の場合が受け入れられる。代わりに、1 つの式の中の衝突は、呼び出しの引数どうしの間でしか見つけられない。引数の借用は、呼び出しが行われるまで隠れた変数に持たせて生かしておくので、`f(&mut x, &x)` と `x += x`（オーバーロードされた `+=`）は衝突になる。

ほかの規則は次のとおり。

- ローンは、それが通る変数が上書きされると消える（Polonius の `loan_killed_at`）。
- 評価順は Rust に合わせる。`a = b` では `b` を先に、`S { f, ..base }` では `base` を最後に評価する。
- クロージャは変数ではなく場所をキャプチャする（RFC 2229: `p.x`、`*r`、パターンが束縛する部分）。場所ごとに、使われ方から値・`&mut`・`&` のどれでキャプチャするかを決める。
- acg 自身が合成する呼び出しは、利用者の借用として扱わない。読み出しに使う `index_mut` と、演算子を書き換えたメソッド呼び出しがこれにあたる。

## 見つける誤り

| コード | 内容 |
|---|---|
| E0382 / E0381 | ムーブ済み・未初期化の値の使用（パターン、`for` ループ、`move` クロージャによるムーブを含む） |
| E0499 / E0502 / E0503 / E0505 / E0506 | 生きているローンと衝突するアクセス |
| E0597 / E0515 | 借用が借用先より長く生きる（スコープの終わり、ブロックの外への持ち出し、引数の先への格納、戻り値） |
| E0507 / E0508 | 参照を通したムーブ、添字からのムーブ |
| E0596 / E0594 / E0384 | `mut` でない変数や `&` 参照の先の変更、不変の変数への 2 回目の代入 |

acg は関数の最初の誤りでその関数を打ち切るので、報告するのは関数ごとに最初の誤りだけである。`ZUSTC_BORROWCK=0` で検査を止め、`=1` でムーブだけを検査する。`ZUSTC_BK_DEBUG=1` で記録したイベントを表示する。

## 結果

比較の基準は直前のコミット（ac2361e）である。tests/ui は報告 07 と同じ 1.100.0 のものを使う。

| 種類 | 前の pass | 後の pass | 後の pass 率 |
|---|---:|---:|---:|
| run-pass | 1120 | 1120 | 46.42% |
| check-pass | 834 | 834 | 46.15% |
| build-pass | 65 | 65 | 48.15% |
| compile-fail | 2298 | 2578 | 35.04%（31.23% から） |

ベースラインの一覧にあるテストで回帰したものはない。一覧は 4317 件から 4597 件になった。

別の理由ですでに失敗しているテストでの誤検出は、回帰として現れない。そこで、失敗している run-pass / check-pass / build-pass のテストをすべて別に調べたが、借用検査の誤りは 1 件も出なかった。

ディレクトリ別に、通る compile-fail のテストの数:

| ディレクトリ | 前 | 後 | 対象 |
|---|---:|---:|---:|
| borrowck | 30 | 159 | 354 |
| nll | 12 | 41 | 187 |
| closures | 21 | 36 | 115 |
| moves | 2 | 21 | 49 |
| liveness | 4 | 9 | 16 |

コストは、生成したベンチマークのプログラムに対する `zustc check` の命令数（valgrind）で測った。

| プログラム | なし | あり | 変化 |
|---|---:|---:|---:|
| gen1000 | 782.7 M | 800.0 M | +2.2% |

位置を区別しない前処理がないときは +6.3% だった。残りの大半は解析ではなく、下ろしながらの記録である。

cratebench のクレート（fnv、adler2、hex、itoa、rustc-hash、cfg-if）は今もビルドでき、同じ出力を出す。うち 2 つでは、最初に誤検出が出た。

- prelude のビューのメソッド（`ChunksExact::remainder`）を、ビュー自身から借りるものとして扱っていた。
- `self` の 1 つのフィールドに代入するクロージャを、`self` 全体を可変に借りるものとして扱っていた。

## 残っていること

- シグネチャに対する region の誤り（E0621、E0521、"lifetime may not live long enough"）。ローンだけでなく、universal region と、本体の宣言に対する outlives の検査が要る。
- 型を通した正確な流れ。変数は初期化式で読んだものすべてのローンを持つので、呼び出しで取り出した値（`v.get(0).cloned()`）もまだ `v` を借りているとみなされる。これによる誤検出を避けるため、E0515 と、ブロックの外へ持ち出す E0597 は、式が直接借りるものだけを見る。
- E0716（借用中に一時値が drop される）、E0510、スコープの終わりの `Drop` による使用、配列や struct パターンからの部分ムーブ、関数ごとに 2 つ以上の誤りを出すこと。
- `tests/selfhost_compiler.sh` は実行していない。生成した 1 ファイルのコンパイラの構文エラーで先に進まず、これは直前のコミットでも同じである。
