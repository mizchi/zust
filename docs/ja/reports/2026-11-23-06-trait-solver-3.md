# trait solver、その 3: 関連型

日付: 2026-11-23

[その 2](2026-11-23-05-trait-solver-2.md) の続き。zustc は `<T as Tr>::Assoc` を `Program::assoc_of` で正規化していた。その名前の
関連型を定義し、self 型が寛容に合う最初の impl を使う。どのトレイトか、トレイト引数、impl の where 節は見ない。また solver は、
束縛 (`Tr<Assoc = X>`) と射影への where 節をすべて節から落としていた。

## モデル

`Normalize.lean`: impl は定義を持つ (`AImpl`)。`NormTo g n u` は、ある impl が `g` に当てはまり (頭が合い where 節が成り立つ)、
`n` をインスタンスが `u` になるものとして定義していること。`normalize` がアルゴリズム: 頭が合い、where 節を solver が証明する
impl の、マッチングで見つけた代入のもとでの定義。

- `normalize_sound`: 返すものは正規形。
- `normTo_functional`: 頭が単一化する impl が同じ impl であり (コヒーレンス)、定義が頭で束縛されるパラメータだけを名指すなら、
  1 つのゴールの正規形は 1 つ。
- `binding_no_sound`: なので `A` が別の型に正規化される境界 `T: Tr<A = x>` は成り立たない。E0271 はこれに依る。

モデルの定理は 15 個になった (`formal/run.sh lean`)。

## 実装

`traits.rs` では:

- impl の節が定義を持つ (`Clause::assocs`。impl のメンバのアイテムから);
- `Cx::normalize` はモデルに従う: そのトレイトの impl (またはほかの impl が定義しないとき、その名前を定義するプログラムの
  どのトレイトの impl でも) のうち、頭が正確に合い where 節が strict な `yes` になるもの。答えは 1 つか、なし:
  トレイト引数のある impl、すべては読めていない節、2 つの答えは不明にする;
- `Cx::isubst` は impl の where 節をインスタンス化し、その射影を `normalize` で正規化する (`assoc_of` は使わない);
- 述語の束縛 (`Pred::eqs`) はトレイトの後で確かめる (`solve_pred`): 別の型なら `No`。

driver では:

- 要約が落とす where 節 (射影への `where T::Assoc: Foo`、具体型への `where (): Array<Element = &()>`) を impl ヘッダの文字列から
  読んで節に足す (`TraitDb::add_where`)。impl がすべて読めたかどうかも同じ読み取りで決める (E0119 とスーパートレイトの検査用);
- トレイトが関連型に付ける境界 (`type Sibling: Bar2<Ok = Self::Ok>`) を各 impl の定義について確かめる。`Self::Ok` は solver で
  正規化する: 定義の場所で E0271 か E0277;
- 呼び出しの境界の束縛が別の型に正規化されるなら E0271。rustc と同じ文言 (`type mismatch resolving <W<i32> as Tr>::Assoc == ()`)。

## `-> impl Tr`: 隠れた型を境界と照らし合わせる

要約は不透明な戻り値型の境界を持たない (印の型が代わりに立つ) ので、本体が与える型が `Tr` であることを誰も確かめていなかった:
`impl Test for ()` がなくても `fn test() -> impl Test { () }` を受け入れていた。いまは `resolve_opaque` が隠れた型を決めた後で、
driver が関数のシグネチャから境界を読み、solver に聞く (`solve_no_sound` により `no` は本物のエラー):

- ジェネリックでない関数の `-> impl Tr + Send`: 境界ごとに、プログラムのトレイトは束縛つきで (別の型に正規化されれば E0271)、
  auto trait、std のトレイトはスカラーと普通の構造体について;
- `-> impl Tr` と宣言したトレイトのメソッド: 各 impl のメソッドが返す型が Tr であること (`fn make() -> impl Shape` に対する
  `impl Factory for B { fn make() -> u8 }`);
- 引数がすべて束縛の std の境界 (`impl Iterator<Item = &u32>`) は束縛なしで聞く (弱いゴールなので `no` はそのまま成り立つ)。

`()` について std のトレイトを確かめると、`Program::implements` が std の `()` への impl を知らないことが分かった (`(): Default` や
`(): Debug` が no になり、check-pass が 2 件退行した)。`()` はいま std の一覧から答え (導出できるトレイトはすべて、Display
と iterator ではない)、スカラーは 12 のトレイトそれぞれについて rustc と照らし合わせた:
`tests/check.rs::trait_solver_opaque_std_traits_like_rustc` が rustc の 120 の答えを持つ。

tests/ui の compile-fail: 4533 → 4539 (+6): `impl-trait/projection-mismatch-in-impl-where-clause.rs`、
`impl-trait/in-trait/doesnt-satisfy.rs`、`suggestions/issue-81098.rs`、`suggestions/impl-trait-return-trailing-semicolon.rs`、
`diagnostic-width/impl-trait-invalid-iterator-error.rs`、`associated-types/fn-ptr-coercion-normalize-ice-132767.rs`。
退行なし。新しいテスト: `tests/compile_errors/trait_solver_opaque{,_in_trait}.rs`、`examples/trait_solver.rs` の成功するケース。

## 残っているもの

- ジェネリック関数の `-> impl Tr` (インスタンスごとの型) と入れ子のもの (`Option<impl Tr>`) は確かめない。導出できる
  トレイトと auto trait 以外の std のトレイト (`impl Termination`) も。
- std も定義する名前だけでの射影 (`T::Item`)、ジェネリックな関連型、型推論の中の正規化 (`ast_infer` はまだ `assoc_of` を使う)。
