# リージョン (ライフタイム) 検査、その 40: OnceCell、コンストラクタが作る値の well-formedness、呼ばれるジェネリック関数、受け手の self 型の省略されたライフタイム (issue #169)

日付: 2026-11-26

その 39 ([2026-11-26-02](2026-11-26-02-region-check-39.md)) は #263 でマージした。この段階は #169 の穴の続きを扱う:
ライフタイムのテストを借用検査の前で止めていた std の型と、`T: 'static` の検査と受け手のライフタイムの検査が届いて
いなかった 3 か所である。

## 1. 加えたもの

- **`std::cell::OnceCell` と `Rc::try_unwrap` / `Rc::into_inner` (Arc のものも)。** prelude の OnceCell は、1 スレッド
  用の OnceLock である (`new`、`get`、`get_mut`、`get_or_init`、`set`、`into_inner`、`take`)。std と同じく Sync では
  ない (sync/suggest-once-cell.rs は今もトレイト境界で拒否する)。`try_unwrap` は、その Rc がただ 1 つのとき値を返し、
  値を落とさずに箱を解放する。regions/wf-bound-region-in-local-soundness-issue-148854.rs は "cannot find type
  `OnceCell`" だった。
- **パラメータを 'static で縛る型の、コンストラクタが作る値。** `struct St<T: 'static>` で、T が 'static でない
  ジェネリック関数の中の `St(Some(x))`、`St::<T>(..)`、`En::A(x)`、`En::<T>::B` は rustc の E0310 である: 値の型が
  well-formed でない。これまで確かめていたのは、構造体リテラルの型と、パスが書く型引数だけだった (その 24)。今は、
  その型 (その名前か、そのバリアント) を名指すパスの型と、そのパスの呼び出しの型を、構造体リテラルと同じく確かめる。
- **呼ばれるジェネリック関数も、プレースホルダーで確かめる。** インスタンスが作られるジェネリック関数は、それらで
  しか確かめていなかった。インスタンスからは、関数の型が求める `T: 'static` はわからない: T が `&u8` のとき、検査は
  参照のリージョンを新しいものとして扱う。そのため `extend::<&String>(&data)` が、extend の本体の `Outer::<T,
  Inner<T>> { .. }` の E0310 を隠していた (`struct Inner<T: Display + 'static>`、上のテスト)。今は、パラメータを
  'static で縛るプログラムの構造体か列挙型を本文が名指す関数を、プレースホルダーでも確かめる。そこで報告するのは
  E0310 (満たされない `T: 'static`) だけであり、その 12 の再検査がムーブだけを報告するのと同じである。作るのは、プログラムにそうした
  型があるときだけである。
- **シグネチャの型が、クロージャの中でも `T: 'static` を導く。** `struct IfaceToken<T: 'static>` での `fn foo<T>() ->
  IfaceToken<T>` は、本体で T: 'static を与える。本体のクロージャの中で T: 'static を求める呼び出し
  (`data_::<T>(&())`) を報告していた (check-pass のテスト borrowck/nested-closure-with-generic-ice.rs で、foo が
  呼ばれないとき。上の項目で、呼ばれるときにも報告するようになった)。今は、関数のシグネチャの型が、'static の境界が
  かかる引数としてプレースホルダーを持つとき、そのプレースホルダーは 'static である。
- **受け手の self 型の省略されたライフタイム (E0308)。** `impl Pair<&str, isize>` での `self: &Pair<&str, isize>`、
  `impl<'a> Foo<'a>` での `self: Foo<'_>` や `self: Foo`、`impl Tr for W<&u8>` での `self: Rc<W<&u8>>` は、impl の
  self 型が impl のライフタイムを持つところに、メソッド自身のライフタイムを名指す: rustc の "mismatched `self`
  parameter type" (lifetimes/elided-lifetime-mismatch-in-self-type.rs)。既存の検査が比べていたのは、受け手が名前で
  書くライフタイム引数だけだった。型の中の fn ポインタや `dyn Fn(&u8)` が束縛するライフタイムは見ない。
- **型推論での、`Box<dyn Tr>` の impl のメソッド。** `impl MyTrait for Box<dyn O>` で `val: &Box<dyn O>` の
  `val.use_self()` は、そこでメソッドを見つけなかった (オブジェクトのものだけを探していた)。そのため、それによる
  結果の `impl Trait` は "cannot infer the `impl Trait` return type" だった。オブジェクト自身のメソッドの後の
  フォールバックである。

## 4. まだ扱っていないもの

- **`Box<dyn Tr>` の impl を通した借用** (`impl MyTrait for Box<dyn O> { fn use_self(&self) -> &() }` で、ローカルの
  `val: Box<dyn O>` の `val.use_self()` を返す): rustc の E0515 で、ここでは受理する。その呼び出しを
  リージョン検査がたどらない (suggestions/impl-on-dyn-trait-with-implicit-static-bound-needing-more-suggestions.rs)。
- **impl の self 型が省略されたライフタイムを持つところに `'static` を書く self 型** (`impl Pair<&str, isize>` での
  `self: &Pair<&'static str, isize>`、E0308) と、impl の型とは別の型の受け手 (`impl<T> W<T>` での `self: &W<&u8>`、
  rustc の E0307): 受理する。
- **`impl<T> Tr for &T` が省くデフォルトメソッド** (span/issue-24805-dropck-trait-has-items.rs): コード生成器が
  (`Self = &T` では) 扱わないので、この dropck のテストはそこで止まる。
