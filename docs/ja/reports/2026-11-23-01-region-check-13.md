# リージョン (ライフタイム) 検査、その 13: impl のヘッダ、`&mut` のムーブと再借用、二相借用、クロージャの `'static` 注釈、mismatched_lifetime_syntaxes リント (issue #1)

日付: 2026-11-23

その 12 ([2026-11-22-09](2026-11-22-09-region-check-12.md)) は #64 でマージした。この段階では、tests/ui で受け入れて
いたケースをさらに扱う。その多くは借用検査のものである: `let` が `&mut` のローカルをどうムーブし、どう再借用するか、
メソッドの `&mut self` をいつ取るか、クロージャが別のクロージャを呼ぶとき何を借用するか。また、impl のメソッドを
impl のヘッダを通してトレイトと比べ、本体に `'static` と書くクロージャを検査し、`mismatched_lifetime_syntaxes`
リントを加える。正しいコードへの誤ったエラーが 2 つなくなった: クロージャの中の `let _ = s;` と、`Box<dyn Fn()>` に
した `move || { let _ = r; }` である。

## 1. 加えたもの

### 借用検査

- **`let b = a;` は `&mut` のローカルをムーブする。** `s: &mut String` で `let alias = s; s.len(); alias.push('a')`
  を受け入れていた (rustc では E0382)。注釈のない `let` では、型推論が見つけた型を初期化式に期待型として渡していた。
  型が期待される所で読む `&mut` のパスは再借用されるので、ムーブが見えていなかった。その型は注釈ではないので、
  そこでの `&mut` のパスは今はムーブする。
- **`let b: &mut T = a;` は `*a` を再借用する。** 注釈のある `let` は型強制の場所である。b は `*a` のローン
  (rustc の `&mut *a`) を持つので、b が生きている間に `*a` に書くと E0506 になる
  (borrowck/borrowck-loan-of-static-data-issue-27616.rs)。以前は、b は a のコピーを持ち、ローンを持たなかった。
  `&mut` の共有の再借用が生きている間にその `&mut` をムーブすることも、今は報告する
  (borrowck/borrowck-move-mut-base-ptr.rs)。
- **メソッドの `&mut self` は、引数が生きている呼び出しの時点で取る。** `fn ext(&mut self, _: &S)` での
  `v.ext(&v)` を受け入れていた (E0502)。二相借用の予約 (引数を評価する間の共有のローン) が終わり、`&mut` のローンを
  取るのは、引数の値がなくなった後だった。今は `&mut` のローンを演算子のものと同じく呼び出しの時点で取り、そのとき
  引数はまだ保たれている。
- **`v.extend(&v)` と、`shared = &v` での `v.extend(shared)`。** `extend` は
  `let __exr_ext = <arg>.iter(); v.extend(__exr_ext)` として下ろす。そのローカルはイテレータが借用するものを
  持っていなかったので、v の `&mut` はそれと衝突しなかった (borrowck/two-phase-reservation-sharing-interference-2.rs)。
  今はそれを持ち、持っている間に v の `&mut` を取る。
- **キャプチャした `FnMut` のクロージャを呼ぶクロージャは、それを可変で借用する。** キャプチャしたものを変更する
  `tick1` で `let tick2 = || { tick1(); };` とすると、`tick1` を `&mut` でキャプチャする。なので tick2 自身も
  `FnMut` であり、どちらの束縛にも `mut` が要る (E0596、
  unboxed-closures/unboxed-closures-infer-fnmut-calling-fnmut-no-mut.rs)。
- **クロージャの中の `let _ = place;` は何もキャプチャしない (エディション 2021)。** `move || { let _ = s; }` は
  s をクロージャにムーブしていたので、後で s を使うと「ムーブした値の使用」になった。`move || { let _ = r; }` の
  `Box<dyn Fn()>` は r の借用が `'static` であることを要求していた。rustc はどちらも受け入れる (RFC 2229 の fake
  read)。エディション 2021 より前は、rustc と同じくクロージャは変数をキャプチャする。どのエディションかは
  サマリーのキャッシュのキーに入る。
- **ブロックの末尾の一時値は、下ろしたときの値が持つものを持つ。** `Drop` の impl を持つ一時値の受け手
  (ブロックの末尾の `id(rows).len()`、`rows.wrap().len()`) は、ブロックのローカルより後に drop される。それが持つ
  ものは、下ろしたときに借用したものからではなく型から読んでいたので、`rows` を通して持つ `stmt` のローンを
  見落としていた (nll/issue-54556-stephaneyfx.rs、E0597)。
- **実行時にしか分からない引数で呼ぶコンストラクタは一時値を作る。** `f(&Some(s))` を昇格した定数と取り違えていた
  ので、借用が文より長く生きても気付かなかった (E0716)。今は定数の引数のコンストラクタだけを昇格する。
- **呼び出しの結果が指す先からコピーで取り出した参照は、そこに届いた借用を持たない。** `names: Vec<&str>` での
  `let t = *names.first().unwrap(); names.clear();` を拒否していた。rustc は受け入れ、main も拒否する。
  `names.first().copied()`、`HashMap<u8, &str>` の `m[&1]`、`w.iter().copied().next()`、`&&str` の `r.clone()` も同じ
  だった。今は、コピーした型の値を持つ型の場所 (入れ物、または参照そのもの) のローンを、その場所が持つものとして
  扱う。それ以外のローン (`*id(&&s)` の `&s`) は保つ。
- **`Clone` の境界のない `x: T` での `(&x).clone()` は参照のコピーである。** それは x を借用するので、返すと E0515
  になる (borrowck/borrowck-return-variable-on-stack-via-clone.rs)。

### リージョン

- **impl のヘッダを通して、impl のメソッドをトレイトと比べる。** `impl HaveRelationship<&ProofReader> for Article`
  では、トレイトの `fn get_relation(&self) -> To` の `To` はヘッダの `&ProofReader` であり、`&self` がそれより長く
  生きると分かっていない impl のリージョンである。`fn get_relation(&self) -> &ProofReader` を受け入れていた
  (traits/param-without-lifetime-constraint.rs、「`impl` item signature doesn't match」)。今はヘッダのトレイトの
  引数が比較の普遍リージョンになる。ヘッダの `&'static` は比べず、impl のメソッドの `&'static` の入力はより一般的で
  ない (E0308)。
- **本体に `'static` の注釈があるクロージャを検査する。** `|| { let p: &'static mut usize = &mut self.food; }` を
  受け入れていた (regions/regions-addr-of-upvar-self.rs)。クロージャはリージョンのシグネチャがあるときだけ
  リージョン検査をするが、これにはなかった: 境界も、注釈のある引数もなく、関数の検査はオフだった。今はその
  クロージャが、関数自身の `let x: &'static T` と同じくそこで関数の検査をオンにし、シグネチャを得る。そうすると、
  キャプチャを通して届くものは `'static` より短く借用されている。
- **関数のシグネチャで、別の数のライフタイム引数を書いた構造体は E0107。** `struct Foo<'c, 'd>` に対する
  `Foo<'_, '_, 'a>` をシグネチャでは検査していなかった (lifetimes/noisy-follow-up-erro.rs、
  generic-associated-types/missing_lifetime_args.rs)。プログラム自身の型だけを検査する。そのように書いた prelude の
  型 (`Cow<'static, str>`) は検査しない。prelude の型はすべてがライフタイム付きで宣言されてはいないからである。

### リントと行

- **`mismatched_lifetime_syntaxes`。** `#![deny(mismatched_lifetime_syntaxes)]` か、アイテム自身の `#[deny(..)]`
  があるとき、入力のライフタイムを出力で別の書き方にする自由関数はエラーになる。書き方は、名前付き (`'a`)、省略
  (`&u8`)、隠したもの (`S<'_>` に対する `S`) である。例: `&'a u8` を受けて `&u8` を返す、`&u8` を受けて `S` を
  返す。出力の省略したライフタイムは省略規則どおりに決まる: 受け手のライフタイム、なければただ 1 つの入力の
  ライフタイムである。メッセージは rustc のものである (lifetimes/mismatched-lifetime-syntaxes-details/:
  example-from-issue48686.rs、missing-lifetime-kind.rs、not-tied-to-crate.rs、path-count.rs、static.rs)。
- **名前付きの入力ライフタイムが 1 つのときの `impl Trait + use<'_>`。** `fn e<'a>(v: &'a u8) -> impl FnOnce() +
  use<'_>` は E0106 (「missing lifetime specifier」) だった。そこでの `'_` はただ 1 つの入力ライフタイムである。
- **検査が始まる所の、引数のない呼び出しの E0310。** 検査がその呼び出しで始まった関数の中の、
  `fn s<T: 'static>()` に対する `s::<T>()` を、関数の最初の行で報告していた。今は呼び出しで報告する。
- **`&` を通して書くクロージャのキャプチャ。** `z.0.0: &(String, String)` での `|| { z.0.0.0 = .. }` を、本体の
  中の使用ではなく、rustc と同じくクロージャで報告する
  (closures/2229_closure_analysis/diagnostics/cant-mutate-imm-borrow.rs、mut_ref.rs)。

## 4. レビュー (CodeRabbit、rustc 1.97 と照らした)

#67 への CodeRabbit の最初のレビューには 11 件の指摘があった。それぞれを、それを示すプログラムに zustc をかけて
確かめた。9 件は書かれたとおりの誤った結果を示した。残りの 2 件は、試した中では誤った結果を示さなかったが、これも
直した。すべてをテストする (`part13_review`)。

9 件:

- **リストとしての `mismatched_lifetime_syntaxes` の属性** (2 件)。`#[deny(dead_code, mismatched_lifetime_syntaxes)]`
  はアイテムのリントをオンにしなかった。クレート全体の deny の下で、`#[allow(dead_code, mismatched_lifetime_syntaxes)]`
  と `#[expect(..)]` はそれをオフにしなかった。今はアイテムの `allow` / `expect` / `warn` / `deny` / `forbid` の
  リストを読む。
- **構造体と同じ名前の型パラメータ** (`struct S<'s>` があるときの `fn f<'a, S>(x: &'a u8) -> (Option<S>, &'a u8)`) を、
  ライフタイムを隠す構造体と取り違えていた: リントの誤ったエラーである。そのような構造体は、その関数では除く。
- **`let _ = x;` は unused 変数のリントにとって x の使用である。** fake read の後、エディション 2021 で
  `#![deny(unused_variables)]` が x を未使用と報告していた。
- **クロージャの中の `let .. else` のブロック** (2 件)。その中の `let _ = x;` を fake read として見つけていなかった
  が、キャプチャの解析はそれを飛ばしていたので、x の下ろしが失敗した (「cannot find value」)。その中の
  `let p: &'static usize = x;` はクロージャの検査をオンにしなかった。今はどちらの `let` も `else` のブロックの中で
  見つける。
- **プログラム自身の `clone`。** S に `fn clone(&self) -> &'static S` があるときの `(&local).clone()` を参照のコピー
  と読んでいたので、それを返すと誤った E0515 になった。今はその読み方を、`clone` メソッドのない参照先だけにする。
- **クロージャの中の `let _ = s.missing;`** は fake read として飛ばすので、ないフィールドを報告していなかった。今は
  クロージャを作る所で E0609 になる。
- **`fn get(&self) -> &u8` と `fn take(&mut self, _: &u8)` での `s.take(s.get())`** を受け入れていた (rustc では
  E0502)。引数の共有のローンを、`&mut self` を取るまで保っていなかった。呼び出しの `&mut self` を引数の後で取る
  とき、今は参照を持つ引数が借用するものをそれまで保つ。`&&str` の `r.clone()` はコピーで取り出した `&str` である
  (1 節) ので、`v.push(v.first().unwrap().clone())` は受け入れたままである。

2 件:

- **キャッシュのキーの中のエディション。** エディションはクロージャが何をキャプチャするかを決めるが、関数のキーと
  クレートの指紋はそれを持っていなかった。1 つのファイルを 2 つのエディションで同じディレクトリにビルドする場合は
  もともと正しかった。クロージャのサマリーが親のキーを変えるからである。今はどちらもエディションを持つので、
  ワークスペースのクレートの指紋も変わる。
- **`trait Dup: Clone`。** サマリーはトレイトのスーパートレイトから `Clone` と `Copy` を除くので、`T: Dup` を確かに
  Clone でない型と取り違えていた。試したプログラムでは誤った結果にならなかった。今はそれらの印を保ち、テストが
  このケースを守る (`duplicate::<T: Dup>(x)` がビルドでき、動く)。

## 5. まだ扱わないもの

- **impl のヘッダの中のトレイトオブジェクトの既定のライフタイム。** `impl DebugWith<dyn DebugContext> for Foo` では
  トレイトの `Cx` は `dyn DebugContext + 'static` になるので、`cx: &dyn DebugContext` での `bar.debug_with(cx)` は
  借用したデータを逃がす (nll/issue-54779-anon-static-lifetime.rs)。オブジェクトのリージョンは呼び出しでの新しい
  変数であり、ヘッダの `'static` ではない。`&dyn Error` で呼ぶ `impl dyn Error + 'static` のメソッドも同じである
  (regions/regions-static-bound-on-type-param.rs)。
- **型パラメータのあるトレイトオブジェクト** (`dyn A<T>`) は書いたままのテキストを保つ: その型の構造体の
  フィールドはインスタンスの型引数を取らないので、`B<'a, T>(&'a (dyn A<T> + 'a))` での `B(&*v)` は推論されない
  (regions/regions-close-object-into-object-*.rs)。
- **クロージャの本体が参照でキャプチャするローカルに要求すること** は、その関数に戻さない: ローカル x に対する
  クロージャの `let p: &'static usize = &x;` は受け入れる。その要求はクロージャの外から来たクロージャの環境に
  かかり、関数はそれを見ない。リージョンが関数自身のもの (引数の、`self` の) であるキャプチャだけを検査する。
- **関数の型パラメータに `T: 'static` を要求する、クロージャの中の呼び出し** (nll/issue-98693.rs) は検査しない:
  クロージャの本体には、関数の型パラメータのプレースホルダのリージョンがない。
- **参照を持つローカルを、その借用先のメソッドに渡すこと** (`let w = &v; v.ext(w)`): 引数は受け手の `&mut` を取る
  前に読まれ、w のローンは呼び出しまで保たれない。
- **`mismatched_lifetime_syntaxes`** は自由関数のシグネチャだけを検査し (メソッドとトレイトのアイテムは検査しない)、
  ソースの最初の食い違いだけを報告する (rustc はそれぞれを報告する)。マクロの展開は検査しない
  (lifetimes/mismatched-lifetime-syntaxes-details/macro.rs)。
