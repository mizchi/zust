# リージョン (ライフタイム) 検査、その 10: クロージャのキャプチャ、ガード、パターン、暗黙の再借用、`'static` のインスタンス (issue #1)

日付: 2026-11-22

その 9 ([2026-11-22-06](2026-11-22-06-region-check-9.md)) は #51 でマージした。この段階では、tests/ui で受け入れて
いると分かった場合をさらに扱う。また、生成したコードが値を 2 回 drop するプログラムを zustc が受け入れていた 3 つの
場合を直す: 値でキャプチャを持つクロージャ、オーバーロードした `Deref` が返すものからのムーブ、そして (その 9 の
レビューから) `FnOnce` とみなしていた名前付きの `move` クロージャ。

## 1. 足したもの

### 借用検査

- **drop が要る変数のキャプチャを値で持つクロージャ。** `move` クロージャか、本体がその変数をムーブするクロージャ。
  - 生成するコードは変数全体をクロージャへコピーする。借用検査は、rustc がキャプチャするように、本体が使う部分
    だけをムーブしていた。そのため、クロージャの後で使う部分が 2 回 drop された。これは main で見つけた:
    `p.s: String` での `move || p.n` の後の `drop(p.s)` は `p.s` を 2 回解放する。
  - 本体が `Copy` の部分だけを使い、残りを空にできるときは、クロージャの側のコピーから drop の要る部分を空に
    する。残りを空にできるのは、型の中にプログラムの `Drop` impl がないとき。このとき変数はムーブせず、rustc と
    同じく元の場所で drop する。tests/acg/closure_copy_parts.rs がこれを `Rc` の数で示し、その数は rustc と同じ。
  - 本体が `Copy` でない部分を使うときは、変数全体をムーブする。クロージャの後で部分を使うと E0382 になる。
    rustc はこれを受け入れる。
  - drop の要らない変数は、これまでどおり部分ごとに追う。
- **値でキャプチャした `&mut` はムーブする。** `move` クロージャのとき、または本体の `let` を通すとき
  (`|| { let bar = b; }`) に起きる。借用検査は、渡すと再借用になるので `&mut` を `Copy` と数えるが、そうした
  キャプチャは再借用しない。引数として渡す `&mut` (`drop::<&mut U>(x)`) は再借用かもしれないので、その場合は
  追わない。
- **暗黙の再借用を通した E0713。** `Drop` の値の `&mut` のフィールドを、`&mut` を求める所に渡すと再借用になる:
  `members.push(child.raw)` は `members.push(&mut *child.raw)`。
  - そうしたローンを値より長く生きる所に格納すると E0713 になる。ローカル (nll/issue-53773.rs、ループの中) にも、
    関数が返るときに drop する引数にも当てはまる。
  - 期待する型は、呼び出しが既に知っている型パラメータでもよい (`Vec<&mut T>::push`)。
  - リージョンが 1 つの関数では、ローンの生きる長さを知っているリージョン検査を、この場合のために有効にする。
- **`Drop` の値がスコープの終わりで drop されるときの E0713。** 値の `&mut` のフィールドを通した借用で、値の後も
  使われているもの (ブロックの中の `r = &mut *s.0;` と、その後の `*r`)。これまでは、返す借用だけが E0713 だった。
- **`break` と `continue` は抜けるスコープを終える。** ジャンプが抜けるスコープのローカルは、スコープの終わりと
  同じく、ジャンプの所でスコープの外に出る。r を後で使う `loop { let x = 1; r = &x; break; }` は E0597 で、
  `continue` を通す同じ形も同じ。
- **match のガード:**
  - ガードが成り立たないと、次の arm は scrutinee をもう一度検査する。そのため、ガードがそこからムーブしたものを
    使うことになる (E0382、match の所: nll/issue-27282-move-match-input-into-guard.rs)。
  - scrutinee 全体を値で束縛するもの (`x => x`) は全体を読む。そのエラーは arm の所
    (borrowck/issue-31287-drop-in-guard.rs)。
  - arm の束縛をムーブするガードの中のクロージャは E0507。何をムーブするかは束縛の型で決める。
- **パターン:**
  - 構造体のパターンは、タプル構造体のものと同じく、部分を名前で追う。`let S { x: ax, .. } = a;` は `a.x` を
    ムーブするので、a を借用している間は E0505 (borrowck/borrowck-move-subcomponent.rs)。
  - enum でない構造体のパターンは、構造体そのものを読まない。部分のパターンが検査するものだけを読む。
  - arm で束縛した参照は match の外へ流れる (`let a = match y { Y(ref mut a, _) => a };`)。ローカルが持つものを、
    スコープの外に出ても保つようにしたので、その前に読んだ値は先へ流れる。生きていないローカルは、生きている
    ローンを持たない。`y.0` の 2 つ目の `ref mut` は E0499 で、`y.1` のものは構わない
    (borrowck/borrowck-anon-fields-*.rs)。`ref` の束縛のローンは、その arm の所で報告する。
- **代入は古い値を drop する。** 値が借用しているものを見るかもしれない `Drop` は、値のスコープの終わりと同じく、
  そこでそのローンを使う。ループの中で `w = W(&mut base);` の前の `base = false;` は E0506
  (borrowck/drop-in-loop.rs)。
- **オーバーロードした `Deref` が返すものからのムーブの E0507。** 例えば、x が `Rc<Bar>` の `x.field`
  (nll/issue-52086.rs)、ユーザーの `Deref` を通して届くフィールド、`*w`。zustc はこれらを受け入れて値をコピーで
  取り出していたので、値は 2 回 drop された。`Box` は対象外。
- **`self` が可変の束縛なのは `mut self` のときだけ。** `self`、`&self`、`&mut self` を取るメソッドの中の
  `(&mut self).bar()` は E0596。
- **キャプチャの部分を `ref mut` で束縛するクロージャ** (`let (ref mut x, _) = p;`) は、それを可変で借用する。
  そうしたクロージャは `FnMut` で `Copy` でないので、2 回目のムーブは E0382。

### リージョン

- **`Copy` の impl が `'static` のインスタンスに対するものである型のコピー** (`impl Copy for Foo<'static> {}`)。
  コピーするたびに `Foo<'_>: Copy` を示すので、コピーした値が借用するものは `'static` でなければならない
  (借用の所で E0597)。
- **型の `'static` のインスタンスに対する impl の関連定数** (`impl A<'static> { const IC: i32 = 10; }`)。
  `A::<'a>::IC` は `'a` が `'static` であることを求める ("lifetime may not live long enough")。トレイトの impl の
  定数にも、範囲パターンの中でも当てはまる。
- **型パラメータの `Fn` の境界を通した呼び出し**は、引数のリージョンを境界のものと関係づける。
- **ライフタイムを書かずに書いた `Box` の型エイリアス** (`type B<'a> = Box<&'a isize>` での `Box<B>`)。その
  リージョンはそれぞれ省略したものとする。これまでは、エイリアスの印を中の `Box` 自身のものとみなしていたので、
  パラメータのリージョンを追っていなかった。

### prelude

- `MutexGuard<T>` は、T が実装するとき `Debug` と `Display` を実装する。

## 5. レビュー

#53 への CodeRabbit の指摘を rustc 1.97 で確かめた。1 巡目の 7 件すべてが正しく、すべて直してテストした
(tests/regionck.rs の `part10_review` と、tests/acg/closure_copy_parts.rs の enum の場合)。

- **実行時の誤った値:** 1 つのバリアントの enum を持ち、その `Copy` のフィールドを使う `move` クロージャ
  (`E::V(u32, Rc<i32>)` での `let E::V(n, _) = e;`) は 0 を読んでいた。クロージャの側のコピーを、フィールドも
  含めて丸ごと空にしていた。1 つのバリアントの enum は、構造体と同じくフィールドごとに空にし、タグは残す。
- **拒んでいた正しいコード:**
  - `impl<'b> Copy for Foo<'static, 'b> {}` があると、`Foo` のどのコピーも借用すべてに `'static` を求めていた。
    ライフタイムがすべて `'static` の impl だけを追うようにした (6 節を参照)。
  - クロージャの中の `ref mut` のパターン (`let (ref mut x, _) = p;`) は p 全体を可変で借用していたので、外で
    生きている `p.1` の共有の借用と衝突した。パターンが `ref mut` で束縛する部分を借用するようにした。
  - ガードのブロックの中で arm の名前を束縛し直す `let` (`let foo = ..;` の後に foo をムーブするクロージャ) を、
    arm の束縛とみなしていた (E0507)。検査はブロックの `let` を追うようにした。
- **見逃していたエラー:**
  - クロージャの中の `let bar = (b);` が b をムーブしていなかった: 括弧がムーブの検査からキャプチャを隠していた。
  - `let r = { let s = Scribble(&mut x); &mut *s.0 };` の後で r を使うと E0713。`&mut` のフィールドを通した
    借用はブロックの終わりで s とともになくなり、r はその後でそれを受け取る。
  - `Rc` への参照を通したムーブ (`r: &Rc<S>` での `r.value`) は、`Rc` そのものを通すときと同じく E0507。
- **2 巡目** (3 件、すべて正しい; tests/regionck.rs の `part10_review_2`):
  - 1 巡目の修正の後、`impl Copy for Foo<&'static u32> {}` を追わなくなっていた: ライフタイムを書かないパスはそれ
    自身の場所として数えられ、検査はそれを `'static` 以外のライフタイムとみなしていた。
  - キャプチャの解析が辿らない `ref mut` のパターンの部分 (`S { value: ref mut y }`) を落としていたので、共有で
    借用していた。可変で借用するようにした (その共有の借用が生きていれば E0502)。
  - arm の束縛を名指すガードの中の `move` クロージャは、本体が借用するだけでも、作るときにそれをムーブする
    (E0507)。

## 6. まだ扱わないもの

- **self 型が `'static` とほかのライフタイムを持つ `Copy` の impl** (`impl<'b> Copy for Foo<'static, 'b>`) は
  追わないので、`'static` の場所がローカルを借用するコピーは見逃す。検査するには、型でなく場所を分けて保つ必要が
  ある。

- **プログラムの `Drop` impl を持つ型で、クロージャが値で持ち、本体が `Copy` の部分だけを使うもの。** クロージャは
  まだ値全体を持つ。生成するコードは変数をムーブ済みとするが、借用検査は残りを使わせる:
  `let c = move || x.id; drop(x);` は x を 2 回 drop する。rustc の部分ごとのキャプチャには、クロージャが部分
  そのものを持つ必要があり、生成するコードはまだそうしない。
- **値で変数を持つクロージャが使う、`Copy` でない部分**は、変数全体をムーブする。クロージャの後で残りを使うと
  E0382 になり、rustc はこれを受け入れる。
- **クロージャが引数として渡す `&mut`** (`FnMut` の境界に渡すクロージャの中の `drop(r)`) は、再借用かもしれない
  ので、ムーブとして追わない。
- **その 9 から:** 型パラメータでない型への where 句、関数本体の中のアイテムのそれ以外のエラー、大文字の名前の
  ローカル、E0582 と射影、書式の引数と impl の境界、`match *ptr` のガードでの `*ptr = ..` (rustc では E0506)。
  [その 9](2026-11-22-06-region-check-9.md) の 6 節を参照。
- **tests/driver2.rs と `probe/stdin_read`:** バックグラウンドで走らせると、まだときどき失敗する (その 9 を参照)。
