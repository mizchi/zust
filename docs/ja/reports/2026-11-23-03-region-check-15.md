# リージョン (ライフタイム) 検査、その 15: スライスのパターン、クロージャの変数全体のキャプチャ、`copied` のイテレータ、エディション 2024 のブロックの末尾、`unused_mut`、GAT の引数 (issue #1)

日付: 2026-11-23

その 14 ([2026-11-23-02](2026-11-23-02-region-check-14.md)) は #69 でマージした。この段階では、スライスのパターンの
要素をそれぞれの場所にし、エディション 2021 より前のクロージャで変数全体をキャプチャし、イテレータの借用を
`copied` / `cloned` のアダプタに残し、エディション 2024 でブロックの末尾の一時値をブロックとともに終え、lint の
`unused_mut` を加え、ジェネリックな関連型の引数と、`impl` / `dyn` の型や where 節に書いたライフタイムを検査する。また、構造体と同じ名前の fn の呼び出しを、その構造体のコンストラクタとして
コンパイルしていたのを直す。

## 1. 加えたもの

### 借用検査

- **スライスのパターンの要素は場所である。** `s: &mut [i32]` での `if let [ref first, ref second, ..] = *s { if let
  [_, ref mut second2, ..] = *s { .. } }` を受け入れていた (borrowck/borrowck-slice-pattern-element-loan-slice.rs、
  E0502)。(配列でない) スライスの要素には場所がなかったので、ローンもなかった。今は、rustc の MIR と同じく、要素を
  パターンの端から、パターンが要る最小の長さとともに数え、rustc の `place_projection_conflict` と同じく重ねる:
  - 先頭から b 番目と末尾から e 番目は、b + e が両方のパターンが要る最小の長さに届くとき、同じ要素でありうる
    (`[ref a, ..]` と `[.., ref mut b, _, _, _]` は、長さ 4 のスライスの同じ要素でありうる);
  - 残り `[f..-t]` は、b >= f のとき先頭から b 番目を、e > t のとき末尾から e 番目を持つ;
  - 2 つの残りは重なりうる。

  残り `ref mut t @ ..` は、自分の `mut` ではなくパターンの既定の束縛モードから可変性を取っていたので、`&[T]` の型に
  なっていた (run-pass のテストの borrowck/borrowck-slice-pattern-element-loan-rpass.rs が、今はパスする)。スライスの
  残りも場所なので、それが借用するものからムーブするパターン (`&[Foo { string: a }, ..]` に照合する `ref tail @ ..`)
  を報告する (borrowck/borrowck-move-out-of-vec-tail.rs)。
- **エディション 2021 より前、クロージャは変数全体をキャプチャする。** `self.thing.bar(|| { &self.number; })` は、
  `self.thing` の `&mut` が予約されている間に `self` を借用する (nll/issue-51268.rs、E0502)。今はエディション 2015 と
  2018 で、キャプチャする場所をその変数まで切る: `fancy_num.num` を使う `move` のクロージャは fancy_num 全体をムーブし、
  それが借用されている間なら E0505 である (error-codes/E0504.rs)。`&mut` の変数を通した一意な借用は `*x` のままであり、`mut x` を
  要らない。クロージャの本体では、クロージャが参照で持つ変数は、その参照の `*x` のままである
  (nll/issue-40510-4.rs は受け入れたままである)。
- **イテレータの `copied` / `cloned` はイテレータの借用を持つ。** これらをどの場合も `Option<&T>` のものとして扱って
  いた: 結果は受け手の根が持つものを持ち、借用を持たなかった。今は:
  - `v.iter().copied()` は v の借用を持つので、それが生きている間の `v.push(1)` は E0502 である;
  - `impl Iterator<Item = u8>` として返す `s.0.iter().copied()` は s のライフタイムをキャプチャする
    (nll/issue-73159-rpit-static.rs、E0700);
  - そのようなイテレータから取り出すもの (`.next()`、`.collect()`、その上のアダプタを通しても) は写しである:
    `names.iter().copied().filter(..).collect::<Vec<&str>>()` は names の借用を持たない。これは main でも誤った
    エラーだった。

- **エディション 2024: ブロックの末尾の一時値はブロックの終わりで消える。** `let _ = { String::new().as_str() }
  .len();` を受け入れていた (lifetimes/tail-expr-in-nested-expr.rs、E0716)。今は、(関数の本体でない) ブロックの末尾
  を、その一時値にとって 1 つの文とし、一時値はブロックとともに終わる。値がそれらの 1 つへの参照であるブロックは、
  その終わりより後まで保たれるので、それをすぐ使うのも E0716 である。2021 では、一時値は囲む文の終わりまで生きたまま
  である。

### lint

- **`unused_mut`** を `#![deny(unused_mut)]` (または `unused`、`warnings`) のもとで: 何も可変を要らない `let mut` は、
  その `let` でのエラーである (nll/issue-61424.rs、nll/capture-mut-ref.rs、
  lint/unused/unused-mut-warning-captured-var.rs)。借用検査が、何かが可変を要る `mut` のローカルに印を付ける:
  - それが所有するものの `&mut`、`+=`、一部への書き込み;
  - その全体への 2 度目の代入 (`let mut x;` では、データフローが見つけるとおり);
  - (それが持つ `&mut` を通してではなく) その変数そのものを変えるクロージャ;
  - for ループの `&mut` / `iter_mut`;
  - そのローカルが所有する配列の `&mut self` を取るメソッド (`a.swap(0, 1)`: 配列のメソッドはそのメモリの上に
    下ろす)。`&mut` の束縛を通したもの (`s: &mut [i32]` の `s.sort()`) ではない。

  これは、クレートが deny し、ソースのどこにもその `allow` / `warn` / `expect` を書いていない所でだけ検査する: クレート
  より下の lint のレベルは追わない。引数は検査しない。その位置をまだ持たないからである。

### リージョンとシグネチャ

- **ジェネリックな関連型の引数で、そのトレイトや impl のものと同じ名前のもの**: ライフタイムは E0496、型パラメータ
  は E0403 である (generic-associated-types/shadowing.rs)。
- **`impl` と `dyn` の型、where 節の型の中の E0261**。その項目が `for<..>` を書かない所で: `'a` のない
  `Box<dyn X<Y<'a> = &'a ()>>` (generic-associated-types/issue-67510.rs)、`impl Iterator<Item =
  Self::Item<'missing>>` (impl-trait/in-trait/missing-lt-outlives-in-rpitit-114274.rs)、`&'missing Self: Add<Self>`
  であり、その述語で報告する (traits/eval-caching-error-region.rs。これはもう 1 つのエラーでもうパスしていた)。

### コード生成

- **中かっこの構造体と同じ名前の fn は呼ばれ、そのコンストラクタと取り違えない。** `struct AddFlags { .. }` と
  `fn AddFlags(..) -> AddFlags` では、`&AddFlags(1)` を構造体のコンストラクタとして static に昇格していた: fn が
  呼ばれないので、その出力と結果が失われ、一時値も作らないので、生かしたままの `arg(&AddFlags(1))` を受け入れていた
  (borrowck/rvalue-borrow-scope-error.rs、E0716)。今は、昇格、リージョン検査の定数、借用検査の一時値が、呼び出しの
  下ろし方と同じく、そのようなパスを fn とする。tests/acg/fn_named_like_struct.rs が出力を rustc のものと比べる。

### 基盤

- **フェイクリードのエディションのフラグはスレッドのものである** (`ast_closure::WILD_FAKE_READS`)。これはそれぞれの
  解析が設定するプロセス全体のフラグだったので、1 つのプロセスで同時に走るエディションの違う 2 つの解析 (テストは
  スレッドで走る) が、互いのものを読んでいた。その 14 はこれを、まだ扱わないものに挙げていた。エディション 2015 と
  2018 を検査するこの段階のテストで、それが起きた。

## 4. レビュー (CodeRabbit、rustc 1.97 で確かめた)

#71 への CodeRabbit の最初のレビューには 5 件の指摘があった。それぞれを、それを示すプログラムを zustc と rustc で
動かして確かめた。4 件は当たっており、直してテストした (`part15_review`):

- **`<` から離れた `for`。** `Box<dyn for\n<'a> Fn(&'a u8)>` (間に改行や空白がある) は誤った E0261 だった: 束縛子を
  `for<` か `for <` としてだけ探していた。今は `<` の前のどんな空白や改行も数える。
- **下ろし方が作る束縛。** `#![deny(unused_mut)]` のもとの `let Foo { value: &n } = Foo::<&'static u32> { value: &X };`
  が、下ろし方の作る束縛 `#sl0` を報告していた。`#` で始まる名前は検査しない。
- **配列を読むだけのメソッド。** `let mut a = [1, 2]; a.len();` を報告していなかった (rustc では unused_mut): 配列の
  どのメソッドも、それを `mut` に要るものとして数えていた。今は `&mut self` を取るもの (`swap`、`sort`、
  `copy_from_slice` ..) だけである。
- **`&mut` の束縛を通したスライスのメソッド。** `let mut s: &mut [i32] = &mut a; s.sort();` を報告していなかった:
  メソッドは s が指すものを書き換え、それに `mut s` は要らない。

5 件目、ローカルが持つ copied のイテレータ (`let mut it = v.iter().copied(); it.collect()`) を返すと v の借用が
残る (誤った E0515)、は起きなかった: zustc はこれを受け入れ、プログラムは rustc のものと同じものを出力する。

2 回目には 1 件あった。プログラムの `impl Touch for [i32; 2] { fn touch(&mut self) }` での
`let mut a = [0, 1]; a.touch();` は、配列を読むだけなので誤った unused_mut になる、という指摘だった。それは起きなかったが、
より悪い理由による: その呼び出しは型の不一致 (`&mut [i32; 2]` を期待し `&[i32; 2]` を見つけた) で、main でもそうだった。
今はそのようなメソッドは配列を `&mut` で取る: その可変の借用であり、`mut` でなければ E0596、`mut` を要る使い方である。

1 回目と 2 回目のレビュー本文にある差分の外への指摘と、3 回目の 2 件は、どれも当たっており、直してテストした
(`part15_review`):

- `(` の前に空白のある `#[allow (unused_mut)]` を、許可として数えていなかった (誤った unused_mut)。
- エディション 2024: `{ (String::new().as_str(),) }.0.len()` を受け入れていた (rustc では E0716)。今は、参照である値だけで
  なく、末尾の一時値への参照を持つブロックの値も、その終わりより後まで保ち、タプル・配列・構造体の末尾の要素を、その直接の
  一時値とする。
- `&mut self` のメソッドでの `a: [String; 1]` の `a.touch()` は「borrow of moved value」だった: 配列を値として読んでいた。
  今はムーブなしに読む (`&self` のメソッドでも)。
- 配列に実装したトレイトの `unsafe fn` を、`unsafe` の外で呼べていた (rustc では E0133)。
- `struct S<T: Sized>` での `struct W<T: ?Sized + Clone> { value: S<T> }` は、#70 が加えた検査による誤った E0277 だった:
  std の `Clone`、`Copy`、`Default` は `Sized` を上位トレイトに持つ。

## 5. まだ扱わないもの

- **引数の `unused_mut`** (`fn foo(mut self)`、クロージャの `|(mut x, _)|`: lint/unused/lint-unused-mut-self.rs、
  nll/unused-mut-issue-50343.rs): その位置をまだ持たない。クレートより下の lint のレベルも追わない: lint の `allow` が
  どこかにあればそれを止める (lint/unused/lint-unused-mut-variables.rs)。
- **`mut` と宣言しないローカルの E0596** を、for ループの `v.iter_mut()` / `&mut v`、配列の書き換えるスライスの
  メソッド (`a.sort()`、`a.swap(0, 1)`)、配列の `&mut a[..2]` では報告しない: これらは、検査が読む `&mut` の
  アクセスなしに下ろされる。`unused_mut` はこれらを `mut` を要るものとして数える。
- **配列のフィールドの `iter()` を通した E0700** (impl-trait/static-return-lifetime-infered.rs): 配列の `iter()` は
  その借用を記録しない。ローカルの配列の `arr.iter()` を `for` ループの外で使うのも、まだ扱わない。
- **エディション 2021 より前のクロージャの中の `let _ = place;`** は変数をキャプチャするが、そのローンを作らない
  ので、クロージャが生きている間の `x.thing = 1` を受け入れる (rustc では E0506)。
- **エディション 2024 の関数の本体の末尾** は、その一時値について 2021 の規則のままである。
- その 14 から: E0700 はもう一度代入するローカルを追わず、リージョン検査はクロージャの正確なキャプチャを扱わない。
