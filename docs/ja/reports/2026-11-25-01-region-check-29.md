# リージョン (ライフタイム) 検査、その 29: drop が借用したものを使う一時値、それを終わらせるスコープ、返す一時値の E0515 (issue #1)

日付: 2026-11-25

その 28 ([2026-11-24-14](2026-11-24-14-region-check-28.md)) は #154 でマージされた。この段階で加えるもの:

- フィールドアクセスの基底やメソッドの受け手として作られた、型が `Drop` を実装する一時値。それは drop されるまで、
  借用したものを保つ;
- そういう一時値を、rustc が drop するところで drop するスコープ: `if` や `while` の条件、match のガード、ループ;
- 一時値の借用を保つ値を返すところでの E0515。一時値がなくなるところでの E0716 ではない;
- シグネチャが名指すスライスのイテレーターの型 (`&mut std::slice::Iter<'a, T>`) に対するイテレーターのライブラリ;
- lowering が作ったノード (Vec の `&*v`) での、前の借用の位置。

## 1. 加えたもの

- **drop が借用したものを使う一時値。** `impl Drop for D<'_>` のある `struct D<'a>(&'a [i32])` を考える。
  `for x in D(&*v).iter() { v.push(*x); break; }` では、`D` の一時値はループが終わるまで生き、その drop は `&*v` を
  使いうる。rustc は `v.push` で E0502 を出す (borrowck/issue-82462.rs)。zustc は、受け手を評価したところで一時値の
  借用を落としていた。
  - フィールドアクセスの基底 (`D(&*v).0`) やメソッドの受け手 (`D(&*v).iter()`) であるそういう一時値は、今は drop
    されるまで借用を保つ:
    - その文の終わりまで;
    - ループの頭のものは、ループの後まで;
    - `while let` の検査される値のものは、各反復まで。
  - これをするのは、drop が借用したものを使いうる型 (dropck) に限る。`Drop` のない `W` での `W(&*v).iter()` は今も
    受理する。`let n = D(&*v).0.len(); v.push(n as i32);` も受理する。
  - ブロックの末尾としての `match D(&*v).0.len() { n => v.push(n as i32) }` は、rustc と同じく `v` の E0597 である:
    一時値はブロックの局所変数より長く生きる。
  - これまでは、`std::slice::Iter<'_, i32>` を返す、プログラム自身の型の `iter()` は型検査に失敗していた:
    - 「`.iter()` is only supported directly in a `for` loop」;
    - または「no method named `into_iter` found for `Iter<i32>`」。
  - 型だけを名指すところでは、prelude のイテレーターのライブラリを取り込んでいなかった。今は取り込む。
    `xs: &mut std::slice::Iter<'a, i32>` でもそうする。
- **そういう一時値を終わらせるスコープ。** rustc では、`if` や `while` の条件と match のガードは終わりのスコープ
  (terminating scope) である: その一時値は、その終わりで、分岐や本体やアームを実行する前に drop される。この作業の
  最初の版は、上の一時値を文の終わりまで保っていた:
  - それは、ブロックの末尾にある条件やループで、誤った E0597 を出した;
  - ガードの一時値がそのアームとぶつかった。最初のサイクルは、run-pass のテストである
    match/match-ref-binding-in-guard-3256.rs を拒否した。
  - 今は、条件とガードの一時値をその終わりで drop する。`if D(&*v).0.len() > 0 { v.push(1); }` と
    `while D(&*v).0.len() < 5 { v.push(1); }` は、rustc と同じく受理する。
  - ループの頭の一時値は、ループとともに drop する。fn の末尾では、zustc は今、これらのケースで rustc と一致する:
    - `for x in D(&*v).iter() {}` と `while D(&*v).0.len() > 5 {}` は受理する;
    - `for x in D(&*v).0.iter() {}` と `while let Some(_) = D(&*v).0.first() { break; }` は E0597 である。
- **返す一時値の借用。** `fn f(xs: Vec<i32>) -> Vec<&'static i32>` で
  `for ref x in xs { result.push(x); } result` を考える。`x` はループの要素、つまり一時値を借用する。rustc は
  `result` で E0515 (「cannot return value referencing temporary value」) を出す。zustc はループの頭で E0716 を
  出していた。
  - 返す値が保つ一時値の借用の E0716 は、今はそれを返すところでの E0515 である。
  - 返す局所変数の使用 (`println!`) やそれへの代入 (`result = Vec::new()`) の後でもそうである。rustc も同じものを
    出す。
  - `&mut std::slice::Iter` の上では、要素の一時値はループの頭で作られる。次の要素のためにそれを束縛すると、その古い
    借用が `result` の保つものから落ちるので、return は何も保っていなかった: E0716 は fn の行にあった。
    - 今は、E0716 はその借用を保つ生きた局所変数を覚えておく。
    - そのどれかを return すると、そこでの E0515 になる。
  - どの返す値も保たない借用は E0716 のままである (そういう `result` の `*result[0]`)。
- **lowering が作ったノードの位置。** Vec の `&*v` は `&v[..]` に lowering され、そのノードは位置を持たない。そこでの
  エラーの前の借用は「(at 1:1)」か fn の行にあった。今はオペランドの `v` にあり、rustc が指すところである。

## 4. レビュー

CodeRabbit は 28f9156 の #155 をレビューし、3 つを指摘した。どれも zustc と rustc 1.97 で確かめた:

- **実行時の、ガードの一時値。** 検査はガードの一時値をそのアームの前で終わらせるが、コンパイルしたコードはそれを
  アームの後で drop していた。
  - D の drop が借用したものを表示する `_ if D(&x).ok() => { x = 2; }` を考える。プログラムは `drop 2` を表示した。
    rustc のものは `drop 1` を表示する。main も同じだった。
  - 今は、ガードの一時値を分岐の前で drop する。
  - 新しい driver2 の probe である tests/probe/guard_temp_drop.rs が、それをビルドして実行する。期待する出力は
    rustc 1.97 のものである。
- **メソッドが値で受ける一時値の受け手。** `fn consume(self)` に対する `(D(&x).consume(), { x = 2; })` は誤った
  E0506 だった。隠れた局所変数が、受け手の借用を文の終わりまで保っていた。
  - 今は、受け手を値で受ける呼び出しが、その局所変数の保つものを終わらせる。
  - 参照で受ける受け手 (`peek(&self)`) は借用を保ち、rustc と同じく E0506 である。
- **借用した一時値を使った後に代入される、返す局所変数。**
  `let mut r = String::new().as_str(); println!("{}", r); r = "ok"; r` を考える。指摘は、これは return での E0515 では
  なく、一時値での E0716 だと言った。rustc 1.97 は zustc と同じく return で E0515 を出すので、変えていない。
- tests/regionck.rs が 2 つ目と 3 つ目を確かめる (`part29_review`)。

## 5. まだ扱わないもの

- **`&` の式自身の位置。** AST の `&` は位置を持たないので、`D(&v)` や Box での `&*b` の借用はそのオペランドにある。
  それは rustc の `&` の 1 列後で (rustc の 4:42 に対して 4:43)、main と同じである。メッセージの「(at …)」だけに
  現れる。
- **fn の最初のエラーの後のエラー。** zustc は fn ごとに 1 つのエラーを出す。fn の末尾としての
  `match D(&*v).0.len() { n => v.push(n as i32) }` では、rustc は E0597 とその後に E0502 を出し、zustc は E0597 を
  出す。
- **一時値の `Box::new(..)` に対して呼ぶ `self: Box<Self>` のメソッド。** `fn f(self: Box<Self>)` に対する
  `Box::new(S).f()` は、main と同じく「mismatched types: expected `Box<S>`, found `S`」を出す。
