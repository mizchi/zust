# リージョン (ライフタイム) 検査、その 35: 参照を持たない型のドロップ (issue #1)

日付: 2026-11-25

その 34 ([2026-11-25-06](2026-11-25-06-region-check-34.md)) は #161 でマージした。#1 はいまは閉じており、残りの作業は
#166–#171 にある。この段階は、参照を持たない `Drop` の型のドロップ検査を直す。#161 の最後のレビューの軽微な指摘である。

## 1. 変えたもの

- **参照を持たない型のドロップ。**
  - ドロップ検査は、`Drop` の impl のある型をすべて、その値が借用するものを見うるドロップとしていた。
  - そのため、`Token` をフィールドのない `Drop` の型として、`let mut d = (None, Token); { let x = 1; d.0 = Some(&x); }`
    は main で E0597 だった。
  - 自分への借用を持つ値についての、その 34 の検査も同じ門を使っていたので、
    `let d = (Cell::new(None), 1, Token); d.0.set(Some(&d.1));` も E0597 だった。
  - rustc はどちらも受理する。そのドロップ検査が生きていることを求めるのは、`Drop` の型のパラメータが持つものだけだから
    である。
  - `Drop` の impl は、いまは参照を持ちうる型についてだけ数える。借用を持つ `Drop` の型 (`struct D<'a>(Option<&'a i32>)`)
    は、rustc と同じく E0597 のままである。
- **E0726 は #138 で入った。**
  - この段階は、はじめ impl ヘッダと `async fn` のパラメータの E0726 を、アイテムの構文木から調べていた。
  - その間に main にマージされた #138 が、同じエラーをアイテムのテキストから調べ、同じ 6 つのテストを通す。
  - その検査を 1 つにするため、この段階は E0726 を #138 のものに任せる。
  - #138 の検査が扱わないケースは #171 にある: 自分の型の中のパス (`impl Tr for Vec<Foo>`) と、列 1 ではなく rustc の列。
  - この段階の E0726 のケースのテストは残す (`part35_elided_lifetimes_in_impl_headers_and_async_fns`)。#138 の検査で
    通る。

## 4. レビュー

CodeRabbit の最初のレビュー (c4a0361 の) は 3 つの指摘と 1 つの nitpick をした。どれも、この段階がその後 #138 の
ものに任せて取り除いた E0726 の検査のものである (92800f9):

- トレイトの型引数 (`impl Tr<Foo> for S`) を調べない;
- 構造体と同じ名前の impl の型パラメータ (`impl<Foo> S<Foo> { async fn f(x: Foo) {} }`) を構造体と取り違える;
- 巻き上げた impl の行。

rustc 1.97 で確かめると、main の #138 の検査にも同じ 3 つがある: 1 つ目を受理し、2 つ目に偽の E0726 を出し、3 つ目を
巻き上げたアイテムの行で出す。これらは #171 に挙げた。92800f9 のレビューは指摘をしなかった。
