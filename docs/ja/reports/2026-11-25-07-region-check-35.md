# リージョン (ライフタイム) 検査、その 35: impl ヘッダと `async fn` のパラメータの省略したライフタイム (E0726)、参照を持たない型のドロップ (issue #1)

日付: 2026-11-25

その 34 ([2026-11-25-06](2026-11-25-06-region-check-34.md)) は #161 でマージした。この段階で加えたもの:

- ライフタイムパラメータのあるプログラムの構造体、列挙型、トレイトを名指し、そのどれも書かない impl ヘッダの E0726;
- そういう型の `async fn` のパラメータの E0726;
- 参照を持たない `Drop` の型のドロップ検査。#161 の最後のレビューの軽微な指摘。

## 1. 加えたもの

- **impl ヘッダの E0726。**
  - `struct Foo<'a>` のときの `impl MyTrait for Foo`、あるいは `trait MyTrait<'a>` のときの `impl MyTrait for u32` を
    考える。rustc はパスで "implicit elided lifetime not allowed here" (E0726) を出す。impl ヘッダはパスのライフタイム
    を省略しない。`Foo<'_>` は 1 つを名指す。
  - zustc はこれらを受理していた。すべてのアイテムを要約した時点で、ライフタイムパラメータのあるプログラムの
    構造体、列挙型、トレイトがわかる。その要約がそれを名指す impl ヘッダを読み直し、ライフタイムのどれも書かない
    最初のパスで E0726 を出す。
  - トレイトを先に、次に自分の型を、その中も (`impl Tr for Vec<Foo>`) 調べる。
  - これらは受理する: `'_` か impl 自身のライフタイムを書くパス、参照の省略したライフタイム (`impl Tr for
    &Foo<'_>`)、構造体と同じ名前の impl の型パラメータ。
  - impl-header-lifetime-elision/path-elided.rs、trait-elided.rs、coherence/skip-reporting-if-references-err.rs、
    wf/wf-in-foreign-fn-decls-issue-80468.rs が通る。
- **`async fn` のパラメータの E0726。**
  - `struct Msg<'a>` のときの `async fn f(m: Msg)` は `Msg` での E0726 である。関数が返す future はパラメータの
    ライフタイムを捕まえるので、それは名指さねばならない。async でない関数は、これまでどおりそれを省略する。
  - アイテムの `fn` より前の名前から、それが async かがわかる。そういうアイテムで、要約のパラメータがそういう型を
    名指すものだけを読み直す (async-await/async-fn-path-elision.rs、lifetimes/issue-69314.rs)。
- **参照を持たない型のドロップ。**
  - ドロップ検査は、`Drop` の impl のある型をすべて、その値が借用するものを見うるドロップとしていた。そのため、
    `Token` をフィールドのない `Drop` の型として、`let mut d = (None, Token); { let x = 1; d.0 = Some(&x); }` は
    main でも E0597 だった。自分への借用を持つ値についての、その 34 の検査も同じ門を使っていた:
    `let d = (Cell::new(None), 1, Token); d.0.set(Some(&d.1));` が E0597 だった。rustc はどちらも受理する。その
    ドロップ検査が生きていることを求めるのは、`Drop` の型のパラメータが持つものだけだからである。
  - `Drop` の impl は、いまは参照を持ちうる型についてだけ数える。借用を持つ `Drop` の型
    (`struct D<'a>(Option<&'a i32>)`) は、rustc と同じく E0597 のままである。
