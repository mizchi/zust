# リージョン (ライフタイム) 検査、その 34: `impl Trait + 'static` の引数、フィールドの型の `'static` の境界、`Cell` が格納するもの、自分への借用を見る値のドロップ (issue #1)

日付: 2026-11-25

その 33 ([2026-11-25-05](2026-11-25-05-region-check-33.md)) は #160 でマージした。この段階で加えたもの:

- `impl Trait` の引数のライフタイムの境界 (`impl Debug + 'static`)。呼び出し側はそれを満たさねばならない (E0310);
- 型パラメータを、それを `'static` で縛るプログラムの型に渡すフィールドの E0310;
- 配列の要素の、文脈が与える要素の型への deref 型強制;
- prelude の `Cell`、`RefCell`、`OnceCell` が `&self` を通して格納するもの (`set`、`replace`)、そして場所としての
  `Vec` の要素;
- 借用したものをドロップで見うる値が、自分への借用を持つときの E0597;
- #160 の最後のレビューの軽微な指摘。

## 1. 加えたもの

- **`impl Trait` の引数のライフタイムの境界。**
  - `fn foo(d: impl Debug)` から `bar(d)` と呼ぶ `fn bar(d: impl Debug + 'static)` は、rustc の E0310 である。
    引数の型は `'static` より長く生きねばならないが、foo の `impl Debug` についてはそれを何も言っていない。
  - シグネチャの要約は、`impl Trait` の引数を隠れた型パラメータ (`__impl0`) に持ち上げる。そのトレイトの境界は
    残していたが、ライフタイムの境界はリージョン検査が読む outlives に届かず、呼び出しを受理していた。いまは届き、
    E0310 は rustc の位置である引数で出る。
  - メッセージは、rustc と同じくパラメータを "the parameter type `impl Debug` may not live long enough" と呼ぶ。
- **フィールドが名指す型の `'static` の境界。**
  - `struct Bar<T: 'static>` があるときの `struct Foo<U> { bar: Bar<U> }` は、フィールドでの rustc の E0310 である。
    rustc はフィールドの `&'a U` から `U: 'a` を推論する (RFC 2093) が、`U: 'static` は推論しない。構造体が宣言
    せねばならない。
  - zustc は、ほかの構造体の境界をどこでも読んでいなかった。プログラムの構造体と列挙型の定義は、すべてのアイテムを
    要約した時点でわかる。パラメータを `'static` で縛る型を名指すフィールドの型は、アイテムが宣言するものと突き
    合わせる: その場で (`U: 'static`)、where 節で、あるいはそれを含意しうるトレイトを通して (`U: Any`。これは
    たどらない)。
  - 列挙型のバリアントでも、ほかの型を通しても (`Vec<Bar<U>>`)、関数本体に書いた構造体でも同じ
    (rfcs/rfc-2093-infer-outlives/dont-infer-static.rs)。
  - そういう型の関数のパラメータは受理したままである。rustc はシグネチャの型を well-formed とみなす。
- **配列の要素の deref 型強制。**
  - `[&[u8]; 2]` を期待するところの `x: &[u8]` の `[&x, x]`、`[&x; 1]`、そして `[&str; 2]` としての `String` の
    `[&s, "b"]` は、rustc が各要素で行う型強制である。zustc は型の不一致として拒否していた。
  - 文脈が要素の型を与えるところでは、配列のリテラルの要素と repeat の要素を deref で型強制するようにした。
  - これは #160 の最後の指摘の、型検査の半分である。その借用検査の半分もここに持ち込んだ: repeat の要素は、配列の
    リテラルの要素と同じく、それが写す参照としてたどる。
- **セルが格納するもの。**
  - `d1.0.set(Some(&d2))` は、d2 の借用を d1 に格納する。d1 のドロップがそれを見うる (`Drop` の impl がある) とき
    に、d2 が先にドロップされるなら、`&d2` での rustc の E0597 である。
  - zustc は、`&mut self` を通した格納 (`v.push(&x)`) と、自分の型が引数を借用するライフタイムについて不変である
    プログラムの `&self` のメソッドを通した格納はたどっていた。prelude のセルを通したものはたどらなかった。その
    `set(&self, v: T)` はライフタイムを名指さないからである。
  - prelude の `Cell`、`RefCell`、`OnceCell` の `set` と `replace` は、いまは引数が借用するものをセルに格納する。
  - prelude の `Vec` へのインデックスは要素の型を与えるので、`c.v[0].cell` は c の中の場所であり、それを通した
    格納は c に入る (span/dropck_vec_cycle_checked.rs、span/vec-must-not-hide-type-from-dropck.rs、
    rfcs/rfc-1238-nonparametric-dropck/reject-ex1.rs)。
  - span/dropck_direct_cycle_with_drop.rs と span/dropck_arr_cycle_checked.rs は、格納だけで通る。
- **自分への借用を見る値のドロップ。**
  - `D: Drop` の `d.0.set(Some(&d))` は rustc の E0597 である。d のドロップは、d をドロップしている間にその借用を
    見うる。
  - zustc は、その借用を持ち主とともに死んだものとしていた。借用したものをドロップで見うる値をドロップするとき、
    それが持つ自分への借用は、いまは借用での E0597 である。
  - `Drop` のない型は、rustc と同じく受理する。そのドロップは何も見ない。
  - span/issue-25199.rs が通る。そこでは `container.store(test)` が `container` の借用をそれ自身に格納する。

## 5. まだ扱わないもの

- **セルの循環のほかのエラー。** `d1.p.set(Some(&d2)); d2.p.set(Some(&d1));` で rustc は `d1` も報告する。セルの
  不変性が、d1 と d2 のライフタイムを 1 つにするからである。zustc は最初の `d2` を報告する。
- **`Vec` の要素を通した借用の E0713** (rfcs/rfc-1238-nonparametric-dropck/reject-ex1.rs): rustc は "borrow may
  still be in use when destructor runs" と言い、zustc は同じ行で E0597 を出す。
- **`impl dyn Trait` のメソッド** (regions/regions-static-bound-on-type-param.rs、
  suggestions/impl-on-dyn-trait-with-implicit-static-bound.rs): そういう impl は `dyn Trait + 'static` のもので
  あり、rustc はそれを受け手に求める。zustc の型検査は、まだこれらのメソッドを見つけない。
- **射影を通したフィールドの境界** (`impl<'a, T: 'a> Dummy<'a> for T` のときの `<T as Dummy<'a>>::Out`、
  rfcs/rfc-2093-infer-outlives/regions-enum-not-wf.rs)。
- **高ランクの境界を通した outlives** (`for<'a> G: Outlives<'a>`、nll/local-outlives-static-via-hrtb.rs)。
- その 33 以前から: [その 33](2026-11-25-05-region-check-33.md) の第 5 節を見よ。
