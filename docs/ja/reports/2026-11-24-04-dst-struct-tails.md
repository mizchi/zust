# 最後のフィールドが unsized な struct (`&Foo<[T]>`)

日付: 2026-11-24

[part 2](2026-11-24-03-inference-coercions-2.md) では struct への unsizing (`&Foo<[u8; 3]>` → `&Foo<[u8]>`) を
「ポインタの表現の変更なので別に設計する」として残した。その設計と、末尾がスライスの場合の実装。

## 設計

**どの型が fat か。** `Ty::is_fat` は型の形だけを見るので struct の定義を読めない。そこで、最後のフィールドが
unsized (`[T]`、`str`、またはそういうインスタンス) な struct のインスタンスの番号に印のビット (`DST_TAG = 1 << 31`) を
付ける。印を付けるのはインスタンスを作るときの `instantiate` で、キャッシュにも印付きの番号が入る。そのため、その
インスタンスを指す `Ty::Struct` はどれも印を持つ。`AdtTable` の添字は印を外して引く。番号はそのプログラム自身の表の
ものなので、プロセス全体の登録表は要らない (part 2 が挙げた障害はこれだった)。`is_fat` には「印付き struct への
参照・生ポインタ・Box」の場合が 1 つ増えるだけ。

**表現。** `&Foo<[T]>` は `&[T]` と同じ 16 byte で、データのアドレスと、いちばん内側の末尾の要素数の組。
`Foo<[T]>` 型の場所は `Place::Mem(組, 0, Foo<[T]>)`、つまり組の場所で、スライスの場所と同じ形になる。そのため
`&場所` は組そのものになり、新しい規則は要らない。

**レイアウト。** スライスの末尾は大きさ 0、揃えは要素のもの (今までは 1) にした。これで `Foo<[T]>` での末尾の
位置は、どの `Foo<[T; N]>` での位置とも同じになる。

**フィールド。** 印付き struct の場所では、sized なフィールドは `load(組) + オフセット` にある。末尾のフィールドは
新しい組 `(load(組) + オフセット, load(組 + 8))` になる。式のフィールド (`x.f`) とパターンのフィールド
(`Foo { a, ref inner }`) はこの同じ規則を使う。印付き struct への参照の `*r` と自動 deref は組の場所を返す。

**強制変換。** `unsized_of(S<[T; N]>)` は `(N, S<[T]>)` を返す (入れ子の末尾 `Fat<Fat<[T; 3]>>` もたどる)。変換では
組 `(アドレス, N)` を作る。適用する場所は `&[T; N]` → `&[T]` と同じ: 期待型 (`let`、戻り値、フィールド)、呼び出しの
引数 (ジェネリックな引数 `&Fat<[T]>` は unsized な型と照合して解く)、`&mut`、`*const`/`*mut`、`Box`。

**推論。** 変換の前後は同じ型ではないので、単一化で両辺をつないではいけない。

- `Adt` と印付きインスタンスの単一化では、引数だけを単一化する。スライスの引数 (リテラルの `T` に対する `[u8]`)
  は、引数が配列だと分かってから要素だけを単一化する。最後まで分からないものは `finish_unsize` で処理する。これで
  `&Foo<[u8]>` として書いた `&Foo { inner: [1, 2, 3] }` の要素が `u8` になる。
- 中身がそういう組 (`unsize_pair`: 片方が印付き、または同じ struct のジェネリックな形で、片方の引数が配列でもう
  片方がスライス) の参照・Box・生ポインタは、つながずに中身だけを単一化する。同じ struct のジェネリックな形どうしも
  同じ扱いにする。これまでは `let f2: Box<Fat<[isize]>> = f1;` で `f1` 自体が `Box<Fat<[isize]>>` になり、その前の
  `&*f1` がないはずの組を読んで segfault していた。
- codegen では、期待型が印付き struct なら捨てる (その型の値はない)。リテラルは配列のインスタンスとして作ってから
  変換する。
- 末尾に出てくる型パラメータを他のフィールドも使っている場合 (`struct Foo<T: ?Sized>(Box<T>, T)`) は変換しない。
  rustc でも E0308 になる。

## やっていないこと

- `dyn` の末尾 (`&Foo<dyn Get>`): 末尾の位置が具体型の揃えで決まるが、zustc の vtable はまだそれを持っていない
  (`dst/match-dst-struct.rs`)。
- 印付き struct の `size_of_val`、要素の drop が要る `Box<Foo<[T]>>` の drop。
- part 2 が数えた「unsizing」のテストのうち残りは別の問題による: 定数の昇格 (`static-promotion-issue-101363.rs`)、
  要素を推論する `as &[_]` (`issue-30240-rpass.rs`)、`dyn` の生ポインタの比較 (`mir_raw_fat_ptr.rs`、`raw-fat-ptr.rs`)。

## テスト

- `examples/dst_structs.rs` (期待出力は rustc のもの): let と引数での変換、ジェネリックな `&Fat<[T]>`、`&mut` での
  書き込み、入れ子の末尾、`*val` へのパターン、`Box<Fat<[T; 3]>>` → `Box<Fat<[T]>>`、生ポインタ、大きさ。
- `tests/compile_errors/dst_struct_unsize_elem_mismatch.rs`: `&Fat<[i32; 3]>` は `&Fat<[u8]>` ではない。
- `tests/check.rs`: `dst_struct_tail_coercions_check`。
