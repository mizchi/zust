# リージョン (ライフタイム) 検査、その 14: `impl Trait` の結果のキャプチャ、クロージャの `T: 'static`、ローカルを通した二相借用、`ref` の残りのパターン (issue #1)

日付: 2026-11-23

その 13 ([2026-11-23-01](2026-11-23-01-region-check-13.md)) は #67 でマージした。この段階では、`impl Trait` の結果が
持ってよいものを検査する: `'static` でなければならない隠れた型と、エディション 2024 より前にライフタイムを
キャプチャしない隠れた型 (E0700) である。また、関数の T に `T: 'static` を要求するクロージャの中の呼び出し、参照を
持つローカルを通した二相借用、配列の残りの `ref` での束縛を検査する。

## 1. 加えたもの

### リージョン

- **`impl Trait + 'static` の結果の隠れた型は `'static` である。** `fn foo<T>(x: T) -> impl Any + 'static { x }` を
  受け入れていた (impl-trait/type_parameters_captured.rs、E0310)。`fn baz<'a>(x: &'a u8) -> impl Any + 'static { x }`
  も受け入れていた (「lifetime may not live long enough」)。今はそのような結果の木が `'static` になり、その関数の検査
  がオンになる。何かをキャプチャするクロージャは除く。その木は、使う場所ではなくキャプチャする変数のものである:
  `&'static` のフィールドを通す `|| drop(&m.a.0)` は rustc では `'static` で借用する (RFC 2229)。m のリージョンを
  要求すると誤ったエラーになる (closures/2229_closure_analysis/optimization/edge_case_run_pass.rs)。
- **エディション 2024 より前、境界がライフタイムを名指さない `impl Trait` の結果は何もキャプチャしない (E0700)。**
  次の 2 つを受け入れていた: `fn s(x: &[u8]) -> impl Iterator<Item = u8> { x.iter().copied() }` と
  `fn t(x: &u8) -> impl Display { x }` である。rustc は「hidden type ... captures lifetime that does not appear in
  bounds」と報告する (impl-trait/precise-capturing/forgot-to-capture-lifetime.rs、
  feature-gates/feature-gate-lifetime-capture-rules-2024.rs、self/arbitrary_self_types_pin_lifetime_impl_trait.rs と
  その `-async` 版)。そのような関数が返すものは、引数の参照を通して借用してはならず、参照そのものであってもならない。
  ライフタイムを並べない `use<>` は、何も名指さないものとして数える。次の 3 つは除く:
  - ジェネリックな関数。型パラメータをキャプチャする;
  - エディション 2024。すべてのライフタイムをキャプチャする;
  - リージョンがすべて `'static` の引数 (`x: &'static u8`、`'a: 'static`: impl-trait/equal-hidden-lifetimes.rs)。

  この検査は借用検査で行う。prelude のイテレータの型はライフタイムを書かないので、リージョン検査には
  `Copied<Iter<u8>>` の中のリージョンが見えないからである。
- **関数の T に `T: 'static` を要求する、クロージャの中の呼び出し。** `fn test<T>() { || { assert_static::<T>(); }; }`
  を受け入れていた (nll/issue-98693.rs、E0310)。クロージャの本体のリージョン検査には、関数の型パラメータの
  プレースホルダがない。今はそのような呼び出しを関数の境界と照らす: `T: 'static`、where 節、`Self` が `'static` で
  なければならないトレイトである。

### 借用検査

- **参照を持つローカルを通した二相借用。** `fn ext(&mut self, _: &S)` での `let w = &v; v.ext(w)` を受け入れていた
  (E0502)。今は、引数がそのようなローカルである `&mut self` の呼び出しも、引数が受け手を名指すときと同じく受け手を
  予約する。ローカルが持つものは、`&mut` を取るまで保つ。
- **配列の `ref tail @ ..` は間の要素を借用する。** 残りの束縛はローンを持っていなかったので、tail が生きている間に
  配列に書くのを受け入れていた (borrowck/borrowck-vec-pattern-move-tail.rs、E0506)。

## 4. レビュー (CodeRabbit、rustc 1.97 と照らした)

#69 への CodeRabbit の最初のレビューには 4 件の指摘があった。それぞれを、それを示すプログラムに zustc と rustc を
かけて確かめた。すべてが正しく、直してテストする (`part14_review`):

- **ローカルに束縛した引数の参照。** 何もキャプチャしない `impl Iterator<Item = u8>` として
  `let y = x; y.iter().copied()` を返すのを受け入れていた (rustc では E0700)。今は、引数の参照から一度だけ束縛した
  (二度と代入しない) ローカルも、それを持つと数える。もう一度代入するローカルは追わない。
- **outlives の境界を通した `'static`。** `fn f<'a: 'b, 'b: 'static>(x: &'a u8) -> impl Display { x }` は誤った
  E0700 だった: 直接の `'a: 'static` だけが引数を `'static` にしていた。今は境界をたどる。
- **ライフタイムのない ADT。** `fn f(x: &'static String) -> impl Display { x }` は誤った E0700 だった: パス `String`
  は、ライフタイムなしで書いた型の印を持ち、それをリージョンと取り違えていた。今はリージョンを持たない型の印を
  無視する。ライフタイムのある型をライフタイムなしで書いたもの (`Parser<'a>` に対する `Parser`) は数えたままである。
- **引数が意味する `T: 'static`。** `fn f<T>(_: &'static T) { let c = || needs_static::<T>(); }` は誤った E0310
  だった: `&'static T` は `T: 'static` を意味する。今は T を名指す `&'static ..` の引数がその境界を与える。

## 5. まだ扱わないもの

- **フィールドを通した E0700。** `fn iter_values_anon(&self) -> impl Iterator<Item = u32> { self.x.iter().map(|a| a.0) }`
  (impl-trait/static-return-lifetime-infered.rs) は受け入れる: フィールドの上のイテレータの連なり (`self.x.iter()`) は、
  受け手のローンを結果に運ばない。`impl Iterator + 'static` の結果も同じである。
- **リージョン検査でのクロージャの正確なキャプチャ。** クロージャの木はキャプチャする変数のものなので、
  `m.a: &'static Int` での `|| drop(&m.a.0)` の `Box<dyn FnMut() + 'static>` を拒否する。rustc は受け入れる。この作業の
  前からそうであり、上で `impl Trait + 'static` からクロージャを除くのはこのためである。
- **クロージャの本体が参照でキャプチャするローカルに要求すること** は、まだ関数に戻さない。
- **impl のヘッダの中のトレイトオブジェクトの既定の `'static`** (nll/issue-54779-anon-static-lifetime.rs) と、
  **型パラメータのあるトレイトオブジェクト** (`dyn A<T>`) は、その 13 と同じである。
- **クロージャのキャプチャの規則のエディションはプロセスのフラグである** (`ast_closure::WILD_FAKE_READS`)。それぞれの
  解析が設定する。エディションの違う 2 つの解析が 1 つのプロセスで同時に走ると、互いのものを読みうる。zustc は
  1 つのプロセスで一度に 1 つの解析を行う (並列のビルドは fork する)。1 つのプロセスの中のテストの解析はすべて 2021
  以降のエディションを使い、フラグを同じに設定するので、今はこれは起きない。
