# リージョン (ライフタイム) 検査、その 25: プレースホルダーの関連型、プレースホルダーを指すパスの型引数、呼び出し元の where 節が満たす呼び出し先の境界、トレイトの境界に対する impl の関連型 (issue #1)

日付: 2026-11-24

その 24 ([2026-11-24-10](2026-11-24-10-region-check-24.md)) は #130 でマージされた。この段階で加えるもの:

- プレースホルダーの関連型 (`<T# as MyTrait<'a>>::Output`) と、それが outlive するもの;
- プレースホルダーの型への参照であるパスの型引数の well-formedness;
- 呼び出し元の、型に対する where 節だけが満たす呼び出し先のトレイト境界。その領域を取る;
- impl の関連型の値と、トレイトの宣言がそれに与えるライフタイムの境界 (E0477)。

## 1. 加えたもの

- **プレースホルダーの関連型。** `fn foo<'a, T>() -> &'a () where T: MyTrait<'a>` の中で、`fn bar<'a, T>() where T: 'a`
  に対する `bar::<T::Output>()` を受理していた (rustc では E0309、nll/ty-outlives/projection-where-clause-none.rs と
  -env-wrong-bound.rs)。何も呼ばないジェネリックな関数は、型パラメータごとのプレースホルダー (`T#`) で検査する。
  `<T# as MyTrait<'a>>::Output` が見つからなかったので、その関数はまったく検査していなかった。
  - そういう関連型は、今はそれ自身のプレースホルダーである。境界のトレイトがそれを宣言し、境界がそれを束縛しない
    (`Iterator<Item = u32>` でない) ときにそうする。トレイトが宣言するとおりに縛られる (Program::assoc_placeholder)。
  - その領域は universal なもので、型がどこにあっても同じである。パラメータの `&'x T::Foo` でもそうである。それが
    outlive するもの:
    - トレイトの宣言がそれを縛るもの (`type Output: 'a`)。サマリーは関連型のライフタイムの境界を、ほかの境界と一緒に、
      `'static` またはトレイトのライフタイムの位置として持つ;
    - 関数の where 節が言うもの (`T::Output: 'b`、`<T as MyTrait<'a>>::Output: 'b`。`T::Output` として持ち、トレイトの
      引数は比べない);
    - そのプレースホルダーと境界のライフタイムがすべて outlive するもの。rustc の、射影の構成要素の規則である。
  - 型検査がその関連型をそのプレースホルダーと見るところでだけ作る: `impl<T> Trait for T { type Assoc = T; }` では
    型検査は `T::Assoc` を T とし、リージョン検査もそうする。
  - 型引数を持つ境界、または関数が名前を持たないライフタイム (境界自身の `for<'x>`) を持つ境界のものは作らない。
    where 節が、サマリーが読まない型をライフタイムで縛るところ (射影の型エイリアスの `StrategyFor<A>: 'static`、
    nll/ty-outlives/issue-53789-*.rs) でも作らない: そこではそれが outlive するものがすべては分からない。
  - borrow check はそういう型を Copy と取る。それを Copy にするものは、そのトレイトの where 節 (`trait Op where
    Self::Output: Copy`) や関数の where 節でありえて、それらは読まないからである
    (associated-type-bounds/assoc-type-bound-through-where-clause.rs)。
  - メッセージは rustc と同じく関連型を名指す:「the associated type `<T as MyTrait<'a>>::Output` may not live long
    enough」。リージョン検査のメッセージに、プレースホルダーの `#` の印はもう出ない。
- **プレースホルダーの型への参照であるパスの型引数。** `fn func<'x, T: Trait1<'x>>(t: &'x T::Foo)` の中の
  `wf::<&'x T>()` を受理していた (rustc では E0309、regions/regions-implied-bounds-projection-gap-1.rs)。T は `'x` を
  outlive しなければならないが、`&'x T::Foo` はそれを含意しない。その 24 は、パラメータを `'static` で縛る構造体を
  含む型についてだけ、パスの型引数を確かめていた。今はプレースホルダーの型への参照も確かめる。ただし、どのパラメータの
  型も結果の型も辿れるときに限る。そうでなければ、それらが含意するものがすべては分からない
  (implied-bounds/normalization.rs)。
- **呼び出し元の where 節だけが満たす呼び出し先の境界。** `where 'max: 'min, &'max G: Get` を持つ関数の中で、
  `fn impls_get<G>() where G: Get` に対する `impls_get::<&'min G>()` を受理していた (rustc では「lifetime may not live
  long enough」、variance/variance-{co,contra,in}variant-self-trait-match.rs)。
  - zustc check の最後の回では、プレースホルダーを含む型 (`&G#`) で、境界が成り立つと分からないものを、満たすものと
    取る: ジェネリックな関数の where 節が満たしうるからである。以前はその関数を検査していなかった。
  - 型パラメータでない型に対する関数の where 節は、書いたとおりの木を持つ。そういう節だけが満たす呼び出し先の境界
    (その型に合うトレイトの impl がない) は、型をその節のものにする。トレイトの `Self` は不変なので、`'min` と `'max`
    は同じでなければならない。
  - その型に合う impl もあるところ (`impl<'x, T> Get for &'x T`) では、これをしない。rustc はそこでも where 節を先に
    取るので、そういうプログラムを rustc は拒否し、zustc は受理する (第 5 節)。
- **トレイトの境界に対する impl の関連型 (E0477)。** `trait Foo<'a> { type Value: 'a; }` で、`impl<'a> Foo<'static> for
  &'a i32 { type Value = &'a i32; }` を受理していた (rustc では「the type `&'a i32` does not fulfill the required
  lifetime」、regions/regions-assoc-type-region-bound-in-trait-not-met.rs、-static-bound-in-trait-not-met.rs)。
  プログラムのトレイトが分かったところで、トレイトの宣言がライフタイムで縛る impl の関連型を読み直す。その値が名指す
  impl のライフタイムは、境界を outlive しなければならない: `'static`、または impl のトレイトパスがその位置に書く
  トレイトのライフタイムである。分かっているのは、ヘッダーの境界と、その self 型が含意するものである。値の中の
  `for<..>` が束縛するライフタイムは、値自身のものである。

## 4. レビュー

CodeRabbit のレビューの指摘は 3 件で、それぞれ zustc と rustc 1.97 で確かめた。3 件とも成り立ち、どれも main
(25c18d6) のマージの次のコミットで直した。2 件は、この段階が持ち込んだ誤ったエラーだった (rustc も main もその
プログラムを受理する):

- **呼び出し元の、その位置のパラメータで読んだ呼び出し先の射影。** `fn take<V: Tr>(_: &V::Out)` で、
  `fn f<'a, T: Tr, U: Tr>(x: &'a U::Out)` の中の `take::<U>(x)` が「the associated type `<U as Tr>::Out` may not live
  long enough (it must outlive `<T as Tr>::Out`)」になっていた。プレースホルダーの関連型の領域を型パラメータの位置で
  探しており、呼び出し先のシグネチャではそれは呼び出し先のものである。今はプレースホルダーの領域で探す。型引数の木が
  そのパラメータに与えるもので、呼び出し先の `V` には呼び出し元の `U` である。それを通した本当の要求
  (`take::<U>(x)` を `&'static U::Out` として返す) は、これまでどおり報告する。
- **関連型の値の中の型エイリアス。** `type Erased<'a> = ();` での `type Value = Erased<'a>;` が誤った E0477 になって
  いた: エイリアスは `'a` を指すが、その本体は使わない。今は、プログラムの型エイリアスを書く値を E0477 で確かめない。

3 件目は行だった: 関数の本体の中の impl は外へ移され、その E0477 は移した先の行になっていた。今は書いた行になる。

tests/regionck.rs がこれらのケースを確かめる (`part25_review`)。

## 5. まだ扱わないもの

- **impl も合うところで先に取られる where 節** (`&'max G: Get2` と `impl<'x, T> Get2 for &'x T` での
  `impls2::<&'min G>()`): rustc は where 節を選び、zustc は境界を impl に任せる。
- **where 節のものと違うトレイトの引数を持つ射影** (`<T as MyTrait<'b>>::Output: 'a` に対する
  `<T as MyTrait<'a>>::Output`、nll/ty-outlives/projection-where-clause-env-wrong-lifetime.rs): where 節は
  `T::Output` として持ち、トレイトの引数は比べない。
- **型引数を持つ境界や、スーパートレイトのプレースホルダーの関連型** (`T: DoubleEndedIterator` の `Item`)、そして
  プレースホルダーの関連型自身の関連型 (`T::Output::Inner`)。
- **トレイトオブジェクトを通した構造体の型引数の推論** (`struct B<'a, T>(&'a (dyn A<T> + 'a))` での `B(&*v)`、
  regions/regions-close-object-into-object-*.rs): 誤った「type annotations needed」。
- **`&dyn Error` の `err.is::<T>()`** (このメソッドは `dyn Error + 'static` のもの、
  regions/regions-static-bound-on-type-param.rs)。
- **impl の暗黙の境界を伴う、トレイトのシグネチャに対する impl のメソッド** (`fn listeners<'b>(&'b self) -> &'a
  MessageListeners<'b>`、implied-bounds/impl-implied-bounds-compatibility.rs、E0491)。
