# リージョン (ライフタイム) 検査、その 22: 注釈とパラメータでの射影の関連型、ローカルからキャストするクロージャ (issue #1)

日付: 2026-11-24

その 21 ([2026-11-24-05](2026-11-24-05-region-check-21.md)) は #123 でマージした。この段階で加えるもの:

- `let` の型として書いた射影の領域。impl の関連型の値から取る;
- 型がそういう射影であるパラメータの暗黙の境界。main にもある誤ったエラーがなくなる;
- ローカルが持ち、関数ポインタ型にキャストするクロージャ。注釈付きのパラメータと突き合わせる。

## 1. 加えたもの

- **`let` の型として書いた射影は、関連型の値が書く領域のものである。** `impl Foo for () { type Out = &'static u32; }` で
  `let _: <() as Foo>::Out = &a;` を受け入れていた (rustc では E0597)。`impl<'a> Foo for &'a () { type Out = &'a u32; }`
  での `let _: <&'static () as Foo>::Out = &a;` もそうだった (nll/user-annotations/normalization.rs)。要約は、値が
  ライフタイムを指す impl の関連型のコードを、impl のライフタイムに対して持つ (`Summary::assoc_regions`、
  `Program::assoc_regions`)。その 19 が impl の定数にしたのと同じである。`let` の注釈の射影は、その名前の impl の関連型が
  1 つだけ self 型に合うところで、それを取る: impl のライフタイムは self 型がそこに書くもの (`<&'_ () as Foo>::Out` では
  新しいもの)、blanket impl の型引数は書いたとおりの self 型である。こういう注釈は関数のリージョン検査を始める。
- **型がそういう射影のパラメータは、値が含意する境界を持つ。** `impl<T: 'static> Tr for T { type Ty = &'static T; }` で
  `fn test<'a>(x: &'a u8, _wf: <&'a u8 as Tr>::Ty) -> &'static u8 { x }` は誤った「lifetime may not live long enough」
  だった (main でも。rustc は受け入れる): `_wf` の型は `&'static &'a u8` で、`'a: 'static` を含意する。要約は型が射影の
  パラメータを辿らない。今は関数のリージョン検査がそれに値の木を取り、その暗黙の境界は既知である
  (implied-bounds/assoc-ty-wf-used-to-get-assoc-ty.rs には、もう 16 行目の誤ったエラーはない)。
- **ローカルが持ち、関数ポインタ型にキャストするクロージャ。** `let c = |_: &'static u32| {}; let f = c as fn(&u32);` を
  受け入れていた (rustc では E0308): 型と突き合わせていたのは、キャストに書いたクロージャだけだった (その 20)。ライフタイム
  で注釈したパラメータを持つクロージャを struct ごとに持っておき、それを持つローカルのキャストでも同じようにパラメータを
  確かめる。報告はキャストのところである。

## 4. レビュー

CodeRabbit のレビューの指摘は 6 件で、それぞれ zustc と rustc 1.97 で確かめた。6 件とも成り立った。5 件はリージョン検査についてのもので、どのプログラムも main も受理していた: この段階で加えたもの、またはその 20 の取りこぼしである。6 件目のビルドキャッシュについてのものはバグだった:

- **ビルドキャッシュ** (b874b80f で修正)。関連型の値を変えても、その射影を書く関数はキャッシュの結果を使い続けていた。
  `type Out = &'a u32` を `&'static u32` に変えても、今はエラーになる `let x: <&'b () as Foo>::Out = r;` のキャッシュした
  ビルドが残った。`type Out = u32` を `u64` に変えても `size_of_val` は 4 のままだった。こちらは main にもある。今は関数の
  キーが、プログラムの関連型の定義、つまりその impl のメンバのテキストを持つ。依存するクレートの関数では、見えるクレートの
  ものを持つ。tests/driver2_cache.rs が確かめる (`associated_type_invalidates`)。
- **初期化式のない `let`** (1643b40f)。`type Out = &'static u32` の `let x: <() as Foo>::Out; x = r;` を受理していた。今は
  x が射影の木を持ち、代入はそこへ流れ込む。
- **impl の self 型の中の型引数とライフタイム** (1643b40f)。2 つのプログラムを受理していた:
  - `impl<T> Foo for W<T> { type Out = (&'static u32, T); }` で、`<W<&'static u32> as Foo>::Out` が `T` に新しい領域を
    与えていた;
  - `impl<'a, T> Foo for W<'a, T>` で、`<W<'static, &'static u32> as Foo>::Out` が `'a` を失っていた。書かれた型の領域が
    impl の self 型より多いからである。

  今は impl の self 型を、書かれた型の木と部分ごとに突き合わせる。そのライフタイムと型パラメータは、それぞれの位置の部分を
  取る。
- **ライフタイムを指す関数ポインタ型** (1643b40f)。`fn(&'a u32)` に強制する `|_: &'static u32| {}` を 4 つの場所で受理して
  いた。rustc はどれも「lifetime may not live long enough」を報告する:
  - ローカルのキャスト;
  - `let`;
  - キャスト;
  - 呼び出し (`fn want<'a>(_: &'a u32, _f: fn(&'a u32))` の `want(x, ..)`)。

  クロージャは型の与えるものを受け取るので、型の領域が注釈の領域より長生きしなければならない: ここでは `'a: 'static`
  である。`where 'a: 'b` があれば、`fn(&'a u32)` としての `|_: &'b u32|` は rustc と同じく受理する。その 20 はこれらの領域を
  脇に置いていた。
- **関数ポインタ型の型エイリアスへのキャスト** (`type F = fn(&u32);` の `c as F`) は直していない。要約はエイリアスの定義の
  ライフタイムを持たないので、そこでは `fn(&u32)` と `fn(&'static u32)` が同じに見える。第 5 節に記録する。

2 回目のレビューの指摘は 1 件で、成り立った。495e2d75 の次のコミットで直した。`impl<'a> Foo for fn(&'a ())` で、
`let _: <fn(&'static ()) as Foo>::Out = r;` を受理していた。rustc は「lifetime may not live long enough」を報告する。impl の
self 型の照合に関数ポインタ型の場合がなかったので、`'a` が新しいままだった。今は関数ポインタのパラメータと結果を部分ごとに
突き合わせ、関数ポインタ型のコードの先頭の印は self 型のコードから除く。

tests/regionck.rs がこれらのケースを確かめる (`part22_projection_review`、`part22_closure_fnptr_named`)。修正と main
(014c605) をマージした状態で、tests/ui に回帰はない: main に対して compile-fail は
4639 → 4640、run-pass 1857 と check-pass 1524 は変わらない。パスする run-pass のテストで、main が受理し、これが拒否するものは
ない。KPI ワークフローが、プッシュした先頭を main に対して測る。

## 5. まだ扱わないもの

- **呼び出しでの、射影を正規化した型** (`fn test<'a>(x: &'a u8, _wf: <&'a u8 as Tr>::Ty)` の `test(&x, &&3)`、
  implied-bounds/assoc-ty-wf-used-to-get-assoc-ty.rs の 24 行目): 呼び先の要約は、型が射影のパラメータのコードを持たない
  ので、呼び出しはそれを辿らない。関数の中と `let` の注釈では、今は辿る。
- **関数ポインタ型の型エイリアスへのキャスト** (`type F = fn(&u32);` の `c as F`): 要約はエイリアスの定義のライフタイムを
  持たない (第 4 節)。
- **結果が抜け出す領域のあいだ借用される、クロージャの `ref` パラメータ** (`.filter_map(|ref line|
  self.make_entry(line))`、borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs の 6 行目)。
- **ライフタイムを固定する関数ポインタ型の型エイリアスを通して渡す関数アイテム**: `type G = for<'cx> fn(&'cx S) ->
  &'static S;` の `want_G(baz)` (regions/regions-fn-subtyping-return-static-fail.rs)。要約はエイリアスの定義の
  ライフタイムを持たず、関数の要約はそのモジュールのエイリアスを見ない。
- **関数ポインタ型の別々の束縛ライフタイム** (`for<'a, 'b> fn(&'a u32, &'b u32) -> &'a u32`) は、関数アイテムを渡す
  ところで 1 つのプレースホルダーになる: 領域のコードは束縛を持たない (その 19 の第 4 節)。
- **関数で作り、別のクロージャの本体で呼ぶクロージャ** (adt-tuple-struct-calls.rs の
  `annot_reference_named_lifetime_across_closure`)。内側の本体は、外側のクロージャのシグネチャなしで単独に検査する。
- **struct のフィールドを通して、または別のクロージャの本体で呼ぶクロージャの、呼び出しが借用するもの**
  (closures/issue-113087.rs)。持つのは、ローカルの名前で呼ぶクロージャだけである。
- **使われない定数の初期化式** (main の中の `const z: &'static isize = { let p = 3; &p };`、static/issue-18118.rs) と、
  定数の初期化式のブロックの中の関数アイテム (borrowck/borrowck-fn-in-const-c.rs)。定数は使うところで展開して検査する。
- **型がトレイトのライフタイムを指すトレイトの定数** (`<T as Foo<'a>>::C`、`T: Foo<'a>` の `T::C`、
  nll/user-annotations/constant-in-expr-trait-item-2.rs、-3.rs)。何も呼ばないジェネリックな関数は、定数を使うところに
  届かない。
- **ガードの一時値を通して読む `&mut` の暗黙の再借用** (後で使う `let val: &_ = x.borrow().0;`、
  borrowck/issue-36082.rs)。
- **スライスでも `str` でもない型の `Cow<'_, T>`**、関数の中の `use std::option::Option::Some as S;`
  (lifetimes/temporary-lifetime-extension-tuple-ctor.rs)。
- **`let` の初期化式以外で値としてムーブされる `&mut`**: ジェネリックな f の `f(a[0])`、`vec![a[0]]` (E0508)。
- その 17 から:
  - 1 か所に書いたプログラムの 2 つの deref (`(&mut **w).bump()`);
  - ある型への impl があいまいなトレイト (borrowck/mut-borrow-in-loop-2.rs)。
- その 16 から:
  - ジェネリックな関数の `dyn Tr<T>`;
  - `&*vec![1].iter().next().unwrap()`;
  - opaque 型のメンバー制約 (E0700);
  - タプルの推論の中の `&mut`;
  - フィールドごとの領域;
  - `static` クロージャの借用検査。
