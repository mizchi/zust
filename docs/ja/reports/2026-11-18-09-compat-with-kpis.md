# KPI を見ながら tests/ui の互換性を上げる

Date: 2026-11-18

この報告は、rustc の tests/ui（[報告 07](2026-11-18-07-rustc-ui-tests.md)）に対して、失敗の分類ごとに 1 つずつ入れた一連の変更をまとめる。作業は借用検査（[報告 08](2026-11-18-08-borrow-checking.md)）の後に始めた。

それぞれの変更は、次のすべてを満たすときだけ残した。

- **run-pass に回帰がない**: ベースラインの一覧にある run-pass のテストで、通らなくなったものがない。
- **リポジトリ自身の検査が通る**: ワークスペースのテスト、`tests/compare.sh`、cratebench のクレートのビルドが通る。
- **KPI が保たれる**: ビルド速度、check の速度、ビルドキャッシュのサイズ、LSP の応答時間が悪くなっていない。

分類は、失敗している run-pass / check-pass のテストの最初のエラーをまとめて作った。

## 結果

| 種類 | 前 | 後 |
|---|---:|---:|
| run-pass | 46.42% | **52.92%**（1277） |
| check-pass | 46.15% | **57.83%**（1045） |
| build-pass | 48.15% | **56.30%**（76） |
| compile-fail（注釈の行でのエラー） | 35.04% | **38.16%**（2808） |

`bench/rust_ui_passing.txt` の通るテストの一覧は 4597 件から 5206 件になった。

compile-fail のテスト約 70 件が一覧から外れた。これらは、zustc が構文（ジェネリックなトレイト、共用体、`PhantomData`、一部の構文など）に未対応だったために弾かれ、その位置がたまたま注釈の行だったものである。どれも、zustc にまだない検査が要るようになった。どれがそうかはコミットメッセージに書いてある。必要な検査は次のとおり。

- 型の既定値と境界の well-formedness
- coherence
- ブランケット impl の境界の検査
- `dyn` と `async` を通した Send
- 寿命の shadowing
- lint

## 変えたこと

- **トレイト。**
  - ジェネリックなトレイト（`trait Tr<T>`）。トレイトのパラメータをメンバの総称引数にする。これだけで 216 件が新たに通った。
  - メンバの有無にかかわらずブランケット impl を扱い、そのトレイトの既定メソッドも使えるようにした。ブランケット impl のあるトレイトはどの型でも実装済みとみなす。impl の境界はまだ検査しない。
  - `()` への impl。
  - マーカートレイト（Send、Sync、UnwindSafe、RefUnwindSafe、Unpin）の impl を、宣言なしで受け付ける。
  - Send / Sync を自動トレイトとして扱う。
  - 組み込みトレイトの `Trait::method(x)`。
  - プリミティブ型に同名の静的関数とメソッドがあるとき、メソッド呼び出しは常にメソッドを選ぶ。選択がハッシュ集合の順序に依っていた。
- **アイテム。**
  - 共用体。全フィールドをオフセット 0 に置き、フィールド 1 つのリテラルを書ける。
  - 関数本体の中の `const` / `static`。マクロの展開から出てくることが多い。
  - `#![crate_type = "lib"]` のソースは `main` を要しない。
  - 利用者の `Map` / `Filter` / `Zip` が、prelude のアダプタとぶつからない。
- **式とパターン。**
  - 16 進や定数式で書いた列挙型の判別値と、バリアントが 1 つの列挙型のキャスト。
  - 定数式で書いた配列長。
  - `x as Box<dyn Tr>`。
  - 定数を名前で書いた識別子のパターンは、その値と比べる。
  - マクロの本体の `let` の束縛の衛生性。
  - 整数リテラルのレシーバ（`4.f()`）。
  - 本体に値のない `-> impl Trait` の関数。
  - 値として使った const ジェネリクスのパラメータは、期待される整数型をとる。
- **構文解析。**
  - 関連型の境界（`Iterator<Item: Debug>`）。
  - `for<'a>` の型。
  - 値の後ろの GAT の where 句と、修飾された GAT のパス。
  - C の可変長引数。
- **prelude（単一スレッド）。**
  - `Arc` とアトミック型。
  - `thread::spawn`。クロージャをその場で実行し、`join` がその値を返す。
  - `mpsc` のチャネル（共有のキュー）。
  - `PhantomData`。
  - `std::sync::atomic` の `Ordering` と mpsc の型は、そのモジュールから取り込んだときに名前を付け替える。zustc は名前を最後のセグメントで解決するので、この付け替えで `cmp::Ordering` や利用者自身の `Receiver` と区別する。
- **検査。** どれも利用者の項目にだけ報告する（prelude の型はこれらの規則を破ることがあるため）。
  - E0403 ほか、ジェネリクスの宣言の検査。
  - E0207：制約されない impl のパラメータ。
  - E0392：使われない型・寿命パラメータ。
  - E0735：パラメータの既定値の中の `Self`。
  - E0740：drop が要る共用体のフィールド。
  - 未知の derive マクロ。
  - ジェネリックな型の E0072。
  - `thread::spawn` の E0373 と Send。
  - `use<..>` のキャプチャの一覧。

## KPI

KPI は、`bench/ci_bench.py` が生成するプログラムに対する valgrind の命令数と、`bench/lsp_parity.py` の p50 の応答時間である。どちらも同じマシンで測った。

| KPI | 前 | 後 |
|---|---:|---:|
| gen5000 の no-op ビルド | 746.0 M 命令 | 685.7 M 命令（-8.1%） |
| gen5000 の 1 関数編集 | 709.3 M 命令 | 648.1 M 命令（-8.6%） |
| gen5000 の check | 3971.0 M 命令 | 3912.7 M 命令（-1.5%） |
| gen5000 のビルドキャッシュ | 1902.8 KiB | 1902.8 KiB |
| gen1000 のビルドキャッシュ | 387.2 KiB | 387.2 KiB |
| LSP の definition / hover / completion / references の p50 | 0.65 / 0.47 / 1.28 / 3.36 ms | 0.53 / 0.43 / 1.09 / 3.06 ms |
| LSP の起動から索引ができるまで | 135 ms | 116 ms |

途中で 3 つの変更が KPI を悪くし、どれも同じ計測で見つけて直した。

- 新しい std の名前のために、ビルドのたびにソース全体を何度も走査していた。
- prelude の名前の付け替えで単語を走査していた。直すまでは check の命令数が 8.6% 増えていた。
- prelude の選別が、アイテムごと・パターンごとのメモを持ってすべてのアイテムを探していた。これをソース全体の 1 回の検索に替えたことで、no-op ビルドが以前より軽くなった。

この共有マシンでは実時間が ±20% ほど揺れるので、比較には命令数を使っている。

## 次にやること

失敗している run-pass / check-pass のテストで多いのは次のものである。

- まだ型が分からないもの：`Pin`、一部の位置の `impl Trait`、`NonNull`、`UnsafeCell` など
- `async` のブロックと関数
- 整数リテラルの推論による型の不一致
- `impl Trait` を返すジェネリックな関数
- キャプチャしないクロージャの `fn` ポインタへの強制変換
- 前処理が外へ移さない、ブロックの中のアイテム
