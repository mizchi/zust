日付: 2026-11-21

その後の段を扱う。最初のエラーがライフタイムに関するもので、まだ通らないテストを、種類ごとに 1 つずつ見ていった。

## 1. 加えたもの

- **シグネチャ:**
  - 型がライフタイムを書かない struct である引数 (`struct S<'a>` のときの `fn f(s: S) -> &T`) はライフタイムを
    持ちうるので、結果の省略したライフタイムは E0106 ではない。何行かにわたって書いた結果の E0106 は、その省略した
    参照で報告する。
  - impl の self 型の `'_` (`impl S<'_>`) は、それぞれ impl のライフタイムになる。メソッドの中の `Self { .. }` は、
    新しいリージョンの値ではなく、その self 型の値を作る。
  - `for<'a> T: 'a` は `T: 'static`。
  - early-bound のライフタイムの E0195。extern ブロック、フィールドのトレイトオブジェクトの `'_`、関連型の値、
    レシーバのないメソッドでの E0106。
- **変性:** トレイトオブジェクトを持つ struct は、そのトレイトの引数が名指すライフタイムについて不変
  (`Box<dyn FnOnce(&mut &'a isize)>`)。
- **本体:**
  - トレイトオブジェクトへのポインタのキャスト。行き先を推論させるもの (`p as _`) と、末尾がトレイトオブジェクトの
    struct へのポインタも。
  - String と Vec の `*s` は、ローカルが所有する場所 (`&*line` は line を借りる)
  - 初期化のない `let` の注釈の型は well-formed。e を追えないときの `let _: T = e;` も。
  - 組み込みのメソッドの結果はレシーバを借りる
- **クロージャ:**
  - 参照でキャプチャしたものの可変借用を返すクロージャは `FnMut`: "captured variable cannot escape `FnMut` closure
    body"
  - 境界に照らして検査するクロージャは、キャプチャした関数のローカルに、外から来るリージョンで届く。シグネチャが
    束縛するリージョンがそこへ流れると "borrowed data escapes outside of closure"
  - 何も期待されないところで作ったクロージャ (`let f = |_| ();`) の、型を書かない引数のリージョンは 1 つ。どんな
    リージョンの参照でも取る境界に渡すと "not general enough"。結果が引数を借りる fn を、結果が型パラメータである
    境界に渡すのも同じ。
  - `sort_by_key` や `max_by_key` などに渡すクロージャを検査する (`v.sort_by_key(|p| &p.name)`)。prelude が書く
    とおり std でも高階の境界だから。prelude のほかの境界は飛ばしたまま。
- **借用検査:**
  - 参照を通した再借用で、シグネチャのライフタイムより長生きする必要があるものは、関数の終わりまで生きる。NLL の
    universal なリージョンがすべての点を含むのと同じ (`keep: &mut Vec<&'a u8>` のとき
    `keep.push(&v[0]); v.push(1);` は E0502)。リージョン検査が再借用ごとにそのリージョンを記録し、借用検査は、
    その借用を作ったところから生かす。
  - `move` のないクロージャは、読むだけの値のコピーを借りる。rustc のクロージャは、読むだけのものを参照で
    キャプチャするから。読む参照は別: 参照を期待するところに渡す参照は再借用され、クロージャはそのコピーを持つ。
  - ローカルを借りるクロージャを返すと、そのクロージャで E0373
  - `&f()` を返すと E0515
  - 代入 (`x = &f();`) や、参照を持つローカルのメソッド (`v.push(&f());`) が借りる一時値は、文の終わりで
    なくなる (E0716)
- **構文と lint:**
  - E0637: 境界としての `'_` (`impl<'b: '_>`)、境界の引数のライフタイムのない `&` (`where T: Tr<&u32>`)
  - fn と impl の `#![deny(unused_lifetimes)]`、`#![deny(single_use_lifetimes)]`

## 4. 計測の後

f91a81d の後の段。通る compile-fail は 3910 (5db66d5) で、失ったテストはない。

- ローカルの型のリージョンより長生きする必要がある借用は、そのローカルが持つ。そのローカルが生きているあいだ
  生きる (NLL と同じ)。`impl<'a> Foo<'a>` の `fn insert(&'a mut self)` での `foo.insert(); foo.insert();`、
  `&mut self` のメソッドがしまう引数 (`s.set(&mut y); y += 1; s.get();`)
- 何も期待されないところで作ったクロージャのシグネチャは、すべての呼び出しで 1 つ: `let f = |y| y; f(&z); f(x)`
  は、z の借用が流れ込むものを返す
- 本体の `let` の注釈と、トレイトの境界と where 句での E0261
- `match` が `ref` で束縛する一時値は、文の終わりでなくなる。`let` が延ばす一時値 (`let x = &f();`) は、その
  ブロックのローカルと一緒になくなる
- 調整: `rg_call` は、呼び出しごとに `Rg` 全体 (約 1.4 KiB) を 2 回出し入れしなくなった。再借用の到達の計算は、
  辺を 1 本の配列で辿る。patterns check は 700.8M から 700.2M。main (18e598d) に対して、KPI の入力の命令数で
  gen5000 check +0.19%、traits check +0.29%、patterns check +0.66%。

その後、3927 (a4ae97e) まで:

- ライフタイムを持つプログラムの struct と enum を、フィールド、型の別名、関連型でライフタイムを書かずに名指す
  (`type B = Bar<u8>;`)、あるいは違う数を書く (`Buzz<'a, 'b>` に `Buzz<'a>`) と E0106 / E0107。const と static の
  ものは 'static。ドライバは、要約の型がそのような struct を名指す項目だけを読み直す。
- E0195: 型パラメータの境界が名指すライフタイム (`T: Test<'p>`) は early-bound
- `dyn Fn(&'static u8)` と fn ポインタを通した呼び出しは、実引数を引数のリージョンへ流す。値として使う fn アイテム
  (`&drop::<&'a i32>`) は、型引数のリージョンを持つ。static への代入は、値のリージョンを 'static にする
- ライフタイムを書くパターンのパス (`Foo::Bar::<'static> { .. }`) は、照合する値の型の注釈
- `vec![&f()]` の一時値は文と一緒になくなる。返す反復子のアダプタ (`filter_map(|..| ..)`) は、渡したクロージャと、
  それが借りるものを持つ (E0373)
- シグネチャにリージョンのない fn の `impl Trait` の結果は 'static (隠れた型は何も捕捉しない)。
  `impl A<&'static u8>` の中の `Self(..)` は、その型を作る
- 呼び出しは、引数の型が well-formed であることを要る (`&'a Foo<'b>` なら 'b: 'a)
- 何も期待されないところで作ったクロージャが、引数をキャプチャしたものへしまう (`|input| x.0 = input`、
  `v.push(s)`) と、それを含む関数はそれを見て、呼び出しの実引数はそこへ流れる

その後、3944 (84cd2b7) まで:

- レシーバの借用は実引数より先: 実引数が名指す共有のレシーバは、実引数を評価するあいだ借用を保つ
  (`v.get({ v.push(2); 0 })` は E0502)。二相借用の予約も同じ (`v.push(v.pop().unwrap())` は E0499)。`IndexMut` を
  通して書く場所 (Vec の `v[v.len() - 1] = 1`) は、添字より先に借りる
- キャプチャしたものの `&mut self` のメソッドを呼ぶクロージャ (`|| v.push(4)`)、添字を通して書くクロージャは、それを
  `&mut` でキャプチャする
- `&mut` を期待するところに渡す `&mut` のローカルは再借用される (`f(x)` は `f(&mut *x)`)。シグネチャのライフタイムより
  長生きする必要があるものは関数の終わりまで生きるので、ループの中の同じ呼び出しは E0499。`&mut (dyn Tr + 'a)` を
  `&mut (dyn Tr + 'b)` として渡すと、オブジェクトのライフタイムは縮む (unsize の変換)
- メモリにない値の `ref` の束縛 (`let ref y = a;`、`let ref x = 0;`) は、メモリに置いたコピーを束縛する。`ref mut` が
  借りるローカルはメモリに置く。注釈の付いた束縛の場所は、注釈の型を持つ
- 調整 (このブランチの KPI の入力の命令数): 検査の状態 (約 1 KiB) は、検査が最初に書くときに作る。検査が除く関数
  (traits の入力のすべて) は、それを作らず、コピーせず、drop しない。compile_once は compile と同じ結果の型を返す
  (関数ごとにコピーが 1 回減る)。辿る struct の型ごとに、struct の表のロックは 1 回で、型引数をコピーしない。片側に
  リージョンのない flow は何も関係づけない。traits check は 1,175.3M から 1,174.5M、patterns check は 701.0M から
  699.6M。

## 5. 試して、入れなかったもの

- **ブロックの末尾の式の一時値:** edition 2021 までは、それを囲む文の終わりまで生きる (y を所有するブロックの
  末尾の `y.borrow().clone()`)。edition 2024 はブロックで終わらせる。zust 自身のコードは edition 2024 なので、
  2021 に従うとそれを拒否してしまう。
- **E0713:** `Drop` を持つ値が持つ `&mut` を通した借用が、その値の drop のときにまだ使われているもの。関数の終わりの
  引数の drop は、まだ借用検査のイベントになっていない。
- **struct のフィールドの暗黙の境界のコストの調整を 2 つ:** リージョンのない struct を飛ばすもの、フィールドが何も
  導かない定義を飛ばすもの。測れる差がないか、削るより足すほうが多かったので、入れなかった。

## 6. まだ扱わないもの

- 呼ばれないジェネリック関数: `zustc check` はそもそも検査しない。ライフタイムと借用の、落ちている 451 のテストの
  うち 120 は、最初のエラーがその中にある (`impl<'a, T> FuncWrapper<'a, T>` のループの中の `(self.func)(arg)` も
  そう)。検査するには、型パラメータの代わりの型と、型パラメータのリージョンを universal なリージョンとして扱う
  ことが要る
- クロージャの本体が、それを含む関数に要るもの (rustc の closure requirements): 境界のないクロージャは単独で
  検査する
- prelude のイテレータ: その型はライフタイムを持たないので、`.iter().map(..).collect()` が借りるものを見失う
- 高階のトレイト選択 (`fn(&i32)` に対する `impl<A> Foo for fn(A)`)
- パスが書くライフタイム引数の数 (E0107)、シグネチャの中のライフタイムを持つ型の別名
