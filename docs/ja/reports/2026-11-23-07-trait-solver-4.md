# trait solver、その 4: 誤ったエラーを減らす

日付: 2026-11-23

その 1–3 では zustc が弾く誤ったプログラムを増やした。今回は逆向き: トレイトの仕組みが弾いていた正しいプログラム
(tests/ui の run-pass と check-pass)。

## 1. solver 自身の誤った `No`

`solve_no_sound` は、*zustc が読んだ impl について*、成り立つゴールに solver が `No` を言わないことを約束する。check-pass /
run-pass のテストが 2 件、solver に弾かれていた。どちらも、zustc の見ているプログラムが本物より厳しいところで、
弱める規則 (その 1) が禁じていることだった:

- `overloaded/overloaded-autoderef-vtable.rs`: `call_fn_vals` がレシーバの構造体の型引数を、構造体の順のまま impl の型引数に
  していた。`impl<T, H: Helper<T>> Deref for WithHelper<H, T>` は T と H が入れ替わり、solver は入れ替わったゴールに正しく
  no と言っていた。いまは impl のパラメータを self 型から照合して解く。
- `higher-ranked/.../issue-90950.rs`: zustc は `Cow<'_, str>` を `__CowStr`、`Cow<'_, [T]>` を prelude の `Cow<T>` で表す。
  パラメータ T の `Cow<'_, T>` への impl は zustc の 2 つの型を覆うのに、解決した頭は片方しか覆わない。そういう頭はいま
  任意の型に弱める (`two_reps`)。

## 2. `implements` が間違っているところ

`Insts::request` は `Program::implements` が no と言えば呼び出しを弾いていた。この文字列ベースの判定は多くの impl を見落とす:
`(): PartialEq`、`Range<i32>: Clone`、`i32: Foo<A = usize>`、`&F: Fn()`、`String: AsRef<T>`。solver だけを信じる
(最初の試み) と、正しく弾いていたものを 46 件失った。`implements` は solver が判断できない std のトレイトの多くで正しい
(呼べないものの `Fn`、`Future`、`Into`、`UnwindSafe`、derive の境界) から。いまの規則:

- プログラムのトレイト: solver の `No` だけ;
- std のトレイト: `implements` の `No`。ただし見落とすと分かっているところは除く。それは、モデル化していない std の
  ブランケット impl (`Borrow`、`Any`、`DoubleEndedIterator`)、クロージャか型パラメータへの参照の `Fn` トレイト (`&F` は F が
  持つ Fn トレイトすべて、`&mut F` は FnMut / FnOnce)、`()` の導出できるトレイト (solver が std の一覧から答える)、
  インスタンスの型で成り立つ境界 (T = str の `AsRef<T>`、`Into<&'a str>`)。最後のものは `No` を取り消すだけ:
  型を文字列に入れて聞き直すと `implements` が誤る新しい文字列になり、二度目の問いが正しいプログラムを弾いたので、
  弾く理由には決してしない。

古い判定が理由違いで正しかった場合には、本来の理由を与えた:

- `dyn Tr<A = T>` は、Tr が A に付ける境界を T が破るなら Tr でない (`type Y: Clone` での `dyn X<Y = str>`);
- unsized な型は `Copy` / `Clone` / `Sized` / `Default` でなく、呼べない値 (スカラー、配列、プログラムの構造体) は `Fn` で
  ない;
- `impl Trait` 引数のパラメータを名指す turbofish の E0107 (`foo::<str, String>`)。

`dyn Tr` への型強制も同じ規則に従う (プログラムのトレイトは solver で)。

受け入れるプログラムが増えて誤コンパイルが 1 つ見えた: `() == ()` (と `()` のほかの比較) が実行時に panic していた。
いまは定数。

compile-fail の 2 件が通らなくなった。どちらも偶然通っていたもので、rustc のエラーはライフタイムについてのもの
(zustc の `Ty` はライフタイムを消す): `borrowck/implementation-not-general-enough-ice-133252.rs`、
`impl-header-lifetime-elision/dyn-trait.rs`。

## 3. トレイト引数つきの関連型

`<S as Trait<usize>>::Assoc` は構文木で `usize` を失い、`Assoc` を定義する impl を self 型だけで選んでいた: 最初の impl、
または定義がトレイト引数に依るとき (`impl<X> Trait<X> for S { type Assoc = X; }`) は見つからない。トレイトに型引数のある
修飾パスは、いま self 型と引数のタプルの関連型 `#targs:Trait#Assoc` になる (ジェネリックな関連型と同じやり方)。具体的な
とき、定義を impl のトレイト引数 (`AssocDef::trait_args`) とともに、solver の `mtch` で正確に照合して引く。そうでないか、
何も合わないときは self 型だけで引く従来のやり方に戻るので、これまで解決していたものは変わらない。

## 結果

tests/ui、この回の初めとの比較:

| 種類 | 前 | 後 |
|---|---:|---:|
| run-pass | 1832 | 1842 |
| check-pass | 1512 | 1520 |
| build-pass | 102 | 102 |
| compile-fail | 4539 | 4542 (うち 1 件は偶然) |

新たに「通った」compile-fail の 1 件は、その行で別の理由 (対応していないキャスト) で弾かれていたので
`bench/rust_ui_accidental.txt` に載せた。`cargo test --release --workspace`: 375 件成功。失敗する 2 件は zust-analyzer の
LSP hover テストで、rust-src が要る (ここには入っていない)。

新しいテスト: `tests/compile_errors/trait_solver_dyn_binding_bound.rs`、`tests/compile_errors/turbofish_impl_trait_arg.rs`、
弾かれていた形それぞれの `examples/trait_solver.rs` のケース (self 型と順の違うパラメータの impl、`&F: Fn`、
`T: Borrow<T>`、`(): PartialEq + Default`、`<Pick as Choose<u16>>::Out`)。

## 残っているもの

- 「cannot find associated type」が残るのは、X を定義する impl の中の `Self::X` で、X の定義がトレイト引数だけが束縛する
  impl のパラメータを名指すとき (`unsized/issue-40231-*.rs`)、と値がジェネリックな構造体の定義 (構造体のフィールドを
  解決した後に登録される: `wf/issue-48638.rs`、`macros/type-macros-hlist.rs`)。
- std のトレイトのほとんどはまだ `implements` が判定する。prelude の impl を solver の節にすれば両方向が正確になる。
- 正しいコードへの誤ったエラーで最も多いのはトレイトではない: 「mismatched types」(122 件) で、主に型推論と型強制。
