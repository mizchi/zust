その 18 ([2026-11-23-07](2026-11-23-07-region-check-18.md)) は #105 でマージした。この段階で加えるもの:

- クロージャの呼び出しの結果。本体がそれを作る引数の借用を持つ;

## 1. 加えたもの

### クロージャ

- **クロージャの呼び出しは、本体が結果を作る引数の借用を持つ。** これらを受け入れていた:
  - g を後で使う `let some = |a| Some(a); let g = some(&temp());` (E0716);
  - コンストラクタを値として書いた `let some = Some; let g = some(&temp());` (E0716、
    lifetimes/temporary-lifetime-extension-tuple-ctor.rs のケース);
  - g を後で使う `let g = some(&x); drop(x);` (E0505)。

  rustc はこういうクロージャに 1 つのシグネチャを推論し、結果の領域は本体によってパラメータの領域に結びつく。ここでは、
  本体の値がどのパラメータから作られるかを、書かれたとおりに、クロージャを作るところで取る: パラメータそのもの、
  コンストラクタの引数、その中の場所の `&`、そのビュー (`s.as_str()`)、`if` や `match` のそれぞれの腕。パラメータを読む
  だけ、またはそれを渡して呼ぶだけのクロージャ (`|k| m.get(k)`、`|a| a.len()`) は、その借用を持たない。
- **クロージャの本体がパラメータに求めることは、呼び出しの引数に求める。** c がローカルのとき、次のそれぞれで `f(&c)` を
  受け入れていた (E0597):
  - `let f = |x| { let y: &'static u32 = x; };`;
  - `let f = |x| W::<&'static u32>(x);`、`let f = |x| id::<&'static u32>(x);`;
  - `struct W<T>(T)` のコンストラクタを値とした `let f = W::<&'static u32>;`。

  注釈やターボフィッシュが領域を指し、クロージャのパラメータがそこへ流れ込む。共有のシグネチャ (呼び出しの引数が流れ込む
  領域) はそれより長生きしなければならないので、引数の借用もそうなる。
- **ライフタイムを書くクロージャの本体は、ほかに求めるものがなくても検査する。** クロージャのリージョン検査は、境界、注釈
  付きのパラメータ、キャプチャのどれかがあるときだけだった。`|| { let c = 66; let y: &'static u32 = &c; }` を受け入れて
  いた (E0597)。関数の 'a を指す `let y: &'a u32 = &c;` も同じだった。今は `let` の注釈、キャスト、ターボフィッシュに
  ライフタイムを書く本体を、入れ子のクロージャも含めて検査する: クロージャの本体の `let f = S::<&'a u32>; f(&c);` は
  E0597 である。これらで nll/user-annotations/adt-tuple-struct-calls.rs が通る。

### リージョン検査

- **関数ポインタの型が領域を束縛するところに渡す関数アイテムは、そのどれについても成り立たなければならない。**
  `fn want(f: for<'cx> fn(&'cx S) -> &'static S)` と `fn baz(x: &S) -> &S` で `want(baz)` を受け入れていた (rustc では
  E0308、ここでは「lifetime may not live long enough」)。パラメータの型が束縛する領域は新しい変数で、アイテムの値も結果の
  省略された領域を新しいものとしていた。今はそれらは呼び出しの 1 つのプレースホルダーで、アイテムの値はシグネチャと同じく
  省略する (`for<'a> fn(&'a S) -> &'a S`)。`for<'cx> fn(&'cx S) -> &'cx S` には `fn foo(x: &S) -> &'static S` でよい。
  `let` の注釈 (`let g: for<'cx> fn(&'cx S) -> &'static S = baz;`) も同じように検査する。
- **型が impl のライフタイムを指す impl の定数は、パスが書く領域のものである。** `impl<'a> Foo<'a> { const C: &'a u32 =
  &22; }` で `<Foo<'a>>::C` を `&'static u32` として返すのを受け入れていた (「lifetime may not live long enough」、
  nll/user-annotations/constant-in-expr-inherent-1.rs)。要約は、こういう定数の型の、impl のライフタイムに対するコードを
  持つ。使うところでは、パスが self 型に書く領域をそれらに与え (`Foo::<'a>::C` も)、書かないものには新しい領域を与える。

## 5. まだ扱わないもの

- **ライフタイムを固定する関数ポインタ型の型エイリアスを通して渡す関数アイテム**: `type G = for<'cx> fn(&'cx S) ->
  &'static S;` の `want_G(baz)` (regions/regions-fn-subtyping-return-static-fail.rs)。要約はエイリアスの定義の
  ライフタイムを持たず、関数の要約はそのモジュールのエイリアスを見ない。
- **関数で作り、別のクロージャの本体で呼ぶクロージャ** (adt-tuple-struct-calls.rs の
  `annot_reference_named_lifetime_across_closure`)。内側の本体は、外側のクロージャのシグネチャなしで単独に検査する。
- **型がトレイトのライフタイムを指すトレイトの定数** (`<T as Foo<'a>>::C`、`T: Foo<'a>` の `T::C`、
  nll/user-annotations/constant-in-expr-trait-item-2.rs、-3.rs)。何も呼ばないジェネリックな関数は、定数を使うところに
  届かない。
- **結果が境界の束縛するパラメータに結びつくのに、キャプチャしたものを返すクロージャ** (`F: FnMut(&isize) -> &isize`
  と `x: &'x isize` の `take(|_z| x)`、lifetimes/closure-lifetime-bounds-10291.rs)。そこでは関数の領域に、境界の領域
  より長生きすることを求めていない。次の段階で進めている。
- **ガードの一時値を通して読む `&mut` の暗黙の再借用** (後で使う `let val: &_ = x.borrow().0;`、
  borrowck/issue-36082.rs)。
- **スライスでも `str` でもない型の `Cow<'_, T>`**、関数の中の `use std::option::Option::Some as S;`
  (lifetimes/temporary-lifetime-extension-tuple-ctor.rs)。
- **`let` の初期化式以外で値としてムーブされる `&mut`**: ジェネリックな f の `f(a[0])`、`vec![a[0]]` (E0508)。
- その 17 から:
  - 1 か所に書いたプログラムの 2 つの deref (`(&mut **w).bump()`);
  - ある型への impl があいまいなトレイト (borrowck/mut-borrow-in-loop-2.rs)。
- その 16 から:
  - ジェネリックな関数の `dyn Tr<T>`;
  - `&*vec![1].iter().next().unwrap()`;
  - opaque 型のメンバー制約 (E0700);
  - タプルの推論の中の `&mut`;
  - フィールドごとの領域;
  - `static` クロージャの借用検査。
