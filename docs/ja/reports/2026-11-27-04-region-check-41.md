# リージョン (ライフタイム) 検査、その 41: 特殊化する、または型より多くを求める Drop の impl と、所有する場所の `ref` 束縛

日付: 2026-11-27

その 40 ([2026-11-26-03](2026-11-26-03-region-check-40.md)) は #278 でマージした。この段階は、`Drop` の impl が守るべき
規則 (drop の検査が頼るライフタイムと境界) と、`ref` 束縛が作る借用を扱う。

## 1. 加えたもの

- **E0366: `Drop` の impl の self 型は、impl 自身のパラメータを、それぞれ 1 度だけ書く。**
  - 拒否するもの: `impl Drop for P<i8>`、`impl Drop for N<'static>`、`impl<One> Drop for V<One, One>`、`impl<'l> Drop
    for W<'l, 'l>`、`impl Drop for X<3>`。
  - 受理するもの: `impl Drop for H<'_>`。
  - 以前はどれも拒否しなかった (dropck/issue-38868.rs、dropck/reject-specialized-drops-8142.rs)。
- **E0367: `Drop` の impl が型のパラメータに求めるのは、定義が求めるものだけである。** impl のヘッダと where 節の
  述語それぞれを、定義の境界と where 節に照らして確かめる:
  - ライフタイムが outlive するライフタイム: インラインか where 節の `'b: 'a`。定義の outlives は推移的に成り立つ
    (`'c: 'b` と `'b: 'a` は `'c: 'a` を与える);
  - 型が outlive するライフタイム: 定義が `T: 'a` しか書かないところの `T: 'static`;
  - トレイト境界。std のものとプログラム自身のもののスーパートレイトとともに: `T: Ord` は `T: PartialOrd` を与える;
  - 関連型の等式: 定義が `T: Trait` と書くところの `T: Trait<Assoc = U>`;
  - `Sized`: impl のパラメータは、`?Sized` と書かない限り Sized である。

  定義のフィールドが導く outlives も、rustc が型について推論するのと同じく (RFC 2093) 数える: `struct DropMe<'a,
  T>(&'a T)` は `T: 'a` を与える。self 型が持たないパラメータの述語は成り立ちうるので、確かめない (`impl<'r, T: 'r>
  Drop for R<T>`)。メッセージは rustc のもの: "`Drop` impl requires `'b: 'a` but the struct it is implemented for does
  not"。プログラム自身のトレイトで縛られたパラメータは、トレイト境界について確かめない: 要約がトレイトのスーパー
  トレイトをすべては記録しないためである。
- **所有する場所の `ref` 束縛は、それを借用する。** `|ref line: String| make_entry(self, line)` で、束縛の
  リージョンは新しいもので、引数と関係がなかった。その結果を impl のライフタイムを通して返すことを受理していた。
  rustc の E0515 である。今は、`ref` 束縛は、借用検査がパターンを置く場所の、`&place` と同じ貸し出しである。
  それはその場所を関数が所有し、参照を通さずに届くときである: クロージャの引数のパターン (`__p0`)、`let` や `match`
  の対象とそのフィールド。参照を通すとき (`|&ref x| ..`、`self: &S` での `match self`) はそうしない: そこでは束縛は
  参照が指すものを借用する。
- **メッセージの "function parameter"。** パターンが束縛するクロージャの引数 (`__p0`) の借用は、合成した名前で報告
  していた: "`__p0` is dropped when the function returns"。今のメッセージは rustc のもの: "cannot return value
  referencing function parameter"。

## 4. レビュー

#324 への CodeRabbit のレビューには 4 つの指摘があった。どれも zustc と rustc 1.97 で確かめた。

- **直したもの: 誤った E0367。**
  - 2 度書いた定義の境界 (`struct S<T: Iterator>(T) where T: Iterator<Item = u8>`) は最初のものだけを、その等式なし
    に残していた。そのため `impl<T: Iterator<Item = u8>> Drop for S<T>` を拒否していた。今は同じトレイトをもう一度
    書くと、その等式も加わる。
  - パラメータを Sized にするトレイトで縛られた `?Sized` のパラメータ (`T: ?Sized + Clone`、`Copy`、`Default`、
    `: Sized` を持ちうるプログラムのトレイト) では、impl の `T: Sized` は何も足さない。それを拒否していた。
- **直したもの: その修正による E0367 の見逃し (2 度目のレビュー)。** そこではプログラムのトレイトをすべて Sized と
  数えていたので、`trait Tr {}` と `struct S<T: ?Sized + Tr>` での `impl<T: Tr> Drop for S<T>` を受理していた。今は
  トレイトのヘッダから `Sized`、`Clone`、`Copy`、`Default` を読み (`trait Tr: Sized`、`where Self: Sized`)、
  スーパートレイトを通してたどる。
- **しなかったもの: 等式の値。** `struct S<T: Iterator<Item = u8>>` での `impl<T: Iterator<Item = u16>> Drop for S<T>`
  を受理する (rustc の E0367)。等式が定義のものかは、あるかどうかだけで確かめる。下に挙げる。

## 5. まだ扱っていないもの

- **境界の等式の値** (定義が `Item = u8` と書くところの `Item = u16`): 比べない。
- **prelude の関数に渡すクロージャ** (impl のライフタイムを通して `line` の借用を返す `v.into_iter().map(|line|
  self.me(&line))`、rustc の E0515、borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs): そうしたクロージャの
  本体はリージョンのシグネチャを得ない (その境界は prelude のもの) ので、本体をリージョン検査しない。先に `let` に
  束縛したクロージャは検査する。
- **本体の注釈でのトレイトオブジェクトの引数の不変性** (`Box<dyn Foo<Bar = &'static u32>>` を受ける `let _:
  Box<dyn Foo<Bar = &'a u32>> = make();`、variance/variance-associated-types2.rs): 受理する。シグネチャでの同じものは
  (不一致として) 報告する。
- **別のモジュールにある同じ名前の型の Drop の impl**、またはパスとして書いた self 型 (`self::S<T>`): 確かめない。
