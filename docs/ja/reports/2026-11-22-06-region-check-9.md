# リージョン (ライフタイム) 検査、その 9: ブロックの末尾、match のガード、デストラクタ、関数本体の中のアイテム (issue #1)

日付: 2026-11-22

その 8 ([2026-11-22-05](2026-11-22-05-region-check-8.md)) は #48 でマージした。最後のレビューでの修正は、そのレポートを
書いた後に入った: リテラルの中の定数のブロックは昇格する、構造体の更新はその基を読む、再借用 (`q = &mut *p`) を通した
書き込みは p が指す先に届く、`&mut` の `&mut` を通した書き込みは内側が指す引数の先へ逃げない。このステップでは、
tests/ui で受け入れてしまっていた借用検査の場合をさらに扱い、関数の中に書いた関数の借用のエラーを報告する。

## 1. 加えたもの

### 借用検査

- **引数として渡すブロック:** ブロックの末尾が借用するものを、呼び出しが受け取る。
  - `gimme({ let v = 22; &(v,) })` を文の後で使えば、`gimme(&(v,))` と同じく E0716。
  - `let x: &str = { mk().as_str() };` も同じ。受け手の `mk()` はその文の一時値。
  - ブロックの末尾そのものの借用は、これまでどおり `let` が延ばす: `let s = { let v = 1; &(v,) };` は受け入れる。
- **`&{ .. }` は一時値:** ブロックの値は、末尾が名指すものからムーブかコピーしたもの。`gimme(&{ let v = 4; (v,) })`
  を文の後で使えば E0716。
- **`let _ = x;` は x を生かす:** x を読むことではないが、rustc の fake read はそこで x を生かす。
  - なので `let r = &y; y = 2; let _ = r;` は E0506。
  - x をムーブした後の `let _ = x;` は、これまでどおり受け入れる。
- **E0510、検査する場所を変える match のガード:**
  - パターンが scrutinee を検査する match のガードで、その場所、それを含む場所、それが指す先に代入するとエラー。
    可変で借用するのも同じ (それをキャプチャするクロージャを通してでも)。
  - rustc の fake borrow は浅いので、場所の一部は対象外 (`match s` のガードでの `s.b = 2`)。
  - 何も検査しない match (`match x { y if .. }`) は何も借用しない。
  - 検査は、借用検査のイベントを作った順に辿る。ガードはソースの 1 つの部分なので、データフローは要らない。
- **E0713、デストラクタが走るときにまだ使われている借用:**
  - `Drop` を実装した型の値の `&mut` のフィールドを通した借用を、関数が返す。値の `drop` は関数が戻るときに走り、
    そのフィールドを使うかもしれない (`s: Scribble` での `&mut *s.0`)。
  - Box を通しても (`s: Box<Scribble>` での `(*s).0`)、ローカルが持つ参照を通しても (`let r = &*v.0; &r.0`) 同じ。
  - `&` のフィールドは対象外: 共有の借用はコピーして持ち出せる。
- **ユーザーの `Deref` を通して届くメソッド:** ターゲットの `get` に対する `x.get()` は `deref(&self)` を呼ぶ。受け手は
  共有で借用され、self から借用する結果はそこから借用する。結果を使う間に `x.c` に代入すれば E0506。以前は受け手を
  読むだけだった。
- **E0507、キャプチャしたものをムーブで持ち出すクロージャ:** 境界が `Fn` か `FnMut` を求める所に書いたクロージャは、
  その種類のクロージャ。キャプチャをそこから持ち出すと (`take_mut(|| { let s: String = val; })`)、rustc と同じく
  ムーブの位置でエラー。名前で渡すクロージャは、以前からクロージャの位置で E0525。
- **`v: &mut Vec<T>` での `for n in v` は v をムーブする:** `IntoIterator::into_iter(v)` は型パラメータを取り、そこは
  型強制の場所でないので、`&mut` は再借用されない。v を 2 回目に回すと E0382。`v.iter_mut()`、`&mut *v`、`&` は
  変わらない。

### リージョン

- **トレイトの引数は不変:** 呼び出し先の境界 `G: Get<T>` (T = `&'min i32`) と、自分の型パラメータ G に境界
  `G: Get<&'max i32>` を持つ呼び出し元を考える。2 つのリージョンは同じでなければならないので、`'max: 'min` しか
  分からなければ、その呼び出しはエラー ("lifetime may not live long enough")。

### 関数本体の中のアイテム

- `fn main() { fn helper() { .. } }`: helper は、検査の前にソースの最後の行より後ろへ移される。`zustc check` はその
  行より後ろのエラーをすべて捨てていたので、そうした関数の借用のエラーは一度も報告されなかった。
- その借用検査とリージョン検査のエラーは、アイテムを移す前の行で報告するようになった。
- それ以外のエラーは、これまでどおり報告しない。アイテムが元の場所で名指せるもの (周りの impl の `Self`、頼っている
  `&mut T` の境界など) を typeck はすべては知らないので、そうしたエラーは正しいプログラムを拒んでしまう。

### prelude

- `Pin<P>` は `Display` と `Debug` を実装し、std と同じくポインタが表示するものを表示する。それを表示するテストは、
  借用のエラーに届く前にその型エラーで止まっていた。

## 5. レビュー

#51 への CodeRabbit の指摘を、rustc 1.97 と突き合わせて確かめた。

- **拒んでいた正しいコード:**
  - キャプチャした名前を束縛し直すクロージャ (`Fn` の境界に渡す `move` クロージャの中の
    `let val = String::new(); drop(val);`) が E0507 だった。ムーブの検査が名前で見ていたため。今はスコープを辿る:
    `let` の後や、その名前を束縛する arm、ループ、`if let`、入れ子のクロージャの中では、キャプチャではない。`let`
    より前のムーブは、これまでどおり E0507。
  - `Drop` の型の `data: &mut &'static u32` に対する `&**s.data` が E0713 だった。`&mut` の deref の後の `&` の deref
    を越える借用は、共有の参照が指す先の借用で、drop はそこに届かない。
  - `match s { S { .. } if { s = ..; false } => .. }` が E0510 だった。`S { .. }` は何も検査しない。
  - `Fn` の境界に渡すクロージャの中の、n が整数の `let (n, _) = pair;` が E0507 だった。キャプチャを分解する `let`
    は、値で束縛する部分のうち、型が `Copy` でないものだけをムーブする。ムーブの検査は、部分について型検査が
    知っていることを受け取る。
- **見逃していたエラー:**
  - ガードは scrutinee だけでなく、パターンが検査する場所を守る: arm が `.0` を検査する match のガードでの
    `pair.0 = None` は E0510、`pair` そのものへの代入も同じ。`pair.1` は対象外。
  - 束縛の元になる場所の deref の手前も守る: `match *ptr { v if .. }` のガードでの `ptr = &2` は E0510。
  - フィールドの中の `Drop` の値を通した E0713 (`w: Wrapper(Scribble)` での `&mut *(w.0).0`)。
  - 外側の `Fn` / `FnMut` のクロージャがキャプチャしたものをキャプチャする、入れ子の `move` クロージャの E0507
    (入れ子のクロージャの位置)。
  - `Deref` を通して届く受け手は、引数を評価する間も借用されたまま (`w.read(drop(w))`、E0505)。
  - トレイトの境界にある、呼び出し先の `'static` (`G: Get<'a>` からの、`G: Get<'static>` の `need_static::<G>()`)。
  - 関数本体の中の関数: 借用のエラー `cannot use .. because it was mutably borrowed` と `use of partially moved
    value` も報告し、メッセージが名指す位置も、関数を移す前の行にする。
  - `Pin<P>` が `Debug` と `Display` を実装するのは、P が実装するときだけ。
- **変えないもの:** `r: &mut i32` での `take_mut(move || read(r))` を拒むという指摘があったが、受け入れている。

## 6. まだ扱わないもの

- **型パラメータでない型への where 句** (`where &'max G: Get`): typeck はそうした境界を知らないので、関数の
  プレースホルダーのインスタンスが型検査を通らず、リージョンを検査しない (variance/variance-*-self-trait-match.rs)。
- **関数本体の中のアイテムの、それ以外のエラー:** 1 節を参照。
- **その 8 のレビューから:** 大文字の名前のローカル (`V`) は定数とみなすので、`gimme(&(V,))` の E0716 は見逃す。
  E0582 は射影のライフタイム (`X::Assoc<'a>`) を入力と数える。構文解析は、それとモジュールの型を区別できない。
- **#51 のレビューから:**
  - zustc の書式の引数の検査は、見つけた impl の境界を見ないので、`Pin<&NoDebug>` の `{:?}` を受け入れる (そうした
    境界を持つ汎用の impl すべてで同じ)。
  - クロージャがキャプチャする `&mut` は、ムーブを検査するキャプチャに入らない (渡す所で再借用されるため)。なので
    `FnMut` の境界に渡すクロージャの中の `drop(r)` の E0507 は見逃す。
  - `match *ptr { v if .. }` のガードでの `*ptr` への代入は、rustc では E0506 (ガードの束縛がそれを借用する)。
    受け入れている。
  - キャプチャを分解する `move` クロージャ (`let P { n, .. } = p;`) は、rustc のようにパターンが束縛するフィールド
    でなく、p 全体をキャプチャする。そうしたクロージャを 2 つ作ると、2 つ目はムーブした p の使用になる。
- **tests/driver2.rs と `probe/stdin_read`:** 1 つのテストのプロセスで多くのプログラムをビルドし、テストをバック
  グラウンドで走らせると、プログラムが与えていない入力を読むことがある。単独で走らせても、フォアグラウンドでも、
  CI でも通る。原因はまだ分からない。
