# リージョン (ライフタイム) 検査、その 2: 最初の版が残したもの (issue #1)

日付: 2026-11-21

最初の版 ([2026-11-20-01](2026-11-20-01-region-check.md)) は、関数の本体をシグネチャの全称リージョンに照らして検査した。この
レポートは、それがマージされた後の作業を扱う。あのレポートが挙げた欠け、および通らないテストが示した欠けである。

## 1. 加えたもの

- **検査が追うようになった値:**
  - 定数の昇格 (promotion) で static にならない一時値 (`&(5_i32.reverse_bits())`、`&(n + 1)`、`&[&FOO]`、
    `impl Drop for Test` のある `&Test`)、および文の中の呼び出しの一時値
  - `Box::new(x)`、配列のリテラル、タプルとタプル構造体のコンストラクタ (`B(a)`)、キャスト
  - クロージャ: キャプチャするもの (値で: そのリージョン。参照で: ローカルの借用)
  - トレイトオブジェクトを通した呼び出し (`Self` をそのオブジェクトとする)。`&self` を取る prelude のメソッドは self の借用を返す
  - 呼び出しに書いた型引数 (`f::<&'a u32>()`)
  - 添字の場所 (`&mut v[..]`)。共有参照を通した再借用は、その参照のぶんだけ生きる (NLL の supporting prefixes)
- **値が流れるところの型強制:** トレイトオブジェクトへは、値のすべてのリージョンがオブジェクトのリージョンより長生きする。配列から
  スライスへ。参照から、それが deref する先へ。
- **トレイトオブジェクトのライフタイム:** 書いた境界、なければ既定 (それを包む参照、型パラメータのただ 1 つの境界、どちらもなければ
  シグネチャでは `'static`。本体では推論する)。
- **クロージャの本体:** 渡される先の境界が与えるシグネチャに照らして検査する。境界が束縛するリージョンはプレースホルダ。呼び出し先の
  ライフタイム、型パラメータのインスタンス (`-> R`)、クロージャの環境は外から来る。境界がなく注釈のあるクロージャは、引数の省略した
  リージョンを自分で束縛し、結果のリージョンは外から来る。prelude の境界は飛ばす: prelude はライフタイムを書かず、std の境界には
  高階でないものもある (`is_sorted_by_key`)。
- **書いた型の well-formedness (`crates/syntax/src/wf.rs`):** `&'a T` は、T の中のすべてのライフタイムが `'a` より長生きすること
  (E0491) と、T の中のすべての型パラメータがそう宣言されていること (E0309、E0310) を要る。fn の境界と where 句、impl の関連型の値、
  struct の `&'static` のフィールドで検査する。ほかのアイテムが決めること (トレイトの `: 'a` のスーパートレイト、struct の要求) は
  検査しない。
- **ゲートが外す関数:** `'static` が要るところ (`let` の注釈、キャスト、呼び出し先) から検査を始め、そのとき引数の木を作る。
- **エラーを報告する場所:**
  - 戻り値として逃げる借用: 戻すところで (E0515)
  - クロージャのキャプチャ: 本体が最初に使うところで
  - 呼び出しのエラー: 呼び出しで (`call_fn` には位置が渡らない)
- **fn ポインタの型** は自分のリージョンを持つ (引数について反変)。それが束縛するリージョンはそれ自身のもの。それを持つ struct は、
  そこから変性を得る。それを名指す型の別名は不透明なまま。
- **さらに追う値と場所:** `let _: T = e;`、`if` / `match` の値、`self: &Struct` のレシーバ、トレイトオブジェクトを通して
  `&self` のメソッドのために借りる Box の中身、Vec・配列・スライスを回る `for` ループの要素。
- **本体の中の well-formedness:** `let` の注釈の型と struct リテラルの型 (定義の境界)。impl の self 型は well-formed
  (そのメソッドでは暗黙の境界、呼び出しでは要求)。型引数の well-formedness は暗黙の境界になる (`Option<&'s &'l ()>` は
  'l: 's を与える)。
- **トレイトの `Self: 'x` 境界:** `trait Wedding<'t>: 't` は、`dyn Wedding<'k> + 'r` に 'r: 'k を要る (E0478)。impl の self 型は、
  トレイトが要るものより長生きする。これはドライバが検査する: すべてのトレイトが見えるのはドライバだけだから。
- **比較:** 両辺は 1 つの型なので、その不変な部分は同じになる。
- **クロージャのキャプチャ** は、外の関数のリージョンを保ち、その関数が知るとおりに関係づける。
- **遅い検査:** 遅れて始めた検査が、それより前に束縛されたローカルに出会ったら、関数を先頭から検査し直す (ベンチマークの関数で
  そうなるものはない)。
- **借用検査の側:**
  - `Drop` が借りているものを使いうる値の drop 検査
  - `ret_from` は、結果のライフタイムより長生きすると宣言したライフタイムも取る (`fn f<'a, 'b: 'a>(x: &'b T) -> &'a T` は x を借りる)
  - トレイトが自由にしておく引数を、ヘッダのライフタイムに結びつける impl のメソッド (`fn next(&'a mut self)`): E0308。
    ほかのライフタイムを名指す self 型のレシーバ (`self: Foo<'b, 'a>`): E0308
  - E0392: 境界の `Fn(..)` の引数でだけ使うライフタイムも、使っている

## 3. KPI

`bench/kpi_track.py --dry-run --lsp` で、main (18e598d) と d4ed42d を比べた。その後の段 (14faccc まで) は、patterns check を
+0.12% 足し (検査が有効な関数の for ループの要素)、gen5000 と traits を変えるのは 0.01% 未満。

- **いちばん費用がかかった段はクロージャの本体。** 最初の版は traits を +1.68%、patterns を +0.80% にした:
  - クロージャの引数ごとに、境界のテキストを解析し直していた。`fn_bound_of` は、解析したテキストを返すようにした。
  - prelude の関数に渡すクロージャも検査していた。今は飛ばす。
  - 残るのは、プログラム自身の境界に渡すクロージャの検査。
- **ほかの段は、それぞれ 0.05% 未満。**
  - well-formedness の検査は、境界か where 句が参照を書くときだけ走る。
  - 新しいフックは、検査が有効な関数でだけ仕事をする。
  - 要約がトレイトの `Self: 'x` 境界について持つものは、フィールドではなく、既存のリストの項目にした: `Summary` を大きくする
    だけで gen5000 が +0.06% になった (割り当てとコピー)。
  - 比較のフックは、まず検査が有効かを見る: 二項式ごとに演算子を照合すると gen5000 が +0.04% になった。

## 4. まだ扱わないもの

- 呼ばれないジェネリック関数: `zustc check` はそもそも検査しない (E0310 のテストの多く)
- 高階のトレイト選択 ("implementation of `Trait` is not general enough")
- 型強制や呼び出しが選ぶ impl の要求 (`impl Tr for S<T> where T: 'static`)
- 要約の時点の well-formedness 検査での、struct 自身が引数に要るものと、トレイトが要るもの
- prelude のイテレータ: その型はライフタイムを持たないので、`.iter().map(..).collect()` が借りるものを見失う
- prelude の関数に渡すクロージャ
