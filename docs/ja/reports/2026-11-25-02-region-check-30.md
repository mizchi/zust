# リージョン (ライフタイム) 検査、その 30: アームでの値の束縛のムーブ、型に対する outlives の境界、オブジェクトのライフタイムとしてのトレイト自身の境界、一時値に対する `self: Box<Self>` (issue #1)

日付: 2026-11-25

その 29 ([2026-11-25-01](2026-11-25-01-region-check-29.md)) は #155 でマージされた。この段階で加えるもの:

- 値の束縛のムーブの E0382 を、rustc が出すところであるそのアームで出す;
- 型に対する outlives の境界が含意する outlives の関係 (`D<'a>: 'b`、`Self: 'b`、`&'a T: 'b`);
- `trait Any: 'static` としての std の `Any` と、トレイト自身の境界をデフォルトとする、省略されたオブジェクトの
  ライフタイム;
- 型自身の `Index` とその後の `Deref` を通したフィールドの読み出し (`v[0].f`);
- 一時値の `Box` に対して呼ぶ `self: Box<Self>` のメソッド。

## 1. 加えたもの

- **アームでの値の束縛のムーブ。** `match a { [_, _, _x] => {} }` の後の `match a { [.., _y] => {} }` を考える。rustc は
  `_y`、つまり 2 つ目のアームの行で E0382 を出す。zustc は検査される値の `a`、その前の行で出していた。
  - 検査される値が所有するものからのムーブは、今はそのアームにある。`ref` の束縛の借用はすでにそうだった。
  - 参照を通したムーブ (`match *x { Some(_s) => {} .. }`) はできない。それは検査される値のところにとどまり、rustc は
    そこで E0507 を出す。
  - match のアームの外のパターンは、これまでどおり検査される値のところである。
  - borrowck/borrowck-move-out-from-array-match.rs は今は通る: その 10 のエラーはどれも rustc の行にある。
- **型に対する outlives の境界。** `fn f<'a, 'b>(x: D<'a>) -> &'b i32 where D<'a>: 'b { x.0 }` を考える。zustc は
  「lifetime may not live long enough」を出した。rustc は受理する。`D<'a>: 'b` は `'a: 'b` を含意するからである
  (rustc の outlives components)。
  - パラメータでない型に対する境界は、今はその型が名指す各ライフタイムについて `'x: 'b` を、その中のジェネリクスの
    各型パラメータについて `T: 'b` を与える: `D<'a>: 'b`、`E<'a, T>: 'b`、`&'a T: 'b`。
  - impl のメソッドでの `Self: 'b` は、impl の self 型のライフタイムについてそれを与える。
  - 射影 (`<T as Tr>::X: 'b` は T について何も言わない) やトレイトオブジェクトの境界は通さない。
  - 呼び出し側はその境界を満たさなければならない: `d: D<'x>` での `f(d)` を `&'static i32` として返すのは、rustc と
    同じくエラーである。
- **オブジェクトのライフタイムとしてのトレイト自身の境界。** std の `Any` は `trait Any: 'static` である。
  - 構造体の中の `Box<dyn Any + 'a>` は、今は E0478 である。`'static` の境界を持つプログラム自身のトレイトと同じで
    ある (regions/explicit-static-bound-on-trait.rs)。
  - 省略されたオブジェクトのライフタイムは、トレイト自身の境界をデフォルトとし、それを満たす。`trait MyAny: 'static`
    での `&'a dyn MyAny` は `&'a (dyn MyAny + 'static)` で、エラーではない。main はそれに E0478 を出していた。今は、
    書かれたオブジェクトのライフタイム (`dyn MyAny + 'a`) だけをトレイトの境界と照らす。
- **型自身の `Index` とその後の `Deref` を通したフィールド。** `impl<T> Index<usize> for MyVec<T>` (`Output = T`)、
  `v: MyVec<MyPtr<Foo>>`、`impl<T> Deref for MyPtr<T>` での `v[0].f` を考える。zustc は「no field `f` on type
  `MyPtr<Foo>`」を出した。
  - オーバーロードした添字が見積もられる型は、今はその `index` が参照を返す先の型なので、フィールドは `Deref` を
    通して読まれる。
  - その借用は検査される: borrowck/borrowck-overloaded-index-and-overloaded-deref.rs は rustc の行で E0506 である。
- **一時値の `Box` に対する `self: Box<Self>`。** `fn f(self: Box<Self>)` に対する `Box::new(S).f()` と `mk().f()` は、
  「mismatched types: expected `Box<S>`, found `S`」を出した (その 29 の第 5 節)。受け手は Box が指す先の型で渡されて
  いた。今は Box の型を持つ: run-pass の self/explicit-self.rs が通る。

## 4. レビュー

CodeRabbit は c8f43e9 の #156 をレビューし、2 つを指摘した。どちらも zustc と rustc 1.97 で確かめ、直した:

- **型エイリアスに対する境界。** `ty_parts` は、型エイリアスのパスに書かれたライフタイムを読んでいた。
  `type Erased<'a> = ();` では、`Erased<'a>: 'static` は `'a` について何も言わないが、`'a: 'static` と取られていた。
  `&'a i32` を `&'static i32` として返すのを受理していた。rustc は「lifetime may not live long enough」を出す。
  - fn のサマリーはそれ自身のアイテムから作られ、どの名前がエイリアスかを知らない。今は、型に対する境界がその部分に
    ついて含意するものをそこで別にして持ち、各部分が入っているパスの名前を添える。
  - プログラムは、それらの名前のどれも型エイリアスでないところでそれを加える。構造体の `W<'a>: 'static` は今も
    `'a: 'static` を与え、その呼び出し側は今もそれを満たさなければならない。
  - 今そう読むのは fn 自身の境界だけである。impl や型の境界は、この作業の前と同じく印だけを持つ。
- **一時値の Box に対する、`self: Box<Self>` の `unsafe fn`。** `unsafe fn f(self: Box<Self>)` に対する
  `Box::new(S).f()` は今は型検査が通るが、`unsafe` の外でも受理されていた。rustc は E0133 を出す。今はその経路でも、
  ほかと同じく呼び出しを確かめる。
- tests/regionck.rs が両方を確かめる (`part30_review`)。
- その 2 度目のレビューは、b86c086 で 4 つを指摘した:
  - **`self: Box<Self>` の呼び出しのリージョン検査。** その呼び出しは、main での Box の局所変数に対する呼び出しと同じく、
    結果の木を残していなかった。`Box::new(S(&x)).get()` が局所変数 `x` について借用するものを返すのを受理していた。
    rustc は E0515 を出す。今は呼び出しが受け手の木を与え、結果のものを保つ: 一時値の Box でも Box の局所変数でも
    E0515 である。
  - **ジェネリックな関連型に対する境界。** `T::A<'a>: 'static` は `'a` からなる型として読まれ、`'a: 'static` を
    与えていた。今は、型パラメータか `Self` から始まるパスは 1 つの component で、そこから何も導かない。
  - **いくつもの impl を持つ型自身の `Index`** (`Index<usize>` と `Index<&str>`)。見積もられた型は最初の impl の
    ものだった。今はいくつもあるところでは何もない。そういう添字は、main と同じく zustc では「mismatched types」で
    ある。
  - **`self: Box<Self>` を持つ、固有の `unsafe fn` と同じ名前のトレイトの安全なメソッド。** 指摘は安全なものが選ばれると
    言った。rustc 1.97 は固有のものを選んで E0133 を出し、zustc も同じである: 変えていない。
  - tests/regionck.rs がそれらを確かめる (`part30_review`)。
- その 3 度目のレビューは、c4e970a で `Self: 'b` について同じことを見つけた: impl の self 型のライフタイムは、その型が
  ライフタイムを落とすエイリアスであるところでも (`impl<'a> Leak<'a> for Erased<'a>`)、その部分として取られていた。今は
  それも別にして持ち、プログラムは self 型が型エイリアスを名指さないところでそれを加える。tests/regionck.rs がそれを
  確かめる。
- その 4 度目のレビューは、14fcb02 で、その検査が粗すぎることを見つけた。self 型の中の名前は、型エイリアスを隠す impl の
  型パラメータであるところでも (`type T = ();` と `impl<'a, T> D<'a, T>`)、型エイリアスとして取られていた。そのため、
  そこでの `Self: 'b` は 'a について何も含意しなかった。rustc は受理する。
  - impl のヘッダーは、今は self 型の各ライフタイムについて、それを囲む型の名前を記録する。
  - プログラムは、そのどれも型エイリアスでないところで `'a: 'b` を加える。型パラメータはライフタイムの引数を持たないので、
    その中にはない。
  - そのため、エイリアス `T` のある `D<'a, T>`、`D<'a, Erased<'a>>`、`dyn Tr + 'a` は `'a: 'b` を含意し、
    `W<Erased<'a>>` は含意しない。どれも rustc 1.97 と同じで、tests/regionck.rs がそれらを確かめる。
  - 0f529d9 のその要約は、名前の記録がないライフタイムがどのエイリアスの外にもあるとされることを記した。それは、記録が
    届くより深く入れ子になった型でだけ起きる。そういうライフタイムは、今は何も含意しない。
