# リージョン (ライフタイム) 検査、その 36: `x @ sub` のパターン、定数の初期化式の中のアイテム、トレイトオブジェクトにボックスした `Fn` のパラメータ、impl のメソッドのライフタイムの境界 (issue #171)

日付: 2026-11-25

その 35 ([2026-11-25-07](2026-11-25-07-region-check-35.md)) は #172 でマージした。この段階は、#171 の項目と、tests/ui の
落ちている借用検査のテストから取る:

- `x @ sub` のパターンの借用とムーブ、そして `ref` / `x @ sub` のパラメータ;
- `const` / `static` の初期化式のブロックに書いた fn;
- `Fn` のパラメータを `Box<dyn Fn..>` にボックスするジェネリックな fn。これは検査されずにいた;
- impl のメソッドとジェネリックな関連型のライフタイムの境界の、トレイトのものとの比較 (E0195、E0276)。

## 1. 加えたもの

- **`x @ sub` のパターン。**
  - rustc は、借用検査の前に各 `x @ sub` を調べる (その THIR の `check_borrow_conflicts_in_at_patterns`)。x がムーブ
    し、sub に `ref` があれば "borrow of moved value" である。`ref x` で sub にムーブがあれば "cannot move out of value
    because it is borrowed" である。一方に `ref mut`、他方に `ref` か `ref mut` があれば "cannot borrow value as
    mutable ..." か "as immutable ..." である。
  - そしてその借用検査: sub が先に束縛するので、sub がその一部をムーブした後に x がムーブすると E0382 である
    (`a @ NC(b, c @ NC(d, e))` の "use of partially moved value")。全部なら "use of moved value" である (`a @ b`)。
  - zustc は sub を束縛してから x を束縛し、どちらも調べていなかった。
  - パターンの束縛は、いまは各 `x @ sub` について、sub の各束縛がどう束縛するかを集める: ムーブで (`Copy` でない型)、
    コピーで、参照で。それを x がどう束縛するかと、rustc と同じく、パターンで突き合わせる。
  - `Copy` の部分、2 つの `ref`、`Copy` の y の `ref x @ y`、デフォルトの束縛モードは、rustc と同じく受理する。
  - ムーブは借用検査のものであり、rustc は `return;` の後のコードをそれに渡さない: そこではパターン自身の検査だけが
    成り立つ (pattern/move-ref-patterns/by-move-sub-pat-unreachable.rs)。
- **`ref` と `x @ sub` のパラメータ。** `fn f(ref a @ b: U)` と `fn g(ref x: U)` は "unsupported pattern" だった。
  パターンが参照で束縛するか部分パターンを持つパラメータは、分解するものと同じく、いまは `let` で束縛する。
- **定数の初期化式の中のアイテム。**
  - `const MOVE: fn(&String) -> String = { fn broken(x: &String) -> String { return *x } broken };` は、1 行目での
    "nested items are not supported" だった。
  - トップレベルの `const` / `static` の初期化式のブロックに書いた fn は、いまは fn の本体に書いたものと同じく外に
    移すので、検査される: rustc と同じく `*x` での E0507。E0596 (span/borrowck-fn-in-const-b.rs) と、rustc の E0713
    の行での E0515 (borrowck/borrowck-fn-in-const-c.rs) も。ビルドはそれを実行する。
  - そういうブロックのほかのアイテムも同じである (`const _: () = { impl Tr for S {} };`)。外に移したアイテムの
    シグネチャの中の型の構文エラー (`Box<dyn X< : 32 >>`) は、アイテム自身の構文のほかのエラーと同じく、書いた行で
    出す (generic-associated-types/parse/trait-path-*.rs)。
- **トレイトオブジェクトにボックスした `Fn` のパラメータ。**
  - `zustc check` は、何も呼ばないジェネリックな fn を、各型パラメータのプレースホルダーで検査する。`FnMut(bool)` で
    縛ったプレースホルダーを `Box<dyn FnMut(bool)>` にボックスすると "not a closure" という型エラーで、その fn はまったく
    検査されなかった。
  - そういうプレースホルダーの vtable は、いまはその呼び出しの欄を持たない: そのインスタンスは検査するだけで、実行
    しない。
  - そのため `let b: Box<dyn FnMut(bool)> = Box::new(f); drop(f);` は E0382、`fn b<F: FnMut(bool)>(f: F) -> Box<dyn
    FnMut(bool)> { Box::new(f) }` は E0310 (F は `'static` より長く生きねばならない) であり、そういう fn のほかの
    エラーも見つかる (moves/moves-based-on-type-no-recursive-stack-closure.rs)。
- **impl のメソッドのライフタイムの境界。**
  - where 節が型を縛るトレイトのメソッドのライフタイム (`fn foo<'a>(..) where T: 'a`) は early-bound である。
    zustc はライフタイムの境界とメソッド自身の型パラメータの境界だけを数えていたので、境界のない impl の
    `fn foo<'a>(..)` がそれに合っていた。いまは rustc と同じく E0195 である
    (trait-bounds/impl-missing-where-clause-lifetimes-from-trait.rs)。
  - トレイトのものが `'static` で縛られていないところで、`'static` で縛った impl のメソッドの型パラメータ (トレイトの
    `F: Debug + 'a` に対する `F: Debug + 'static`) は、impl のヘッダがトレイトに `'static` を与えるのでなければ、
    `'static` での E0276 である (typeck/issue-18937.rs)。メソッドの境界の検査は、引数のあるトレイトの impl
    (`impl<'a> A<'a> for B`) も読むようにした。そのトレイトを見つけていなかった。
  - トレイトの宣言が含意しない、ジェネリックな関連型自身のライフタイムの間の outlives は、その位置で比べて
    (トレイトの `where 'a1: 'b1` に対する `where 'b2: 'a2`)、境界での E0276 である
    (generic-associated-types/mismatched-where-clause-regions.rs)。

## 4. まだ扱わないもの

- **`it.by_ref().take(n)`** (#171): 直すには `Take<&mut I>`、つまり `Self = &mut I` の参照の上のアダプタが要る。
  zustc の型パラメータへの参照の impl は、deref を通して T のメソッドに届く (#2) ので、まだ作らない。
- **プレースホルダーのインスタンスの型エラー。** 何も呼ばないジェネリックな fn をプレースホルダーで検査すると、
  その借用検査とリージョン検査のエラーだけを残す。tests/ui の多くのテストがそこで型エラーを期待し、zustc はそれを
  見つけて捨てている (与えられていない `T: Debug`、境界が与えないメソッド): #169。
- **境界のメソッドを呼ぶジェネリックな fn** は、プレースホルダーで検査しない (その型検査が traits の KPI の +4.9%
  にあたる)。そのすべてを検査した実験では、compile-fail のテストが 10 増えて通り、check-pass のテストが 5 落ちた。
- **`x @ sub` のパラメータのエラーの位置**: パターンではなく、その fn で出す。パターンは位置を持たない。
- **impl のヘッダを通した E0276**: ヘッダがトレイトのパラメータに渡す型の、impl のメソッドの境界 (トレイトの
  `where T: 'a` に対する `where V: 'a`、compare-method/region-unrelated.rs) と、メソッドの where 節の中の、ヘッダの
  ライフタイムの間の outlives (`where 'a: 'b`、compare-method/region-extra.rs)。ヘッダのトレイトの引数は持って
  いない。
