# リージョン (ライフタイム) 検査、その 38: トレイトオブジェクトの impl のメソッドと、それが求める `'static` (issue #169)

日付: 2026-11-26

その 37 ([2026-11-25-10](2026-11-25-10-region-check-37.md)) は #221 でマージした。この段階は #169、ライフタイムの
テストを借用検査の前で止める型検査の穴に取りかかる。そこに挙げたもののうち、後ろにライフタイムのエラーも持つ
`impl dyn Trait` のメソッドから始める。それらは見つからず、それを呼ぶテストはどれも "no method named .. found for
`dyn Tr`" か、`impl Trait` の結果の型で止まっていた。

## 1. 加えたもの

- **`impl dyn Tr` と、オブジェクトについてのトレイトの impl のメソッド。**
  - オブジェクトの vtable にないメソッドは、いまは次の順に探す:
    - `impl dyn Tr { .. }` か `impl X for dyn Tr { .. }` のもの。プログラムはそれを `__dyn_Tr::m` として持つ;
    - それでなければ、オブジェクトが実装するトレイトのデフォルトメソッド (`impl MyTrait for dyn Tr {}`)。
  - そのメソッドは、オブジェクトのペアをその `&self` として呼ぶ。ジェネリックな impl `impl<T> MyTrait<T> for dyn
    ObjectTrait<T>` は、そのパラメータを受け手のオブジェクト (`dyn ObjectTrait<u8>`) から取り、メソッド自身の
    ターボフィッシュは渡す。
  - トレイトオブジェクトの val についての `MyTrait::use_self(val)` は、トレイトを名指したそのメソッド呼び出しで
    ある。モジュールの中では、パスがトレイトのデフォルトそのものを名指すので、`Self` をオブジェクトとして直接
    呼ばれ、オブジェクトについての impl は選ばれなかった。
  - オブジェクトが実装する、その名前のデフォルトを持つ 2 つのトレイトは、rustc と同じくあいまいである (E0034)。
  - `-> impl Trait` の本体の型の推論も、これらのメソッドをたどる: `fn use_it<'a>(val: &'a dyn ObjectTrait) -> impl
    OtherTrait<'a> + 'a` の結果としての `val.use_self()` は "cannot infer the `impl Trait` return type" だった。
    オブジェクトのトレイトはそのテキストの空白ごと (`ObjectTrait < u8 >`) 探していたので、ジェネリックなものの
    メソッドは見つからなかった。
- **トレイトオブジェクトについての impl が求める `'static`。**
  - impl のヘッダの self 型の、参照の後ろにないトレイトオブジェクト、`impl dyn Tr` や `impl X for dyn Tr` は
    `dyn Tr + 'static` である。そのデフォルトはヘッダのものであり、後で `Self` を持つ `&self` のものではない。
  - そのような impl を通した呼び出しは、受け手のオブジェクトのライフタイムが `'static` であることを求める。
    `val: &'a dyn ObjectTrait` では、それは呼び出しでの rustc の E0521 ("borrowed data escapes outside of
    function") である。zustc は同じ行に "lifetime may not live long enough (`'a` must outlive `'static`)" として
    出す。
  - オブジェクトがライフタイムを書く impl (`impl MyTrait for dyn ObjectTrait + '_`) は、それに何も求めない。
  - シグネチャがオブジェクトを名指さない、`impl MyTrait for dyn Tr {}` を通したデフォルトメソッドでは、要求は
    受け手のオブジェクトの領域から `'static` への辺である。そのような呼び出しでは、`'static` を求めるほかの呼ばれる
    側と同じく、リージョン検査を始める。

- **レビューの修正 (#237)。** これらの impl を通した呼び出しを、vtable を通した呼び出しと同じく確かめる:
  - `unsafe` の外の unsafe なメソッド (E0133);
  - 共有参照を通した `&mut self` のメソッド (E0596);
  - 借用検査のための受け手の借用 (ローカルの `Box<dyn Tr>` の `b.get()` と `(*b).get()` を返すのは E0515)。明示的な
    deref の受け手 (`(*b).get()`) は、vtable を通しても b のどの場所も借用しなかった: いまは `&*b` と同じく借用する。
    関数が所有するものの借用と、それに届くまでに通る参照を通した再借用である (`b: &Box<dyn Tr>` の `(*b).get()`
    は所有するものの借用ではない);
  - 式のための結果の木;
  - オブジェクトだけでなく受け手の借用に結び付ける `&self` の結果 (`fn leak(x: &(dyn Tr + 'static)) -> &'static u8
    { x.get() }`)。

  トレイトがライフタイムを取る impl (`impl<'a> dyn Obj<'a>`) のオブジェクトには `'static` を与えない: トレイト自身の
  境界 (`trait Obj<'a>: 'a`) がそのデフォルトでありうる。`dyn Obj<u8> + '_` についての impl は、オブジェクトの引数で
  見つける。オブジェクト自身の `pick` のそばの `Ext::pick(x)` は、vtable のではなく Ext のを呼ぶ。

  2 回目と 3 回目のレビューのもの:
  - impl の self 型であるトレイトオブジェクトだけに `'static` を与える。パスの引数の中のオブジェクトは、main と
    同じく書いたままにする。その型の境界がデフォルトでありうる (`struct W<'a, T: ?Sized + 'a>` での `impl<'a>
    W<'a, dyn Obj>`) が、ヘッダは std の型 (`Box<dyn Tr>`、`'static`) と同じ名前のユーザーの型 (`struct
    RwLock<'a, T: ?Sized + 'a>`) を見分けられない。`W<'a, dyn Obj + 'a>` の `w.get()` は誤ったエラーだった。
  - `E3::pick(x)` は、`impl dyn O3` の固有の `pick` ではなく E3 のデフォルトを呼ぶ。rustc が 2 を出すところで
    3 を出していた。
  - 結果に期待される型がメソッドに届く (`fn make<T: Default>(&self) -> T` での `let v: u8 = x.make()`)。
  - `impl Trait` の本体の型の推論は、impl のパラメータをオブジェクトの引数から (`dyn O<u8>` を通した
    `impl<T> Get<T> for dyn O<T>`)、メソッド自身のパラメータをそのターボフィッシュから (`x.make::<u8>()`) 解く。
  - tests/probe/dyn_impl_methods.rs は、これらのプログラムを rustc の出力と比べて走らせる。

## 4. まだ扱わないもの

- **`Box<dyn Tr>` についての impl** (`impl MyTrait for Box<dyn ObjectTrait>`): そのメソッドは見つかるが、呼び出しの
  受け手にリージョンの木がなく (rg_recv は struct の受け手だけをたどる)、ヘッダはそのオブジェクトに `'static` を
  与えないので、それが要る `'static` は確かめない。対のもう 1 つのテスト、
  suggestions/impl-on-dyn-trait-with-implicit-static-bound-needing-more-suggestions.rs はそのような impl でできている。
- **トレイトのメソッドの省略された結果**: `fn get(&self) -> &u8` の結果を、メソッドを vtable を通して呼ぶとき
  (トレイトで宣言したもの) と、`impl Ext for dyn Tr {}` を通してトレイトのデフォルトを呼ぶときに、受け手の借用に
  結び付けない。そのため 2 つのエラーを見逃す:
  - ローカルの `Box<dyn Tr>` の `b.get()` を返すこと (E0515);
  - `x: &(dyn Tr + 'static)` の `x.get()` を `&'static u8` として返すこと。

  ライフタイムを書けば (`fn get<'a>(&'a self) -> &'a u8`) 結果を結び付ける。vtable の場合は main でも同じである。
- **トレイトが宣言するライフタイムの境界**: `trait Obj<'a>` が境界を宣言しないときも、`impl<'a> dyn Obj<'a>` の
  オブジェクトに `'static` を与えないので、呼び出しの E0521 を見逃す。ヘッダはトレイトの宣言を見ない。
- **トレイトの名前だけで見つける、オブジェクトについての impl**: ジェネリックな impl を、どの `dyn Obj<..>` に
  ついても取る (E0599 を見逃す)。これは `dyn Obj<u8>` を通した `impl<T> Ext for dyn Obj<Vec<T>>` と、オブジェクトの
  引数が境界を満たさない impl (`dyn O<String>` を通した `impl<T: Copy> Ext for dyn O<T>`) を含む。
- **E0521 自身のメッセージ**: エラーは rustc の行の "lifetime may not live long enough" である。
- **#169 の残り**: deref を通して後で代入する `let`、fn ポインタの注釈からのクロージャのパラメータ
  (`let g: fn(_, _) -> _ = |_x, y| y;`)、`std::cell::OnceCell`、`&T` についての impl のデフォルトメソッド、
  `dyn Error` の `is`、そこに挙げたトレイトの境界。
