# trait solver、その 5: 残りの課題

日付: 2026-11-24

[その 4](2026-11-23-07-trait-solver-4.md) の「残っているもの」を順に進めた。

## 関連型

- 値がジェネリックな構造体である定義 (`impl<R: D> A<R> for AT { type AS = As<R>; }`) は、構造体のフィールドを解決した後に
  登録されていたので、それを名指すフィールド (`struct S(<AT as A<DT>>::AS)`) は何も見つけられなかった。いまはジェネリックな
  定義のレイアウトの直後、ほかの構造体より先に登録する (`wf/issue-48638.rs`、`mir/mir_struct_with_assoc_ty.rs`、
  `associated-types/recursive-enum-with-assoc-type-selfref.rs`、`traits/issue-103563.rs`)。
- トレイトの impl のメソッドのシグネチャの `Self::X` は、その impl 自身の X (impl のパラメータはそのまま)。X がトレイト引数
  だけが束縛するパラメータを名指すときも (`impl<E> Structure<E> for Slice { type FfiPtr = (*const E::FfiUnit, usize); }`)。
  `unsized/issue-40231-*.rs` はシグネチャを越えるようになり、その先の、ジェネリックなコードでの `S::FfiPtr` を通る型推論で
  止まる。

## std の impl を節にする: 測ってから、別のやり方で

作る前に、zustc が受け入れてしまう、std のトレイトの境界がエラーの compile-fail テストを数えた。2 回以上出るのは `Copy` だけ
(`String: Copy` ×4、`T: Copy` ×4、`[bool]: Copy`) で、残りは高階の境界、`Self`、ジェネリクスを含むプログラムのトレイト。
なので代わりに:

- 型パラメータは、境界がすべて zustc がスーパートレイトを知っているトレイトで、どれも与えないとき std のトレイト (Copy、
  Clone、Debug ..) を持たない (`TraitDb::placeholder_lacks`)。パラメータが何でも成り立つので、どこからも呼ばれないジェネリック
  関数からも報告する (`where-clauses/where-clause-constraints-are-local-for-{trait,inherent}-impl.rs`);
- `<Self as Tr>::X` を名指すトレイトのメソッドは、トレイト自身、そのスーパートレイト、メソッドの where 節から `Self: Tr` が要る
  (`associated-types/associated-types-for-unimpl-trait.rs`、`associated-types-no-suitable-supertrait{,-2}.rs`、
  `associated-types-projection-to-unrelated-trait-in-method-without-default.rs`)。

## メッセージの名前

solver のメッセージは rustc と同じ名前を使う: `impl Trait` 引数のパラメータは `__impl0` でなく `impl Sync`、モジュールの中の
名前は zustc が平らにした `a__b__Hidden` でなく `Hidden` (`traits::display_ty`、`display_name`。単体テストつき)。

## 正しいコードの「mismatched types」: 調査と 1 件の修正

run-pass / check-pass / build-pass の 130 件が「mismatched types」で落ちる。関わる型で分けると:

| 群 | 件数 | 要るもの |
|---|---:|---|
| 後で別の型 (`u8`、`usize`、`Box<isize>`) を求められる前に `i32` に決まった整数リテラル | 15 | 文をまたいでリテラルの型変数を開いたままにする型推論 |
| 構造体への unsize (`&Foo<[u8; 3]>` から `&Foo<[u8]>`)、`&[u8; 5] as *const [u8]` | 11 | unsized な末尾を持つ構造体への fat pointer (レイアウトとコード生成) |
| 解かれないままのジェネリックなパラメータ (`expected T0`) | 10 | より多くの位置でのインスタンスの型引数の推論 |
| 別々のクロージャの型、関数アイテムとクロージャ | 5 | クロージャの型の単一化 |
| そのほか | 約 90 | それぞれ 1、2 件 |

ここで直したもの: 数値リテラルの型がまだ決まっていない Box (か配列) の `b.clone()` は、clone が何であるべきかのために
リテラルを開いたままにする (`closures/closure-upvar-last-use-analysis.rs`)。最初の版はレシーバの型変数そのものを共有し、
型強制の先がレシーバに戻ってしまった (`let c: Box<dyn A> = v.clone()` で `v` が `Box<dyn A>` になり、
`coercion/method-return-trait-object-14399.rs` が退行した)。いまは決まっていないリテラルのときだけ。

これらの群はトレイトの解決でなく型推論とコード生成で、この順で次の作業になる。
