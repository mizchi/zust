# リージョン (ライフタイム) 検査、その 28: ジェネリックなトレイトオブジェクトの型引数、2021 より前の裸のトレイトオブジェクト、E0223 (issue #1)

日付: 2026-11-24

その 27 ([2026-11-24-13](2026-11-24-13-region-check-27.md)) は #151 でマージされた。この段階で加えるもの:

- 型パラメータを名指すトレイトオブジェクトの型引数 (`struct S<U>` の中の `Box<dyn Fn(U) -> U>`、ジェネリックな
  関数の中の `&dyn A<T>`)。ジェネリックな型や関数を使うところで与えられ、そこから推論される;
- そういうトレイトオブジェクトのリージョン検査。型のエラーが隠していた (regions/regions-close-object-into-object-*.rs);
- 2021 エディションより前の、ポインタの後ろのトレイトの名前を、そのトレイトオブジェクトとして;
- トレイトなしで名指したトレイトオブジェクトの関連型の E0223。

## 1. 加えたもの

- **ジェネリックなトレイトオブジェクトの型引数。** zustc は `dyn` の型をそのテキスト (`A < T >`) として持つ。
  テキストが名指す型パラメータは、型を書いたところではなく、型を使ったところで名前で探されていた。main は誤った
  エラーを出した:
  - `fn app<T>(s: &S<T>, x: T)` の中の `(s.f)(x)` に対する `struct S<U> { f: Box<dyn Fn(U) -> U> }`:
    「cannot find type `U`」;
  - `fn repeat<T: Clone>(t: T) -> Box<dyn FnMut() -> T>`: 呼び出し元の `f()` が「cannot find type `T`」になった;
  - `Box<dyn A<String>>` で呼ぶ `fn unbox<X>(v: Box<dyn A<X>>) -> X`: 「mismatched types」;
  - `struct B<'a, T: 'a>(&'a (dyn A<T> + 'a))` と `v: &dyn A<i32>` での `B(v)`: 「type annotations needed」。
  - 今は、型を解決するところで、テキストの中の型パラメータにその番号の印を付ける。インスタンスでパラメータが表す
    型は書き出す。
  - 置き換えは、各パラメータの引数を書き入れる。2 つのトレイトオブジェクトの型引数を突き合わせて、呼び出しや
    コンストラクターの型パラメータを推論する。
  - 呼び出しのパラメータがまだ分からないところでは、期待される型は以前と同じくパラメータの名前を持つ。`T` が
    分かる前に `Box<dyn Fn(T) -> T>` に渡すクロージャがそれである。クロージャはそれへ強制変換され、クロージャ
    自身の型が `T` を決める。
- **そういうトレイトオブジェクトのリージョン検査。** regions/regions-close-object-into-object-2.rs は、
  `v: Box<dyn A<T> + 'a>` で `Box::new(B(&*v))` を返す。zustc は rustc と同じく E0515 を出す。以前は `B(&*v)` で
  型検査が失敗し (「type annotations needed」)、その関数は検査されなかった。
- **2021 より前の裸のトレイトオブジェクト。** 2015 と 2018 のエディションでは、トレイトの名前は型である:
  そのトレイトオブジェクトである (`Box<X>` は `Box<dyn X>`)。
  - zustc は `X + 'a` をそう読んだが、`X` だけは読まなかった: `as Box<X>` は「cannot find type `X`」になった。
  - 今は、ポインタ (`&`、`*const`、`*mut`、`Box`) の後ろのトップレベルのトレイトの名前は、そのトレイト
    オブジェクトである。
  - ほかのところのトレイトの名前はそうではない。`Trait::method()` のようなところである: この作業の最初のサイクルは
    すべてをそう読み、通っていた 14 のテストが落ちた。
  - モジュールのトレイトもそうではない。zustc はそこでそのプライバシーを確かめない。glob import を通して名指した
    private なものはエラーである (privacy/privacy-ns1.rs)。
- **E0223。** `<dyn Trait<i32>>::Ty` は、トレイトオブジェクトの関連型をそのトレイトなしで名指し、E0223 である
  (associated-item/ambiguous-associated-type-with-generics.rs)。
  - main は別の理由でこのプログラムを拒否していた: `dyn Trait<i32>` に `Ty` を見つけなかった。
  - 型引数を突き合わせるので、今は `impl<A> Assoc for dyn Trait<A>` がそれを与える。`<dyn Trait<i32> as
    Assoc>::Ty` は `i32` である。

## 4. レビュー

CodeRabbit は 552ed3a の #154 をレビューし、5 つを指摘した。どれも zustc と rustc 1.97 で確かめた:

- **シグネチャとフィールドのエディション。** プログラムは 2021 エディションで組み立てられ、クレートのエディションは
  その後に設定されていた。そのため、2015 のシグネチャ (`fn take(x: &X)`) や構造体のフィールド (`x: &'a X`) の
  裸のトレイトオブジェクトはそう読まれなかった: main と同じく「cannot find type `X`」である。
  - 今はプログラムをクレートのエディションで組み立てる。
  - フィールドを解決する前にトレイトの名前が分かっている。
  - それで、通っていたテストである dyn-keyword/dyn-2018-edition-lint.rs を受理した: `bare_trait_objects` の lint を
    deny する。今は、lint が deny されるところで、そういうオブジェクトはエラーである。それを名指す行で出す。
- **T が分かり U が分からないところの、`Box<dyn Fn(T) -> U>` に対するクロージャ。** `fn f<T, U>(a: T, cb: Box<dyn
  Fn(T) -> U>, b: U)` に対する `f(1i32, Box::new(|x: i32| x), 2i32)` を考える。main は受理し、この作業は「mismatched
  types」を出した。クロージャは `Box<dyn Fn(i32) -> U>` へ強制変換され、それはパラメータの名前にもその引数にも
  合わなかった。
  - 今は、そういう型が、分かっているパラメータのいくつかを与えたパラメータのテキストであるところで合う。
  - 引数は呼び出しでインスタンスの型を取る。
- **印のような名前のプログラム自身の型** (`struct __S0`)。印が名指す構造体に解決されていた。今はプログラム自身の型は
  その型である。
- **書き換えがつなげる 2 つの記号。** `dyn` の型のテキストは、印を置き換えた後につなぎ直す。テキストが離している
  2 つの記号 (`/ *`) がつながりえた。今は離れたままである。
- **パラメータを与えるフィールドより前にクロージャのフィールドがある構造体リテラル。** `struct S<T> { cb: Box<dyn
  Fn(T) -> T>, value: T }` に対する `S { cb: Box::new(|x: i32| x), value: 1i32 }` を考える。指摘は、フィールドの順に
  よって失敗すると言った。再現しなかった: どちらの順も、rustc と同じくビルドして実行できる。
- tests/regionck.rs が最初の 3 つを確かめる (`part28_review`)。
- 直した後: tests/ui で落ちるものはなく、run-pass の検査は main が受理するものを拒否せず、`cargo test` は通る。
  ここで測った main (becb570) に対して、patterns edit を除いて、+0.35% (traits check) より大きく増える KPI はない。
  - kpi_track の実行は、patterns edit を 283.955 → 285.858 M (+0.67%) と測った。
  - それだけを各バイナリで 3 度測ると 285.609 → 286.000 M (+0.14%) で、どの実行でも同じである。kpi_track の実行は、
    それをほかの KPI の後に測る。
  - 直したものの最初の版は、traits check を +0.84% と測った。各引数をインスタンスのパラメータの型と照らす検査が
    遅延しなくなっていた。今はまた遅延する。
- CodeRabbit の 2 度目のレビューは、5297119 で 4 つを指摘した:
  - **トレイトオブジェクトのほかの境界** (`dyn A<i32>` に対する `dyn A<T> + Send`)。これはこの作業のものではない:
    `dyn` の型のテキストは自動トレイトを持たない。main でもそうなので、そこでは 2 つは 1 つの型である。
  - **印のように始まる名前のトレイト** (`__Pretty`、prelude の `__PathExt`) は、パラメータを持つ型として読まれていた。
    今は印は `__zp{i}_{name}` と `__zs{id}` で、形の整った印だけを数える。
  - **印のように見えるジェネリックなパラメータや宣言のない名前** (`fn f<T, __zp0_U>`、`let x: __zs0`)。今は
    ジェネリックなパラメータの名前を先に引く。構造体の印は、プレースホルダーかクロージャのものだけを読む。dyn_src が
    そう書く構造体である。
  - **クレートの `deny` の後の `allow(bare_trait_objects)`。** 今は裸のトレイトオブジェクトを許す。アイテムの
    `#[deny]` は、今もクレートのものとして扱う。
  - tests/regionck.rs が後の 3 つを確かめる (`part28_review`)。
- CodeRabbit の 3 度目のレビューは、ab3d20d で 2 つを指摘した。どちらも直した:
  - **ほかの lint の後に bare_trait_objects を名指すアイテムの `#[deny(..)]`** (`#[deny(unused, bare_trait_objects)]`):
    今はリスト全体から読む。
  - **トレイトオブジェクトの引数の中の参照の可変性。** `dyn A<&T>` は、引数の強制変換と同じく `dyn A<&mut i32>` に
    合っていた。トレイトオブジェクトの引数は強制変換の場所ではないので、今は可変性がそろう: `&dyn A<&T>` に
    `&dyn A<&mut i32>` を渡すのは、rustc (E0308) とも main とも同じく「mismatched types」である。
  - tests/regionck.rs が両方を確かめる (`part28_review`)。
- その後 CodeRabbit は、`dyn` の型の中の、印のような名前のジェネリックなパラメータ (`&dyn A<__zp0_U>`) が印と取られる
  ことを見つけた。今はそこでも、型の環境が与える名前を先に引く。宣言のない、印である名前 (`__zp0_U`) は今も印として
  読む: `__z` の名前はコンパイラーのものである。prelude の `__core_*` と同じである。

## 5. まだ扱わないもの

- **impl から型引数を推論する、ジェネリックなトレイトオブジェクトへの強制変換。** `impl A<i32> for i32` での
  `B(&9)` や、`fn use_a<T>(a: &dyn A<T>) -> T` に対する `use_a(&5)` を考える。rustc は `T = i32` と推論する。
  zustc はしない (「type annotations needed」、「cannot infer type parameter `T`」)。
- **regions/regions-close-object-into-object-4.rs と -5.rs の E0310。** `Box<dyn X + 'static>` へ閉じ込める
  `Box<dyn A<U> + 'a>` を考える: zustc は E0515 を出し、`U` が十分長く生きないかもしれないことは出さない。
- **モジュールのパスで書いたトレイトオブジェクトの型引数** (`dyn A<m::S>`)。パラメータに書き出す同じ型は `S` なので、
  2 つのテキストは違う: main と同じく「mismatched types」である。
- **クロージャの結果だけが与える `dyn Fn` の結果のパラメータ** (`fn g<T, U>(cb: Box<dyn Fn(T) -> U>, a: T) -> U` に
  対する `g(Box::new(|x: i32| x as i64), 7)`): main と同じく「cannot infer type parameter `U`」である。
- その 27 以前から: [その 27](2026-11-24-13-region-check-27.md) の第 5 節を見よ。
