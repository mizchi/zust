# リージョン (ライフタイム) 検査、その 33: `&` を通した `ref mut`、参照が与えるものからのムーブ、ガードの束縛、`Box` と `Pin` の受け手、局所変数から返すクロージャ、返す集約が持つ借用 (issue #1)

日付: 2026-11-25

その 32 ([2026-11-25-04](2026-11-25-04-region-check-32.md)) は #159 でマージされた。この段階で加えるもの:

- デフォルト束縛モードが共有参照によるところでの `ref mut` の束縛の E0596;
- オーバーロードされた deref や、場所でない参照が与えるものからのムーブの E0507;
- match のガードが腕の束縛を共有参照で見ることの検査 (E0507 / E0594 / E0596);
- `self: Box<Self>` や `self: Pin<&mut Self>` の受け手のムーブ;
- 局所変数に置いて `impl Trait` として返すクロージャの、rustc の E0597;
- 返すタプル、配列、構造体のリテラルが持つ借用;
- #159 の 3 度目のレビューの、2 つの軽微な指摘。

## 1. 加えたもの

- **デフォルト束縛モードが共有参照によるところでの `ref mut`。**
  - `o: &Option<i32>` での `if let Some(ref mut v) = o` や、`(&arr.get(0), 0)` に対する
    `(Some(Foo::Bar(ref mut val)), _)` を考える。そこではデフォルト束縛モードが共有参照によるので、`ref mut` は `&` を
    通して可変に借用する。rustc は束縛で E0596 を出す。エディション 2024 は、そこに書いた `ref mut` も拒否する。
  - zustc はこれらを受理していた。今は、束縛の腕での E0596 である (pattern/issue-52240.rs)。
- **オーバーロードされた deref が与えるものからのムーブ。**
  - `wrap: Wrap<Struct>` で `Wrap: Deref` のとき、`if let Some(mut val) = wrap.field` は、`deref` が返す参照から
    `field` をムーブする: 検査される値での rustc の E0507 である。
  - zustc は、deref を通して届くフィールドを、束縛が drop を要るところでしか検査していなかったので、`NonCopy(())` は
    受理されていた。今は、Copy でないものを値で束縛するどれも、さらに深くても (`w.a.b`)、E0507 である
    (borrowck/deref-field-pattern-ref-suggestion-issue-146995.rs)。メッセージは、rustc と同じく、型を引数とともに
    名指す (`Wrap<Struct>`)。
- **場所でない参照からのムーブ。** Copy でない値の `*&x`、`*v.first().unwrap()`、`*id(&s)` は、rustc と同じく E0507
  (「cannot move out of a shared reference」) である。zustc はこれらを受理していた: その参照は一時値で、借用検査は
  その場所を持たなかった (sync/atomic-types-not-copyable.rs)。
- **match のガードが見る、腕の束縛。**
  - ガードは腕の束縛を共有参照で見る。ガードでそれをムーブすること (`A(v) if { drop(v); false }`) は rustc の E0507
    (「cannot move out of `v` in pattern guard」)、それへの代入 (`Some(mut y) if { y += 1; .. }`) は E0594、それを可変に
    借用すること (`v.push(1)`、`&mut` の束縛を通しても: `Some(ref mut y) if let Some(ref mut z) = *y`) は E0596 である。
  - zustc はこれらを、ガードの中のクロージャでしか検査していなかった。今は、アクセスごとに検査する。クロージャの
    キャプチャは、その本体がそれで何をするかを見る、クロージャの検査に任せる。
  - rfcs/rfc-0107-bind-by-move-pattern-guards/rfc-reject-double-move-across-arms.rs と
    rfcs/rfc-2294-if-let-guard/guard-mutability-1.rs、-2.rs が通る。
- **`&` パターンの下に `ref` の束縛がある、一時値の検査される値。** その 31 は、`&` パターンが値で束縛するところで、
  一時値の検査される値に自身の場所を与えたが、どれかのパターンが `ref` で束縛するところではそうしなかった。`&` パターンの
  下の `ref` は、一時値の中の参照が指すものを借用するので、今はそれを妨げない:
  `match (a, b) { (None, &c) => .., (&Some(ref c), _) => .. }` は検査される値での E0507 である
  (suggestions/option-content-move-from-tuple-match.rs)。
- **`Box` と `Pin` の受け手。** `self: Box<Self>` や `self: Pin<&mut Self>` のメソッドはその受け手をムーブする: 2 度目の
  呼び出しは rustc の E0382 である。zustc は受け手を借用としていた (moves/pin-mut-reborrow.rs)。
- **局所変数に置いて `impl Trait` として返すクロージャ。**
  - `impl FnMut()` として返す `let mut c = || { p.x += 5; println!("{:?}", p) }; c` について、rustc は、クロージャが
    キャプチャする場所のクロージャの中での使用 (`println!` の中の `p`) で E0597 を出し、クロージャで E0373 は出さない。
    クロージャそのものを返すものや、`Box<dyn ..>` の中に入れて返すものは E0373 のままである。
  - zustc は今はその E0597 を、キャプチャする場所そのものの最初の使用で出す (部分のより強い使用 `p.x += 5` は、
    これまでどおりキャプチャの仕方を決める)。そのため、クロージャの本体の中のマクロの引数は、ソースの中での位置で読む
    (closures/2229_closure_analysis/diagnostics/borrowck/borrowck-4.rs)。
- **返す集約が持つ借用。**
  - `fn f(x: &str) -> (&str, &&str) { (x, &x) }` は rustc の E0515 である。シグネチャが 2 つのリージョンを持つところでは
    リージョン検査がそれを出す。1 つのところでは借用検査が出すべきだったが、それはタプル、配列、構造体のリテラルを
    追っていなかった。今は追う。
  - `x` が参照であり、集約の型が `&&` を求めないところの部分 `&x` (`self: &[T]` での `W { slice: &self }`) は、`*x` の
    参照をコピーする deref の強制変換で、`x` の借用ではない: それは `x` として追う
    (traits/self-without-lifetime-constraint.rs)。
- **#159 の 3 度目のレビュー**の、ここに持ち込んだ 2 つの軽微な指摘 (どれも rustc 1.97 で確かめた):
  - enum の型の別名を通して書いた variant (`type A = E;`、`A::V`) は、`E::V` と同じく何もキャプチャしない;
  - パターンが検査する共用体の別のフィールドへのガードの書き込みは、そのフィールドそのものへのものと同じく E0510 である。
- enum の variant のフィールドは、rustc が書くとおり、variant なしで `y.0` と示す。

## 5. まだ扱わないもの

- **static や const の初期化子の中のムーブ** (`static Y: usize = get(*&X);`、
  borrowck/move-in-static-initializer-issue-38520.rs): 借用検査は初期化子に対して走らない。
- **パラメータの型を 1 つの呼び出しから推論し、ループの中で使うクロージャ** (closures/issue-113087.rs): そのパラメータの
  リージョンは 1 つのリージョンであり、zustc はそれを高ランクとしている。
- **ゼロサイズの型の `self: Box<Self>`**: 受け手のムーブを記録しない。
- **`macro_rules!` の本体の位置**: 130 の compile-fail のテストが、そのエラーのすべてをマクロの本体の中に期待する
  (うち 66 が wrong-line)。zustc はそういうエラーをマクロの呼び出しで出す。
- その 32 以前から: [その 32](2026-11-25-04-region-check-32.md) の第 5 節を見よ。
