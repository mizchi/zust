# リージョン (ライフタイム) 検査、その 17: 生ポインタ、`DerefMut` の受け手、scrutinee とループの一時値、そして添字・ディスパッチ・turbofish の推論の誤ったエラー (issue #1)

日付: 2026-11-23

その 16 ([2026-11-23-04](2026-11-23-04-region-check-16.md)) は #88 でマージした。この段階では、次の検査を加える:

- 生ポインタを通したムーブと書き込みの借用検査
- `Box<dyn Fn>` に入れたクロージャ
- 場所でない配列
- プログラムの `DerefMut` を通って届く `&mut self` のメソッド
- 不変な self の型に格納する `&self` のメソッド
- `match`・`let`・ループの 1 回が持つ一時値

また、借用検査より前でテストを止めていた誤ったエラーを直す:

- スライスへの `Deref` を通した添字
- トレイトオブジェクトにした参照への blanket impl のメソッド
- `&mut` の場所の中のメソッド呼び出し
- 参照を持たない値のローン
- `BinaryHeap::peek_mut`
- 自由な fn の呼び出しの turbofish

## 1. 加えたもの

### 直した誤ったエラー

- **`Deref` がスライスへの構造体の `c[i]`** は、deref した先を添字で引く。「cannot index into a value」だった。借用は構造体の
  ものなので (`c.deref()[i]`、`&mut c[i]` なら `deref_mut`)、要素を使っている間に別のフィールドへ書くと E0506 になる
  (borrowck/issue-81365-6.rs)。構造体自身の `Index` が先である。tests/acg/index_through_deref.rs が出力を rustc のものと
  比べる。
- **トレイトオブジェクトにした参照への blanket impl のメソッド。** `impl<A> Foo for A` のもとで、`v: &i32` の
  `Box::new(v)` を `Box<dyn Foo>` として使うと「`Foo::get` has no implementation for `&i32`」だった。静的なディスパッチは
  今、トレイトに既定のないメソッドについて、境界が参照に成り立つ blanket impl を取る
  (span/regions-close-over-type-parameter-2.rs)。tests/acg/blanket_impl_dyn_ref.rs を参照。
- **`&mut` の場所の中のメソッド呼び出しは、その受け手を変更可能な場所にしない。** `s: Pin<&S>` の
  `&mut *s.0.borrow_mut()` は「cannot borrow `s` as mutable」だった (typeck/issue-73592-borrow_mut-through-deref.rs)。
  メソッド呼び出しは値であり、その受け手はその self の型が決める。prelude の `Pin<&T>` は共有で deref する。std のものに
  共有のポインタへの `DerefMut` はないからである。
- **参照を持たない型の値はローンを運ばない。** `let (b, log) = match *e { (G(_, log), ref mut d) => (*d, log) };` では、
  log が d のローンを持っていた。タプルが、d を通して読む bool である `*d` のソースを取ったからである。型が参照を持たない
  場所の読み出しや呼び出しの結果は、今はソースを渡さない。セミコロンのある文は、囲む値に何も加えない。ただし、その中の
  `break` がループに与えるものは除く (drop/issue-23611-enum-swap-in-drop.rs、誤ったエラー)。
- **`BinaryHeap::peek_mut`。** prelude に `peek_mut` がなかった。その `PeekMut` は最大の要素へ deref する。`deref_mut` を
  通した変更の後に drop されると、std のものと同じく、その要素を再び下へふるい落とす。型推論・低レベル化・借用検査に
  とって prelude のガードであり、生きている間はヒープの `&mut` の借用を持つ。tests/acg/binary_heap_peek_mut.rs が出力を
  rustc のものと比べる。
- **呼び出しの turbofish は、fn の型引数を推論に与える。** `let c = 66; id::<u32>(c);` は「mismatched types: expected
  `T0`, found `i32`」だった。推論が自由な fn の呼び出しの turbofish から型引数を取らなかったので、c は既定の `i32` に
  なった。turbofish の型は今、fn 自身のジェネリクスの変数である。すべての型引数を書いた自由なジェネリックな fn
  (`let f = id::<&'static u32>;`) は、そのインスタンスの fn ポインタの型を持つ。なので `f(&c)` も c の型を決め、rustc が
  報告するのと同じく E0597 になる (nll/user-annotations)。tests/acg/fn_turbofish_infer.rs が出力を rustc のものと比べる。
- **`ref` で束縛する定数の scrutinee は昇格される。** v を後で使う `match Some(1) { Some(ref x) => v.push(x), .. }` は
  誤った E0716 だった。`&Some(1)` と同じく static に昇格される。`ref mut` は一時値のままである。

### 借用検査

- **生ポインタが指すものからのムーブは E0507 である。** 次のものを受け入れていた
  (borrowck/borrowck-move-from-unsafe-ptr.rs):
  - `x: *const Box<isize>` の `let y = *x;`
  - `(*x).a`
  - ムーブする `*x` のパターン

  生ポインタの deref は、借用検査の場所ではなかった。コピーと `ref` の束縛は問題ない。
- **`*const` のポインタを通した書き込みは E0594 である。** `ptr: *const i32` の `*ptr = 3` と `(*p).a[1] += 1` を受け入れて
  いた (borrowck/no-invalid-mut-suggestion-for-raw-pointer-issue-127562.rs)。`*mut` のポインタを通した書き込みと、
  `*const` の値そのものへの書き込みは問題ない。
- **`Box<dyn Fn()>` が期待される所で Box に入れたクロージャは `Fn` である。** `Box<dyn Fn() -> Box<i32>>` としての
  `Box::new(|| x)` を受け入れていた。`Box<dyn FnMut()>` としての `move || v` も同じである。そのようなクロージャが捕捉した
  ものをムーブして出すのは、境界が `Fn` / `FnMut` を求める所と同じく E0507 である。`Box<dyn FnOnce()>` ならムーブしてよい。
- **どのローカルの場所でもない配列からのムーブは E0508 である。** 要素の型が `Copy` でないとき、次のものを受け入れていた
  (borrowck/move-error-in-promoted*.rs):
  - 定数の配列の `C[0]`
  - 一時的な配列の `[S][0]` と `mk()[0]`
- **`&self` のメソッドは、self の型が不変であるライフタイムで借用した引数を格納する。** `RefCell<Vec<&'c mut i32>>` を
  持つ `C<'c>` の `fn push(&self, r: &'c mut i32)` を考える。`c.push(&mut y)` を 2 回呼ぶのを受け入れていた。引数の借用は
  c の `'c` (またはそれより長く生きるライフタイム) のものなので、c がそれを持つ。受け手は引数の後、呼び出しで使われる
  (E0499、borrowck/mut-borrow-conflict-in-closures-vec.rs)。共変な self の型は何も格納しない。
- **プログラムの `DerefMut` を通した `&mut self` のメソッドは、受け手を変更可能に借用する。**
  `W: DerefMut<Target = Vec<usize>>` の `w.push(2)` は `deref` を通って `push` に届き、w を共有で借用していた。`mut w`
  なしでも、`&W` を通しても、w の共有のローンがあっても受け入れていた。今は、autoderef がそれに `deref_mut` を取るのと
  同じく `(&mut *w).push(2)` である。w は変更可能に借用される: `mut` がなければ E0596、共有のローンがあれば E0502 であり、
  `w.push(w.len())` は E0502 である。rustc と同じく、`deref` ではなくユーザーの `deref_mut` が、連鎖のリンクごとに 1 回
  走る。tests/acg/deref_mut_methods.rs が出力を rustc のものと比べる。
- **drop が借用するものを使いうる scrutinee の値は、その文の終わりまで生きる。**
  `match heap.peek_mut() { Some(_) => { heap.pop(); } .. }` を受け入れていた。rustc は E0499 を報告する
  (borrowck/issue-85581.rs、issue-47646.rs)。scrutinee は、ガードの drop が使う文の一時値である。それは今、腕の間ずっと
  そのローンを持つ。腕が一部をムーブして出すときも同じである。パターンが値全体を取るときはそうしない。その `ref` の束縛が
  取る、それ自身の記憶域の借用は、その drop が使うものから外す (dropck/eager-by-ref-binding-for-guards.rs)。末尾でない
  ブロックの最後の文は、どの文とも同じく、ブロックのローカルより前にその一時値を終える。以前は、fn の最後の
  `match (borrow, ()) { .. };` が誤った E0597 だった。
- **`let` が延ばすのは `&` が借用するものであり、それを作る一時的な受け手ではない。**
  `let r = &mut *RefCell::new(1).borrow_mut();` と `let s = &*String::from("b").as_str();` で r / s を後で使うのを
  受け入れていた。受け手の一時値は文の終わりでなくなるが、`let` が持つ結果はそれを借用している (E0716)。低レベル化が
  ガードの deref を複製したもの (`*g.deref_mut()`) は、今、借用検査が追う一時値を持ち続ける。
- **ループの要素と、その本体の末尾の一時値は、1 回ごとになくなる。** 次のものは、その `ref` の束縛が借用する一時値を文の
  終わりまで持っていた:
  - `for ref x in 0..3 { v.push(x); }`
  - `while let Some(ref x) = it.next() { .. }`
  - `loop { match it.next() { Some(ref x) => v.push(x), .. } }`

  1 回を越えて持つ借用を受け入れていた。ループの本体は終端のスコープなので、rustc は E0716 を報告する。`for` ループの
  `ref` の束縛は、今、その 1 回の一時値を借用する。`while let` の scrutinee の一時値と、ループの本体の末尾の一時値は、
  1 回ごとの終わりで終わる。参照を持つ値 (`Option<&String>` の `Some(ref s)`) はそのままにする。束縛の `*s` がその参照を
  コピーして出すからである (5 節)。

## 5. まだ扱わないもの

- **参照を通して場所からコピーして出した参照** (`a: &String` の `let r = &a; t = *r;` で、a のスコープの後で t を使う) は、
  a が持つものだけでなく a のローンも持つ。main でも誤った E0597 である。場所でない値の `*x` はすでに追っている。場所に
  ついては、コピーするときにそのローカルが持つローンが要るが、借用検査のソースはそれを場所の型で名指さない。同じ理由で、
  参照を持つループの要素や scrutinee の `ref` の束縛 (`for ref s in v.iter()`) は、自分の一時値を借用しない。
- **1 つの場所に書いたプログラムの 2 つの deref** (W とそれが deref する X がどちらも `DerefMut` の `(&mut **w).bump()`) は、
  W の `deref_mut` を 2 回呼ぶ: 内側の `*w` に再び届く。autoderef が同じように届くメソッド呼び出しは、それぞれを 1 回呼ぶ。
- **`'static` の型引数を持つ、値としてのタプル構造体のコンストラクタ** (`let f = SomeStruct::<&'static u32>; f(&c);`) は、
  引数に対して検査しない (nll/user-annotations/adt-tuple-struct-calls.rs)。`SomeStruct::<&'static u32>(&c)` の呼び出しは
  検査する。
- **ある型への impl があいまいなトレイト** (`impl Trait<&mut Events<R>> for Other` と並ぶ blanket の
  `impl<T, U> Trait<U> for T where T: From<U>`): rustc は、パラメータの型がまだ推論されていない `&mut` の引数を再借用しない
  ので、それはムーブされる (ループの中で E0382、borrowck/mut-borrow-in-loop-2.rs)。zustc は先に impl を選ぶ。
- その 16 から: ジェネリックな fn の `dyn Tr<T>` (regions/regions-close-object-into-object-1.rs)、
  `&*vec![1].iter().next().unwrap()` (`unwrap` の値を通した E0716)、opaque 型のメンバー制約 (E0700)、タプルの推論の `&mut`
  (borrowck/issue-36082.rs)、フィールドごとのリージョン、バリアントの `use … as S`、そして `static` なクロージャの借用検査。
