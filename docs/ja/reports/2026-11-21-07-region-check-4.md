# リージョン (ライフタイム) 検査、その 4: 何も呼ばないジェネリック関数 (issue #1)

日付: 2026-11-21

その 3 ([2026-11-21-06](2026-11-21-06-region-check-3.md)) は #39 でマージした。その最後の章に書いたとおり、`zustc check`
はジェネリック関数を、要求されたインスタンスについてだけ検査する。ライフタイムと借用の、落ちている 451 のテストの
うち 120 は、最初のエラーが何も呼ばないジェネリック関数の中にあった。この段は、それらの関数を検査する。

## 1. 加えたもの

- **代わりの型のインスタンス:** 検査の最後に、どのインスタンスも要求されなかったプログラムのジェネリック関数を、もう 1
  回インスタンスにする。型パラメータごとに代わりの型を入れる (`Program::placeholder`)。
  - 代わりの型は、フィールドのない struct で、名前は `T#` (プログラムの型が持たない名前)。
  - パラメータの境界が名指すトレイトと auto トレイトを実装し、境界がそう言えば `Copy`。
  - 除くもの: トレイトのデフォルトメソッド、クロージャの本体、依存するクレートの関数。
- **マーカーの境界だけ:** 型パラメータの境界がマーカーのトレイト (`Copy`、`Sized`、`Send`、`Sync`、`Unpin`) だけの関数
  に限る。代わりの型はトレイトのメソッドを持たない。それ以上の境界を持つ関数は、型検査の作業をしたあげくに、ほぼ
  失敗するから。
- **報告するもの:** この巡では、型検査のエラーは報告しない (代わりの型は、境界が許すことのすべてはできない)。借用検査と
  リージョン検査のエラーは報告する。
- **この巡が辿るもの:** 本体が作るクロージャを数段まで辿る。ほかのジェネリック関数のインスタンスは辿らない。foo の中の
  `foo(p, |x| f(x))` は終わらないし、そうした関数は、自分の代わりの型のインスタンスを持つ。
- **切り方:** `ZUSTC_NO_PLACEHOLDERS=1` で、この巡を除く。

途中で見つけたもの:

- **`_` の引数:** `_` の引数が 2 つあれば、リージョン検査にとって 2 つのローカル (`_#k`) になった。以前は 2 つ目が 1 つ
  目の導く境界を隠し、`fn foo<'a, 'b>(_: &'a &'b (), v: &'b u8, _: &()) -> &'a u8` を拒否していた。
- **フィールドが分からない型:** フィールドが分からない型 (代わりの型の関連型) の struct リテラルは、パニックでなく
  エラーにした。
- **ライフタイムを書く impl のメソッド:** ジェネリック関数のインスタンスが、トレイトにライフタイムを書く impl
  (`impl Trait<'static> for ()`) のメソッドを呼ぶとき、その呼び出しは辿らない。ジェネリックな本体は、自分の境界
  (`(): Trait<'a>`) のもとで、impl ではなくトレイトのシグネチャでそのメソッドを呼んだから。
- **#39 のレビュー (minor):** ライフタイムの lint の走査で、ブロックコメントを入れ子にした。シグネチャの入力の
  ライフタイムは、分からない型の後も数える。

## 4. まだ扱わないもの

- **代わりの型のリージョン:** 代わりの型はリージョンを持たない。`T: 'a` と E0310 / E0309 のテストには、型パラメータの
  リージョンを universal なリージョンとして扱い、`T: 'a` の境界で縛ることが要る。
- **メソッドを持つ境界:** 境界のメソッドと、代わりの型の `dyn` への変換がない。impl ではなくトレイトのシグネチャが要る。
