# リージョン (ライフタイム) 検査、その 16: deref の型強制、ブロックのローカルより長く生きるブロックの値とガード、`&mut` の引数、一時値の場所 (issue #1)

日付: 2026-11-23

その 15 ([2026-11-23-03](2026-11-23-03-region-check-15.md)) は #71 でマージした。この段階では、よくある形の誤ったエラー、
`&T` が期待される所での参照 `a: &T` の `&a` (deref の型強制) を直す。また、より多くの値が借用するものを追う: 呼び出しの
`&mut` の引数、クロージャの境界の結果、型パラメータの引数を持ちうる結果、str のビュー、サイズの決まらない Box の中身、
`let ref` の一時値、一時値の中の場所 (`&f().0`)、そしてブロックのローカルより長く生きる、ブロックの値とガードである。

## 1. 加えたもの

### 直した誤ったエラー

- **`&T` が期待される所での参照の `&a` は deref の型強制である。** `fn f(a: &i32) -> &i32 { &a }` (`if` の枝の中でも)
  は「mismatched types: expected `&i32`, found `&&i32`」だった。`let` や引数を通すと (`let r: &i32 = &a; r`、`g(&a)`)、
  ローカル a の借用を返していた (誤った E0515)。今は、必要なだけ deref した後の、a が持つポインタである: 借用検査では
  `*a` の再借用、リージョン検査では a の木である。a が持つものは追ったままである: `let a = &x; let b = &a; &b` を返すのは
  x の E0515 である。`&mut a` はローカル a の可変の借用のままで、それには `mut` が要る (E0596、
  did_you_mean/issue-37139.rs)。それを通して再借用したものは、その借用より長く生きない。
- **`let ref x = e;` は参照を束縛する。** 型推論はこれを `let x = e;` として束縛していたので、`let ref init = 0i32;` の
  `[x]` は型の不一致だった。nll/return-ref-mut-issue-46557.rs は前はそのような不一致でパスしていた。今は、それが確かめる
  エラーでパスする (下)。

### 借用検査

- **`Box<dyn Tr>` / `Box<[T]>` / `Box<str>` の `&*b` は Box が所有するものを借用する。** その再借用は Box のポインタ
  そのもので、ローンがなかった。今は `let r = &*v; drop(v); r` は E0505、`Box<dyn X>` として返す `Box::new(B(&*v))` は
  E0515 である。それを通したメソッドの自動参照は Box を可変に要る: `mut` と宣言しない `b: Box<[u8]>` の `b.iter_mut()` と、
  `&self` を通した `self.0.sort()` は E0596 で、受け手で報告する。
- **一時値の `let ref`。** `let ref mut x = 1234543;` (または呼び出しの値の `let ref`) の一時値は借用され、ブロックの
  ローカルとともに消える: x を返すのは E0515 であり (nll/return-ref-mut-issue-46557.rs)、内側のブロックを越えて保つ
  それへの参照は E0716 である。定数のもの (`let ref x = 5;`) はそうでない。`let x = &5;` がそうでないのと同じである。
- **呼び出しの `&mut` の引数は、シグネチャにより、ほかの引数が借用するものを蓄える。**
  `fn push<'a>(r: &'a i32, v: &mut Vec<&'a i32>)` (または `fn put<T>(a: T, v: &mut Vec<T>)`) の `push(&x, &mut v)` は v に
  x のローンを持たせていなかったので、v を使っている間の `x = 2;` を受け入れていた
  (borrowck/cannot-assign-borrowed-ref-in-slice.rs、E0506)。今は、名前付きのライフタイムか型パラメータを `&mut place` の
  引数の参照先と共有する引数の借用元が、そこへ流れ込む。
  - 共有するライフタイムがその参照自身のもの (`r: &'a i32`) か、型パラメータがその型 (`a: T`) のとき、引数そのものが流れる。
  - その参照の先にあるとき (`b: &mut T`) は、参照先が持つものが流れる: `swap(&mut values, &mut x.values)` は x に values の
    ローンを蓄えない (run-pass のテスト borrowck/borrowck-mut-uniq.rs は受け入れたままである)。
  - 型が参照を持たない参照先は何も受け取らない。省略されたライフタイムや別のライフタイムは流れない。
- **クロージャの境界を通した呼び出しは、境界のライフタイムにより、その結果が借用するものを持つ。**
  `F: Fn(&isize) -> &isize` での `let y = f(&x); x = 5; drop(y);` は E0506 である。結果は、その結果が名指すライフタイムを
  型が名指す引数か、結果のものが省略されているときは参照を持つただ 1 つの引数の、ローンを持つ。参照のない結果や `'static`
  の結果ではない。
- **str / スライスのビューは、受け手が持つものを持つ。** `v0: &str` の `v0.chars()` は何も持たなかった。受け手が持つものを
  結果に渡すのは prelude の型だけだったからである。ライフタイムをキャプチャしない `impl Iterator<Item = char>` として返す
  と、今は E0700 である (lifetimes/issue-105227.rs)。`s.push('c')` の間保つ `t: &str = &s` の `t.chars()` は E0502 である。
- **エディション 2024 より前、ブロックの末尾はさらに 2 つの形でブロックのローカルより長く生きる。**
  - 文が捨てるブロックの値は、文の終わりで drop される: D の `Drop` が t1 の借用を見うるとき、
    `{ let t1 = D(1); D("other").next(&t1) };` は E0597 である。内側のブロックを通しても同じである
    (nll/issue-54382-use-span-of-tail-of-block.rs)。
  - prelude のガード (`Ref`、`RefMut`、`MutexGuard`) は dropck である: その `Drop` は、守るものの借用を解放する。ブロックの
    末尾で作ったもの (`y.borrow().clone()`、`*a.borrow() + 1`) は、それが借用するローカルを十分に長く生きないものにする
    (E0597、span/issue-23338-locals-die-before-temps-of-body.rs、span/destructor-restrictions.rs)。末尾の一時値は演算子を
    通しても見つけ、下ろし方が呼び出しを複製するとき (ガードが deref する先のメソッド) にも、それが持つものを見つける。
    関数の本体の末尾もそのようなブロックである: c を所有する関数の末尾の `c.borrow().len()` は E0597 である
    (feature-gates/feature-gate-shorter_tail_lifetimes.rs)。
- **ブロックのローカルが持つものを持つブロックの値は、ブロックの後で検査する。** v を後で使う
  `let v = { let x = 1; let y = &x; y };` は E0597 であり、ローカルを通した呼び出しの結果
  (`let f = &shorten_lifetime;` の `f(a, b)`、nll/promoted-bounds.rs) も同じである。ブロックの名前はその後にはないので、
  直接借用する末尾 (`{ let x = 1; &x }`) だけを検査していた。値はブロックの後で使う所で読む。match の対象や呼び出しの
  引数としてでも同じである (span/issue-40157.rs)。ブロックのものを何も持たない値 (`{ let y = &outer; y }`) は問題ない。
  TODO のケースだった tests/security/region_block_tail_escapes.rs は今は捕まえる (ガードや `Some(&v).unwrap()` を通しても)。
  その TODO の項目は消した。
- **結果は、結果が名指すライフタイムより長く生きる型パラメータの引数を持ちうる。**
  `fn scoped<'a, F: Fn() + Send + 'a>(f: F) -> Guard<'a>` の `scoped(|| { let _z = y; })` は、クロージャが持つものを持つ:
  クロージャが借用するものを所有するブロックの後で使うと E0597 である (span/send-is-not-static-ensures-scoping.rs、
  span/regions-close-over-type-parameter-2.rs)。それを教えるのは、結果の中の `'r` についての境界 `T: 'r` である。
- **一時値の中の場所の借用は、その一時値の借用である。** 文の後まで保つ `v = &mk().1;`、`id(&x.borrow().1)`、
  `&v.clone()[0].1`、`&Box::new((0, 1)).1`、`&mk().0[..]` は E0716 である: その場所には、呼び出しが作る一時値の
  フィールド、添字、所有する deref (`Box`、ガードや `Rc` の `Deref`) を通って届く。`let` は前と同じく延長する
  (`let v = &x.borrow().1;` は問題ない)。一時値である参照を通って届く場所 (`&v.iter().next().unwrap().1`) は、一時値の
  ものではない。`&mut` を注釈した所でガードを通して読む `&mut` のフィールド (`let v: &mut i32 = x.borrow_mut().0;`) も、
  一時値を通した再借用である。

### 診断

- **返す `match` の最初より後の腕は、match で報告する。** rustc の責任の割り当てと同じである: その値は match の型へ
  強制され、rustc が名指す制約は match の値を返すことである (regions/regions-free-region-ordering-incorrect.rs)。
  最初の腕、`if` の枝、値を作る腕 (ブロック、`if`、コンストラクタの呼び出し) は、rustc と同じく、それがある所で報告する。

## 4. レビュー (CodeRabbit、rustc 1.97 と照らした)

#88 への CodeRabbit の最初のレビューには 6 つの指摘があった。それぞれを、それを示すプログラムに zustc と rustc を走らせて
確かめた。5 つは当たっていて、直してテストした (`part16_review`):

- **入れ子の末尾の監視 (クラッシュ)。** ブロックの末尾の監視する呼び出しの引数の中のブロック (ブロックの末尾としての
  `c.borrow().get({ let e = RefCell::new(1usize); *e.borrow() }).copied()`) は、終わる時に外側の末尾の位置の監視を
  消していたので、外側の呼び出しがその先を添字で読み、zustc はパニックしていた。今は各末尾が自分の加えた監視だけを消す。
  このプログラムは、rustc と同じ行で e の E0597 である。
- **エディション 2024 の捨てるブロックの値。** D の `Drop` が参照を読む `{ let x = 0; D(&x) };` を、エディション 2024 では
  受け入れていた (rustc では E0597)。2024 の規則が変えるのは末尾の一時値が消える時で、ブロックの値が消える時ではない:
  どのエディションでも、文の終わりで drop を検査する。
- **`dyn Fn` の呼び出しの結果。** `f: &dyn Fn(&i32) -> &i32` で r を後で使う `let r = f(&x); x = 2;` を受け入れていた
  (E0506)。結果に引数のローンを持たせていたのはジェネリックな境界の呼び出しだけだった。今は `dyn Fn` の呼び出しもそうする。
- **`&mut` を通した、型強制された `&x`。** `&'long i32` として返す `x: &'short mut &'long mut i32` の `&x` を受け入れて
  いた (rustc: lifetime may not live long enough)。型強制した再借用 (`&**x`) は今は、明示したものと同じく、通る `&mut` の
  リンクで上限が決まる。共有のリンクではそこで上限が止まる。
- **渡した後に、後の引数が代入するローカル。** `put(r, { r = &x; }, &mut v)` は v に x のローンだけを蓄えていたので、
  `k = 3;` (渡した時 r は `&k` だった) を受け入れていた。rustc の r のリージョンは両方のローンを持ち、両方の書き込みを
  報告する (E0506)。引数が代入するときは、引数より前に渡したローカルが持つものも流れる。

6 つ目、`F: Fn(&'a i32, &'a i32) -> &i32` はその結果に引数が共有する 1 つのライフタイムを与えるべきだ、というものは
当てはまらない: rustc はその境界を拒否する (E0106、missing lifetime specifier) ので、書けない。

2 回目には差分の中の指摘が 1 つ、外のものが 1 つあった。どちらも当たっていて、直してテストした (`part16_review`):

- **ブロックの値を持つものの下の `let ref` の一時値。** r を後で使う `let r = { let ref x = make(); x };` を受け入れて
  いた (rustc では E0716): ブロックのスコープの終わりは、一時値の後に積んだ、外側のブロックの値を持つものの所で止まって
  いた。今は、終わるスコープの一時値はすべてそれとともに消える。
- **型強制した `&x` のリージョン。** `x: &'a mut i32` での `let r: &'a i32 = &x; *x = 2;` を受け入れていた (rustc では
  E0506): 型強制した再借用には、明示した `&*x` と違い、借用検査のローンが従う自分のリージョンがなかった。今はある。
  これを確かめる中で、`&'a i32` として返す `x: &'a mut i32` の `&x` を受け入れていることも分かった: `&mut` のリンク
  だけを通るとき、再借用は型強制が取る x の借用を通るので、rustc では E0515 であり、今はここでもそうである。

3 回目には 1 つあり、当たっていた: その最後の上限はどの場所にも掛かったので、返す `s: &mut S` の `&s.f`、`s: &'a S<'a>` の `&s.r`、
そして `&*x` は誤った E0515 だった (rustc はどれも受け入れる)。今は、関数が所有する場所だけが、型強制のその借用で上限が決まる。参照を
通って届く場所は、明示した経路と同じく、その参照を通した再借用である。`part16_review` で確かめ、所有する `s: S` の
`&s.f` は E0515 のままである。

## 5. まだ扱わないもの

- **ジェネリックな構造体の `dyn Tr<T>` のフィールドと、ジェネリックな関数の `&dyn Tr<T>` の引数** は、T でインスタンス化
  しない: `struct B<'a, T>(&'a (dyn A<T> + 'a))` の `B(&*v)` は「type annotations needed」で、そのジェネリックな関数は
  検査しない (regions/regions-close-object-into-object-*.rs)。トレイトオブジェクトの型はテキストとして持つ。
- **impl が十分に一般的でない高階の境界** (`impl Foo<&'static isize>` だけがある `T: for<'a> Foo<&'a isize>`) と、結果が
  `'static` でなければならない高階の fn ポインタとして渡す fn 項目 (regions/regions-fn-subtyping-return-static-fail.rs):
  束縛されたリージョンは、リージョン検査ではプレースホルダでなく変数である。
- **高階の境界で結ばれたライフタイムを持つ、トレイトの境界のメソッド** (`F: for<'a> FnLike<&'a isize, &'a isize>`、
  higher-ranked/trait-bounds/hrtb-identity-fn-borrows.rs): そのようなメソッドを本体で呼ぶ関数は、プレースホルダの
  インスタンスで検査しない。
- **スライスへの `Deref` を通した添字** (`type Target = [()]` での `self[0]`、borrowck/issue-81365-6.rs) は
  「cannot index into a value」であり、str へのもの (`type Target = str` での `&s[1..3]`) も同じである。
- **タプルを作る時に `&T` へ強制されるタプルの `&mut` の要素** (`RefCell::new((&mut r, s))` の後の
  `let v: &_ = x.borrow().0;`、borrowck/issue-36082.rs): 型推論がその要素を `&i32` とするので、読むのはガードを通した
  再借用でなくコピーである。
- **トレイトオブジェクトの中の、参照についての包括的な impl のメソッド** (`impl<A> Foo for A`、`v: &i32` での
  `Box::new(v) as Box<dyn Foo>`) は、誤った「`Foo::get` has no implementation for `&i32`」である (main でも)。
  span/regions-close-over-type-parameter-2.rs では、テストが確かめる E0597 の横に報告する。
- **生ポインタの参照先からのムーブ** (`x: *const Box<isize>` での `let y = *x;`、
  borrowck/borrowck-move-from-unsafe-ptr.rs) は E0507 でない: 生ポインタの deref は借用検査の場所でない。
- **`for` ループの外の、`mut` のない `let it = v.iter();`** はまだ扱わない。
