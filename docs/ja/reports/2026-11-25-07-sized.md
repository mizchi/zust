# `Sized`: 大きさの決まった型しか置けない場所 (E0277)

日付: 2026-11-25

zustc が誤って受け入れていた rustc の UI テストのうち、トレイトのエラーで最も多かったのは `Sized` の E0277 だった。
期待されるエラーが「the size for values of type `X` cannot be known at compilation time」のテストが 56 ある。zustc は
unsized なローカル変数、unsized な引数、値としての `*s` はすでに拒否していた。この段階で、よくある残りの場合を加えた。

## 1. 加えたもの

- **プログラムのジェネリックな fn の呼び出し。** fn 自身の型パラメータで `?Sized` でないものには、大きさの決まった型を
  与えなければならない: `takes::<str>()`、あるいは `fn takes<T>(_: &T)` に対する `s: &str` での `takes(s)`。
  - 呼び出し側の `?Sized` なパラメータのプレースホルダは unsized かもしれない: `fn relaxed<X: ?Sized>(x: &X) {
    sized::<X>(x) }` は、`relaxed` を誰も呼ばなくてもエラー (`zustc check` はプレースホルダで検査する)。
  - `std::mem::size_of::<T>()` / `align_of::<T>()` も同じ。
- **本体に書いた型。** 大きさの決まった型しか置けない場所に、unsized かもしれない型を置く型:
  - プログラムの struct や enum の、`?Sized` と宣言していないパラメータへの引数 (`Foo<str>`、`T: ?Sized` の
    `Foo<T>`);
  - std の `Vec`、`Option`、`Result`、`VecDeque`、`HashMap` / `HashSet`、`BTreeMap` / `BTreeSet`、`BinaryHeap`、
    `LinkedList` の引数;
  - タプルの最後以外の要素、スライスや配列の要素 (`[[u8]; 2]`)。
- **定義とシグネチャ。**
  - struct の最後以外のフィールド、enum や union のフィールド (`struct S { a: [u8], b: u8 }`);
  - impl の self 型とトレイトの引数 (`impl Foo for Option<[u8]>`);
  - fn の引数の型と戻り値 (`fn f() -> [u8]`、`fn iceman(c: Vec<[i32]>)`、`fn g<X: ?Sized>(x: X)`)。
- **大きさが決まるもの。** 最後のフィールドが `?Sized` なパラメータの struct は、そこに unsized かもしれない
  プレースホルダを与えると、それ自体も unsized かもしれない (`struct Bar<T: ?Sized>` に対する、`T: ?Sized` の
  `Bar<T>`)。`?Sized` なパラメータでも、ほかの境界が `Sized` を含意すれば大きさは決まる (`T: Clone + ?Sized`。
  Clone の親トレイト)。

## 2. 仕組み

- シグネチャの要約は fn 自身の `?Sized` なパラメータを持つ (`SigSyn::own_unsized`)。Program は、fn 自身の
  パラメータ (impl やトレイトのものの後ろ) のうち大きさが決まらねばならないものを、プログラムの fn についてだけ求める。
- `?Sized` なパラメータのために作ったプレースホルダには印を付ける (`StructDef::maybe_unsized`)。
  `Program::maybe_unsized` は unsized な型か、そういうプレースホルダ。`Program::sized_wf` は 1 節の規則で型を辿る。
- プレースホルダのインスタンスから出るエラーには solver の印 (`SOLVED_NO`) を付ける。呼び出し側の型が何であっても
  成り立つので、`zustc check` が報告する。
- 定義とシグネチャは `driver2::sized_error` で検査し、どのプログラムでも走る (既存の well-formedness の検査は、
  境界のあるパラメータがあるときにしか走らない)。

## 3. やっていないこと

- prelude は `?Sized` を宣言していない (`Rc<T>`、`Arc<T>`、`RefCell<T>`、`ManuallyDrop<T>` ...)。そのため検査するのは
  上に挙げた std の型だけで、`T: ?Sized` の `ManuallyDrop<T>` は unsized にならない。
- impl 自身の `?Sized` なパラメータは、そのメソッドの呼び出しからは分からない。そこでは大きさが決まるものとして扱う
  (見逃すことはあっても、誤ったエラーにはならない)。
- 関連型の値と、トレイトの暗黙の `Sized` (`type A;` に対する `type A = str`) は検査しない。

## 4. 結果

rustc の tests/ui: compile-fail のテストが 24 増えて通り (4776 → 4800)、回帰はない。どれも、zustc が報告する行に
rustc の大きさのエラーがあることを確かめた。`cargo test --release --workspace` は通る。

新しいテスト: `tests/compile_errors/sized_*.rs` (ジェネリックな呼び出し、受け渡される `?Sized` なパラメータ、struct の
引数、最後以外のフィールド、メソッドの `Vec<[i32]>`)、`tests/check.rs` (`sized_accepts` は rustc が受け入れる
プログラム、`sized_rejects_maybe_unsized_param` はプレースホルダの場合)。
