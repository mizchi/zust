# リージョン (ライフタイム) 検査、その 26: `&` として渡す `&mut`、強制変換の場所の再借用、呼び出しの引数の再借用、集成型の中の `&mut` (issue #1)

日付: 2026-11-24

その 25 ([2026-11-24-11](2026-11-24-11-region-check-25.md)) は #132 でマージされた。この段階で加えるもの:

- `&T` が期待されるところに渡す `&mut` の局所変数は `&mut` のままである (main も出す誤ったエラー);
- 型を書いた `let`、コンストラクターのフィールド、代入での、`&mut` の場所の再借用;
- リージョン検査がないときの呼び出しの引数の再借用と、それを持つ結果;
- タプル、構造体、クロージャ、配列の中の `&mut`。コピーではなく move される。

## 1. 加えたもの

- **`&` として渡す `&mut`。** `fn g(_: &i32)` に対する `let x = &mut v; g(x); *x = 1;` が、誤った「cannot assign to
  `*x`, which is behind a `&` reference」になった (main でも)。`fn g(_: &Vec<i32>)` で `g(x)` の後の `x.push(2)` も
  そうだった。
  - 型推論が 2 つの参照型を単一化し、`&T` の方が勝っていた。`let` の型は `&T` になり、`&mut v` はそれへ強制変換
    されていた。
  - 今は `&mut T` と `&T` を単一化せず、それらが指すものだけを単一化する。`&Vec<T>` から `&[T]` へと同じく、強制
    変換だからである。
  - 書いた型の穴を推論が埋めるところでは、それが書く参照の可変性を保つ: `let y: &mut [_] = &x[2..4];` は今も型の
    不一致である (array-slice-vec/slice-mut.rs)。
- **強制変換の場所の再借用。** 参照が期待されるところにある `&mut T` の場所は再借用される: 値はその場所が指すものの
  借用を持つ (rustc の `&*p` / `&mut *p`)。場所は、局所変数、フィールド、`*y`、`Box` や `RefCell` のガードを通した
  フィールドでよい。以前は、局所変数 a での `let b: &mut T = a;` だけを再借用していた。その場所:
  - 型を書いた `let` (`&T` でも): `let v: &i32 = x; *x = 1; println!("{}", v);` は E0506 である;
  - コンストラクターのフィールド: `f: &'a i32` での `S { f: x }`、`Option<&i32>` が期待されるところの `Some(x)`;
  - 代入の右辺: `y: &mut i32` での `x = y;` の後、x が生きている間の `*y = 1` は E0506 である。
  - main はこれらのプログラムのいくつかを、誤った理由 (上の推論による「behind a `&` reference」) で拒否していた。
    ほかのものは受理していた。今は rustc と同じく拒否する。
  - 局所変数を通した再借用をその局所変数自身に代入するところ (`y = &mut *y;`、`y = y;`) では、`*y` の借用は残らない。
    y を上書きすると、rustc と同じく、その古い値が指すものの借用は殺される。新しい値のものもである
    (nll/self-assign-ref-mut.rs)。明示的な形は main でも誤ったエラーだった。
- **リージョン検査なしの、呼び出しの引数の再借用。** `fn take(_: &mut i32)` に対する `take(x)` は、今は呼び出しで
  `*x` を借用する。以前は、リージョン検査が有効なところでだけそうしていた。
  - そこで生きている `*x` の借用はぶつかる: `let v = &*x; take(x); println!("{}", v);` は E0502 である。
  - パラメータが `&` のところでは、再借用は共有である (`pick(x, &b)` は `pick(&*x, &b)`)。
  - シグネチャがその引数から借用すると言う結果は、その借用を持つ: `let r = pick(x, &b); *x = 1; println!("{}", r);`
    は E0506 である。
- **集成型の中の `&mut`。** borrow check は、タプル、構造体、クロージャ、配列の中の `&mut` を、`&mut` そのものと
  同じく `Copy` と数えていた。後者は渡すところで再借用されるからである。集成型の中のそれを再借用するものはないので、
  今は集成型は move される。`t: (&mut i32, i32)` で、`*t.0` が借用されている間の `let t2 = t;` は E0505、その後の t の
  使用は E0382 である。

## 5. まだ扱わないもの

- **`it.by_ref().take(n)`** は誤った E0507 になる (main でも)。`&mut I` はそれ自身 `Iterator` だが、zustc は `*it` の
  メソッドを値で取る。エラーを消すだけでは、build がイテレーターをコピーして取り出し、元のものが進まなくなる。
- **型エイリアスを通して書いた、`for<..>` を持つ fn ポインター型** (`type G = for<'cx> fn(&'cx S) -> &'static S;`、
  regions/regions-fn-subtyping-return-static-fail.rs): エイリアスの型は領域を持たない。`let` に直接書けば確かめる。
- **いくつかの領域を束縛する fn ポインター型**: 1 つの universal な領域がそのすべてを表すので、最初の引数の領域を
  返す関数を `for<'x, 'y> fn(&'x u8, &'y u8) -> &'y u8` として受理する。
- **期待される型がまだ推論変数である引数** (2 つの impl が合いうるループの中の `Other::handle(value)`、
  borrowck/mut-borrow-in-loop-2.rs): rustc はそれを move し、zustc は再借用する。
- **`f(&mut i32, &i32)` に対する `f(x, &*x)`**: リージョン検査がないと、最初の引数の再借用はその引数で終わるので、
  2 つ目の借用はそれとぶつからない (rustc では E0502)。
