# リージョン (ライフタイム) 検査、その 32: クロージャが deref を通して使う共有参照を値で持つ、何も検査しないクロージャのパターン、`&mut &T` の E0596、const の初期化子をさらに (issue #1)

日付: 2026-11-25

その 31 ([2026-11-25-03](2026-11-25-03-region-check-31.md)) は #158 でマージされた。この段階で加えるもの:

- クロージャが共有参照 `h` をその deref を通してだけ使うところでの、エディション 2021 の `*h` のキャプチャ;
- 何も検査せず何もキャプチャしないクロージャのパターンと、名指すフィールドをキャプチャする構造体のパターン;
- `let` で `&mut T` へ強制変換する `&mut &T` の E0596;
- Option の `iter()` に対する `for` のパターンを、イテレート対象が書かれたところで束縛する;
- const の初期化子のどこにあるブロックの E0597 と、生ポインタの型の const の dangling pointer。

## 1. 加えたもの

- **クロージャが deref を通してだけ使う共有参照。** `h: &'r H<'r>` の fn から返す
  `v.iter().filter_map(|_| h.mk()).collect()` や、`Box<dyn Fn() -> usize + 's>` として返す `Box::new(|| self.n())` を
  考える。
  - エディション 2021 は、クロージャが使う場所をキャプチャする。クロージャが `h` を deref を通してだけ使うところ
    (メソッド呼び出しの受け手、フィールドや添字の基底、`*h`、呼び出しの引数) では、それは `*h` を参照でキャプチャする:
    局所変数 `h` の借用ではなく、参照先の再借用である。そのためクロージャは fn より長く生きてよく、rustc はどちらも
    受理する。
  - zustc はクロージャが `h` を借用するとしていた: 誤った E0373 である。
  - そういうキャプチャは、今はエディション 2021 から値で持つ (参照のコピーで、同じことである)。借用検査は、そのとき
    参照全体をキャプチャする。
  - クロージャが `h` そのものを使うところ (`|| h`、`let x = h`、`(h, 1)`、`for _ in h`) では、rustc の E0373 は `h` の
    借用についてのものである: それは変えていない。
  - 新しい driver2 の probe である tests/probe/closure_deref_capture.rs が、これらのクロージャを fn が返った後に
    ビルドして実行する。期待する出力は rustc 1.97 のものである。
- **何も検査しないクロージャのパターン。**
  - variant が 1 つの enum での `let _a = || match sv { SingleVariant::A if condition => (), _ => () };` と、その後の
    `let mut mut_sv = sv;` を考える。パターンは何も検査しないので、エディション 2021 は `sv` の何もキャプチャしない。
  - zustc は `sv` をキャプチャしていた: 誤った E0505 である。
  - variant が 1 つの enum の単位 variant と単位構造体 (`let (Unit, a) = x;`) は、今は何もキャプチャしない。
  - 構造体のパターン (`let SStruct { b, .. } = x;`、enum の variant のものも) は、タプル構造体のものがすでにそうして
    いたように、名指すフィールドをキャプチャする。
  - closures/2229_closure_analysis/match/match-edge-cases_2.rs は、今は rustc の 1 つのエラーを持つ。main では、zustc は
    そこで 5 つのエラーを出し、どれも rustc のものではなかった。
- **`&mut T` へ強制変換する `&mut &T` の E0596。**
  - `let Some(n): &mut Option<i32> = &mut &Some(5i32) else { return };` を考える。`let` が書く `&mut Option<i32>` への
    deref の強制変換は `&` を通して可変に借用し、rustc は初期化子で E0596 を出す。
  - zustc はそれを `&Option<i32>` へ強制変換し、後でそれを通した書き込みを出していた (`*n += 1` での E0594)。
  - 今は、普通の `let` でも分解する `let` でも、初期化子での E0596 である。`&mut &mut T` はこれまでどおり強制変換する。
  - let-else/let-else-binding-explicit-mut-borrow.rs と let-else/let-else-binding-explicit-mut-annotated.rs が通る。
- **Option の `iter()` に対する `for` のパターン。**
  - zustc は、`x` が Option である `for p in x.iter()` を `if let Some(__exr_ox) = &x { let p = __exr_ox; .. }` に
    lowering する。その `let` は位置を持たなかった。
  - そのため、パターンを通したムーブ (`x: Option<Box<_>>` での `for &a in x.iter()`) は fn の行にあり、`*__exr_ox` を
    名指していた。
  - 今は、rustc がそこで E0507 を出すとおり、イテレート対象にある。それは「cannot move out of a shared reference」と
    言う (borrowck/borrowck-for-loop-correct-cmt-for-pattern.rs)。
- **const の初期化子をさらに。**
  - その 31 は、const のブロックの末尾を検査した。初期化子のさらに深くにあり、その値が自身の局所変数の 1 つを借用する
    ブロックも E0597 である: `unsafe` ブロックの中の `mem::transmute({ .. { let s = [0; 10]; &s } })`
    (borrowck/const-fn-ptr-borrow-annotation.rs)。
  - 型が生ポインタである const では、そういう借用は借用検査のエラーではない。ポインタはライフタイムを持たないから
    である。rustc の定数の評価はポインタが宙ぶらりんであることを見つけてアイテムで出し、zustc も今はそうする
    (consts/dangling_raw_ptr.rs)。

## 4. レビュー

CodeRabbit が 9912687 をレビューした: 差分へのコメントが 4 つと、差分の外のものが 1 つ。どれも zustc と rustc 1.97 で、
main (4139c8b) とも照らし合わせて確かめた:

- **const の中の、生ポインタの型の `let`。** rustc は `const C: () = { let _: *const u32 = { let x = 42; &x }; };` を
  受理する: `let` は、ブロックが終わる前にその末尾を生ポインタへ強制変換する。この作業は E0597 を出していた (main は
  誤った型の不一致を出していた)。今は、そういうブロックの末尾は見ず、その文を見る。参照の型の `let` なら E0597 のままで
  ある。
- **クロージャの中の、共用体のパターン。** `|| unsafe { let U { a: ref x } = u; }` はフィールド `u.a` をキャプチャして
  いたので、クロージャが生きている間の `u.b` への書き込みが受理されていた (main は rustc と同じく E0506)。今は、共用体の
  パターンは共用体をキャプチャする。
  - zustc は、共用体のパターンを、すべてのフィールドを名指す構造体のものとしてもいた。今は、rustc と同じく、`..` なしで
    1 つのフィールドを名指す。
  - 共用体のフィールドに当てることはそれを読むことで、そのフィールドのパターンが `_` でなければ `unsafe` が要る
    (E0133)。zustc は今はそれをパターンで出す。main でフィールドについての誤ったエラーで通っていた union/union.rs と
    union/union-pat-in-param.rs は、それで通る。TODO.md で誤った理由で拒否されるとしていた tests/security の
    `unsafe_union_pattern` は今は通る: その `//@ todo` の行と TODO.md の項目を消した。
- **クロージャのパターンが値で束縛する `&mut` のフィールド。** `p: &mut T` での `|| { let S { p, .. } = s; p }` は、
  そのフィールドを Copy とし、参照でキャプチャしていた。rustc はそれをムーブする: 呼び出しの後の `s.p` の使用は、main
  と同じく E0382 である。
  - 今はムーブする。タプルやタプル構造体のもの (`let (p, _) = s;`、`let T(p) = s;`) もそうで、それは main も見逃して
    いた。
  - そのときクロージャは `FnOnce` である: rustc と同じく、2 度目の呼び出しは E0382 である。
- **クロージャのパターンの中の定数。** variant が 1 つの enum での `match e { E::ZERO => .., _ => .. }` は、enum の単位
  variant とされ、何もキャプチャしなかった。定数は値を比べるので `e` を読む: クロージャが生きている間の `e = ..` は、
  main と同じく E0506 である。今は、variant 自身の名前だけが何もキャプチャしない。
- **共有参照を deref を通してだけ使う、返される `impl Fn` のクロージャ** (`fn f(h: &u32) -> impl Fn() -> u32 + '_
  { || *h }`)。rustc はエディション 2021 でそれを受理する。zustc は、main と同じくそれを拒否する: クロージャの型を与える
  fn のサマリは、エディションを知らない。ここでは変えていない (第 5 節)。
- tests/regionck.rs の `part32_review` がこれらのケースを確かめる。

## 5. まだ扱わないもの

- **キャプチャした参照そのものを使うクロージャ。** `Box::new(|| { let x = h; x })` は rustc の E0373 である。`h` の
  コピーは `h` を参照でキャプチャするからである。zustc はそこでキャプチャを値で持ち、受理する。
- **局所変数に置いて返すクロージャの E0597。** `let mut c = || { p.x += 5; println!("{:?}", p) }; c` について、
  rustc はクロージャの中の `p` の使用で E0597 を出す。zustc は、直接返すクロージャと同じく、クロージャで E0373 を出す
  (closures/2229_closure_analysis/diagnostics/borrowck/borrowck-4.rs)。
- **トレイトのものより厳しい、impl のメソッドのライフタイムの境界の E0276。** トレイトが `F: Debug + 'a` を持つところでの
  `F: Debug + 'static` は rustc の E0276 である (typeck/issue-18937.rs)。zustc は、それが通したものを後で出す。
- **自身への参照を保存する値の dropck** (span/issue-25199.rs、span/dropck_*)。
- **共有参照を deref を通してだけ使う、返される `impl Fn` のクロージャ** (`|| *h`): rustc はエディション 2021 で
  それを受理する。クロージャの型を与える fn のサマリは、エディションを知らない (第 4 節)。
