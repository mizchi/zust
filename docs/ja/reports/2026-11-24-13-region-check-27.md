# リージョン (ライフタイム) 検査、その 27: 引数の two-phase 再借用、生ポインターの `ptr::swap`、境界のメソッドを通したプレースホルダーの関連型 (issue #1)

日付: 2026-11-24

その 26 ([2026-11-24-12](2026-11-24-12-region-check-26.md)) は #145 でマージされた。この段階で加えるもの:

- 呼び出しの引数の暗黙の `&mut` 再借用を、リージョン検査がないときも two-phase borrow として扱う;
- `mem::swap` の 2 つの `&mut` とは別の、2 つの生ポインターの `ptr::swap`;
- その `Self` の関連型を返す境界のメソッドを呼ぶジェネリックな関数の、プレースホルダーでの検査。シグネチャが
  ライフタイムか `'static` を名指すところに限る;
- 2 つのメッセージでの、プログラムが書いたとおりの名前と、その 26 のレポートの訂正。

## 1. 加えたもの

- **引数の two-phase 再借用。** その 26 は、リージョン検査がないときも、`fn take(_: &mut i32)` に対する `take(x)` が
  呼び出しで `*x` を借用するようにした。その借用は引数のところで終わっていたので、`fn f(_: &mut i32, _: &i32)` に
  対する `f(x, &*x)` を受理していた。rustc は E0502 を出す。
  - rustc では、呼び出しの引数の `&mut` 再借用は two-phase borrow である。ほかの引数を評価する間は予約され、
    呼び出しのときに取られる。
  - 今は、リージョン検査がないときもその再借用を予約する: 呼び出しまで保つ共有の借用である。引数を評価し終えたら、
    一意の借用として取る。メソッドの `&mut self` はすでにこうしていた。
  - `f(x, *x)` と `push(v, v.len())` は予約の間に `*x` を読むので、rustc と同じく受理する。`f(x, &*x)` は借用を取る
    ときにぶつかり (E0502)、`f(x, g(x))` は予約の間にぶつかる (E0499)。
  - `&` のパラメータの共有の再借用も呼び出しまで保つ: `fn f(_: &i32, _: &mut i32)` に対する `f(x, x)` は E0502 で
    ある。
- **生ポインターの `ptr::swap`。** `ptr::swap` と `std::ptr::swap` は、prelude の `mem::swap`、つまり
  `__core_swap(&mut T, &mut T)` に解決されていた。これには 3 つの影響があった:
  - two-phase の再借用と合わせると、`ptr::swap(test, test)` が `*test` の 2 つの一意の借用になった。この作業の最初の
    サイクルは、run-pass のテストである ptr_ops/ptr-swap-overlapping-regions.rs を拒否した;
  - 生ポインターでの `std::ptr::swap(pa, pb)` は「cannot find value」になった;
  - `unsafe` の外での呼び出しを受理していた。rustc は E0133 を出す。
  - 今は prelude の `__core_ptr_swap(*mut T, *mut T)` で、std と同じく unsafe な関数である。`mem::swap(x, x)` は今も
    E0499 である。
- **境界のメソッドを通したプレースホルダーの関連型。** `Iter` に `fn into_item(self) -> Self::Item` がある、
  `fn bad1<T: Iter>(v: T) -> Box<dyn X + 'static>` を考える。`Box::new(v.into_item())` を返すのを受理していた。
  rustc は E0310 を出す (regions/regions-close-associated-type-into-object.rs)。
  - 何も呼ばないジェネリックな関数はプレースホルダーで検査する。本体が、境界のトレイトが宣言するメソッドを呼ぶ関数は
    外す: その型検査がコストで、その検査は領域について多くを言わないからである。
  - その `Self` の関連型 (`Self::Item`) を返すメソッドは、言うことがある。プレースホルダーの関連型は、それ自身の
    universal な領域を持つ (その 25)。そういうメソッドを呼び、シグネチャがライフタイムか `'static` を名指す関数は、
    今はプレースホルダーで検査する。
  - そういうメソッドを呼ぶすべての関数ではない。それは traits の KPI を +4.9% にした。bench/gen_traits.py の
    ジェネリックな関数がそういうメソッドを呼ぶからである。シグネチャがライフタイムを名指さないところでは、呼び出し先
    だけが課す要求は見つからない (第 5 節)。
- **メッセージの名前。**
  - `ptr::swap` の呼び出しの E0133 は `ptr::swap` を名指す。
  - リージョン検査のメッセージは、prelude のものと名前が同じ型やトレイトを、プログラムが書くとおりに名指す:
    `<T as __u_Iter>::Item` ではなく `<T as Iter>::Item` である。
- **その 26 のレポートの第 1 節。** 自分自身への再借用を局所変数に代入すると、その局所変数が指すものの、新しい値の
  借用が殺される、と書いていた。その 26 の 2 度目のレビュー以来、新しい値は古い値が借用していたものを保つ。そこの
  第 4 節が言うとおりである。CodeRabbit が #145 の最後のレビューでこれを指摘した。

- 新しく通る compile-fail は `regions/regions-close-associated-type-into-object.rs` である。zustc は `bad1` (E0310) と
  `bad3` (E0309) を、rustc と同じ行と同じコードで報告する。`bad2` と `bad4` は報告しない (第 5 節)。
- 通っていたテストで落ちるものはない。この作業の最初のサイクルでは 1 つ落ちた: run-pass のテストである
  ptr_ops/ptr-swap-overlapping-regions.rs。直した (第 1 節)。
- パスする 1861 の run-pass のテストを `zustc check` にかけた: main が受理し、これが拒否するものはない。
- tests/regionck.rs がこの段階のケースを確かめる (`part27_*`)。どれも rustc 1.97 と照らし合わせた。
- これを測ったサイクルで、その 25 と 26 と同じく、`cargo test` の `driver2_matches_expected` が一度落ちた。KPI は
  サイクルの前に測り、同時ではなかった。その後、それだけを 3 度走らせたときには通った。サイクルのスクリプトは panic の
  行だけを残し、どのプログラムの出力が違ったかを残していなかった。今は出力の全体を残す。

## 5. まだ扱わないもの

- **呼び出し先だけが課す、プレースホルダーの関連型への要求**。シグネチャがライフタイムを名指さない関数で
  (`fn need<U: 'static>(_: U)` に対する `need(v.into_item())`): そういう関数はプレースホルダーで検査しない。
- **プレースホルダーの関連型を持つ型に対する where 節** (`where Box<T::Item>: X`、
  regions/regions-close-associated-type-into-object.rs の `bad2` と `bad4`): プレースホルダーのインスタンスの型検査は
  それを読まない。すると `Box<T::Item>` を `dyn X` へ閉じ込めるところで型検査が失敗し、その関数は検査されない。
- その 26 以前から: [その 26](2026-11-24-12-region-check-26.md) の第 5 節を見よ。`f(x, &*x)` は今は扱う。
