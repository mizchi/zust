# リージョン (ライフタイム) 検査、その 11: match の末尾、末尾の一時値、クロージャの本体、パスに書いたライフタイム、トレイトオブジェクトの受け手 (issue #1)

日付: 2026-11-22

その 10 ([2026-11-22-07](2026-11-22-07-region-check-10.md)) は #53 でマージした。この段階では、tests/ui で受け入れて
いると分かった場合をさらに扱う。また、構造体リテラル、構造体のパターン、関数として使うコンストラクタに turbofish を

## 1. 足したもの

### 借用検査

- **関数の末尾の match は、arm の値をそのスコープの中で返す。** arm が束縛の 1 つを名指しして (`S(&mut ref mut r) =>
  r`)、またはそれのコンストラクタで (`Some(r)`) 返すものは、束縛がスコープにある間に返る。`Drop` の値の `&mut` の
  フィールドを通すと E0713 になる (nll/enum-drop-access.rs)。タプル構造体やバリアントのコンストラクタは、引数が持つ
  ものを持つ。
- **バリアントのパターンは型でムーブを決める:** n が整数の `let E::V(n, _) = e;` はコピーする。`Fn` の境界に渡す
  クロージャの中でも同じ (#51 のレビューから)。
- **クロージャの中の `if let` / `match` の scrutinee は、パターンと一緒に扱う:** `Fn` の境界に渡すクロージャの中の
  `if let E::V(_, s) = e { drop(s) }` と `match o { Some(s) => drop(s), .. }` は、キャプチャをムーブで取り出す
  (E0507)。
- **ブロックの末尾の一時値は、ブロックのローカルより長く生きる** (エディション 2021)。メソッドを呼ぶ一時値
  (`D(&_t1).end()`) で、その `Drop` が借用しているものを見るかもしれないものは、囲む文の終わりでそのローンを使う。
  そのため、ブロックのローカルのローンは E0597 になる (nll/issue-54556-*.rs)。本体の末尾の一時値も、本体の
  ローカルの後になくなる。エディション 2024 からは、ブロックの終わりで、ローカルより前になくなる。
- **クロージャの中の `a;` は a をムーブする**。`let x = a;` と同じ: それをするクロージャをループの中で作ると、
  2 回目で E0382 になる (moves/issue-75904-move-closure-loop.rs)。
- **ガードは `ref mut` の束縛を共有とみなす:** それを通した代入は E0594、可変の借用は E0596。クロージャの中でも
  同じ (nll/issue-27282-reborrow-ref-mut-in-guard.rs)。
- **パターンが値で束縛する `&mut` はムーブする:** opt が `Option<&mut T>` の `if let Some(x) = opt` をループの
  中に書くと、2 回目で E0382 になる (borrowck/move-in-pattern-mut-in-loop.rs)。
- **借用として書いた受け手は、引数の間も借用したまま:** `(&mut x).with(|v| x = ..)` は E0499
  (borrowck/borrowck-autoref-3261.rs)。
- **返す値が借用するものを、キャストと `Box::new` を通して追う:** `Box::new(B(&*v)) as Box<dyn X>` は E0515。
  ローカルを借用する box したクロージャを返すと E0373 (tests/security/borrow_closure_escapes.rs、これまでは TODO)。
- **クロージャがキャプチャした参照を通した `&mut`** (`x: &mut isize` での `|| set(&mut *x)`) は `*x` を一意に借用
  する。キャプチャは `&mut` のものなので、`&` を通すと E0596 になり、同時に生きているそうしたクロージャ 2 つは
  衝突する (rustc の E0524。borrowck/borrowck-closures-mut-of-*.rs)。
- **クロージャが参照で持つキャプチャは、本体の中では、それが指す場所である。** 本体はそれを自分の場所として借用し、
  代入する。そのため、本体の中の `let p = &this.x; &mut this.x;` は E0502 になる
  (borrowck/borrowck-closures-unique-imm.rs)。本体がそうしたキャプチャを通してムーブしたり書いたりするものは、
  これまでどおり、クロージャを作る所で検査する。
- **トレイトオブジェクトのメソッドは受け手を借用する。** `&self` / `&mut self` で借用し、self から借用する結果は
  そのローンを持つ。構造体のメソッドと同じ。x が `&mut dyn Foo` の
  `let y = x.borrowed(); let z = x.mut_borrowed(); y.use_ref();` は E0502 (borrowck/borrowck-object-lifetime.rs)。
  これまでは、呼び出しは何も借用していなかった。

### リージョン

- **ライフタイムを書いたコンストラクタのパスは、値の型を与える** (nll/user-annotations/adt-*.rs)。タプルの
  バリアント (`SomeEnum::SomeVariant::<&'static u32>(&c)`)、構造体の形のバリアント、ユニットのバリアント
  (`SomeOtherVariant::<Cell<&'static u32>>`。不変の `Cell` を通して、もう 1 つの引数と関係づく)、タプル構造体、
  構造体リテラルで当てはまる。
- **パスで呼ぶとき、型が impl のライフタイムを与える:** `impl<'a> A<'a> { fn new(x: &'a u32, ..) }` での
  `A::<'a>::new(&v, 22)` と `<A<'a>>::new(&v, 22)` は、v が `'a` より長く生きることを求める
  (nll/user-annotations/method-ufcs-inherent-1.rs、-3.rs)。
- **ライフタイムを書いた構造体のパターンのパス:** `let Foo::<'static> { field: _z } = foo;` は、foo が借用する
  ものが `'static` であることを求める (pattern_substs_on_*_struct.rs)。
- **修飾したパスを通したトレイトの定数:** `impl Tr for A<'static>` での `<A<'a> as Tr>::IC` は、`'a` が
  `'static` であることを求める。これは見逃していた (#53 のレビューから)。
- **ゲート。** リージョン検査は、シグネチャのリージョンが 2 つ未満の関数を外す。そうした関数で検査を有効にする
  場合を 2 つ足した:
  - パスにライフタイムを書いた文 (ソースのどこかにそれがあるとき)。文の中でパスより前にある借用も追う。
  - フィールドが自分のライフタイムを 2 つ入れ子にする構造体 (`p: &'a mut &'b i32`) の値。そうした値は、それを
    作る借用どうしを関係づける。メソッドが一方を他方を通して格納するかもしれないため。その前に束縛した
    ローカルに木がなければ、関数の始めから検査する (nll/capture-ref-in-struct.rs)。

### 拒否しなくなった正しいコード

- **turbofish を書いた構造体リテラル** (`S::<u32> { t: 1 }`) は "cannot find struct" だった。インスタンスは
  turbofish が書くもので、型推論でも同じ。
- **turbofish を書いた構造体のパターン** (`let P::<u16>(a, b) = ..`、`S::<String> { t, .. } =>`) は "cannot find
  struct or variant" だった。
- **関数として使う、turbofish を書いたタプル構造体やバリアント** (`let f = P::<u16>;`、`.map(Some::<u32>)`) は
  "unsupported path" だった。
- **turbofish の参照のために借用する整数リテラル** (`let c = 66; P::<&u32>(&c);`) は "expected `&u32`, found
  `&i32`" だった。型推論は、タプルのコンストラクタのインスタンスを turbofish から取るようにした。
- tests/acg/turbofish_ctors.rs がこれらを実行し、出力を rustc のものと比べる。
- **`()` での、そして数・`()`・`Box` への参照を通した、ブランケット impl のメソッド** (`impl<T> Fake for T` と
  `r: &mut ()` での `r.use_mut()`) は "no method `use_mut` on type `()`" だった。Self は参照先で、参照が受け手に
  なる。rustc のメソッドの探索が `&mut self` をそれと合わせるのと同じ。`&mut` を通した `&self` のメソッドは、
  それを共有にする。こうした受け手では、impl の境界が成り立たなければならない
  (`impl<T: ?Sized> FutureExt for T where T: Future` は `()` のものではない)。借用検査のテストの多くが、この
  `Fake` トレイトを使う。

### 型の検査

- **値と別の構造体の、穴のある注釈:** `let x: Foo<_> = Bar::<usize>(..)` は初期化式の所で不一致になる。これまでは
  穴があると注釈を検査せず、エラーは後で、x を `Foo<usize>` として使う所で報告していた。型の名前の中の穴は `_` と
  表示する。
- **フィールドが `Copy` でも `ManuallyDrop` でもない、ジェネリックな union のインスタンス**は E0277:
  `union U<T: Copy> { a: T }` での `U { a: Rc::new(0u32) }` (union/union-generic.rs)。

## 4. レビュー (CodeRabbit、rustc 1.97 で確かめた)

最初の回の指摘は 11 件。10 件は書かれたとおりに成り立ち、1 件は別の形で成り立った。すべて直し、テストした
(`part11_review` と tests/acg/turbofish_ctors.rs):

- 実行時の値の誤り: `let P::<u16>(x, _) = P(300, 1);` は x を `i32` にしていた (`x.leading_zeros()` は 7 でなく
  23)。今は、パターンの turbofish が、型推論の中で照合する値のインスタンスを与える。
- 見逃していて、今は報告するエラー:
  - scrutinee と別のインスタンスのパターンの turbofish (`S<u8>` に対する `S::<u16>(_)`);
  - 期待するインスタンスに対する、構造体リテラルに書いた引数 (`let _: S<u8, u8> = S::<u16, _> { .. }`);
  - `Copy` でない、union の `&mut` のフィールド;
  - ライフタイムを名指しするメソッド呼び出しの turbofish (ゲートが外す関数の中の `Q.take::<&'static u32>(&c)`);
  - 複数行に書いた turbofish より前にある、同じ文の中の借用;
  - 別のブランケット impl を通したブランケット impl の境界 (`impl<T: Marker> Other for T`)。
- `E::<'static>::V::<u8>(&local, 0u8)` は rustc では E0109: 引数は 1 つのセグメントにだけ書ける。zustc も、
  ライフタイムを追うのでなく、これを拒否するようにした。
- 拒否しなくなった正しいコード: `fn id(self) -> Self` と `r: &mut u8` での `r.id()`、そして arm の束縛と同じ名前の
  引数を持つ、ガードの中のクロージャ。
- id がクロージャの関数の id と同じとき、構造体をクロージャとみなしていた。今はクロージャの構造体の表で調べる。
- rustc との違いが 1 つ残る: その場で作る scrutinee と別のインスタンスのパターンの turbofish
  (`match S(1u8) { S::<u16>(_) => .. }`) は、パターンの所でなく、scrutinee を作る所で報告する。
- 2 回目の指摘は 2 件で、どちらも成り立った。ブランケット impl の境界は、型そのものに対する impl でも成り立つように
  した (`impl<T: Marker> Other for T` と並ぶ `impl Other for ()`): `().go()` は拒否されていた。ブランケットの
  メソッドの参照の受け手は再借用するようにした。self から借用する結果 (`fn get(&mut self) -> &mut Self`、
  `fn id(self) -> Self`) はそのローンを持つので、それを使っている間の `*r = 5;` は E0506 (`part11_review_2`)。

## 5. まだ扱っていないもの

- **リージョンを与える境界に渡さないクロージャ**には、本体のキャプチャのリージョン検査がない。そうしたクロージャ
  の中の `let p: &'static mut usize = &mut self.food;` は見逃すエラー (regions/regions-addr-of-upvar-self.rs)。
  関数のライフタイムを書いたクロージャの本体 (`|| { SomeStruct::<&'a u32>(&c); }`) も同じ。
- **関数として使い、後で呼ぶ、turbofish を書いたタプル構造体** (`let f = SomeStruct::<&'static u32>; f(&c);`):
  クロージャにするので、その引数の型は書かれていない。
- **フィールドがジェネリックなトレイトオブジェクトの構造体** (`struct B<'a, T: 'a>(&'a (dyn A<T> + 'a))`)。
  トレイトオブジェクトの型はトレイトのテキストなので、型パラメータをトレイトオブジェクトを通して推論しない。
  そのため、`v: Box<dyn A<u8>>` での `B(&*v)` は "type annotations needed" になる。rustc はこれを受け入れる。
  ジェネリックな関数の中では、このエラーを報告せず本体を検査しないので、返す `Box::new(B(&*v)) as Box<dyn X>` は
  見逃す E0515 (regions/regions-close-object-into-object-*.rs)。
- **型が impl のライフタイムを名指しする定数** (`impl<'a> Foo<'a> { const C: &'a u32 }`): `&'static u32` として
  返す `<Foo<'a>>::C` は見逃すエラー (nll/user-annotations/constant-in-expr-*.rs)。
- **数の場所で呼ぶブランケット impl の `&mut self` のメソッド** (`impl<T> Fake for T` での `n.use_mut()`) は、
  main と同じく "expected `&mut u8`, found `&u8`"。数はコピーで渡す。
- **大文字の名前の関数** (`fn AddFlags(..)`) はコンストラクタとみなすので、文の後まで借用するその結果は見逃す
  E0716 (borrowck/rvalue-borrow-scope-error.rs)。
- **文の終わりで drop するブロックの値** (`{ ..; D("other").next(&_t1) };`) は、そこでローンを使わない
  (nll/issue-54382-use-span-of-tail-of-block.rs)。
- **zustc がもう出さないエラーでだけ通っていたテストが 2 つある:**
  - derives/derive-assoc-type-not-impl.rs は、`Bar::<NotClone> { x: 1 }.clone()` で "cannot find struct" だった。
    derive した `Clone` が `T` に付ける境界は検査しない。
  - suggestions/issue-97704.rs は、`async { Ok::<_, i32>(()) }` で "cannot infer the return type of this closure"
    だった。今は型を推論し、future に適用した `?` は検査しない。
- **その 10 から:** プログラムの `Drop` impl を持つ型で、クロージャが値で持ち、本体が `Copy` の部分だけを使うもの。
  [その 10](2026-11-22-07-region-check-10.md) の 5 節を参照。
