# リージョン (ライフタイム) 検査、その 37: ヘッダを通した impl の where 節、参照で渡すクロージャ、`mut rest @ ..` (issue #171)

日付: 2026-11-25

その 36 ([2026-11-25-08](2026-11-25-08-region-check-36.md)) は #182 でマージした。この段階は、#182 のレビューが残した
ものと、#171 のさらに一部を取る:

- impl のメソッドの where 節の、impl のヘッダのトレイトの引数を通した、トレイトのものとの比較 (E0276);
- トレイトのシグネチャが型パラメータについて含意する `'static`。その型の構造による;
- `Fn` / `FnMut` を求めるところに参照で渡すクロージャ (E0525) と、キャプチャのフィールドを外にムーブする move
  クロージャ;
- デフォルトの束縛モードが参照によるところの `mut rest @ ..`。

## 1. 加えたもの

- **ヘッダのトレイトの引数を通した impl の where 節。**
  - `trait Master<'a, T, U>` の `fn foo() where T: 'a` に対する、`impl<'a, U, V> Master<'a, U, V> for ()` の `fn foo()
    where V: 'a` は、境界での rustc の E0276 である: トレイトの `T: 'a` は impl の `U: 'a` であり、V については何も
    言わない (compare-method/region-unrelated.rs)。`Master<'a, U::Item, U>` での、トレイトの `T: 'a` に対する `where
    U: 'a` (proj-outlives-region.rs) と、何も与えない impl の `where 'a: 'b` (region-extra.rs) もそうである。
  - zustc はメソッド自身の型パラメータの境界だけを比べていた (その 36) ので、これらを受理していた。
  - impl のメソッドの where 節は、いまはそこで成り立つものと突き合わせる: トレイトのパラメータを impl の引数に
    置き換えた、トレイトのメソッドの where 節とトレイトのヘッダの境界、impl のヘッダの境界、そしてそれらが導く
    outlives (`'a: 'b, 'b: 'c` は `'a: 'c` を与える)。ライフタイムより長く生きる型は、その部分が長く生きるものを
    与える (RFC 1214): impl の `[U]: 'a`、`&'b U: 'a`、`Bar<'b, T>: 'a` としてのトレイトの `T: 'a` は、`U: 'a`、
    `'b: 'a`、`T: 'a` を与える (traits/elaborate-type-region.rs、run-pass)。射影のもの (`U::Item: 'a`) は U について
    何も与えない。impl の `Self` はその自分の型である。
  - シグネチャの型が含意するものは、与えられたものとする。型の構造で読む: `x: &'a T` は `T: 'a` を、`&'b &'a u8`
    は `'a: 'b` を含意する; タプルの部分同士は互いについて何も含意しない (`(&'a u8, &'b u8)`)。impl のヘッダの型は
    ここでは何も与えない: rustc 1.97 は `impl<'a, T> Tr<'a> for &'a T` と `impl<'a, T> Tr<'a, &'a T> for ()` の
    `where T: 'a` を E0276 で拒否する。
  - トレイトのメソッドの、それ自身の型パラメータの境界は、成り立つものではない (`fn run<U>() where U: 'a` は impl
    の U について何も言わない)。デフォルトのあるパラメータについて省いたトレイトの引数は、そのデフォルトである
    (`trait Tr<'a, T = ()>` の `Tr<'a>`)。エラーは成り立たない述語の境界に出し、fn の本体に書いた impl はそれを
    書いた行に出す。
- **シグネチャが含意する `'static`。** impl のメソッドの `T: 'static` についてのその 36 の検査は、トレイトの
  シグネチャの型が `'static` と T を名指すところではどこでも飛ばしていたので、`fn f<T>(x: (T, &'static str))` は
  `T: 'static` の E0276 を隠していた (#182 の最後の指摘)。いまは型をその構造で読む: `&'static` の後ろの T、または
  1 つのパスの引数の中で `'static` と並ぶ T (`W<'static, T>`。その定義が T をそれで縛りうる) は、それを含意しうる;
  タプルの部分同士は含意しない。
- **参照で渡すクロージャ。**
  - キャプチャを変更するクロージャ `func` の `requires_fn(&func)` は、クロージャでの rustc の E0525 である: `&F`
    は F が `Fn` のときだけ `Fn` である (closures/fnmut-shared-reference-requires-fn.rs、
    fnmut-shared-reference-suggestion-issue-118843.rs)。zustc は名前で渡すクロージャだけを調べていた。`FnMut` を
    求めるところの `&mut c` は、同じく c が `FnMut` であることを求める。パラメータの型が参照であるところ
    (`_: &F`) では、境界は c 自身の型にかかる: `fn inspect<F: FnMut()>(_: &F)` の `inspect(&c)` は受理する。
  - キャプチャしたもののフィールドを外にムーブする move クロージャ (`move || { let t = s.1; }`) は "moving a
    captured value out of a closure is not supported" だった。いまは、キャプチャ全体を外にムーブするときと同じく、
    クロージャの環境のそのフィールドを空にするので、残りのドロップはそれを何も解放しない。rustc はこれを受理する。
- **参照を通した `mut rest @ ..`。** エディション 2024 より前では、デフォルトの束縛モードが参照によるところで、
  `mut` は値で束縛するので、`let [mut b @ ..] = &[1u8];` は b を `[u8; 1]` にする。zustc はそれを `&[u8]` として
  束縛し、`let _: [u8; 1] = b;` は偽の "mismatched types" だった (#182 のレビュー)。`Copy` の要素の配列について、
  間の要素をそれ自身の配列にコピーする。

## 4. まだ扱わないもの

- **キャプチャのフィールドをムーブする move でないクロージャ** (`|| { let t = s.1; }`): エディション 2021 は
  `s.1` を値でキャプチャし、そのクロージャは `FnOnce` である。zustc はキャプチャを参照で取る。ムーブがそれに依る
  フィールドの型が、キャプチャを決めるところではわからないからである。そしてムーブで "moving a captured value out
  of a closure is not supported" を出す。クロージャを 1 度呼ぶところではそれは偽のエラーであり (main でも)、`Fn`
  を求めるところでは違うエラーである (クロージャでの rustc の E0525、
  closures/2229_closure_analysis/diagnostics/closure-origin-tuple-diagnostics.rs)。
- **const のブロックを引数に持つ impl のヘッダ** (`impl<'a, U> Tr<'a, { b'>' as usize }, U> for W<U>`): ヘッダは
  最初の `{` までを読むので、そのメソッドの where 節は比べない (E0276 を見逃す)。
