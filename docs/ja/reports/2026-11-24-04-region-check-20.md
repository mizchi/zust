# リージョン (ライフタイム) 検査、その 20: 境界が束縛する領域に対するクロージャ、box にしたクロージャのシグネチャ、キャプチャしたローカルの領域、クロージャの呼び出しが借用するもの (issue #1)

日付: 2026-11-24

その 19 ([2026-11-24-01](2026-11-24-01-region-check-19.md)) は #109 でマージした。この段階はクロージャについてである:

- 境界の結果が、境界の束縛する領域に結びつくところで、キャプチャしたものを返すクロージャ;
- `Box<dyn Fn(..)>` が期待されるところで box にするクロージャ。トレイトオブジェクトがそのシグネチャである;
- キャプチャしたローカルの領域。クロージャの外のものである;
- 境界が領域を束縛するところ、または関数ポインタ型がそうするところで、関数のライフタイムの 1 つで注釈したパラメータ;
- パラメータがすべての呼び出しで 1 つの領域を持つクロージャの呼び出しが借用するもの。クロージャがそれを持つ。

## 1. 加えたもの

- **境界の結果が束縛された領域に結びつくところで、キャプチャしたものを返すクロージャ。** `F: FnMut(&isize) -> &isize`
  と `x: &'x isize` の `take(|_z| x)` を受け入れていた (rustc では「lifetime may not live long enough」)。結果の領域は
  パラメータのもので、境界がそれを束縛するので、`'x` はどの領域よりも長生きしなければならない。境界の束縛する領域より
  長生きしなければならない関数の領域は、報告していなかった: 境界の中の呼び先のライフタイムが、それらを結びつけるかも
  しれないからである。それが成り立つのは、シグネチャが外からの領域 (closures/explicit-closure-lifetime-issue-87290.rs
  の `impl FnOnce(&mut &mut &'a i32)` のような、呼び先のライフタイム) を持つときだけである。持たなければエラーである。
- **`Box<dyn Fn(..)>` が期待されるところで box にするクロージャは、トレイトオブジェクトをシグネチャとする。**
  `drop::<Box<dyn for<'z> FnMut(&'z isize) -> &'z isize>>(Box::new(|z| x))` を受け入れていた。その型で注釈した `let` の
  同じものもそうだった: box の中身がトレイトオブジェクトのとき、`Box::new` は引数に期待する型を与えなかったので、
  クロージャには検査に使う境界がなかった。今はクロージャの引数がトレイトオブジェクトを取る。`&dyn Fn(..)` が期待される
  ところの `&|x| ..` と同じである (lifetimes/closure-lifetime-bounds-10291.rs)。
- **キャプチャしたローカルの領域は、クロージャの外のものである。** パラメータ z が、境界か注釈の束縛する `&isize` で
  ある クロージャで、`ay = &y` をキャプチャしたローカルとして `ay = z` を受け入れていた (rustc では E0521「borrowed data
  escapes outside of closure」)。関数で普遍でないキャプチャの領域は、クロージャの本体では新しい変数だった。今はそれらは
  クロージャの外からの領域で、シグネチャの束縛する領域はそこへ流れ込んではならない (regions/regions-nested-fns.rs)。
- **境界が領域を束縛するところで、関数のライフタイムの 1 つで注釈したパラメータ。** `F: FnOnce(&u32)` の
  `closure_expecting_bound(|x: &'x u32| ..)` を受け入れていた (rustc では「lifetime may not live long enough」): 境界の
  コードを取り、注釈のライフタイムは脇に置いていた。境界の領域がそれの束縛するもので、注釈が関数のライフタイムの 1 つか
  `'static` を指すとき、そのライフタイムはそこのどの領域でもなければならない: それ自身のプレースホルダーと両向きに
  結びつける。こういう注釈は、関数のリージョン検査が止まっていれば始める (ライフタイムを指さない関数の
  `take(|_x: &'static u32| {})`) (closures/closure-expected-type/expect-region-supply-region-2.rs)。
- **関数ポインタ型が領域を束縛するところでも同じ。** `let _: fn(&()) = |_: &'a ()| {};` を受け入れていた (rustc では
  「lifetime may not live long enough」、nll/user-annotations/issue-54124.rs)。`let g: fn(&u32) = |_: &'static u32| {};`
  もそうだった。注釈の関数ポインタ型が、クロージャのパラメータのコードを与える: それが束縛する領域 (そこで省略された
  もの、または `for<'x>`) はプレースホルダーで、境界のときと同じく注釈のライフタイムと結びつける。そういう型の
  パラメータに渡すクロージャも同じように検査する (`fn want(f: fn(&u32))` の `want(|_: &'static u32| {})`)。パラメータの
  コードは呼び先の要約から取り、呼び先がライフタイムを指さなければすべて束縛されたものとする。ライフタイムを指す
  注釈付きのパラメータは、ここでも関数のリージョン検査を始める。
- **パラメータがすべての呼び出しで 1 つの領域を持つクロージャは、呼び出しが借用するものを持つ。**
  `let g = |x| { let _: &u32 = x; };` で `g(&a); a = 2; g(&a);` を受け入れていた (rustc では E0506)。その前に作った
  `let f = |_| {};` で、ループの中の `f(&a)` もそうだった (E0597)。何も期待されないところで作り、パラメータが参照である
  クロージャは、そこにすべての呼び出しで 1 つの領域を持つ (その 19)。その領域はクロージャの型の中にあり、クロージャを
  使う間ずっと続く。今は、ローカルの名前を通した呼び出しは、そういうパラメータへの引数が借用するものを、そのローカルへ
  流し込む。struct のフィールドの中のクロージャは脇に置く: フィールドの境界がシグネチャを与えるかもしれない
  (`F: Fn(&u32)` の `S { f: |x| .. }`)。

## 4. レビュー

#111 への CodeRabbit のレビューには 1 つの指摘があり、それを示すプログラムに zustc と rustc 1.97 を走らせて確かめた。
当たっていて、直して確かめた (`part20_closure_fnptr_annotated`): 関数ポインタ型が領域を束縛するところで、ライフタイム
パラメータを持たない struct への参照を飛ばしていた。`let _: fn(&S) = |_: &'static S| {};` を受け入れていた (rustc では
「lifetime may not live long enough」)。`fn want<'b>(_f: fn(&S), _y: &'b u32)` の `want(|_: &'static S| {}, &1)` も
そうだった。パス `S` は、struct のライフタイムパラメータの数 (ここでは 0) だけの領域を表す印で書かれ、コードが注釈の
ものと合わなかった。今は、印を除いたコードが型の領域と合うときには印を除く。パラメータの `'static` と同じである。

## 5. まだ扱わないもの

- **ライフタイムを固定する関数ポインタ型の型エイリアスを通して渡す関数アイテム**: `type G = for<'cx> fn(&'cx S) ->
  &'static S;` の `want_G(baz)` (regions/regions-fn-subtyping-return-static-fail.rs)。要約はエイリアスの定義の
  ライフタイムを持たず、関数の要約はそのモジュールのエイリアスを見ない。
- **関数ポインタ型の別々の束縛ライフタイム** (`for<'a, 'b> fn(&'a u32, &'b u32) -> &'a u32`) は、関数アイテムを渡す
  ところで 1 つのプレースホルダーになる: 領域のコードは束縛を持たない (その 19 の第 4 節)。
- **関数で作り、別のクロージャの本体で呼ぶクロージャ** (adt-tuple-struct-calls.rs の
  `annot_reference_named_lifetime_across_closure`)。内側の本体は、外側のクロージャのシグネチャなしで単独に検査する。
- **struct のフィールドを通して、または別のクロージャの本体で呼ぶクロージャの、呼び出しが借用するもの**
  (closures/issue-113087.rs)。持つのは、ローカルの名前で呼ぶクロージャだけである。
- **使われない定数の初期化式** (main の中の `const z: &'static isize = { let p = 3; &p };`、static/issue-18118.rs) と、
  定数の初期化式のブロックの中の関数アイテム (borrowck/borrowck-fn-in-const-c.rs)。定数は使うところで展開して検査する。
- **型がトレイトのライフタイムを指すトレイトの定数** (`<T as Foo<'a>>::C`、`T: Foo<'a>` の `T::C`、
  nll/user-annotations/constant-in-expr-trait-item-2.rs、-3.rs)。何も呼ばないジェネリックな関数は、定数を使うところに
  届かない。
- **ガードの一時値を通して読む `&mut` の暗黙の再借用** (後で使う `let val: &_ = x.borrow().0;`、
  borrowck/issue-36082.rs)。
- **スライスでも `str` でもない型の `Cow<'_, T>`**、関数の中の `use std::option::Option::Some as S;`
  (lifetimes/temporary-lifetime-extension-tuple-ctor.rs)。
- **`let` の初期化式以外で値としてムーブされる `&mut`**: ジェネリックな f の `f(a[0])`、`vec![a[0]]` (E0508)。
- その 17 から:
  - 1 か所に書いたプログラムの 2 つの deref (`(&mut **w).bump()`);
  - ある型への impl があいまいなトレイト (borrowck/mut-borrow-in-loop-2.rs)。
- その 16 から:
  - ジェネリックな関数の `dyn Tr<T>`;
  - `&*vec![1].iter().next().unwrap()`;
  - opaque 型のメンバー制約 (E0700);
  - タプルの推論の中の `&mut`;
  - フィールドごとの領域;
  - `static` クロージャの借用検査。
