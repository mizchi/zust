# Region (lifetime) checking, part 33: `ref mut` through a `&`, moves out of what a reference gives, a guard's bindings, `Box` and `Pin` receivers, a closure returned from a local, borrows held in returned aggregates (issue #1)

Date: 2026-11-25

Part 32 ([2026-11-25-04](2026-11-25-04-region-check-32.md)) was merged with #159. This step adds:

- E0596 for a `ref mut` binding where the default binding mode is by shared reference;
- E0507 for a move out of what an overloaded deref or a reference that is no place gives;
- the checks of a match guard's view of the arm's bindings by shared reference (E0507 / E0594 / E0596);
- the move of a `self: Box<Self>` or `self: Pin<&mut Self>` receiver;
- rustc's E0597 for a closure held in a local and returned as an `impl Trait`;
- the borrows a returned tuple, array or struct literal holds;
- the two minor findings of #159's third review.

## 1. What was added

- **`ref mut` where the default binding mode is by shared reference.**
  - Take `if let Some(ref mut v) = o` with `o: &Option<i32>`, or `(Some(Foo::Bar(ref mut val)), _)` against
    `(&arr.get(0), 0)`. The default binding mode is by shared reference there, so `ref mut` borrows mutably through
    the `&`. rustc reports E0596 at the binding; edition 2024 also rejects the `ref mut` written there.
  - zustc accepted these. They are E0596 at the binding's arm now (pattern/issue-52240.rs).
- **Moves out of what an overloaded deref gives.**
  - `if let Some(mut val) = wrap.field` with `wrap: Wrap<Struct>` and `Wrap: Deref` moves `field` out of the
    reference `deref` returns: rustc's E0507 at the scrutinee.
  - zustc checked a field reached through a deref only where the binding needs a drop, so `NonCopy(())` was
    accepted. It is E0507 now for any binding by value of what is not Copy, also deeper (`w.a.b`)
    (borrowck/deref-field-pattern-ref-suggestion-issue-146995.rs). The message names the type with its arguments
    (`Wrap<Struct>`), as rustc does.
- **Moves out of a reference that is no place.** `*&x`, `*v.first().unwrap()` and `*id(&s)` of a value that is not
  Copy are E0507 ("cannot move out of a shared reference"), as in rustc. zustc accepted them: the reference is a
  temporary, which the borrow check had no place for (sync/atomic-types-not-copyable.rs).
- **A match guard's view of the arm's bindings.**
  - A guard sees the arm's bindings by shared reference. Moving one out in the guard (`A(v) if { drop(v); false }`)
    is rustc's E0507 ("cannot move out of `v` in pattern guard"); assigning to one (`Some(mut y) if { y += 1; .. }`)
    is E0594; borrowing one mutably (`v.push(1)`, also through a `&mut` binding: `Some(ref mut y) if let Some(ref mut
    z) = *y`) is E0596.
  - zustc checked these only inside closures in the guard. They are checked at each access now. A closure's
    captures are left to the closure checks, which see what its body does with them.
  - rfcs/rfc-0107-bind-by-move-pattern-guards/rfc-reject-double-move-across-arms.rs and
    rfcs/rfc-2294-if-let-guard/guard-mutability-1.rs, -2.rs pass.
- **A temporary scrutinee with `ref` bindings under a `&` pattern.** Part 31 gave a temporary scrutinee a place of its
  own where a `&` pattern binds by value, but not where any pattern binds by `ref`. A `ref` under a `&` pattern
  borrows what a reference in the temporary points to, so it no longer stops that:
  `match (a, b) { (None, &c) => .., (&Some(ref c), _) => .. }` is E0507 at the scrutinee
  (suggestions/option-content-move-from-tuple-match.rs).
- **`Box` and `Pin` receivers.** A method of `self: Box<Self>` or `self: Pin<&mut Self>` moves its receiver: a second
  call is rustc's E0382. zustc took the receiver for borrowed (moves/pin-mut-reborrow.rs).
- **A closure held in a local and returned as an `impl Trait`.**
  - For `let mut c = || { p.x += 5; println!("{:?}", p) }; c` returned as `impl FnMut()`, rustc reports E0597 at the
    use in the closure of the place it captures (`p` in `println!`), not E0373 at the closure. A closure returned
    itself, or in a `Box<dyn ..>`, stays E0373.
  - zustc reports that E0597 now, at the first use of the captured place itself (a part's stronger use, `p.x += 5`,
    still decides how it is captured). The arguments of a macro in a closure's body are read at their positions in
    the source for this (closures/2229_closure_analysis/diagnostics/borrowck/borrowck-4.rs).
- **Borrows held in returned aggregates.**
  - `fn f(x: &str) -> (&str, &&str) { (x, &x) }` is rustc's E0515. The region check reports it where the signature
    has two regions; with one, the borrow check had to, and it did not follow a tuple, an array or a struct literal.
    It does now.
  - A part `&x` of `x` a reference, where the aggregate's type wants no `&&` (`W { slice: &self }` with
    `self: &[T]`), is a deref coercion that copies `*x`'s reference, not a borrow of `x`: it is followed as `x`
    (traits/self-without-lifetime-constraint.rs).
- **#159's third review**, two minor findings carried here (each checked with rustc 1.97):
  - a variant written through a type alias of the enum (`type A = E;`, `A::V`) captures nothing, as `E::V` does;
  - a guard's write to another field of a union that the pattern tests is E0510, as one to the field itself is.
- Fields of an enum's variant are shown as `y.0`, without the variant, as rustc writes them.

## 4. Review

CodeRabbit made four inline findings on #160. Each was checked with zustc and rustc 1.97, and against main:

- **A struct update's base** (major): `W { r: x, ..s }` returned the loans of all of s, also where the literal takes
  only `n: usize` from s. That is a false E0515, which main does not give. The base is now followed only where the
  fields it gives may hold a reference. Where a written field may hold one too, the base's loan may be in that field's
  region only, so the base is followed only for a struct of one lifetime, with no type parameter, where a field the
  base gives has that lifetime:
  - `V { r: x, ..s }` of `V<'a>` is E0515, as in rustc;
  - of `V<'a, 'b>`, or with only a `&'static str` given, it is accepted, as in rustc.
- **A closure in a guard that borrows an arm's binding mutably** (major): `Some(mut y) if { let mut c = || { y += 1;
  }; c(); true }` was accepted, on main too. A capture's mutable borrow of a binding is now E0596 at the closure,
  rustc's position. The capture's other accesses are still not checked there; the guard's move and `ref mut` checks
  see those.
- **Nested guards** (minor): a guard inside a guard's `match` replaced the outer arm's bindings with its own. The
  guards' bindings are now a stack, so `y += 1` in the inner guard is E0594, as in rustc. main accepted it too.
- **A unit struct's name in a `let`** (minor): `let Unit = *w;` through a Deref was E0507, and `let Unit = u;` moved
  u (E0382 at a later use). main has both errors. A unit struct's name of the value's type is now a pattern that
  binds and moves nothing, and rustc accepts both.

Tests: `part33_review_of_160` in tests/regionck.rs.

## 5. Not covered yet

- **Moves out of a static's or a const's initializer** (`static Y: usize = get(*&X);`,
  borrowck/move-in-static-initializer-issue-38520.rs): the borrow check does not run on initializers.
- **A closure whose parameter's type is inferred from one call and used in a loop** (closures/issue-113087.rs): the
  parameter's region is one region, which zustc takes as higher-ranked.
- **`self: Box<Self>` of a zero-sized type**: the receiver's move is not recorded.
- **Spans of `macro_rules!` bodies**: 130 compile-fail tests expect all their errors in a macro's body (66 of them
  wrong-line). zustc reports such errors at the macro's call.
- **The fields of a struct update's base, one by one**: where the literal writes a field that may hold a reference,
  the base's loans are not known by field. For a struct of several lifetimes, or with type parameters, the base is
  then not followed, and a loan the result keeps through it is not reported.
- From part 32 and before: see [part 32](2026-11-25-04-region-check-32.md), section 5.
