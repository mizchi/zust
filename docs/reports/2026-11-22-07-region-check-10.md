# Region (lifetime) checking, part 10: closures' captures, guards, patterns, implicit reborrows, and `'static` instances (issue #1)

Date: 2026-11-22

Part 9 ([2026-11-22-06](2026-11-22-06-region-check-9.md)) was merged with #51. This step takes more of the cases
tests/ui showed accepted. It also fixes three ways zustc accepted programs whose generated code drops a value twice:
a closure that holds a capture by value, a move out of what an overloaded `Deref` gives, and (from part 9's review) a
named `move` closure taken for `FnOnce`.

## 1. What was added

### Borrow check

- **A closure that holds a capture by value, of a variable that needs dropping.** This is a `move` closure, or one
  whose body moves the variable.
  - The generated code copies the whole variable into the closure. The borrow check moved only the parts the body
    uses, as rustc captures them, so a part used after the closure was dropped twice. This was found on main:
    `move || p.n` then `drop(p.s)` with `p.s: String` frees `p.s` twice.
  - When the body uses only `Copy` parts and the rest can be emptied, the closure's copy is emptied of the parts that
    need dropping. The rest can be emptied when the type has no `Drop` impl of the program's in it. The variable is
    then not moved, and it is dropped where it is, as in rustc. tests/acg/closure_copy_parts.rs shows this with `Rc`
    counts, which are the same as rustc's.
  - When the body uses a part that is not `Copy`, the whole variable is moved. A part used after the closure is then
    E0382, which rustc accepts.
  - A variable that needs no dropping is followed by its parts, as before.
- **A `&mut` captured by value is moved.** That happens in a `move` closure, or through a `let` in the body
  (`|| { let bar = b; }`). The borrow check counts a `&mut` as `Copy` because passing one reborrows it, but such a
  capture is not reborrowed. A `&mut` passed as an argument (`drop::<&mut U>(x)`) may be reborrowed, so that case is
  not followed.
- **E0713 through an implicit reborrow.** A `&mut` field of a `Drop` value, passed where a `&mut` is expected, is
  reborrowed: `members.push(child.raw)` is `members.push(&mut *child.raw)`.
  - Such a loan stored where it outlives the value is E0713. This holds for a local (nll/issue-53773.rs, in a loop),
    and for a parameter, which is dropped when the function returns.
  - The expected type may be a type parameter the call already knows (`Vec<&mut T>::push`).
  - In a fn of one region, the region check knows how long the loan lives, so it is turned on for this case.
- **E0713 when a `Drop` value is dropped at its scope's end.** This covers a borrow through a `&mut` field of the
  value that is still in use after it (`r = &mut *s.0;` in a block, then `*r` after it). Before, only a returned
  borrow was E0713.
- **`break` and `continue` end the scopes they leave.** The locals of the scopes a jump leaves go out of scope at the
  jump, as they do at the scopes' ends. `loop { let x = 1; r = &x; break; }` with r used after is E0597, and so is the
  same through `continue`.
- **Match guards:**
  - After a guard fails, the next arm tests the scrutinee again. So what the guard moved out of it is used (E0382, at
    the match: nll/issue-27282-move-match-input-into-guard.rs).
  - A binding of all of the scrutinee by value (`x => x`) reads all of it. That error is at the arm
    (borrowck/issue-31287-drop-in-guard.rs).
  - A closure in a guard that moves one of the arm's bindings out is E0507. What it moves goes by the binding's type.
- **Patterns:**
  - A struct pattern follows its parts by name, as a tuple struct's did. `let S { x: ax, .. } = a;` moves `a.x`, so
    it is E0505 while a is borrowed (borrowck/borrowck-move-subcomponent.rs).
  - A pattern of a struct that is not an enum does not read the struct itself, only what its parts' patterns test.
  - A reference bound in an arm flows out of the match (`let a = match y { Y(ref mut a, _) => a };`). What a local
    holds is now kept when it goes out of scope, so a value read from it before then flows on. A local that is not
    live holds no live loan. A second `ref mut` of `y.0` is E0499, and one of `y.1` is fine
    (borrowck/borrowck-anon-fields-*.rs). A `ref` binding's loan is reported at its arm.
- **An assignment drops the old value.** A `Drop` that may see what the value borrows uses those loans there, as it
  does at the end of the value's scope. `base = false;` before `w = W(&mut base);` in a loop is E0506
  (borrowck/drop-in-loop.rs).
- **E0507 for a move out of what an overloaded `Deref` gives.** Examples are `x.field` with x an `Rc<Bar>`
  (nll/issue-52086.rs), a field reached through a user's `Deref`, and `*w`. zustc accepted these and copied the value
  out, so it was dropped twice. A `Box` is not affected.
- **`self` is a mutable binding only as `mut self`.** `(&mut self).bar()` in a method taking `self`, `&self` or
  `&mut self` is E0596.
- **A closure that binds part of a capture by `ref mut`** (`let (ref mut x, _) = p;`) borrows it mutably. Such a
  closure is `FnMut` and not `Copy`, so a second move of it is E0382.

### Regions

- **A copy of a type whose `Copy` impl is for its `'static` instance** (`impl Copy for Foo<'static> {}`). Each copy
  proves `Foo<'_>: Copy`, so what the copied value borrows must be `'static` (E0597 at the borrow).
- **An associated const of an impl for its type's `'static` instance** (`impl A<'static> { const IC: i32 = 10; }`).
  `A::<'a>::IC` requires `'a` to be `'static` ("lifetime may not live long enough"). This also holds for a trait
  impl's const, and in a range pattern.
- **A call through a type parameter's `Fn` bound** relates its arguments' regions to the bound's.
- **A type alias for a `Box`, written without its lifetimes** (`Box<B>` with `type B<'a> = Box<&'a isize>`). Each of
  its regions is elided. Before, the alias's marker was taken for the inner `Box`'s own, so the parameter's regions
  were not followed.

### Prelude

- `MutexGuard<T>` implements `Debug` and `Display` when T does.

## 5. Not covered yet

- **A type with a `Drop` impl of the program's, held by a closure by value, of which the body uses only `Copy`
  parts.** The closure still holds all of the value. The generated code marks the variable moved, while the borrow
  check lets the rest be used: `let c = move || x.id; drop(x);` drops x twice. rustc's captures of parts need the
  closure to hold the parts themselves, which the generated code does not do yet.
- **A part that is not `Copy`, used by a closure that holds its variable by value,** moves all of the variable. The
  rest used after the closure is E0382, which rustc accepts.
- **A `&mut` that a closure passes as an argument** (`drop(r)` in a closure for an `FnMut` bound) is not followed as
  a move, as it may be reborrowed.
- **From part 9:** where-clauses on types that are not type parameters, the other errors of items in fn bodies, a
  local named in uppercase, E0582 and projections, format arguments and impl bounds, and `*ptr = ..` in a guard of
  `match *ptr` (E0506 in rustc). See [part 9](2026-11-22-06-region-check-9.md), section 6.
- **tests/driver2.rs and `probe/stdin_read`:** this still fails sometimes when run in the background (see part 9).
