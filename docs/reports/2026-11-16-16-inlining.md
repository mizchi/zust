# Inlining small functions (driver2 `-O`)

Date: 2026-11-16

- minclif has no IR and turns instructions into machine code immediately, so inlining is done at the syntax tree level (`src/acg/p9_inline.rs`).
  Once the call's arguments have been built in ABI form (the copied address for aggregates passed by value, the destination for sret), instead of calling,
  the callee's body is code-generated into the same function. The body's parameters are bound to those values, and `return` / `?` / the tail value become
  a jump to the continuation block (checked by `emit_return`). The callee's type inference, scope and drop state are swapped in and restored afterwards
- Functions that are inlined: those whose body syntax tree is small (up to 1600 characters as a Debug string), that contain no closures, macros or nested items,
  and that are not special bodies (drop glue, etc.) or unwrap / expect that report the caller location. Both prelude and user functions (`Vec::len` /
  `Option::is_some` / `Parser::tok`, etc., about 300). Inside an inlined body, at most one more level; at most 400 times per function
- A caller that may inline user functions puts the callee item's hash and lines into its cache key. Panic locations are
  based on the callee's lines (the same location as rustc -O). Functions from dependency crates are not inlined (their bodies are not part of the interface
  hash, so if they change, the users would not be rebuilt)
- The callee's type inference does not depend on the caller, so it runs only once per instance (reused within the process)
- Functions called only from inlined bodies are not reachable from the caller's names: non-generic functions that the relocations of compiled machine code point to
  are also compiled (without this, they were undefined at link time)
- Along with this, minclif got a peephole optimization that skips instructions re-reading a value that was just written (`rax_holds`: if the previous instruction is
  "write rax to v's slot", do not read v. Cleared at the start of a block)
- `tests/driver2_inline.rs`: builds probe / examples / acg with and without `-O`, and checks that output, stderr and exit code are the same
- Effect (time for the self-hosted compiler to compile itself; each compared doing the same work with `ZUSTC_NO_INLINE=1`):
  no inlining 20.85 seconds → inlining 19.76 seconds → plus skipping re-reads 18.32 seconds (12% faster). Inlining makes the generated code 27% larger, and
  `-O` compilation about 20% slower (after reusing type inference). minclif places every value on the stack, so even when calls are
  removed, value loads and stores remain and the effect is small. Large speedups need register allocation
