# Building small real-world crates (`cratebench/`)

Date: 2026-11-16

The sources of small crates from crates.io are placed as-is in `cratebench/vendor/` (licenses included), and built as a workspace together with an app that uses them
(`cratebench/apps/<name>/main.rs`). `python3 cratebench/run.py [names..]` compares with
rustc (the lib as an rlib with `--extern`): whether the output is the same as rustc -O, build time (cold / noop / one edit in the app),
run time and size. The targets are in `cratebench/crates.txt` (name, edition, features).

Added:
- Evaluation of `#[cfg(..)]` / `#[cfg_attr(..)]` / `cfg!(..)` (`crates/syntax/src/cfg.rs`. Features come from the workspace's `features=a,b`
  or `--features=`. Values for x86-64 Linux; `debug_assertions` is true unless -O). `extern crate x;` is removed
- Macro calls in item position are also expanded inside `mod` / `impl` / `trait`. `$x:expr` stops at the end of an expression (`$($len:expr)+`)
- Constant expressions: associated consts in impls (`i128::MAX_STR_LEN`), integer methods such as `u128::MAX.ilog10()`. `const _: () = ..;` is skipped
- prelude: `chunks_exact` (`remainder`), `Read` / `BufRead` (implementations for `&[u8]`), `ExactSizeIterator`, `slice::Iter::len`
- Methods and bounds of `impl Tr for &[u8]`, built-in `AsRef<str>` / `AsRef<[T]>` (the target of `as_ref()` comes from the expected type or the function's bounds),
  `FromIterator` bounds, closures inside blanket impls, `&mut [u8; N] as &mut [u8]`, `&u8 >> 4`
- `?` inside closures: the error type of the returned Result is taken from the `?`
- When impls with the same name are lined up per array length (`impl FromHex for [u8; 1]` .. `[u8; 4096]`), the one whose self type matches is chosen
- A type alias name that starts with a lowercase letter because of the crate prefix (`fnv__FnvHashMap`) is no longer skipped as a module
- Bugs fixed: the `&&str` → `&str` deref coercion loaded a fat pointer (corrupting the value). For a let without annotation where
  the type from type inference differs from the actual type, a coercion is tried, and if that fails the actual type is used

Builds are 2 to 4 times faster than rustc, and edit builds are 5 to 10 times faster. Execution is slower than rustc -O (adler2 was 40 times slower).

What we fixed after looking at adler2's inner loop (`+=` on `U32X4([u32; 4])` and `chunks_exact`) (-O run time 478 → 114 ms, fnv 137 → 112 ms):
- SROA for the Cranelift path too: with the same test as minclif (`minclif::sroa`: slots whose address is used only by load / store),
  each (offset, type) of a slot becomes a Cranelift Variable (Cranelift does not turn stack slots into SSA).
  `ZUSTC_CLIF_NO_SROA=1` turns it off
- A variable holding a slot address (an inlined `&mut self`) is also treated as that address if all its definitions are the same address
- Copies of small scalar arrays (up to 16 elements) and `[0; N]` initialization read and write at the element width (with 8 bytes at a time the widths do not match and they cannot become variables)
- The inlining size is measured by the number of source tokens (up to 110) instead of the length of the syntax tree's Debug output (Debug is inflated by positions and similar;
  a 4-statement `add_assign` came to 1565 characters). `ChunksExact::next` is also inlined

Remaining (about 10 times rustc -O): the address really does escape in `a_vec.0.iter()`, copies of enums (`Option<&[u8]>`) go 8 bytes at a time,
and rustc uses SIMD.
itoa also builds (below). either is not supported (`Pin` / `Future` / the io traits / `Error` / `fmt::Binary`, etc.).

Added for itoa (-O run time 440 → 73 ms; rustc -O is 32 ms):
- Integer consts are folded at the use site (`u8::MAX.ilog10() as usize + 1` was computed in u128 at every use: 74% of the run time).
  Evaluation uses i128 and does not model intermediate truncation, so expressions containing `!` and those whose result is outside the type's range are computed at run time
- `999.try_into().expect(..)` (an integer literal that fits in the type) is a constant
- Closure bodies are inlined too (such as `(self.f)(x)` inside `Map::next`. Captures are bound as fields of `__env`.
  `ZUSTC_NO_INLINE_CLOSURE=1` turns it off). Closures from dependency crates are not inlined (the same as other functions)
- prelude: `MaybeUninit<T>` (uninit fills with 0), `hint::unreachable_unchecked`. Built-ins: `mem::zeroed`, integer
  `ilog2` / `ilog10` / `unsigned_abs`, `get_unchecked(_mut)` (turned into indexing), `try_into` from a slice → `&mut [T; N]`
  (when the target is not known from type inference, it comes from the expected type of `.unwrap()`)
- Constants: `<u64 as Integer>::MAX_STR_LEN` (associated consts via qualified paths), `Self::C` inside impls on primitive types,
  expressions as const generic arguments (`enc::<{ u128::MAX_STR_LEN - 16 }>`), `*b"..."` in statics
- The name collision avoidance when flattening modules also renamed associated type definitions inside impls (`type Buffer = ..`) (when there was
  a `struct Buffer` with the same name at the top level)
- When `const _` was skipped, the index of the loop that assigns const types got out of step

Added for rustc-hash and cfg-if:
- `#[cfg]` inside macro call arguments and macro_rules! is not evaluated (it was removing cfg_if!'s `if #[cfg(..)] { .. }`).
  Instead it is evaluated on each round of macro expansion (`#[cfg(p)] $crate::cfg_if! { .. }` before expanding its contents). Features are per crate
- No space is inserted after a Joint punctuation captured in `$t:tt` (the `-` of `->`) (it was becoming `- >`)
- prelude: `BuildHasher` (`hash_one`), `split_first_chunk::<N>()` / `first_chunk` (passing a turbofish to a prelude function)
- Hash for `[T]` writes a sequence of integers with one `write`, like std's `hash_slice` (so FxHasher values match std)
- `<<` inside a type (`Either<<&L as IntoIterator>::IntoIter, ..>`) is `<` plus the `<` of a qualified path
