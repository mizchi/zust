# Region (lifetime) checking, part 15: slice patterns, closures' whole-variable captures, `copied` iterators, edition 2024 block tails, `unused_mut`, and GAT parameters (issue #1)

Date: 2026-11-23

Part 14 ([2026-11-23-02](2026-11-23-02-region-check-14.md)) was merged with #69. This step makes a slice's pattern
elements places of their own, captures whole variables in closures before edition 2021, keeps an iterator's borrow in
its `copied` / `cloned` adapter, ends a block's tail temporaries with the block in edition 2024, adds the
`unused_mut` lint, and checks a generic associated type's parameters and the lifetimes written in `impl` / `dyn`
types and where clauses. It also fixes a call of a fn named like a struct, which was compiled as the struct's
constructor.

## 1. What was added

### Borrow check

- **A slice's pattern elements are places.** `if let [ref first, ref second, ..] = *s { if let [_, ref mut second2,
  ..] = *s { .. } }` with `s: &mut [i32]` was accepted (borrowck/borrowck-slice-pattern-element-loan-slice.rs, E0502).
  The elements of a slice (not an array) had no place, so no loan. They are now counted from the pattern's ends, with
  the least length the pattern needs, as rustc's MIR does, and they overlap as in rustc's `place_projection_conflict`:
  - the b-th element from the start and the e-th from the end may be one when b + e reaches the least length both
    patterns need (`[ref a, ..]` and `[.., ref mut b, _, _, _]` may be one element of a slice of 4);
  - a rest `[f..-t]` holds the b-th from the start when b >= f, and the e-th from the end when e > t;
  - two rests may overlap.

  A rest `ref mut t @ ..` took its mutability from the pattern's default binding mode, not from its own `mut`, so it
  was typed `&[T]` (borrowck/borrowck-slice-pattern-element-loan-rpass.rs, a run-pass test, now passes). A slice's rest
  is a place too, so a pattern that moves out of what it borrows (`ref tail @ ..` matched against `&[Foo { string: a },
  ..]`) is reported (borrowck/borrowck-move-out-of-vec-tail.rs).
- **Before edition 2021, a closure captures whole variables.** `self.thing.bar(|| { &self.number; })` borrows `self`
  while the `&mut` of `self.thing` is reserved (nll/issue-51268.rs, E0502). The captured places are now cut to their
  variables in editions 2015 and 2018: a `move` closure that uses `fancy_num.num` moves all of fancy_num, which is E0505
  while it is borrowed (error-codes/E0504.rs). A unique borrow through a `&mut` variable stays `*x`, which needs no `mut x`. In a
  closure's body, a variable the closure holds by reference stays `*x` of its reference (nll/issue-40510-4.rs is still
  accepted).
- **An iterator's `copied` / `cloned` holds the iterator's borrow.** These were taken as `Option<&T>`'s in every case:
  the result held what the receiver's root held, not the borrow. Now:
  - `v.iter().copied()` holds v's borrow, so `v.push(1)` while it lives is E0502;
  - `s.0.iter().copied()` returned as `impl Iterator<Item = u8>` captures s's lifetime (nll/issue-73159-rpit-static.rs,
    E0700);
  - what is taken out of such an iterator (`.next()`, `.collect()`, also through adapters over it) is the copies:
    `names.iter().copied().filter(..).collect::<Vec<&str>>()` does not hold names' borrow. This was a false error on
    main too.

- **Edition 2024: a block's tail temporaries go away at the end of the block.** `let _ = { String::new().as_str() }
  .len();` was accepted (lifetimes/tail-expr-in-nested-expr.rs, E0716). A block's tail (not the function's body) is now
  a statement of its own for its temporaries, which end with the block. A block whose value is a reference into one of
  them is held past their end, so using it at once is E0716 too. In 2021 the temporaries still live to the end of the
  enclosing statement.

### Lints

- **`unused_mut`** under `#![deny(unused_mut)]` (or `unused`, `warnings`): a `let mut` that nothing needs mutable is an
  error at its `let` (nll/issue-61424.rs, nll/capture-mut-ref.rs, lint/unused/unused-mut-warning-captured-var.rs).
  The borrow check marks the `mut` locals that something needs mutable:
  - a `&mut` of what they own, `+=`, or a write of a part;
  - a second assignment of all of it (for `let mut x;`, as the dataflow finds it);
  - a closure that mutates the variable itself (not through the `&mut` it holds);
  - a for loop's `&mut` / `iter_mut`;
  - a method that takes `&mut self` of an array the local owns (`a.swap(0, 1)`: an array's methods are lowered on
    its memory), not through a `&mut` binding (`s.sort()` of `s: &mut [i32]`).

  It is checked only where the crate denies it and no `allow` / `warn` / `expect` of it is written anywhere: lint
  levels below the crate are not followed. Parameters are not checked, as their positions are not kept yet.

### Regions and signatures

- **A generic associated type's parameters named as its trait's or impl's**: a lifetime is E0496, a type parameter
  E0403 (generic-associated-types/shadowing.rs).
- **E0261 in `impl` and `dyn` types, and in a where clause's types**, where the item writes no `for<..>`:
  `Box<dyn X<Y<'a> = &'a ()>>` with no `'a` (generic-associated-types/issue-67510.rs), `impl Iterator<Item =
  Self::Item<'missing>>` (impl-trait/in-trait/missing-lt-outlives-in-rpitit-114274.rs), and `&'missing Self: Add<Self>`,
  reported at the predicate (traits/eval-caching-error-region.rs, which passed already through its other error).

### Code generation

- **A fn named like a braced struct is called, not taken for its constructor.** With `struct AddFlags { .. }` and
  `fn AddFlags(..) -> AddFlags`, `&AddFlags(1)` was promoted to a static as the struct's constructor: the fn was not
  called, so its output and its result were lost, and no temporary was made, so `arg(&AddFlags(1))` kept alive was
  accepted (borrowck/rvalue-borrow-scope-error.rs, E0716). The promotion, the region check's constants and the borrow
  check's temporaries now take such a path for the fn, as the call's lowering does. tests/acg/fn_named_like_struct.rs
  compares the output with rustc's.

### Infrastructure

- **The fake reads' edition flag is of the thread** (`ast_closure::WILD_FAKE_READS`). It was a process-wide flag that
  each analysis set, so two analyses of different editions at once in one process (the tests run in threads) read
  each other's. Part 14 listed this as not covered; the tests of this part, which check edition 2015 and 2018, made it
  happen.

## 4. Review (CodeRabbit, checked against rustc 1.97)

CodeRabbit's first review of #71 had 5 findings. Each was checked by running zustc and rustc on a program that shows
it. Four held, and are fixed and tested (`part15_review`):

- **`for` apart from its `<`.** `Box<dyn for\n<'a> Fn(&'a u8)>` (a line break or spaces between them) was a false
  E0261: the binder was looked for as `for<` or `for <` only. Any spaces or line break before the `<` now count.
- **The lowering's bindings.** `let Foo { value: &n } = Foo::<&'static u32> { value: &X };` under
  `#![deny(unused_mut)]` reported `#sl0`, a binding the lowering makes. Names starting with `#` are not checked.
- **An array's methods that read it.** `let mut a = [1, 2]; a.len();` was not reported (unused_mut in rustc): every
  method of an array counted as needing it `mut`. Only those that take `&mut self` (`swap`, `sort`,
  `copy_from_slice` ..) do.
- **A slice method through a `&mut` binding.** `let mut s: &mut [i32] = &mut a; s.sort();` was not reported: the
  method mutates what s points to, which needs no `mut s`.

The fifth, that a copied iterator held by a local (`let mut it = v.iter().copied(); it.collect()`) returned keeps v's
borrow (a false E0515), did not happen: zustc accepts it, and the program prints what rustc's does.

The second round had one. `let mut a = [0, 1]; a.touch();` with the program's `impl Touch for [i32; 2] { fn
touch(&mut self) }` was said to be a false unused_mut, as the array was only read. That did not happen, but for a worse
reason: the call was a type mismatch (`&mut [i32; 2]` expected, `&[i32; 2]` found), on main too. Such a method now
takes the array `&mut`: a mutable borrow of it, E0596 when it is not `mut`, and a use that needs the `mut`.

## 5. Not covered yet

- **`unused_mut` of parameters** (`fn foo(mut self)`, a closure's `|(mut x, _)|`: lint/unused/lint-unused-mut-self.rs,
  nll/unused-mut-issue-50343.rs): their positions are not kept yet. Lint levels below the crate are not followed
  either: any `allow` of the lint turns it off (lint/unused/lint-unused-mut-variables.rs).
- **E0596 of a local not declared `mut`** is not reported for a for loop's `v.iter_mut()` / `&mut v`, an array's
  mutating slice methods (`a.sort()`, `a.swap(0, 1)`), and `&mut a[..2]` of an array: these are lowered without the
  `&mut` access the check reads. `unused_mut` counts them as needing `mut`.
- **E0700 through an array field's `iter()`** (impl-trait/static-return-lifetime-infered.rs): an array's `iter()`
  records no borrow of it. A local array's `arr.iter()` outside a `for` loop is not supported yet.
- **`let _ = place;` in a closure before edition 2021** captures the variable but makes no loan of it, so
  `x.thing = 1` while the closure lives is accepted (E0506 in rustc).
- **Edition 2024's function body tail** keeps the edition 2021 rule for its temporaries.
- From part 14: E0700 does not follow a local assigned again, and a closure's precise captures are not modeled in the
  region check.
