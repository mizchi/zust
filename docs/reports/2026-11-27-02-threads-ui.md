# rustc's thread tests on OS threads

Date: 2026-11-27

After [report 2026-11-27-01](2026-11-27-01-native-threads.md), some rustc UI tests of threads still failed, in
`tests/ui/threads-sendsync/`, `tests/ui/thread-local/` and `tests/ui/std/`. This report adds what they need. None of
it is specific to one test.

## What changed

### `thread::Builder` (recursive-thread-spawn)

`Builder::new().name(..).stack_size(..).spawn(f)`, as std's. `spawn` gives `io::Result<JoinHandle<T>>`: what
`pthread_create` fails with is an `Err` there (`thread::spawn` panics with it, as before), and so is a size the
attribute refuses. The stack size is rounded
up to whole pages, and raised to 64 KiB at least: glibc refuses one below `PTHREAD_STACK_MIN` (16 KiB), and std
raises a smaller one to that. zustc's floor is higher, as a margin for its own frames. The
name lives in the thread's shared part (`__ThreadInner`): `Thread::name()` gives it, and a panic in that thread
prints `thread '<name>' panicked at ..`, as std's. `thread::spawn` is `__exr_spawn` with no name and 2 MiB.
`Builder::spawn` is checked as `thread::spawn` is (`spawns` in `crates/typeck/src/acg/p2_call.rs`): a capture held
by reference is E0373, and the closure's captures and its value must be Send (E0277), as std's `F: Send + 'static`,
`T: Send + 'static`. A path call (`Builder::spawn(b, f)`) is checked too: its closure is the argument after the
builder (tests/security/send_rc_builder_path.rs). A closure given as a value, not written in the call (a local, a
block `{ move || .. }`, an `if`), is checked by its type once the call's arguments are evaluated
(`check_spawn_value`), for `thread::spawn` too: before, one in a block was not checked at all
(tests/security/send_rc_block_closure_thread.rs, spawn_builder_block_borrow.rs). A program's own `Builder` is not checked so. A thread-local key
that `pthread_key_create` cannot make fails the spawn with its error (`Builder::spawn` gives `Err`; `thread::spawn`
panics, as before).

### A closure is Sync through what it borrows (send-is-not-static-par-for)

A closure's capture held by reference is a raw pointer field of its struct (`*mut T`), and a raw pointer is neither
Send nor Sync, so `|x| *m.lock().unwrap() += x` failed `F: Sync`, though rustc's closure holds a `&Mutex<_>`. The
three places that judge the auto traits (`Program::auto_trait`, the trait solver's `auto_rec`, and acg's
`auto_trait_fails`) now take such a field as the reference it stands for. They find it with `Program::ref_capture`,
from the closure's definition (a capture not moved, in a closure that is not `move`). Either way the closure is
Sync when T is Sync. For Send, the kind of reference matters:

- a capture the body assigns to, through, or borrows mutably (`c = ..`, `v[0] = ..`, `*g += 1`, `&mut c`;
  `ast_closure::mutates_capture`, recorded as `ClosureDef::mutated`) is a `&mut T` (or a unique borrow): Send when T
  is Send, so `|| c = Cell::new(1)` is Send, as rustc's. Not where the body binds the name again anywhere (a `let`,
  a pattern, a nested closure's parameter): an assignment there may be to the other variable, so the capture is
  taken as either kind (tests/security/send_cell_shadowed_capture.rs);
- any other may be either kind, as a `&mut self` method called on it (`v.push(..)`) is not seen without types: Send
  when T is Sync (`&T`) and Send (`&mut T`). A closure that changes a `Vec<Cell<_>>` only through `push` is
  therefore not Send, where rustc's is (TODO.md).

A raw pointer the closure holds by value (`move || unsafe { *p = 1 }`) is still
neither, and a borrowed `Cell` or `Rc` still fails `Sync` and `Send`, as rustc's. acg judges a closure by its
captures alone, not by its type arguments (which name the raw pointers too). `Program::auto_trait` now knows the std
types acg's check knows: a lock's guard and a `StdoutLock` are not Send, a RefCell's guards neither, a `Mutex<T>` is
Sync when T is Send, an `Arc<T>` or `RwLock<T>` when T is Send and Sync. It also tells `&T` from `&mut T`: `&T` is
Send only when T is Sync, so `Mutex<&Cell<i32>>` is not Sync, as rustc's. Before, a closure that borrowed a
`MutexGuard` would have been Send (tests/security/send_mutex_guard_closure.rs). `thread::spawn` does not change: a
borrow there is E0373 first.

### `mpsc`: `recv_timeout`, `into_iter` (mpsc_stress)

- `Receiver::recv_timeout(d)` waits as `recv` does, but on the futex with a timeout (`FUTEX_WAIT`'s relative
  `timespec`, its seconds at most `i64::MAX`, so `Duration::MAX` waits as long as it can) until `CLOCK_MONOTONIC`
  passes the deadline. A failed first read of that clock panics, as std's `Instant::now`; one under the channel's lock
  is taken as the deadline reached, so the wait ends with `Timeout` and lets the lock go. It gives `RecvTimeoutError::Timeout` then, or
  `Disconnected` once no sender is left, as std's (with std's Display texts). Only `recv_timeout` reads the clock,
  so a program that never calls it needs none.
- `Receiver::into_iter()` keeps the receiver in the iterator (`__RecvIntoIter`), so a sender sees the receiver alive
  while the loop runs.

### `thread::park_timeout` (std/park-timeout-wakeup-59020)

As std's: a token that is there is taken at once; otherwise one futex wait with the timeout, then the state goes
back to empty (a token given meanwhile is taken). Like std's, it may return early.

### `sync::Barrier`

std's: a count under a lock and a generation. The thread that makes the count n is the leader
(`BarrierWaitResult::is_leader`). It starts the next generation and wakes the others, which wait on a futex word that
each generation bumps. A program's own `struct Barrier` (mpsc_stress has one) shadows it, as with the other std names.

### thread_local! (tls-init-on-init, tls-try-with)

- An initializer that reaches the same thread_local! again (its `with`) made the value first. std keeps the outer
  initializer's value and drops the inner one after, and so does `with` now: it replaces the slot, then drops the
  old value (`lexer::expand_thread_local`).
- A closure whose body is only `panic!(..)` (or `unreachable!`, `todo!`, `unimplemented!`), and that nothing else
  types, returns `!`. Before, its return type stayed unknown and the call failed (`FOO.try_with(|_| panic!(..))`).
  It is rustc's fallback, which is `!` in every edition since rustc 1.100. A bound on the callee's type parameter is
  checked against `!` where the call resolves: `foo(|| panic!())` with `R: Bar` is E0277, as rustc's
  (never_type/fallback_change/fallback-closure-ret.rs; with `()` it was accepted).

## What was checked

- `tests/threads/builder.rs` (new, both backends, against rustc's output): a named thread and one without a name,
  a small stack, the name in a panic message (stderr), `park_timeout` (one that times out, one with a token, one
  unparked by another thread), `recv_timeout` in time, timed out and disconnected,
  `into_iter` over 4 senders, a `Barrier` of 6 threads over 50 rounds (no thread passes early, one leader per round),
  and the `par_for` of send-is-not-static-par-for.
- The auto traits of closures, against rustc: a borrowed `Cell` or `Rc` is not Sync, a borrowed `Cell` makes the
  closure not Send, a raw pointer moved in is not Send, a borrowed `MutexGuard` or `Ref` is not Send (also with
  `*g += 1`), an assigned `Rc` is not Send, and a borrowed `Mutex` is Send and Sync. A closure that assigns a borrowed
  `Cell` (`c = ..`, `cells[0] = ..`) or takes a `&mut` of it is Send (in tests/threads/builder.rs).
- tests/security (new cases): spawn_builder_borrow.rs (E0373 through `Builder::spawn`), send_rc_builder_thread.rs
  (an `Rc` moved into it, E0277), send_rc_builder_result.rs (an `Rc` it returns), send_rc_builder_path.rs (a path
  call), send_mutex_guard_closure.rs (a borrowed `MutexGuard`, E0277), send_cell_shadowed_capture.rs and
  send_cell_shadowed_let_else.rs (a `Cell` only read, with another `c` assigned inside the closure, in an inner block
  or a `let .. else` block, E0277).
- A stack size whose rounding would overflow (`usize::MAX`) gives `Err`.
- The rustc UI tests (rust_ui.py): 0 regressions, 6 newly passing: threads-sendsync/mpsc_stress.rs,
  recursive-thread-spawn.rs, send-is-not-static-par-for.rs, tls-init-on-init.rs, tls-try-with.rs and
  std/park-timeout-wakeup-59020.rs. In threads-sendsync, 52 of 59 pass now (47 before).
- `cargo test --release --workspace`.

## What is left

The thread tests that still fail need something else:

- std-sync-right-kind-impls: `sync::Weak`, and `net::TcpStream` / `TcpListener` / `UdpSocket`, which zustc lacks.
- send_str_hashmap, send_str_treemap: an integer literal's type, inferred from a later use, in a map's value.
- sync-send-in-std: `to_socket_addrs` (name resolution).
- sync-send-iterators-in-libcore: macros it uses.
- tls-in-global-alloc: `#[global_allocator]`.
- unwind-resource: unwinding.
