# Region (lifetime) checking, part 30: a by-value binding's move at its arm, outlives bounds on types, a trait's own bound for an object's lifetime, `self: Box<Self>` on a temporary (issue #1)

Date: 2026-11-25

Part 29 ([2026-11-25-01](2026-11-25-01-region-check-29.md)) was merged with #155. This step adds:

- the E0382 of a by-value binding's move at its arm, where rustc reports it;
- the outlives relations that an outlives bound on a type implies (`D<'a>: 'b`, `Self: 'b`, `&'a T: 'b`);
- std's `Any` as `trait Any: 'static`, and an elided object lifetime that defaults to the trait's own bound;
- a field read through a type's own `Index` and then its `Deref` (`v[0].f`);
- a `self: Box<Self>` method called on a temporary `Box`.

## 1. What was added

- **A by-value binding's move at its arm.** Take `match a { [_, _, _x] => {} }` and then `match a { [.., _y] => {} }`.
  rustc reports E0382 at `_y`, the second arm's line. zustc reported it at the scrutinee `a`, the line before.
  - A move out of what the scrutinee owns is now at its arm, as a `ref` binding's borrow already was.
  - A move through a reference (`match *x { Some(_s) => {} .. }`) cannot be made. It stays at the scrutinee, where
    rustc reports E0507.
  - A pattern outside a match arm is at its scrutinee as before.
  - borrowck/borrowck-move-out-from-array-match.rs passes now: its ten errors are all on rustc's lines.
- **Outlives bounds on types.** Take `fn f<'a, 'b>(x: D<'a>) -> &'b i32 where D<'a>: 'b { x.0 }`. zustc reported "lifetime
  may not live long enough"; rustc accepts it, as `D<'a>: 'b` implies `'a: 'b` (rustc's outlives components).
  - A bound on a type other than a parameter now gives `'x: 'b` for each lifetime the type names, and `T: 'b` for each
    of the generics' type parameters in it: `D<'a>: 'b`, `E<'a, T>: 'b`, `&'a T: 'b`.
  - `Self: 'b` in an impl's method gives it for the lifetimes of the impl's self type.
  - Not through a projection (`<T as Tr>::X: 'b` says nothing of T) or a trait object's bounds.
  - A caller must meet the bound: returning `f(d)` with `d: D<'x>` as a `&'static i32` is an error, as in rustc.
- **A trait's own bound for an object's lifetime.** std's `Any` is `trait Any: 'static`.
  - `Box<dyn Any + 'a>` in a struct is E0478 now, as for a trait of the program's with a `'static` bound
    (regions/explicit-static-bound-on-trait.rs).
  - An elided object lifetime defaults to the trait's own bound, which it then meets. `&'a dyn MyAny` with
    `trait MyAny: 'static` is `&'a (dyn MyAny + 'static)` and no error; main reported E0478 for it. Only an object
    lifetime written out (`dyn MyAny + 'a`) is checked against the trait's bound now.
- **A field through a type's own `Index` and then its `Deref`.** Take `v[0].f` with `impl<T> Index<usize> for MyVec<T>`
  (`Output = T`), `v: MyVec<MyPtr<Foo>>` and `impl<T> Deref for MyPtr<T>`. zustc gave "no field `f` on type
  `MyPtr<Foo>`".
  - The type an overloaded index is peeked as is now what its `index` returns a reference to, so the field is read
    through the `Deref`.
  - Its borrow is checked: borrowck/borrowck-overloaded-index-and-overloaded-deref.rs is E0506 at rustc's line.
- **`self: Box<Self>` on a temporary `Box`.** `Box::new(S).f()` and `mk().f()` with `fn f(self: Box<Self>)` gave
  "mismatched types: expected `Box<S>`, found `S`" (part 29, section 5). The receiver was passed with the type of
  what the Box points to. It has the Box's type now: run-pass self/explicit-self.rs passes.

## 4. Review

CodeRabbit reviewed #156 at c8f43e9 and made two findings. Both were checked with zustc and rustc 1.97 and fixed:

- **A bound on a type alias.** `ty_parts` read the lifetimes written in a type alias's path. With
  `type Erased<'a> = ();`, `Erased<'a>: 'static` says nothing of `'a`, but it was taken for `'a: 'static`.
  Returning a `&'a i32` as a `&'static i32` was accepted; rustc reports "lifetime may not live long enough".
  - A fn's summary is made from its own item, which does not know which names are aliases. What a bound on a type
    implies of its parts is now kept apart there, with the names of the paths each part is in.
  - The program adds it where none of those names is a type alias. `W<'a>: 'static` of a struct still gives
    `'a: 'static`, and its caller must still meet it.
  - Only a fn's own bounds are read so now. An impl's or a type's bounds keep the mark only, as before this work.
- **An `unsafe fn` with `self: Box<Self>` on a temporary Box.** `Box::new(S).f()` with `unsafe fn f(self: Box<Self>)`
  type-checks now, but outside `unsafe` it was accepted, where rustc reports E0133. That path checks the call now, as
  the others do.
- tests/regionck.rs checks both (`part30_review`).
- Its second review, at b86c086, made four findings:
  - **The region check of a `self: Box<Self>` call.** That call left no tree for its result, as the call on a Box
    local did on main. Returning what `Box::new(S(&x)).get()` borrows of a local `x` was accepted, where rustc
    reports E0515. The call now gives the receiver's tree and keeps its result's: E0515, for a temporary Box and a
    Box local.
  - **A bound on a generic associated type.** `T::A<'a>: 'static` was read as a type made of `'a`, giving
    `'a: 'static`. A path from a type parameter or `Self` is one component now, of which nothing is derived.
  - **A type's own `Index` with several impls** (`Index<usize>` and `Index<&str>`). The peeked type was the first
    impl's. It is none now where there are several. Such an index is "mismatched types" in zustc, as on main.
  - **An inherent `unsafe fn` and a trait's safe method of the same name with `self: Box<Self>`.** The finding said
    the safe one is chosen. rustc 1.97 chooses the inherent one and reports E0133, as zustc does: not changed.
  - tests/regionck.rs checks them (`part30_review`).
- Its third review, at c4e970a, found the same of `Self: 'b`: the lifetimes of the impl's self type were taken
  for parts of it, also where that type is an alias that drops one (`impl<'a> Leak<'a> for Erased<'a>`). They are kept
  apart now too, and the program adds them where the self type names no type alias. tests/regionck.rs checks it.
- Its fourth review, at 14fcb02, found that check too coarse. A name of the self type was taken for a type alias also
  where it is the impl's type parameter that shadows one (`type T = ();` and `impl<'a, T> D<'a, T>`), so `Self: 'b`
  implied nothing of 'a there. rustc accepts it.
  - The impl's header now records, for each lifetime of its self type, the names of the types around it.
  - The program adds `'a: 'b` where none of those is a type alias. A type parameter is never among them, as it has no
    lifetime arguments.
  - So `D<'a, T>` with the alias `T`, `D<'a, Erased<'a>>` and `dyn Tr + 'a` imply `'a: 'b`; `W<Erased<'a>>` does not.
    Each is as in rustc 1.97, and tests/regionck.rs checks them.
