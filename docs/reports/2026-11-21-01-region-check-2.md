# Region (lifetime) checking, part 2: what the first version left out (issue #1)

Date: 2026-11-21

The first version ([2026-11-20-01](2026-11-20-01-region-check.md)) checked a function's body against the universal
regions of its signature. This report covers the work after it was merged: the gaps that report listed, and the ones
the failing tests showed.

## 1. What was added

- **Values the check now follows:**
  - temporaries that constant promotion does not make static (`&(5_i32.reverse_bits())`, `&(n + 1)`, `&[&FOO]`,
    `&Test` with `impl Drop for Test`), and temporaries of a call in a statement
  - `Box::new(x)`, array literals, tuple and tuple struct constructors (`B(a)`), casts
  - closures: what they capture (by value: its regions; by reference: a borrow of the local)
  - calls through trait objects, with `Self` the object; methods of the prelude taking `&self` return a borrow of self
  - type arguments written at a call (`f::<&'a u32>()`)
  - indexed places (`&mut v[..]`); a reborrow through a shared reference lives as long as that reference alone
    (NLL's supporting prefixes)
- **Coercions where values flow:** to a trait object every region of the value outlives the object's; an array to a
  slice; a reference to what it derefs to.
- **Trait object lifetimes:** the bound as written, else the default (the reference around it, the type parameter's one
  bound, else `'static` in signatures; inferred in bodies).
- **Closure bodies:** checked against the signature the bound they are passed to gives them. The regions the bound binds
  are placeholders; the callee's lifetimes, a type parameter's instance (`-> R`) and the closure's environment come from
  outside. An annotated closure with no bound binds its parameters' elided regions, and its result's come from outside.
  Bounds of the prelude are skipped: it writes no lifetimes, and some of std's are not higher-ranked
  (`is_sorted_by_key`).
- **Well-formedness of written types (`crates/syntax/src/wf.rs`):** `&'a T` needs every lifetime in T to outlive `'a`
  (E0491) and every type parameter in it to be declared to (E0309, E0310). It is checked in a fn's bounds and where
  clauses, an impl's associated type values and a struct's `&'static` fields. What another item decides (a trait's
  `: 'a` supertraits, a struct's requirements) is left unchecked.
- **Functions the gate leaves out:** the check begins where `'static` is required (a `let` annotation, a cast, a callee),
  and then instantiates the parameters' trees.
- **Where errors are reported:**
  - a borrow that escapes as the returned value: at the return (E0515)
  - a closure's capture: where the body first uses it
  - an error of a call: at the call (`call_fn` is given no span)
- **Borrow check side:**
  - drop check for values whose `Drop` may use what they borrow
  - `ret_from` takes lifetimes declared to outlive the result's (`fn f<'a, 'b: 'a>(x: &'b T) -> &'a T` borrows x)
  - an impl method that ties a parameter the trait leaves free to a lifetime of its header (`fn next(&'a mut self)`):
    E0308

  `tests/regionck.rs` keeps the code rustc accepts next to the errors.

- **The costliest step was closure bodies.** Its first version cost traits +1.68% and patterns +0.80%:
  - Every closure argument parsed its bound's text again. `fn_bound_of` now returns the text it parsed.
  - Closures passed to the prelude's functions were checked too; they are skipped now.
  - What is left is the check of closures passed to the program's own bounds.
- **The other steps cost under 0.05% each.**
  - The well-formedness check runs only when a bound or a where clause writes a reference.
  - The new hooks do their work only in functions the check is on for.

## 4. Not covered yet

- generic functions that are never called: `zustc check` does not check them at all (most of the E0310 tests)
- higher-ranked trait selection ("implementation of `Trait` is not general enough")
- requirements of the impl a coercion or a call selects (`impl Tr for S<T> where T: 'static`)
- the iterators of the prelude: their types hold no lifetimes, so what `.iter().map(..).collect()` borrows is lost
- closures passed to the prelude's functions
