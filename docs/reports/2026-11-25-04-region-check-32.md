# Region (lifetime) checking, part 32: a shared reference a closure uses through a deref, held by value; closure patterns that test nothing; E0596 for `&mut &T`; more of const initializers (issue #1)

Date: 2026-11-25

Part 31 ([2026-11-25-03](2026-11-25-03-region-check-31.md)) was merged with #158. This step adds:

- edition 2021's capture of `*h` where a closure uses a shared reference `h` only through a deref of it;
- closure patterns that test nothing and capture nothing, and struct patterns that capture the fields they name;
- E0596 for a `&mut &T` coerced to a `&mut T` at a `let`;
- the pattern of a `for` over an Option's `iter()`, bound where the iterable is written;
- E0597 for a block anywhere in a const's initializer, and a dangling pointer for a const of a raw pointer's type.

## 1. What was added

- **A shared reference a closure uses only through a deref.** Take `v.iter().filter_map(|_| h.mk()).collect()`
  returned from a fn with `h: &'r H<'r>`, or `Box::new(|| self.n())` returned as `Box<dyn Fn() -> usize + 's>`.
  - Edition 2021 captures the places a closure uses. Where it uses `h` only through a deref (a method call's receiver,
    a field's or an index's base, `*h`, a call's argument), it captures `*h` by reference: a reborrow of the referent,
    not a borrow of the local `h`. So the closure may outlive the fn, and rustc accepts both.
  - zustc took the closure to borrow `h`: a false E0373.
  - Such a capture is held by value now (a copy of the reference, which is the same), from edition 2021. The borrow
    check captures the whole reference then.
  - Where the closure uses `h` itself (`|| h`, `let x = h`, `(h, 1)`, `for _ in h`), rustc's E0373 is about the
    borrow of `h`: that is not changed.
  - A new driver2 probe, tests/probe/closure_deref_capture.rs, builds and runs these closures after the fn returns.
    Its expected output is rustc 1.97's.
- **Closure patterns that test nothing.**
  - Take `let _a = || match sv { SingleVariant::A if condition => (), _ => () };` with an enum of one variant,
    and `let mut mut_sv = sv;` after it. The pattern tests nothing, so edition 2021 captures nothing of `sv`.
  - zustc captured `sv`: a false E0505.
  - The unit variant of an enum of one variant and a unit struct (`let (Unit, a) = x;`) capture nothing now.
  - A struct pattern (`let SStruct { b, .. } = x;`, also of an enum's variant) captures the fields it names, as a
    tuple struct's already did.
  - closures/2229_closure_analysis/match/match-edge-cases_2.rs has rustc's one error now. On main, zustc reported
    five errors there, none of them rustc's.
- **E0596 for a `&mut &T` coerced to a `&mut T`.**
  - Take `let Some(n): &mut Option<i32> = &mut &Some(5i32) else { return };`. The deref coercion to the
    `&mut Option<i32>` the `let` writes borrows mutably through a `&`, and rustc reports E0596 at the initializer.
  - zustc coerced it to a `&Option<i32>` and reported the write through it later (E0594 at `*n += 1`).
  - It is E0596 at the initializer now, of a plain `let` and of a destructuring one. A `&mut &mut T` is coerced as
    before.
  - let-else/let-else-binding-explicit-mut-borrow.rs and let-else/let-else-binding-explicit-mut-annotated.rs pass.
- **The pattern of a `for` over an Option's `iter()`.**
  - zustc lowers `for p in x.iter()`, with `x` an Option, to `if let Some(__exr_ox) = &x { let p = __exr_ox; .. }`.
    That `let` had no position.
  - So a move out through the pattern (`for &a in x.iter()` with `x: Option<Box<_>>`) was at the fn's line, naming
    `*__exr_ox`.
  - It is at the iterable now, as rustc reports E0507 there. It says "cannot move out of a shared reference"
    (borrowck/borrowck-for-loop-correct-cmt-for-pattern.rs).
- **More of const initializers.**
  - Part 31 checked the tail of a const's block. A block deeper in the initializer whose value borrows one of its own
    locals is E0597 too: `mem::transmute({ .. { let s = [0; 10]; &s } })` in an `unsafe` block
    (borrowck/const-fn-ptr-borrow-annotation.rs).
  - Of a const whose type is a raw pointer, such a borrow is no borrow check error, as a pointer has no lifetime.
    rustc's evaluation of the constant finds the pointer dangling and reports it at the item, and so does zustc now
    (consts/dangling_raw_ptr.rs).

## 5. Not covered yet

- **A closure that uses a captured reference itself.** `Box::new(|| { let x = h; x })` is rustc's E0373, as the copy
  of `h` captures `h` by reference. zustc holds the capture by value there and accepts it.
- **The E0597 of a closure stored in a local and returned.** For `let mut c = || { p.x += 5; println!("{:?}", p) };
  c`, rustc reports E0597 at the use of `p` in the closure. zustc reports E0373 at the closure, as for a closure
  returned directly (closures/2229_closure_analysis/diagnostics/borrowck/borrowck-4.rs).
- **E0276 for an impl method's lifetime bound that is stricter than the trait's.** `F: Debug + 'static` where the
  trait has `F: Debug + 'a` is rustc's E0276 (typeck/issue-18937.rs). zustc reports what it lets through later.
- **dropck of a value that stores a reference to itself** (span/issue-25199.rs, span/dropck_*).
- From part 31 and before: see [part 31](2026-11-25-03-region-check-31.md), section 5.
