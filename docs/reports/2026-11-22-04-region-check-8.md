# Region (lifetime) checking, part 8: stores through `&mut`, moves out of what cannot be moved, and tuning (issue #1)

Date: 2026-11-22

Part 7 ([2026-11-22-03](2026-11-22-03-region-check-7.md)) was merged with #46. This step takes the borrow check's
cases that tests/ui showed accepted or reported at the wrong place, and makes the check cheaper.

## 1. What was added

### Borrow check

- **Stores through a `&mut`:** what is assigned through a `&mut` a local holds is held by what it points to.
  - With `let q = &mut p; *q = &y;`, p holds the loan of y. Using p after y is gone is E0597, at `&y`.
  - It goes as many derefs deep as the place has (`**r = ..`).
  - A `&mut` that points behind a parameter (`let q = &mut *x;`) stores where the value outlives the function.
  - Before, the loan was held by q alone, so p used after y was accepted.
- **A `&mut` passed for a type parameter:** with `fn generic<T>(x: T)`, `generic(self)` and `self: &mut X` is no
  coercion site, so `self` is moved, not reborrowed. Using it after is E0382.
  - A `&mut` passed where the parameter's type is a `&mut` is still reborrowed.
- **Moves out of what cannot be moved:**
  - A field of a value whose type implements `Drop` cannot be moved out (E0509): `s.f`, `S { a: 2, ..s }`, and a
    pattern that binds such a field by value (`let S { f } = s;`, a match arm, a parameter's pattern).
  - A static cannot be moved out either (E0507): `test(BAR)` with `static BAR: Foo`. A constant is a new value at
    each use.
- **Two fields of a union are the same memory:** `&mut u.s.a` and `&u.z.c` conflict (E0502). Fields of the same
  field (`u.s.a`, `u.s.b`) do not.
- **Tuple, array and struct literals of runtime values are temporaries:** `gimme(&(v,))` with a local v is not
  promoted to a static as `&(1, 2)` is. A borrow of it that is used after the statement is E0716.
- **Where `{x}` in a format string is reported:** the variable that `println!("{x}")` names has the format string's
  position. A use of x uninitialized there (E0381) was reported at the function's first line.

### Signatures

- **E0582:** a `for<'a>` binder whose lifetime only the bound's result names (`F: for<'a> Fn() -> Option<&'a i32>`)
  or only an associated type's binding names (`for<'a> Iterator<Item = &'a i32>`). No type can satisfy the bound.
  The type before `:` of a predicate with its own binder is an input (`for<'a> &'a T: IntoIterator<Item = &'a U>`).
  A generic associated type's binding (`Item<'a> = &'a T`) is not checked: the parser drops its arguments, which may
  name the lifetime.

### After the review

- **A write to one union field while another is borrowed** (`u.b.x = 2` with `&u.a` live) is E0506. It panicked:
  the check that two paths share a prefix took two fields of a union as one, and the write's check then cut the
  loan's path past its end. Two union fields are now a case of their own. Writing one field still initializes the
  whole union, so a field moved out before can be used again (nll/issue-55651.rs).
- **A store through a field's `&mut`** (`*q.0 = &y` with `q = (&mut p, &mut z)`) is not followed. Which loan q.0
  holds is not known, because a local's loans are not kept by field. Following it made z hold y's loan as well.
- **E0509 deeper:** a pattern that binds by value below a field of a `Drop` type (`D { f: Some(x) }`), and a match
  on such a field (`match d.f { Some(x) => .. }`).
- **A `&mut` field passed for a type parameter** (`consume(s.0)`) is moved, as a `&mut` local is.
- **A static moved out by a module's path** (`take(m::BAR)`) is E0507. Only an argument passed by value is checked:
  a path is no place expression, so it is also read as a value where it is not moved (`m::KEY.with(..)`).

## 2. Tuning

`zustc check` of the patterns input, measured with cachegrind (instructions):

| step | instructions (M) | change |
|---|---:|---:|
| main (f9cf20b, part 7 merged) | 717.79 | |
| this work | 708.92 | -1.24% |

Of the drop, the environment variables read once are about half (-0.57% measured alone, before part 7's review
fixes).

- **Environment variables read once:** each `std::env::var_os` call scans the whole environment. Per temporary,
  per function and per closure, the checks for `ZUSTC_NO_FRESH`, `ZUSTC_BORROWCK`, `ZUSTC_BK_DEBUG` and the
  debugging flags took 0.5% of the check. They are now read once.
- **The borrow check's dataflow:**
  - A block's state goes to its last successor without a copy.
  - The report takes each block's state instead of copying it.
  - The liveness loop reuses two buffers.
- **`has_refs` through the function's cache:** the sites that asked it directly now use `bk_ty`, which keeps the
  answer per type.

## 5. Not covered yet

- **What a call stores through a `&mut` it is given:** `s.invoke()` where `invoke(self)` writes `*self.p = self.y`
  (nll/capture-ref-in-struct.rs). The store is in another function, and only its signature's regions tell it.
- **Generic fns with trait bounds on their type parameters (`K: Clone`):** such a fn has no placeholder instance, so
  its body is not checked.
