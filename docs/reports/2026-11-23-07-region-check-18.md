# Region (lifetime) checking, part 18: let extension through constructors, closure capture reborrows, trait objects' drops, `&mut` moved by value, and a scrutinee's drop per arm (issue #1)

Date: 2026-11-23

Part 17 ([2026-11-23-06](2026-11-23-06-region-check-17.md)) was merged with #97. This step adds:

- the temporaries a `let` extends through constructors and literals (rustc since 1.79);
- calls through fn pointers, whose results hold what their arguments borrow;
- the reborrows of a closure's captures, bounded by the closure's environment;
- trait objects whose drop uses what they borrow;
- `&mut` references moved by value where no coercion reborrows them;
- a scrutinee's drop, kept in the arms that do not take the whole value.

It also fixes false errors that stopped tests before the borrow check:

- `vec![&mut x]`;
- `let f: fn(_) -> _ = foo;`;
- a trait object made of a reference whose type implements the trait.

Two of the three findings part 17's review left (section 5 of its report) are done here.

## 1. What was added

### False errors fixed

- **`vec![&mut x]`** of a local number was "internal: borrowed local is not in memory"
  (span/regions-escape-loop-via-vec.rs stopped at it). The walk for the locals whose address is taken read a `&` in
  a macro's arguments as a formatting macro's, which reads the value. Only a formatting macro's is so now.
- **`let f: fn(_) -> _ = foo;`** was "mismatched types: expected `fn(_) -> _`": the holes of a fn pointer
  annotation were not looked into. The region check gave such a local no tree, so a call through it was not followed.
  Its regions are now fresh ones the initializer flows into. `f(x)` of `foo<'a>(&'a u32) -> &'a u32`, returned as
  `&'static`, is "lifetime may not live long enough" (nll/mir_check_cast_reify.rs, mir_check_cast_unsafe_fn.rs).
- **`impl<'a> Foo for &'a isize`** made a `Box<dyn Foo>` of a `&isize` was "no implementation". The dispatch now looks
  up the reference impl's method (`__ref_m` of the referent's type). tests/acg/dyn_of_ref_impl.rs compares the
  output with rustc's.

### Borrow check

- **A `let` extends a `&` of a temporary within its initializer's extending expressions:**
  - a tuple struct's or a variant's constructor's arguments;
  - a tuple's, an array's or a struct literal's fields.

  `let x = Some(&[name]);` used after was a false E0716 (borrowck/array-slice-coercion-mismatch-15783.rs stopped at
  it). A call of a fn and a method's receiver are not extending: `let h = Some(temp().as_str());` used after is still
  E0716.
- **A call through a fn pointer holds what its arguments borrow**, when its result holds references.
  `let f = id::<&String>; let g = f(&temp());` used after is E0716.
- **A capture reborrowed in a closure's body is bounded by the closure's environment.** `|| doit(data)` with
  `data: &'static mut ()` passed where a `&'static mut ()` is expected was accepted
  (nll/issue-42574-diagnostic-in-nested-closure.rs). The environment is the closure's for no longer than a call, so
  the reborrow outliving `'static` is "lifetime may not live long enough". A capture moved out first, a shared
  reference copied, and a callee that takes any lifetime are fine.
- **The constructor of a struct with an unsized field, used as a value, is E0277.** `let _x: fn(_) -> Test = Test;`
  with `struct Test([i32]);` (unsized-locals/issue-30276.rs). The constructor value is written `|a0| Test(a0)`, and a
  closure parameter of a type of no size known is E0277, at the constructor as rustc reports it. This one became
  reachable when the annotation's holes were typed (above).
- **A scrutinee's drop is kept in the arms that do not take the whole value.**
  `match heap.peek_mut() { x if flag => drop(x), _ => heap.push(1) }` was accepted (E0499 in rustc; part 17's review).
  One arm binding the whole value left the scrutinee's drop out of every arm. The arms that take it now move it, and
  its drop holds nothing on their path. The others keep it to the end of the statement.
- **A `&mut` read by value where a `let` with no type written is initialized is moved.** These were accepted (part 17's
  review):
  - `let b = a[0];` with `a: [&mut i32; 1]` (E0508);
  - `let y = unsafe { *p };` with `p: *const &mut i32` (E0507);
  - `let u = *qq;` with `qq: &mut &mut i32` (E0507).

  The borrow check takes a `&mut` as `Copy` for the reborrows of coercion sites, and the type inference gives the
  `let` its type as expected. A `let`'s initializer with no type written is no coercion site. What it reads by value
  out of a place there, through parentheses and block tails, is now moved. An argument and `let c: &mut i32 = a[0];`
  still reborrow.
- **A trait object's drop uses what it borrows.** rustc does not know what a `dyn` type's drop does, so it takes it to
  use all the object borrows. These were accepted:
  - `let mut f: Box<dyn FnMut()> = Box::new(|| v += 1); f(); println!("{}", v);` (E0502: the borrow is used when f is
    dropped);
  - `blah = Box::new(&x) as Box<dyn Foo>;` with x in an inner block (E0597,
    span/regions-close-over-borrowed-ref-in-obj.rs's case).

  A `&dyn Trait` owns nothing and is not affected.

## 5. Not covered yet

- **A fn item passed where a fn pointer type binds its regions** (`want_G(baz)` with
  `type G = for<'cx> fn(&'cx S) -> &'static S` and `fn baz(x: &S) -> &S`, E0308 in rustc;
  regions/regions-fn-subtyping-return-static-fail.rs). The regions such a type binds are variables of their own, and
  a type alias's regions are not followed. A first part, for the type written in the parameter, is in progress for
  the next part.
- **A `&mut` moved by value elsewhere than a `let`'s initializer**: `f(a[0])` with a generic f, `vec![a[0]]` (E0508).
  Only a `let` with no type written is taken as no coercion site.
- **An associated constant's type with the impl's lifetimes** (`<Foo<'a>>::C` with `const C: &'a u32`, returned as
  `&'static`, nll/user-annotations/constant-in-expr-inherent-1.rs).
- From part 17:
  - two derefs of the program's written in one place (`(&mut **w).bump()`);
  - a tuple struct's constructor as a value with a `'static` type argument;
  - a trait whose impls for a type are ambiguous (borrowck/mut-borrow-in-loop-2.rs).
- From part 16:
  - a generic fn's `dyn Tr<T>`;
  - `&*vec![1].iter().next().unwrap()`;
  - the opaque type's member constraints (E0700);
  - `&mut` in a tuple's inference;
  - per-field regions;
  - `use … as S` for a variant;
  - the borrow check of a `static` closure.
