# Region (lifetime) checking, part 42: the Drop check's trait headers and equation values, and the invariance of a trait object's arguments in `let _`

Date: 2026-11-28

Part 41 ([2026-11-27-04](2026-11-27-04-region-check-41.md)) was merged with #324. This part takes three gaps that
part 41 listed: two in the rules a `Drop` impl must keep (E0367), and one in how a value flows into a `let _`'s
annotation.

## 1. What was added

- **A trait makes a `?Sized` parameter Sized only through its header.** With `struct S<T: ?Sized + Tr>`, `impl<T:
  Tr> Drop for S<T>` (whose T is Sized) requires `T: Sized`, E0367, unless Tr implies `Sized`. Part 41 looked for the
  words `Sized`, `Clone`, `Copy` and `Default` anywhere in the trait's header text. Now the header is parsed, and only
  its supertraits and its `where Self: ..` bounds count:
  - Rejected (E0367, as rustc): `trait Tr<U: ?Sized>`, `trait Tr<U: Clone>` (a bound of the trait's own parameter),
    `trait Tr where u8: Clone` (a bound on another type), and `trait Tr: /* Default */ std::fmt::Debug` (a comment).
  - Accepted: `trait Tr: Sized`, `trait Tr where Self: Sized`, `trait Tr: B` with `trait B: Clone`, and `trait Tr:
    std::default::Default`.
- **The values of a bound's equations.** An impl's `T: Iterator<Item = u16>` where the definition writes `T:
  Iterator<Item = u8>` is E0367 ("`Drop` impl requires `<T as Iterator>::Item == u16` but the struct it is
  implemented for does not"). Part 41 checked only that the definition had an equation for the same name. The value
  is compared with the definition's after the impl's parameters are renamed to the definition's (`impl<A:
  Iterator<Item = B>, B> Drop for S<A, B>` with `struct S<T: Iterator<Item = U>, U>` is accepted). A value that names
  a parameter the self type does not have may hold, as before, so it is not checked (`impl<T: Trait<Assoc = U>, U:
  ?Sized> Drop for Foo<T>`, dropck/constrained_by_assoc_type_equality.rs).
- **The arguments of a trait object are invariant in `let _`.** `let _: Box<dyn Foo<Bar = &'a u32>> = make();` with
  `make() -> Box<dyn Foo<Bar = &'static u32>>` needs `'a: 'static`: rustc's "lifetime may not live long enough"
  (variance/variance-associated-types2.rs). A named binding (`let x: ..`) was already rejected (as a type mismatch);
  `let _` leaves types apart only in their lifetimes to the region check, which gives a trait object one region, its
  own. Now a `'static` that the value's type writes in a trait object's arguments (`dyn Foo<..>`, `dyn Fn(..)`) makes
  the annotation's lifetime at that place `'static`. The object's own lifetime (`dyn Foo + 'a`) is not one of these,
  and an elided lifetime of the annotation's (`dyn Foo<Bar = &u32>`) is inferred. A named lifetime of the value's
  type is not taken: it may be a callee's.

## 4. Not covered yet

- **A named lifetime of the value's in a trait object's arguments** (`let _: Box<dyn Foo<&'static u32>> = x;` with `x:
  Box<dyn Foo<&'a u32>>`, rustc's "lifetime may not live long enough"): accepted. The lifetime's name in the value's
  type may be a callee's, so only a `'static` of the value's is taken.
- **The return type of `dyn Fn(..) -> R`** in the item above: not looked at.
- **A closure passed to a prelude function** (`v.into_iter().map(|line| self.me(&line))` returning a borrow of `line`
  through the impl's lifetime, borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs): from part 41.
- **Drop impls of a type in another module of the same name**, or of a self type written as a path (`self::S<T>`):
  from part 41.
- From part 40 and before: see #166–#171.
