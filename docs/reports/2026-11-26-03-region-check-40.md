# Region (lifetime) checking, part 40: OnceCell, the well-formedness of values built by constructors, generic fns that are called, and elided lifetimes in a receiver's self type (issue #169)

Date: 2026-11-26

Part 39 ([2026-11-26-02](2026-11-26-02-region-check-39.md)) was merged with #263. This part takes more of #169's gaps:
a std type that stopped a lifetime test before the borrow check, and three places where the checks of `T: 'static`
and of a receiver's lifetimes did not reach.

## 1. What was added

- **`std::cell::OnceCell`, and `Rc::try_unwrap` / `Rc::into_inner` (and Arc's).** The prelude's OnceCell is
  OnceLock's for one thread (`new`, `get`, `get_mut`, `get_or_init`, `set`, `into_inner`, `take`), and is not Sync, as
  in std (sync/suggest-once-cell.rs is still rejected, now by the trait bound). `try_unwrap` gives the value when the
  Rc is the only one, and frees the box without dropping it. regions/wf-bound-region-in-local-soundness-issue-148854.rs
  was "cannot find type `OnceCell`".
- **A value built by a constructor, of a type that bounds a parameter by 'static.** With `struct St<T: 'static>`,
  `St(Some(x))`, `St::<T>(..)`, `En::A(x)` and `En::<T>::B` in a generic fn whose T is not 'static are rustc's E0310:
  the value's type is not well formed. Only a struct literal's type and the type arguments a path writes were
  checked (part 24). Now the type of a path, or of a call of one, that names the type (its name, or a variant of it)
  is checked as a struct literal's is.
- **A generic fn that is called, checked with placeholders too.** A generic fn of which instances are made was
  checked only with them. An instance does not tell what `T: 'static` the fn's types need: with `&u8` for T, the
  check takes the reference's region as a fresh one. So `extend::<&String>(&data)` hid the E0310 of `Outer::<T,
  Inner<T>> { .. }` in extend's body (`struct Inner<T: Display + 'static>`, the test above). Now a fn whose text
  names a struct or an enum of the program that bounds a parameter by 'static is also checked with placeholders, and
  only an E0310 (a `T: 'static` not met) is reported there, as part 12's recheck reports only moves. It is made only where the
  program has such a type.
- **The signature's types imply `T: 'static` in closures too.** `fn foo<T>() -> IfaceToken<T>` with `struct
  IfaceToken<T: 'static>` gives T: 'static in the body. In a closure of the body, a call that requires T: 'static
  (`data_::<T>(&())`) was reported (borrowck/nested-closure-with-generic-ice.rs, a check-pass test, when foo is not
  called; the item above made it reported when it is). A placeholder is now 'static when a type of its fn's
  signature has it as an argument a 'static bound covers.
- **An elided lifetime in a receiver's self type (E0308).** `self: &Pair<&str, isize>` in `impl Pair<&str, isize>`,
  `self: Foo<'_>` or `self: Foo` in `impl<'a> Foo<'a>`, and `self: Rc<W<&u8>>` in `impl Tr for W<&u8>` name a lifetime
  of the method's own where the impl's self type has the impl's: rustc's "mismatched `self` parameter type"
  (lifetimes/elided-lifetime-mismatch-in-self-type.rs). The existing check compared only lifetime arguments a
  receiver writes by name. Lifetimes that a fn pointer or `dyn Fn(&u8)` in the type binds are not looked at.
- **A method of an impl for `Box<dyn Tr>` in the type inference.** `val.use_self()` with `val: &Box<dyn O>` and
  `impl MyTrait for Box<dyn O>` found no method there (only the object's), so a result `impl Trait` from it was
  "cannot infer the `impl Trait` return type". It is a fallback after the object's own methods.

## 4. Not covered yet

- **A borrow through an impl for `Box<dyn Tr>`** (`val.use_self()` of a local `val: Box<dyn O>` returned, with `impl
  MyTrait for Box<dyn O> { fn use_self(&self) -> &() }`): rustc's E0515, accepted here. The call is not followed by
  the region check (suggestions/impl-on-dyn-trait-with-implicit-static-bound-needing-more-suggestions.rs).
- **A self type with `'static` where the impl's has an elided lifetime** (`self: &Pair<&'static str, isize>` in `impl
  Pair<&str, isize>`, E0308), and a receiver of another type than the impl's (`self: &W<&u8>` in `impl<T> W<T>`,
  rustc's E0307): accepted.
- **Default methods left out of `impl<T> Tr for &T`** (span/issue-24805-dropck-trait-has-items.rs): not supported by
  the code generator (with `Self = &T`), so the dropck test stops there.
- From part 39 and before: see #166–#171.
