# Region (lifetime) checking, part 24: a struct's 'static bound in a generic fn's types, `mut` bindings under a by-reference default binding mode, the outlives of the impl a projection selects (issue #1)

Date: 2026-11-24

Part 23 ([2026-11-24-09](2026-11-24-09-region-check-23.md)) was merged with #126. This step adds:

- a struct's `T: 'static` bound, required of the types a generic fn that nothing calls writes;
- a `mut` binding where the default binding mode is by reference, before edition 2024;
- the outlives that the header of the impl a projection selects declares of its lifetimes.

## 1. What was added

- **A struct's `T: 'static` bound in a generic fn's types.** With `struct Static<T: 'static>(T)`, `let _ =
  None::<Static<T>>;` in `fn a<T>()` was accepted (E0310 in rustc, regions/wf-bound-region-in-local-issue-115175.rs),
  and so were `let _: Option<Static<T>> = None;` and `Vec::<Static<T>>::new()`. Three things were missing:
  - an ADT's `T: 'static` bound was looked up among the ADT's own lifetimes, so it required nothing;
  - a generic fn that nothing calls, checked with placeholders, had its region check off when its signature names
    no lifetime;
  - the type arguments a path writes in an expression (`None::<Static<T>>`) were not checked for well-formedness.

  Each is done now. The type arguments of a path are checked only for types with such a struct: other requirements
  may hold through a parameter's projection, which the check does not follow (implied-bounds/normalization.rs).
- **`mut x` where the default binding mode is by reference.** Before edition 2024, `mut` on a binding resets the
  mode to by value. `for (n, mut m) in &tups {}` with tuples of a type that is not `Copy` was accepted (E0507 in rustc,
  rfc-2005-default-binding-mode/for.rs), and `let (_, mut m) = &(1u8, 2u8); m += 1;` was a false "expected `&u8`".
  Such a binding now moves its value out of the reference matched through: an error when the value is not `Copy`,
  the value's type when it is.
- **The outlives of the impl a projection selects.** `fn visit_seq<'d, 'a: 'd>() -> <&'a () as Visitor<'d>>::Value
  {}` with `impl<'a, 'd: 'a> Visitor<'d> for &'a ()` was accepted ("lifetime may not live long enough" in rustc,
  nll/normalization-bounds-error.rs), and so were such a projection as a parameter's type and as a `let`'s.
  - The summaries keep an impl's associated type's codes also where the impl's header declares `'d: 'a` of its
    lifetimes, even when the value names none (`type Value = ()`). They keep those outlives and the lifetimes the
    impl's trait path writes as its arguments.
  - A projection written as the result's type, a parameter's or a `let`'s requires them of the impl's lifetimes.
    Those lifetimes are the parts of the self type as written where the impl's self type has them, and the lifetimes
    of the trait path as written (`'d` of `Visitor<'d>`). One the path elides is fresh.
  - With `where 'd: 'a` in the function, or a `'static` that meets it, the projection is accepted, as in rustc.
  - A function's cache key holds its impls' headers now, as their outlives are required where a projection selects
    them.

## 4. Review

CodeRabbit's review had 4 findings, each checked with zustc and rustc 1.97. All 4 held, and all are fixed in the
commit that follows 7f2b58e5. One was a false acceptance this part brought in; main rejected the program, though at
another line and with another message:

- **A `mut` binding of a `&mut` through a shared reference.** `let (mut r,) = &(&mut n,);` was accepted (E0507 in
  rustc). The new by-value binding took the `&mut` for Copy, as the borrow check's `is_copy` does every reference.
  A `&mut`, or a tuple or an array with one, is moved out of the reference now, which is the error.

The other three were cases this part's checks did not reach, which main accepted too:

- **A method call's type arguments.** `r.use_ty::<Static<T>>()` with `struct Static<T: 'static>(T)` was accepted
  (E0310 in rustc). Only a path's type arguments were checked; a method call's are too now.
- **An impl whose associated type's value the codes do not follow.** With `impl<'a, 'd: 'a> Visitor<'d> for &'a () {
  type Value = <() as Base>::Out; }`, `<&'a () as Visitor<'d>>::Value` required nothing: the value's codes had the
  mark of a type not followed, and the summaries kept nothing of the impl. They keep the header's outlives now, and
  the value's codes still make no tree.
- **A projection within the written type.** `Option<<&'a () as Visitor<'d>>::Value>` as the result's type required
  nothing: only a type that is itself a projection was looked at. The type's parts are walked now, through paths'
  type arguments, references, pointers, slices, arrays and tuples.

tests/regionck.rs checks the cases (`part24_review`), with the forms rustc accepts.

  with placeholders.
