# Region (lifetime) checking, part 17: raw pointers, `DerefMut` receivers, scrutinee and loop temporaries, and false errors of indexing, dispatch and turbofish inference (issue #1)

Date: 2026-11-23

Part 16 ([2026-11-23-04](2026-11-23-04-region-check-16.md)) was merged with #88. This step adds several checks:

- the borrow check of moves and writes through raw pointers;
- closures boxed as `Box<dyn Fn>`;
- arrays that are not places;
- `&mut self` methods reached through a program's `DerefMut`;
- `&self` methods that store into an invariant self type;
- temporaries that a `match`, a `let` or a loop's iteration keeps.

It also fixes false errors that stopped tests before the borrow check:

- indexing through a `Deref` to a slice;
- a blanket impl's method for a reference made a trait object;
- a method call in a `&mut` place;
- loans of values that hold no reference;
- `BinaryHeap::peek_mut`;
- a free fn call's turbofish.

## 1. What was added

### False errors fixed

- **`c[i]` of a struct whose `Deref` is to a slice** indexes what it derefs to. It was "cannot index into a value". The
  borrow is of the struct (`c.deref()[i]`, `deref_mut` for `&mut c[i]`), so writing another field while the element
  is used is E0506 (borrowck/issue-81365-6.rs). A struct's own `Index` comes first. tests/acg/index_through_deref.rs
  compares the output with rustc's.
- **A blanket impl's method for a reference made a trait object.** With `impl<A> Foo for A`, `Box::new(v)` with
  `v: &i32` used as a `Box<dyn Foo>` was "`Foo::get` has no implementation for `&i32`". The static dispatch now takes
  the blanket impl whose bounds hold of the reference, for a method the trait has no default of
  (span/regions-close-over-type-parameter-2.rs). See tests/acg/blanket_impl_dyn_ref.rs.
- **A method call in a `&mut` place does not make its receiver a mutable place.** `&mut *s.0.borrow_mut()` of
  `s: Pin<&S>` was "cannot borrow `s` as mutable" (typeck/issue-73592-borrow_mut-through-deref.rs). A method call is
  a value, and its self type decides its receiver. The prelude's `Pin<&T>` derefs shared, as std's has no `DerefMut`
  for a shared pointer.
- **A value of a type with no reference carries no loan.** Take
  `let (b, log) = match *e { (G(_, log), ref mut d) => (*d, log) };`: log held d's loan. The tuple took the sources of
  `*d`, a bool read through d. A place read or a call's result whose type holds no reference now passes on no source.
  A statement with a semicolon adds none to the enclosing value, except what a `break` in it gives its loop
  (drop/issue-23611-enum-swap-in-drop.rs, a false error).
- **`BinaryHeap::peek_mut`.** The prelude had no `peek_mut`. Its `PeekMut` derefs to the largest element. When it is
  dropped after a change through `deref_mut`, it sifts the element down again, as std's does. It is a guard of the
  prelude for the type inference, the lowering and the borrow check, and holds the heap's `&mut` borrow while it
  lives. tests/acg/binary_heap_peek_mut.rs compares the output with rustc's.
- **A call's turbofish gives the fn's type arguments to the inference.** `let c = 66; id::<u32>(c);` was "mismatched
  types: expected `T0`, found `i32`". The inference took no type argument from a free fn call's turbofish, so c
  defaulted to `i32`. The turbofish's types are now the variables of the fn's own generics. A free generic fn with
  every type argument written (`let f = id::<&'static u32>;`) has its instance's fn pointer type. So `f(&c)` types c
  too, and is E0597, as rustc reports (nll/user-annotations). tests/acg/fn_turbofish_infer.rs compares the output
  with rustc's.
- **A constant scrutinee bound by `ref` is promoted.** `match Some(1) { Some(ref x) => v.push(x), .. }` with v used
  after was a false E0716. It is promoted to a static, as `&Some(1)` is. `ref mut` is still a temporary.

### Borrow check

- **A move out of what a raw pointer points to is E0507.** These were accepted (borrowck/borrowck-move-from-unsafe-ptr.rs):
  - `let y = *x;` with `x: *const Box<isize>`;
  - `(*x).a`;
  - a pattern of `*x` that moves.

  A raw pointer's deref was not a place of the borrow check. A copy and a `ref` binding are fine.
- **A write through a `*const` pointer is E0594.** `*ptr = 3` with `ptr: *const i32`, and `(*p).a[1] += 1`, were
  accepted (borrowck/no-invalid-mut-suggestion-for-raw-pointer-issue-127562.rs). A write through a `*mut` pointer,
  or of a `*const` value itself, is fine.
- **A closure boxed where a `Box<dyn Fn()>` is expected is `Fn`.** `Box::new(|| x)` as a `Box<dyn Fn() -> Box<i32>>`
  was accepted. So was `move || v` as a `Box<dyn FnMut()>`. Moving out what such a closure captures is E0507, as where
  a bound wants `Fn` / `FnMut`. A `Box<dyn FnOnce()>` may move it.
- **A move out of an array that is no local's place is E0508.** These were accepted, for an element type that is not
  `Copy` (borrowck/move-error-in-promoted*.rs):
  - `C[0]` of a constant array;
  - `[S][0]` and `mk()[0]` of a temporary one.
- **A `&self` method stores an argument borrowed for a lifetime its self type is invariant in.** Take
  `fn push(&self, r: &'c mut i32)` of a `C<'c>` that holds a `RefCell<Vec<&'c mut i32>>`. Calling `c.push(&mut y)`
  twice was accepted. The argument's borrow is for c's `'c` (or a lifetime that outlives it), so c holds it. The
  receiver is used at the call, after the arguments (E0499, borrowck/mut-borrow-conflict-in-closures-vec.rs). A
  covariant self type stores nothing.
- **A `&mut self` method through a program's `DerefMut` borrows the receiver mutably.** `w.push(2)` with
  `W: DerefMut<Target = Vec<usize>>` reached `push` through `deref`, and borrowed w shared. It was accepted without
  `mut w`, through a `&W`, and against a shared loan of w. It is now `(&mut *w).push(2)`, as autoderef takes
  `deref_mut` for it. w is borrowed mutably: E0596 without `mut`, E0502 against a shared loan, and
  `w.push(w.len())` is E0502. The user's `deref_mut` runs instead of `deref`, once per link of the chain, as in rustc.
  tests/acg/deref_mut_methods.rs compares the output with rustc's.
- **A scrutinee value whose drop may use what it borrows lives to the end of its statement.**
  `match heap.peek_mut() { Some(_) => { heap.pop(); } .. }` was accepted. rustc reports E0499
  (borrowck/issue-85581.rs, issue-47646.rs). The scrutinee is a temporary of the statement that a guard's drop uses.
  It now holds its loans through the arms, also when an arm moves a part out. That does not apply when a pattern
  takes the whole value. Its `ref` bindings' borrow of its own storage is left out of what its drop uses
  (dropck/eager-by-ref-binding-for-guards.rs). A block's last statement that is no tail ends its temporaries before
  the block's locals, as any statement does. Before, `match (borrow, ()) { .. };` at the end of a fn was a false
  E0597.
- **A `let` extends what `&` borrows, not the temporary receiver it is made from.**
  `let r = &mut *RefCell::new(1).borrow_mut();` and `let s = &*String::from("b").as_str();`, with r / s used after,
  were accepted. The receiver temporary goes away at the end of the statement, while the result the `let` keeps
  borrows it (E0716). The lowering's copy of a guard's deref (`*g.deref_mut()`) now keeps the temporaries the borrow
  check follows.
- **A loop's item and its body's tail temporaries go away with each iteration.** These kept the temporary their `ref`
  bindings borrow to the end of the statement:
  - `for ref x in 0..3 { v.push(x); }`;
  - `while let Some(ref x) = it.next() { .. }`;
  - `loop { match it.next() { Some(ref x) => v.push(x), .. } }`.

  A borrow kept past the iteration was accepted. rustc reports E0716, as a loop's body is a terminating scope. A
  `for` loop's `ref` bindings now borrow a temporary of the iteration. The temporaries of a `while let`'s scrutinee
  and of a loop body's tail end at the end of each iteration, on a `break` or `continue` too. A value that holds
  references (`Some(ref s)` of an `Option<&String>`) is a temporary that holds them (below).
- **A reference copied out of what a local points to holds what that place holds.** `let r = &a; t = *r;` with
  `a: &String` and t used after a's scope was a false E0597 (on main too): `*r` held the loan of a. A copy out of what
  a local points to (`*r`, `&**s`, a `&&String` where a `&String` is expected) is now a hidden local that holds r's
  loans, each loan of a place that holds such values replaced by what that place's local holds (`Bk::copy_masks`,
  made when the check starts). A `ref` binding's temporary of a value that holds references holds what the value
  holds, so `*s` of `Some(ref s)` is what the `Option<&String>` holds, and s itself kept past it is E0716.
- **A `for` loop's item over `&v` / `v.iter()` holds the loop's loan of v.** `for x in &v { out.push(x); }` with v
  changed after, out still used, was accepted (on main too): the items held nothing. It is E0502 now.

## 4. Review

CodeRabbit's review of #97 had 7 findings. Each was checked with zustc and rustc 1.97 on a program that shows it, and
all 7 held. They are fixed and tested (`part17_review`, tests/acg/deref_mut_slice_methods.rs,
tests/acg/blanket_two_traits.rs):

- `c.reverse()` with `C: DerefMut<Target = [i32]>` ran `deref`, not `deref_mut`: the rewrite to `c.deref().m()` of a
  deref to a slice took no account of a `&mut self` method. It takes `deref_mut` for one now.
- `(ref s, _)` of `(String::from("x"), n)`, returned after the statement, and `for ref s in [(String::from("x"), n)]`
  keeping `&s.0`, were accepted (E0716 in rustc): a value that holds references was left out of the `ref` bindings'
  temporaries. The copied-out references (above, from the next part's work) let them borrow one that holds what the
  value holds.
- `for ref x in [1, 2] { saved = x; break; }` was accepted (E0716): the item's temporary ended only at the body's
  end. It is the body scope's now, which a `break` or `continue` ends too.
- `for (ref i, _) in v.iter().enumerate()` keeping i was accepted (E0716): the pair's `ref` bindings borrowed no
  temporary. They borrow the iteration's now.
- `**p = 1` with `p: *const *mut i32` was a false E0594: the write is through the `*mut`.
- The invariant lifetimes of a `&self` method's self type were found in one pass over the outlives bounds, so their
  order mattered. They are computed to a fixpoint.
- `A::get(&x)` / `B::get(&x)` of two traits' blanket impls: `Program::blanket` keeps one method of each name, so
  B's was "no implementation". The fallback looks the trait's own blanket method up by name and trait.

Main was merged in before the fixes (its #94 and #95: zustscript, CI and test time), with no change to the region
check. The report is 2026-11-23-06, after main's 2026-11-23-05.

CodeRabbit's second review had 10 findings. Each was checked with zustc and rustc 1.97 in the same way.

Six were fixed and are tested (`part17_review2`, tests/acg/blanket_override_default.rs,
tests/acg/for_items_copied.rs). Three of them were errors this work had brought in:

- A struct whose `deref` gives itself, with `s.reverse()` called on it, made zustc overflow its stack. The
  `DerefMut` receiver probe went round the same type. It now stops at a type it has been through, and is E0055 as
  before. A program's struct without the method takes none of the prelude's `&mut self` methods that are known by
  name.
- `for x in v.iter().copied() { saved = x; }` with v changed after was a false E0502. The items held the loop's loan
  of v. The items of `copied` / `cloned` hold what v holds.
- A loop over a value inside a loop over `&v` gave its items the outer loop's loan (a false E0502). Every loop now has
  its own entry.

Three were on main too:

- `&**s` with `s: &&i32`, used after what s points to is gone, was a false E0597. The reborrow held s's own loan
  through the read of s. Through a shared reference, it holds only what that reference holds, as with `*s`. A
  `&mut` inner reference (`s: &&mut i32`) is still E0597, as in rustc.
- A blanket impl that overrides a trait's default method, called through a reference made a trait object, ran the
  default. The blanket impl is now looked for first.
- Two blanket impls of a generic trait (`impl<T> A<u8> for T`, `impl<T> A<u16> for T`): through `dyn A<u16>`, the
  fallback of section 1 ran A<u8>'s method (`8` for rustc's `16`). The fallback now takes a blanket impl only when it
  is the trait's only one and its header's arguments are the call's. Otherwise the call is "no implementation", as
  on main.

The copy-out masks are now made once for each copied type, not for each copy: the remaining finding was about speed.

Three hold and are left for later (section 5):

- the move out of `*p` with `p: *const &mut i32`;
- the move of a `&mut` element out of an array (`let b = a[0];`, main too);
- the scrutinee drop with a by-value binding in another arm.

Main was merged in again (#90 and #91: memchr for wasm32; lints, E0308 positions, E0658 gates and E0107, 79 more
tests/ui) before these fixes.

## 5. Not covered yet

- **A `&mut` reference moved out by value where no coercion reborrows it**: `let y = unsafe { *p };` with
  `p: *const &mut i32` (E0507), and `let b = a[0];` with `a: [&mut i32; 1]` (E0508, main too). The borrow check
  takes a `&mut` as `Copy` for the implicit reborrows of coercion sites (`let b: &mut i32 = a[0];`, an argument). The
  strict rule needs to know whether the read is at a coercion site.
- **A scrutinee whose drop uses what it borrows, with a by-value binding in another arm**:
  `match heap.peek_mut() { x if flag => drop(x), _ => heap.push(1) }` is accepted (E0499 in rustc). A whole-value
  binding in any arm takes the scrutinee's drop away from every arm. The arms that do not move it would need to keep
  it.

- **Two derefs of the program's written in one place** (`(&mut **w).bump()` with W and the X it derefs to both
  `DerefMut`) call W's `deref_mut` twice: the inner `*w` is reached again. A method call that autoderef reaches the
  same way calls each once.
- **A tuple struct's constructor as a value with a `'static` type argument** (`let f = SomeStruct::<&'static u32>;
  f(&c);`) is not checked against the argument (nll/user-annotations/adt-tuple-struct-calls.rs). A call of
  `SomeStruct::<&'static u32>(&c)` is.
- **A trait whose impls for a type are ambiguous** (a blanket `impl<T, U> Trait<U> for T where T: From<U>` beside
  `impl Trait<&mut Events<R>> for Other`): rustc does not reborrow a `&mut` argument whose parameter type is still to
  be inferred, so it is moved (E0382 in a loop, borrowck/mut-borrow-in-loop-2.rs). zustc picks the impl first.
- From part 16: a generic fn's `dyn Tr<T>` (regions/regions-close-object-into-object-1.rs),
  `&*vec![1].iter().next().unwrap()` (E0716 through `unwrap`'s value), the opaque type's member constraints (E0700),
  `&mut` in a tuple's inference (borrowck/issue-36082.rs), per-field regions, `use … as S` for a variant, and the
  borrow check of a `static` closure.
