# Region (lifetime) checking, part 3: closures, loans that outlive the function, lints (issue #1)

Date: 2026-11-21

Part 2 ([2026-11-21-01](2026-11-21-01-region-check-2.md)) left the check at 3844 passing compile-fail tests. This
report covers the steps since: the failing tests whose first error is about lifetimes, taken one kind at a time.

## 1. What was added

- **Signatures:**
  - A parameter whose type is a struct with no lifetimes written (`fn f(s: S) -> &T` with `struct S<'a>`) may hold
    lifetimes, so the result's elided lifetime is no E0106. E0106 is reported at the elided reference of a result
    written over several lines.
  - Each `'_` of an impl's self type (`impl S<'_>`) is a lifetime of the impl, and `Self { .. }` in a method builds
    that self type, not one with fresh regions.
  - `for<'a> T: 'a` is `T: 'static`.
  - E0195 for early-bound lifetimes, E0106 in extern blocks, for `'_` in a field's trait object, for associated type
    values and for methods with no receiver.
- **Variance:** a struct holding a trait object is invariant in the lifetimes the object's trait arguments name
  (`Box<dyn FnOnce(&mut &'a isize)>`).
- **Bodies:**
  - casts of pointers to a trait object, also with an inferred target (`p as _`), and to a struct ending in one
  - `*s` of a String or a Vec is a place the local owns (`&*line` borrows line)
  - the annotation of a `let` with no initializer is well formed, as is `let _: T = e;` when e is not followed
  - the results of builtin methods borrow their receiver
- **Closures:**
  - one that returns a mutable borrow of what it captures by reference is `FnMut`: "captured variable cannot escape
    `FnMut` closure body"
  - checked against a bound, it reaches the function's locals it captures with regions from outside: a region its
    signature binds flowing into one of them is "borrowed data escapes outside of closure"
  - one made where nothing was expected (`let f = |_| ();`) has one region for a parameter with no type written;
    passed where a bound takes a reference for any region it is "not general enough", as is a fn whose result
    borrows its parameter passed where the bound's result is a type parameter
  - closures passed to `sort_by_key`, `max_by_key` and the like are checked (`v.sort_by_key(|p| &p.name)`): those
    bounds are higher-ranked in std as the prelude writes them. The prelude's other bounds stay unchecked.
- **Borrow check:**
  - a reborrow through a reference that must outlive a lifetime of the signature lives to the end of the function,
    as NLL's universal regions hold every point (`keep.push(&v[0]); v.push(1);` with `keep: &mut Vec<&'a u8>` is
    E0502). The region check records each reborrow's region; the borrow check makes the loan live from where it is
    made.
  - a closure with no `move` borrows the copies it reads, as rustc's closures capture what they only read by
    reference (not a reference it reads: one passed where a reference is expected is reborrowed, and the closure
    holds a copy)
  - a returned closure that borrows a local is E0373 at the closure
  - returning `&f()` is E0515
  - the temporaries an assignment (`x = &f();`) or a method of a local holding references (`v.push(&f());`) borrows
    go away at the end of the statement (E0716)
- **Syntax and lints:**
  - E0637: `'_` as a bound (`impl<'b: '_>`), `&` with no lifetime in a bound's arguments (`where T: Tr<&u32>`)
  - `#![deny(unused_lifetimes)]` and `#![deny(single_use_lifetimes)]` for fns and impls

## 4. After the measurements

The steps after f91a81d, at 3910 passing compile-fail tests (5db66d5), no test lost:

- a borrow that must outlive a region of a local's type is held by that local, live while it is (as NLL):
  `foo.insert(); foo.insert();` with `fn insert(&'a mut self)` in `impl<'a> Foo<'a>`, and an argument a `&mut self`
  method stores (`s.set(&mut y); y += 1; s.get();`)
- a closure made where nothing was expected has one signature for all its calls: `let f = |y| y; f(&z); f(x)`
  returns what z's borrow flows into
- E0261 in a body's `let` annotation, and in a trait's bounds and where clause
- a temporary a `match` binds by `ref` goes away at the end of the statement; one a `let` extends
  (`let x = &f();`) with its block's locals
- tuning: `rg_call` no longer moves the whole `Rg` (some 1.4 KiB) out and back twice per call, and the
  reachability of reborrows walks one array of edges: patterns check 700.8M to 700.2M. Against main (18e598d), by
  instructions on the KPI inputs: gen5000 check +0.19%, traits check +0.29%, patterns check +0.66%.

## 5. Tried and left out

- **Temporaries of a block's tail expression** live to the end of the enclosing statement up to edition 2021
  (`y.borrow().clone()` at the end of a block that owns y). Edition 2024 ends them with the block, and zust's own
  code is edition 2024: following 2021 would reject it.
- **E0713** (a borrow through a `&mut` a value with `Drop` holds, still in use when the value is dropped): the
  parameters' drops at the end of the function are not events of the borrow check yet.
- **Two cost tunings of the implied bounds of a struct's fields** (skip structs with no regions; skip definitions
  whose fields imply nothing) changed nothing measurable, or cost more than they saved; they were dropped.

## 6. Not covered yet

- generic functions that are never called: `zustc check` does not check them at all (most of the E0310 tests)
- what a closure's body requires of the function it is in (rustc's closure requirements): a closure with no bound
  is checked alone
- the iterators of the prelude: their types hold no lifetimes, so what `.iter().map(..).collect()` borrows is lost
- higher-ranked trait selection (`impl<A> Foo for fn(A)` against `fn(&i32)`)
- the number of lifetime arguments a path writes (E0107), type aliases with lifetimes in signatures
- implicit reborrows of a `&mut` passed to a call (`(self.func)(arg)` in a loop)
