# Region (lifetime) checking, part 41: Drop impls that specialize or require more than their type, and `ref` bindings of owned places

Date: 2026-11-27

Part 40 ([2026-11-26-03](2026-11-26-03-region-check-40.md)) was merged with #278. This part takes the rules a `Drop`
impl must keep (the lifetimes and bounds the drop check relies on), and a borrow that a `ref` binding makes.

## 1. What was added

- **E0366: a `Drop` impl's self type writes the impl's own parameters, each once.**
  - Rejected: `impl Drop for P<i8>`, `impl Drop for N<'static>`, `impl<One> Drop for V<One, One>`, `impl<'l> Drop for
    W<'l, 'l>` and `impl Drop for X<3>`.
  - Accepted: `impl Drop for H<'_>`.
  - None was rejected before (dropck/issue-38868.rs, dropck/reject-specialized-drops-8142.rs).
- **E0367: a `Drop` impl requires of its type's parameters only what the definition does.** Each predicate of the
  impl's header and where clause is checked against the definition's bounds and where clauses:
  - lifetimes outliving lifetimes: `'b: 'a`, inline or in the where clause; the definition's outlives hold
    transitively (`'c: 'b`, `'b: 'a` give `'c: 'a`);
  - a type outliving a lifetime: `T: 'static` where the definition writes only `T: 'a`;
  - trait bounds, with std's supertraits and the program's own: `T: Ord` gives `T: PartialOrd`;
  - an equation on an associated type: `T: Trait<Assoc = U>` where the definition writes `T: Trait`;
  - `Sized`: an impl's parameter is Sized unless it says `?Sized`.

  The outlives the definition's fields imply count too, as rustc infers them for a type (RFC 2093): `struct
  DropMe<'a, T>(&'a T)` gives `T: 'a`. A predicate on a parameter the self type does not have may hold, so it is not
  checked (`impl<'r, T: 'r> Drop for R<T>`). The message is rustc's: "`Drop` impl requires `'b: 'a` but the struct it
  is implemented for does not". A parameter bounded by one of the program's own traits is not checked for a trait
  bound: the summaries do not record all of a trait's supertraits.
- **A `ref` binding of a place the function owns borrows it.** In `|ref line: String| make_entry(self, line)` the
  binding's region was a fresh one, unrelated to the parameter. Returning the result through the impl's lifetime was
  accepted; rustc's E0515. Now a `ref` binding is a loan of the place the borrow check has the pattern at, as `&place`
  is, where that place is one the function owns and is reached through no reference: a closure's parameter pattern
  (`__p0`), a `let`'s or a `match`'s scrutinee and their fields. Not through a reference (`|&ref x| ..`, or a
  `match self` of `self: &S`): there the binding borrows what the reference points to.
- **"function parameter" in the message.** A borrow of a closure's parameter that a pattern binds (`__p0`) was reported
  with the synthetic name: "`__p0` is dropped when the function returns". Now the message is rustc's: "cannot return
  value referencing function parameter".

## 4. Review

CodeRabbit's reviews of #324 had four findings, each checked with zustc and rustc 1.97.

- **Fixed: false E0367s.**
  - A definition's bound written twice (`struct S<T: Iterator>(T) where T: Iterator<Item = u8>`) kept only the first,
    without its equation, so `impl<T: Iterator<Item = u8>> Drop for S<T>` was rejected. The same trait again gives
    its equations too now.
  - A `?Sized` parameter bounded by a trait that makes it Sized (`T: ?Sized + Clone`, `Copy`, `Default`, or a trait of
    the program's, which may have `: Sized`) needs no `T: Sized` of the impl: it was rejected.
- **Fixed: a missed E0367 of that fix (the second review).** Every trait of the program's counted as Sized there, so
  `impl<T: Tr> Drop for S<T>` with `trait Tr {}` and `struct S<T: ?Sized + Tr>` was accepted. Now a trait's header is
  read for `Sized`, `Clone`, `Copy` and `Default` (`trait Tr: Sized`, `where Self: Sized`), through its supertraits.
- **Not done: the equations' values.** `impl<T: Iterator<Item = u16>> Drop for S<T>` with `struct S<T: Iterator<Item =
  u8>>` is accepted (E0367 in rustc). An equation is checked to be the definition's only by its presence. Listed below.

## 5. Not covered yet

- **The values of a bound's equations** (`Item = u16` where the definition writes `Item = u8`): not compared.
- **A closure passed to a prelude function** (`v.into_iter().map(|line| self.me(&line))` returning a borrow of `line`
  through the impl's lifetime, rustc's E0515, borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs): such a closure's
  body gets no region signature (its bound is the prelude's), so its body is not region-checked. A closure bound to a
  `let` first is.
- **The invariance of a trait object's arguments in a body's annotation** (`let _: Box<dyn Foo<Bar = &'a u32>> =
  make();` of a `Box<dyn Foo<Bar = &'static u32>>`, variance/variance-associated-types2.rs): accepted. The same in a
  signature is reported (as a mismatch).
- **Drop impls of a type in another module of the same name**, or of a self type written as a path (`self::S<T>`): not
  checked.
- From part 40 and before: see #166–#171.
