# Region (lifetime) checking, part 13: impls' headers, `&mut` moves and reborrows, two-phase borrows, closures' `'static` annotations, and the mismatched_lifetime_syntaxes lint (issue #1)

Date: 2026-11-23

Part 12 ([2026-11-22-09](2026-11-22-09-region-check-12.md)) was merged with #64. This step takes more of the cases
tests/ui showed accepted. Most are in the borrow check: how a `&mut` local is moved or reborrowed by a `let`, when a
method's `&mut self` is taken, and what a closure borrows when it calls another. It also compares an impl's method
with its trait through the impl's header, checks closures whose bodies write `'static`, and adds the
`mismatched_lifetime_syntaxes` lint. Two false errors on valid code are gone: `let _ = s;` in a closure, and
`move || { let _ = r; }` made into a `Box<dyn Fn()>`.

## 1. What was added

### Borrow check

- **`let b = a;` moves a `&mut` local.** `let alias = s; s.len(); alias.push('a')` with `s: &mut String` was
  accepted (E0382 in rustc). For a `let` with no annotation, the type that type inference found was passed to its
  initializer as the expected type. A `&mut` path read where a type is expected is reborrowed, so the move was not
  seen. That type is not an annotation, and a `&mut` path there is now moved.
- **`let b: &mut T = a;` reborrows `*a`.** A `let` with an annotation is a coercion site. b holds a loan of `*a`
  (rustc's `&mut *a`), so writing `*a` while b lives is E0506 (borrowck/borrowck-loan-of-static-data-issue-27616.rs).
  Before, b held a copy of a and no loan. A move of a `&mut` while a shared reborrow of it lives
  (borrowck/borrowck-move-mut-base-ptr.rs) is reported now too.
- **A method's `&mut self` is taken at the call, while its arguments are live.** `v.ext(&v)` with
  `fn ext(&mut self, _: &S)` was accepted (E0502). The two-phase borrow's reservation (a shared loan while the arguments
  are evaluated) ended, and the `&mut` loan was taken, after the arguments' values had gone. The `&mut` loan is now
  taken at the call, as an operator's is, while the arguments are still held.
- **`v.extend(&v)` and `v.extend(shared)` with `shared = &v`.** `extend` is lowered as
  `let __exr_ext = <arg>.iter(); v.extend(__exr_ext)`. The local did not hold what the iterator borrows, so v's `&mut`
  did not conflict with it (borrowck/two-phase-reservation-sharing-interference-2.rs). It holds it now, and v's
  `&mut` is taken while it does.
- **A closure that calls a captured `FnMut` closure borrows it mutably.** `let tick2 = || { tick1(); };` with
  `tick1` mutating what it captures captures `tick1` by `&mut`. So tick2 is `FnMut` itself, and both bindings need
  `mut` (E0596, unboxed-closures/unboxed-closures-infer-fnmut-calling-fnmut-no-mut.rs).
- **`let _ = place;` in a closure captures nothing (edition 2021).** `move || { let _ = s; }` moved s into the
  closure, so a later use of s was "use of moved value". A `Box<dyn Fn()>` of `move || { let _ = r; }` required r's
  borrow to be `'static`. rustc accepts both (RFC 2229's fake reads). Before edition 2021 the closure captures the
  variable, as rustc does. Which edition applies goes into the summaries' cache key.
- **A block's tail's temporary holds what its value holds, as lowered.** A temporary receiver that has a `Drop`
  impl (`id(rows).len()`, `rows.wrap().len()` as a block's tail) is dropped after the block's locals. What it holds was
  read off its type, not off what lowering it borrowed, so the loan of `stmt` it held through `rows` was missed
  (nll/issue-54556-stephaneyfx.rs, E0597).
- **A constructor called with an argument known only at run time makes a temporary.** `f(&Some(s))` was taken for a
  promoted constant, so the borrow outlived the statement unnoticed (E0716). Only constructors of constant arguments
  are promoted now.
- **A reference copied out of what a call's result points into does not hold the borrow that reached it.**
  `let t = *names.first().unwrap(); names.clear();` with `names: Vec<&str>` was rejected; rustc accepts it, and main
  rejects it too. So were `names.first().copied()`, `m[&1]` of a `HashMap<u8, &str>`, `w.iter().copied().next()` and
  `r.clone()` of a `&&str`. Now a loan of a place whose type holds the copied type (the container, or the reference
  itself) stands for what that place holds. A loan of anything else (`&s` in `*id(&&s)`) is kept.
- **`(&x).clone()` with `x: T` and no `Clone` bound is the reference's copy.** It borrows x, so returning it is E0515
  (borrowck/borrowck-return-variable-on-stack-via-clone.rs).

### Regions

- **An impl's method against its trait through the impl's header.** In
  `impl HaveRelationship<&ProofReader> for Article`, the trait's `fn get_relation(&self) -> To` has the header's
  `&ProofReader` as `To`, a region of the impl that `&self` is not known to outlive. `fn get_relation(&self) ->
  &ProofReader` was accepted (traits/param-without-lifetime-constraint.rs, "`impl` item signature doesn't match").
  The header's trait arguments are now universal regions of the comparison. A header's `&'static` is not compared,
  and an impl method's `&'static` input is less general (E0308).
- **A closure body with a `'static` annotation is checked.** `|| { let p: &'static mut usize = &mut self.food; }`
  was accepted (regions/regions-addr-of-upvar-self.rs). A closure is region-checked only with a region signature,
  and this one had none: no bound, no annotated parameter, and its function's check was off. The closure now turns its
  function's check on there, as the function's own `let x: &'static T` does, and gets a signature. What it reaches
  through its captures is then borrowed for less than `'static`.
- **E0107 for a struct in a fn's signature written with another number of lifetime arguments.** `Foo<'_, '_, 'a>`
  for `struct Foo<'c, 'd>` was not checked in signatures (lifetimes/noisy-follow-up-erro.rs,
  generic-associated-types/missing_lifetime_args.rs). Only the program's own types are checked. A prelude type
  written so (`Cow<'static, str>`) is not, as the prelude's are not all declared with their lifetimes.

### Lints and lines

- **`mismatched_lifetime_syntaxes`.** With `#![deny(mismatched_lifetime_syntaxes)]`, or the item's own
  `#[deny(..)]`, a free function whose output writes one of its inputs' lifetimes another way is an error. The syntaxes are named
  (`'a`), elided (`&u8`) and hidden (`S` for `S<'_>`). Examples: `&'a u8` in and `&u8` out, or `&u8` in and `S` out.
  The output's elided lifetimes resolve as elision does: to the receiver's lifetime, else to the one input lifetime.
  The messages are rustc's (lifetimes/mismatched-lifetime-syntaxes-details/: example-from-issue48686.rs,
  missing-lifetime-kind.rs, not-tied-to-crate.rs, path-count.rs, static.rs).
- **`impl Trait + use<'_>` with one named input lifetime.** `fn e<'a>(v: &'a u8) -> impl FnOnce() + use<'_>` was
  E0106 ("missing lifetime specifier"). `'_` there is the one input lifetime.
- **E0310 of a call with no argument where the check begins.** `s::<T>()` with `fn s<T: 'static>()`, in a function
  whose check began at that call, was reported at the function's first line. It is reported at the call.
- **A closure's capture written through a `&`.** `|| { z.0.0.0 = .. }` with `z.0.0: &(String, String)` is reported
  at the closure, as rustc does, not at the use in its body
  (closures/2229_closure_analysis/diagnostics/cant-mutate-imm-borrow.rs, mut_ref.rs).

## 4. Review (CodeRabbit, checked against rustc 1.97)

CodeRabbit's first review of #67 had 11 findings. Each was checked by running zustc on a program that shows it. Nine
showed the wrong result they describe. The other two showed none in what was tried, and are fixed too. All are tested
(`part13_review`).

The nine:

- **`mismatched_lifetime_syntaxes` attributes as lists** (two findings). `#[deny(dead_code, mismatched_lifetime_syntaxes)]`
  did not turn the lint on for the item. Under a crate-level deny, `#[allow(dead_code, mismatched_lifetime_syntaxes)]`
  and `#[expect(..)]` did not turn it off. An item's `allow` / `expect` / `warn` / `deny` / `forbid` lists are now read.
- **A type parameter named as a struct** (`fn f<'a, S>(x: &'a u8) -> (Option<S>, &'a u8)` with a `struct S<'s>`) was
  taken for the struct, which hides a lifetime: a false error of the lint. Such a struct is left out for the function.
- **`let _ = x;` is a use of x for the unused-variable lint.** Since the fake reads, `#![deny(unused_variables)]` reported
  x as unused in edition 2021.
- **A `let .. else` block in a closure** (two findings). Its `let _ = x;` was not found as a fake read, though the
  capture analysis skipped it, so lowering x failed ("cannot find value"). Its `let p: &'static usize = x;` did not turn
  the closure's check on. Both kinds of `let` are now found inside `else` blocks.
- **A program's own `clone`.** `(&local).clone()` with `fn clone(&self) -> &'static S` on S was read as the reference's
  copy, so returning it was a false E0515. That reading is now only for a referent with no `clone` method.
- **`let _ = s.missing;` in a closure** is skipped as a fake read, so the missing field was not reported. It is E0609
  now, where the closure is made.
- **`s.take(s.get())`** with `fn get(&self) -> &u8` and `fn take(&mut self, _: &u8)` was accepted (E0502 in rustc). An
  argument's shared loan was not held until the `&mut self` was taken. When a call's `&mut self` is taken after its
  arguments, what an argument holding references borrows is now held until then. `r.clone()` of a `&&str` is a
  copied-out `&str` (section 1), so `v.push(v.first().unwrap().clone())` stays accepted.

The two:

- **The edition in the cache keys.** It decides what a closure captures, but the functions' keys and the crates'
  fingerprints did not hold it. A single file built in two editions into one directory was already right, since the
  closure's summary changes its parent's key. Both now hold the edition, so a workspace crate's fingerprint changes too.
- **`trait Dup: Clone`.** The summaries leave `Clone` and `Copy` out of a trait's supertraits, so a `T: Dup` was taken for
  a type that is surely not Clone. No program tried gave a wrong result. A marker is now kept for them, and a test
  guards the case (`duplicate::<T: Dup>(x)` builds and runs).

## 5. Not covered yet

- **A trait object's default lifetime in an impl's header.** `impl DebugWith<dyn DebugContext> for Foo` makes the
  trait's `Cx` a `dyn DebugContext + 'static`, so `bar.debug_with(cx)` with `cx: &dyn DebugContext` lets borrowed
  data escape (nll/issue-54779-anon-static-lifetime.rs). The object's region is a fresh variable at the call, not the
  header's `'static`. The same holds for a method of `impl dyn Error + 'static` called on a `&dyn Error`
  (regions/regions-static-bound-on-type-param.rs).
- **A trait object with a type parameter** (`dyn A<T>`) keeps its text as written: a struct field of that type does
  not take an instance's type arguments, so `B(&*v)` with `B<'a, T>(&'a (dyn A<T> + 'a))` is not inferred
  (regions/regions-close-object-into-object-*.rs).
- **What a closure's body requires of a local it captures by reference** is not passed back to its function: a
  closure's `let p: &'static usize = &x;` of a local x is accepted. The requirement falls on the closure's environment,
  which is from outside the closure, and its function does not see it. Only a capture whose region is the function's
  own (a parameter's, `self`'s) is checked.
- **A call in a closure that requires `T: 'static`** of the function's type parameter (nll/issue-98693.rs) is not
  checked: a closure's body has no placeholder regions for its function's type parameters.
- **A local holding a reference, passed to a method of what it borrows** (`let w = &v; v.ext(w)`): the argument is
  read before the receiver's `&mut` is taken, and w's loan is not held until the call.
- **`mismatched_lifetime_syntaxes`** is checked for free functions' signatures only (not methods, not trait
  items), and only the first mismatch in the source is reported (rustc reports each). A macro's expansion is not
  checked (lifetimes/mismatched-lifetime-syntaxes-details/macro.rs).
