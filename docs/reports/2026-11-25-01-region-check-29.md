# Region (lifetime) checking, part 29: temporaries whose drop uses what they borrow, the scopes that end them, a returned temporary's E0515 (issue #1)

Date: 2026-11-25

Part 28 ([2026-11-24-14](2026-11-24-14-region-check-28.md)) was merged with #154. This step adds:

- a temporary whose type implements `Drop`, made as a field access's base or a method's receiver, that holds what it
  borrows until it is dropped;
- the scopes that drop such temporaries where rustc drops them: an `if`'s or a `while`'s condition, a match guard, a
  loop;
- E0515 where a value that holds a temporary's loan is returned, not E0716 where the temporary goes away;
- the iterator library for a slice iterator's type named in a signature (`&mut std::slice::Iter<'a, T>`);
- the position of an earlier borrow at a node the lowering made (`&*v` of a Vec).

## 1. What was added

- **Temporaries whose drop uses what they borrow.** Take `struct D<'a>(&'a [i32])` with `impl Drop for D<'_>`. In
  `for x in D(&*v).iter() { v.push(*x); break; }`, the `D` temporary lives until the loop ends, and its drop may use
  `&*v`. rustc reports E0502 at `v.push` (borrowck/issue-82462.rs). zustc dropped the temporary's loans where the
  receiver had been evaluated.
  - Such a temporary as a field access's base (`D(&*v).0`) or a method's receiver (`D(&*v).iter()`) now holds its
    loans until it is dropped:
    - at the end of its statement;
    - after the loop, for a loop's header;
    - with each iteration, for a `while let`'s scrutinee.
  - This is done only for a type whose drop may use what it borrows (dropck). `W(&*v).iter()` with a `W` that has no
    `Drop` is still accepted, and so is `let n = D(&*v).0.len(); v.push(n as i32);`.
  - As a block's tail, `match D(&*v).0.len() { n => v.push(n as i32) }` is E0597 for `v`, as in rustc: the
    temporary outlives the block's locals.
  - Before this, an `iter()` of the program's own type that returns `std::slice::Iter<'_, i32>` failed to type-check:
    - "`.iter()` is only supported directly in a `for` loop";
    - or "no method named `into_iter` found for `Iter<i32>`".
  - The prelude's iterator library was not pulled in where only the type was named. It is now, also for
    `xs: &mut std::slice::Iter<'a, i32>`.
- **The scopes that end such temporaries.** In rustc, an `if`'s or a `while`'s condition and a match guard are
  terminating scopes: their temporaries are dropped at their end, before a branch, the body or the arm runs. The first
  version of this work kept the temporaries above to the end of the statement:
  - that gave false E0597s for a condition or a loop in a block's tail;
  - a guard's temporary conflicted with its arm. The first cycle rejected match/match-ref-binding-in-guard-3256.rs, a
    run-pass test.
  - The temporaries of a condition and of a guard are now dropped at their end. `if D(&*v).0.len() > 0 { v.push(1); }`
    and `while D(&*v).0.len() < 5 { v.push(1); }` are accepted, as in rustc.
  - The temporaries of a loop's header are dropped with the loop. In a fn's tail, zustc now agrees with rustc on these
    cases:
    - `for x in D(&*v).iter() {}` and `while D(&*v).0.len() > 5 {}` are accepted;
    - `for x in D(&*v).0.iter() {}` and `while let Some(_) = D(&*v).0.first() { break; }` are E0597.
- **A returned temporary's loan.** Take `fn f(xs: Vec<i32>) -> Vec<&'static i32>` with
  `for ref x in xs { result.push(x); } result`. `x` borrows the loop's item, a temporary. rustc reports E0515 at
  `result` ("cannot return value referencing temporary value"); zustc reported E0716 at the loop's header.
  - The E0716 of a temporary's loan that a returned value holds is now E0515 where it is returned.
  - This holds also after a use of the returned local (`println!`) or an assignment to it (`result = Vec::new()`),
    where rustc reports the same.
  - Over a `&mut std::slice::Iter`, the item's temporary is made in the loop's header. Binding it for the next item
    drops its old loan from what `result` holds, so the return held none: the E0716 was at the fn's line.
    - The E0716 now keeps the live locals that hold the loan.
    - A return of one of those locals makes it E0515 there.
  - A loan that no returned value holds stays E0716 (`*result[0]` of such a `result`).
- **Positions of nodes the lowering made.** `&*v` of a Vec is lowered to `&v[..]`, whose nodes have no position. The
  earlier borrow of an error there was "(at 1:1)" or at the fn's line. It is at the operand `v` now, where rustc
  points.

## 5. Not covered yet

- **A `&` expression's own position.** The AST's `&` has no position, so the borrow of `D(&v)`, or of `&*b` with a
  Box, is at its operand. That is one column after rustc's `&` (4:43 for rustc's 4:42), as on main. Only the message's
  "(at …)" shows it.
- **The errors after a fn's first.** zustc reports one error for each fn. For `match D(&*v).0.len() { n =>
  v.push(n as i32) }` as a fn's tail, rustc reports the E0597 and then an E0502; zustc reports the E0597.
