# `Sized`: where only a sized type may be (E0277)

Date: 2026-11-25

Among the rustc UI tests zustc wrongly accepted, the largest group of trait errors was E0277 for `Sized`: 56 tests
whose expected error is "the size for values of type `X` cannot be known at compilation time". zustc already
rejected an unsized local, an unsized parameter and `*s` by value, and #149 (merged while this was written) added
`driver2::sized_error`, which reads the concrete unsized types (`[T]`, `str`, `dyn Tr`) written in the program's
items. This step adds what needs the resolved types: type parameters declared `?Sized`, the types written in
bodies, and calls.

## 1. What was added

- **Calls of the program's generic fns.** A fn's own type parameter that is not `?Sized` must be given a sized type:
  `takes::<str>()`, or `takes(s)` with `s: &str` and `fn takes<T>(_: &T)`.
  - A placeholder of a caller's `?Sized` parameter may be unsized: `fn relaxed<X: ?Sized>(x: &X) { sized::<X>(x) }`
    is an error even when nothing calls `relaxed` (`zustc check` checks it with placeholders).
  - The same holds for `std::mem::size_of::<T>()` / `align_of::<T>()`.
- **Types written in bodies.** A type that puts a maybe-unsized type where only a sized one may be:
  - an argument of the program's struct or enum for a parameter not declared `?Sized` (`Foo<str>`, `Foo<T>` of a
    `T: ?Sized`);
  - an argument of std's `Vec`, `Option`, `Result`, `VecDeque`, `HashMap` / `HashSet`, `BTreeMap` / `BTreeSet`,
    `BinaryHeap`, `LinkedList`;
  - a tuple's element other than the last, a slice's or array's element (`[[u8]; 2]`).
- **Definitions and signatures.**
  - a struct's field other than the last, an enum's or a union's field (`struct S { a: [u8], b: u8 }`);
  - an impl's self type and trait arguments (`impl Foo for Option<[u8]>`);
  - a fn's argument types and its result (`fn f() -> [u8]`, `fn iceman(c: Vec<[i32]>)`, `fn g<X: ?Sized>(x: X)`).
- **What is sized.** A struct whose last field is a `?Sized` parameter given a maybe-unsized placeholder may be
  unsized too (`Bar<T>` of a `T: ?Sized` with `struct Bar<T: ?Sized>`). A `?Sized` parameter whose other bounds
  imply `Sized` is sized (`T: Clone + ?Sized`; Clone's supertrait).

## 2. How

- The signature's summary keeps the fn's own `?Sized` parameters (`SigSyn::own_unsized`). Program derives which of
  the fn's own parameters must be sized (those after its impl's or trait's), for the program's fns only.
- A placeholder made for a `?Sized` parameter is marked (`StructDef::maybe_unsized`). `Program::maybe_unsized` is
  an unsized type or such a placeholder; `Program::sized_wf` walks a type for the rules of section 1.
- The errors from a placeholder instance carry the solver's mark (`SOLVED_NO`): they hold whatever the caller's
  types are, so `zustc check` reports them.
- Definitions and signatures are checked in `driver2::sized_wf_error`, on the resolved types, after #149's
  `sized_error` (which reads the written types and reports the concrete ones at rustc's column). It runs for every
  program (the well-formedness check `wf_error` runs only when a parameter is bounded).

## Review fixes (#180)

Each checked against rustc first:

- a by-value `W<T>` of a `T: ?Sized` with `struct W<T: ?Sized>(T)` in a signature is E0277 (the struct's tail
  makes it maybe-unsized: `Program::maybe_unsized_with`); `&W<T>` stays valid;
- a `?Sized` parameter bounded by a program trait whose supertrait implies Sized (`T: Dup + ?Sized` with `trait Dup:
  Clone`) is sized: the parameters are classified once the supertraits are known;
- a closure's `call` takes its parent's parameters, not its own: it no longer makes a `?Sized` one sized;
- a `?Sized` parameter as a trait argument for a parameter of the program's trait not declared `?Sized`
  (`impl<T: ?Sized> Tr<T> for ()` with `trait Tr<T> {}`) is E0277;
- a signature's error is at the argument's or the result's type, as rustc, when the signature spans lines;
- a `let`'s annotation that is not sized is E0277 whatever its initializer (`let _: Vec<str> = loop {};`), and
  in a destructuring `let` too;
- the signature's hash (`Program::hash_sig`) includes which parameters must be sized, so a caller is checked again
  when that changes.

## 3. What it does not do

- The prelude declares no `?Sized` (`Rc<T>`, `Arc<T>`, `RefCell<T>`, `ManuallyDrop<T>`...), so only the std types
  listed above are checked, and `ManuallyDrop<T>` of a `T: ?Sized` is not unsized.
- An impl's own `?Sized` parameters are not known to its methods' calls: they are taken as sized there (a missed
  error, never a false one).
- An associated type's value against the trait's implicit `Sized` (`type A = str` for `type A;`) is not checked.

## 4. Results

rustc's tests/ui: 15 more compile-fail tests pass than on main (5299 → 5314; 24 against main before #149), with no regressions; each was checked to have rustc's size error on the line zustc reports. `cargo test --release --workspace` passes.

New tests: `tests/compile_errors/sized_*.rs` (a generic call, a `?Sized` parameter passed on, a struct's argument,
a field other than the last, a method's `Vec<[i32]>`), and `tests/check.rs` (`sized_accepts`, programs rustc accepts;
`sized_rejects_maybe_unsized_param`, the placeholder cases).
