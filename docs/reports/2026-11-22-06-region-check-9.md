# Region (lifetime) checking, part 9: block tails, match guards, destructors, and items in fn bodies (issue #1)

Date: 2026-11-22

Part 8 ([2026-11-22-05](2026-11-22-05-region-check-8.md)) was merged with #48. Its last review fixes went in after
its report was written: constant blocks in literals are promoted, a struct update reads its base, a store through a
reborrow (`q = &mut *p`) reaches what p points to, and a store through a `&mut` of a `&mut` does not escape through a
parameter the inner one points to. This step takes more of the borrow check's cases that tests/ui showed accepted, and
reports the borrow errors of fns written inside other fns.

## 1. What was added

### Borrow check

- **A block passed as an argument:** what the block's tail borrows is what the call is given.
  - `gimme({ let v = 22; &(v,) })` used past the statement is E0716, as `gimme(&(v,))` is.
  - So is `let x: &str = { mk().as_str() };`: the receiver `mk()` is the statement's temporary.
  - A `let` still extends a block tail's own borrow: `let s = { let v = 1; &(v,) };` is accepted.
- **`&{ .. }` is a temporary:** a block's value is moved or copied out of what its tail names.
  `gimme(&{ let v = 4; (v,) })` used past the statement is E0716.
- **`let _ = x;` keeps x live:** it is not a read of x, but rustc's fake read makes x live there.
  - So `let r = &y; y = 2; let _ = r;` is E0506.
  - `let _ = x;` after x is moved is still accepted.
- **E0510, a match guard that changes the matched place:**
  - In the guard of a match whose patterns test the scrutinee, assigning that place, a place it is part of, or what
    it points to is an error. So is borrowing it mutably, for example through a closure that captures it.
  - rustc's fake borrows are shallow, so a part of the place is not affected (`s.b = 2` in a guard of `match s`).
  - A match that tests nothing (`match x { y if .. }`) borrows nothing.
  - The check walks the borrow check's events in the order they are made. A guard is one piece of the source, so no
    dataflow is needed.
- **E0713, a borrow still in use when a destructor runs:**
  - The borrow is through a `&mut` field of a value whose type implements `Drop`, and the function returns it.
    The value's `drop` runs when the function returns and may use the field (`&mut *s.0` with `s: Scribble`).
  - This holds through boxes (`(*s).0` with `s: Box<Scribble>`) and through a reference a local holds
    (`let r = &*v.0; &r.0`).
  - A `&` field is not affected: a shared borrow is copied out.
- **A method reached through a user's `Deref`:** `x.get()` with `get` on the target calls `deref(&self)`. The
  receiver is borrowed shared, and a result that borrows from self borrows from it. Assigning `x.c` while the result
  is used is E0506. Before, the receiver was only read.
- **E0507, a closure that moves out what it captures:** a closure written where a bound wants `Fn` or `FnMut` is
  that kind of closure. Moving a capture out of it (`take_mut(|| { let s: String = val; })`) is an error at the move,
  as rustc reports it. A closure passed by name was E0525 at the closure already.
- **`for n in v` with `v: &mut Vec<T>` moves v:** `IntoIterator::into_iter(v)` takes a type parameter, which is no
  coercion site, so the `&mut` is not reborrowed. A second loop over v is E0382. `v.iter_mut()`, `&mut *v` and a `&`
  are not affected.

### Regions

- **A trait's parameters are invariant:** take a callee bound `G: Get<T>` with T = `&'min i32`, and a caller whose
  own type parameter G has the bound `G: Get<&'max i32>`. The two regions must be the same, so with only
  `'max: 'min` known, the call is an error ("lifetime may not live long enough").

### Items in fn bodies

- `fn main() { fn helper() { .. } }`: the helper is moved past the source's last line before it is checked, and
  `zustc check` dropped every error past that line. Such a fn's borrow errors were never reported.
- Its borrow and region checks' errors are now reported, at the lines the item was moved from.
- Its other errors are still left out. typeck does not know everything the item may name where it was, such as the
  `Self` of the impl around it or a bound on `&mut T` it relies on, so those errors would reject valid programs.

### Prelude

- `Pin<P>` implements `Display` and `Debug`, printing what its pointer prints, as std's does. A test that printed one
  stopped at that type error before its borrow errors were reached.

  array, not a `Vec` per event.
- Measured alone, these take the check from 710.39M to 705.98M (-0.62%). The new checks add some of it back: the
  match guards' events, the `Drop` owners of E0713, and the receivers' loans through `Deref`.

## 5. Review

CodeRabbit's findings on #51 were checked against rustc 1.97.

- **Valid code that was rejected:**
  - A closure that binds a captured name again (`let val = String::new(); drop(val);` in a `move` closure for an
    `Fn` bound) was E0507: the move checks went by names. They now follow scopes: past a `let`, and in an arm, a loop,
    an `if let` or a nested closure that binds the name, it is not the capture. A move before the `let` is still
    E0507.
  - `&**s.data` with `data: &mut &'static u32` of a `Drop` type was E0713. A borrow past a `&` deref after the `&mut`
    one borrows what the shared reference points to, which the drop does not reach.
  - `match s { S { .. } if { s = ..; false } => .. }` was E0510, though `S { .. }` tests nothing.
- **Errors that were missed:**
  - A guard protects the places the patterns test, not only the scrutinee: `pair.0 = None` in a guard of a match
    whose arms test `.0` is E0510, and so is assigning `pair` itself; `pair.1` is not affected.
  - It also protects the deref prefixes of the place bindings come from: `ptr = &2` in a guard of
    `match *ptr { v if .. }` is E0510.
  - E0713 through a `Drop` value in a field (`&mut *(w.0).0` with `w: Wrapper(Scribble)`).
  - E0507 for a nested `move` closure that captures what the outer `Fn` / `FnMut` closure captures, at the nested
    closure.
  - A receiver reached through `Deref` stays borrowed while the arguments are evaluated (`w.read(drop(w))`, E0505).
  - A callee's `'static` in a trait bound (`need_static::<G>()` with `G: Get<'static>`, from `G: Get<'a>`).
  - An fn in an fn body: the borrow errors `cannot use .. because it was mutably borrowed` and `use of partially
    moved value` are reported too, and the positions a message names are at the lines the fn was moved from.
  - `Pin<P>` implements `Debug` and `Display` only when P does.
- **Not changed:** `take_mut(move || read(r))` with `r: &mut i32` was said to be rejected; it is accepted.

## 6. Not covered yet

- **Where-clauses on types that are not type parameters** (`where &'max G: Get`): typeck does not know such a bound,
  so the placeholder instance of the fn does not type-check, and its regions are not checked
  (variance/variance-*-self-trait-match.rs).
- **Other errors of items in fn bodies:** see section 1.
- **From the review of part 8:** a local named in uppercase (`V`) is taken for a constant, so `gimme(&(V,))` is a
  missed E0716. E0582 counts a projection's lifetime (`X::Assoc<'a>`) as an input, as the parser cannot tell it from
  a module's type.
- **From the review of #51:**
  - zustc's check of a format argument does not look at the bounds of the impl it finds, so `{:?}` of a
    `Pin<&NoDebug>` is accepted (as for any generic impl with such bounds).
  - A `&mut` a closure captures is not among the captures whose moves are checked (it is reborrowed where it is
    passed), so `drop(r)` in a closure for an `FnMut` bound is a missed E0507.
  - Assigning `*ptr` in a guard of `match *ptr { v if .. }` is E0506 in rustc (the guard's binding borrows it); it
    is accepted.
- **tests/driver2.rs and `probe/stdin_read`:** when many programs are built in one test process and the test runs in
  the background, the program sometimes reads input it was not given. It passes run alone, run in the foreground, and
  in CI. The cause is not found yet.
