# Region (lifetime) checking, part 26: a `&mut` passed as a `&`, reborrows at coercion sites, call arguments' reborrows, a `&mut` in an aggregate (issue #1)

Date: 2026-11-24

Part 25 ([2026-11-24-11](2026-11-24-11-region-check-25.md)) was merged with #132. This step adds:

- a `&mut` local passed where a `&T` is expected stays a `&mut` (a false error main gives too);
- the reborrow of a place of a `&mut` at a `let` with a written type, a constructor's field and an assignment;
- the reborrow of a call's argument without the region check, and the result that holds it;
- a `&mut` in a tuple, a struct, a closure or an array, which is moved, not copied.

## 1. What was added

- **A `&mut` passed as a `&`.** `let x = &mut v; g(x); *x = 1;` with `fn g(_: &i32)` gave a false "cannot assign to
  `*x`, which is behind a `&` reference", on main too; so did `x.push(2)` after `g(x)` with `fn g(_: &Vec<i32>)`.
  - Type inference unified the two reference types, and the `&T` won. The `let`'s type became `&T`, and `&mut v` was
    coerced to it.
  - A `&mut T` and a `&T` are not unified now, only what they point to. That is a coercion, as `&Vec<T>` to `&[T]`
    is.
  - Where inference fills the holes of a written type, the reference mutabilities it writes are kept:
    `let y: &mut [_] = &x[2..4];` is still a mismatch (array-slice-vec/slice-mut.rs).
- **Reborrows at coercion sites.** A place of a `&mut T` where a reference is expected is reborrowed: the value holds
  a loan of what the place points to (rustc's `&*p` / `&mut *p`). The place may be a local, a field, `*y`, or a field
  reached through a `Box` or a `RefCell` guard. Before, only `let b: &mut T = a;` with a local a was reborrowed.
  The sites:
  - a `let` with a written type, `&T` too: `let v: &i32 = x; *x = 1; println!("{}", v);` is E0506;
  - a constructor's field: `S { f: x }` with `f: &'a i32`, and `Some(x)` where an `Option<&i32>` is expected;
  - an assignment's right side: `x = y;` with `y: &mut i32`, then `*y = 1` while x lives, is E0506.
  - main rejected some of these programs for the wrong reason, the "behind a `&` reference" of the inference above.
    Others it accepted. They are rejected as rustc does now.
  - A reborrow through a local assigned to the local itself (`y = &mut *y;`, `y = y;`) leaves no loan of `*y`.
    Overwriting y kills the loans of what its old value points to, the new value's too, as in rustc
    (nll/self-assign-ref-mut.rs). The explicit form was a false error on main.
- **A call's argument reborrowed without the region check.** `take(x)` with `fn take(_: &mut i32)` now borrows `*x`
  at the call. Before, it did only where the region check was on.
  - A loan of `*x` that is live there conflicts: `let v = &*x; take(x); println!("{}", v);` is E0502.
  - Where the parameter is a `&`, the reborrow is shared (`pick(x, &b)` is `pick(&*x, &b)`).
  - A result that the signature says borrows from the argument holds the loan:
    `let r = pick(x, &b); *x = 1; println!("{}", r);` is E0506.
- **A `&mut` in an aggregate.** The borrow check counted a `&mut` in a tuple, a struct, a closure or an array as
  `Copy`, as it counts a `&mut` itself: that one is reborrowed where it is passed. Nothing reborrows it inside an
  aggregate, so the aggregate is moved now. With `t: (&mut i32, i32)`, `let t2 = t;` is E0505 while `*t.0` is
  borrowed, and a use of t after it is E0382.

## 4. Review

CodeRabbit's review had 3 findings. Each was checked with zustc and rustc 1.97, and all 3 held. All are fixed in the
commit after the report's.

- **A loan of an owned field dropped by a self-reborrow's rule.** Take `s = S { r: &s.n, n: 1 }; s.n = 5;` with s
  used after. rustc and main report E0506; this part accepted it.
  - The rule that a reborrow through a local assigned to the local itself leaves no loan dropped every loan of a
    part of that local. It drops only the loans through a reference now. A loan of an owned part, like `s.n`, stays.
- **A deref coercion through the reference a `&mut` points to.** `let y: &i32 = x;` with `x: &mut &i32`, then
  `*x = &b;` while y lives: rustc accepts it, and this part gave a false E0506. main gave a false "mismatched types".
  - The coercion is `&**x`. Its loan is of `**x` now, which overwriting `*x` does not touch, as in rustc.
  - `let y: &&i32 = x;` still borrows `*x`, and so does a coercion through a `Box`, which owns what it points to.
- **A fn pointer's result.** `let r = f(x); *x = 1; println!("{}", r);` with `f: fn(&i32) -> &i32` is E0506 in rustc.
  This part accepted it; main rejected it for the wrong reason.
  - A direct call's result held the reborrow of a `&mut` place passed to it. A call through a fn pointer did not:
    the loans made for its arguments are not passed on.
  - The result now holds the reborrows of the arguments it may borrow from, as it already holds what they hold.

tests/regionck.rs checks the cases (`part26_review`).

## 5. Not covered yet

- **`it.by_ref().take(n)`** gives a false E0507, on main too. `&mut I` is an `Iterator` itself, but zustc takes the
  method of `*it`, by value. Dropping the error alone would make a build copy the iterator out, so the original would
  not advance.
- **A fn pointer type with `for<..>` written through a type alias** (`type G = for<'cx> fn(&'cx S) -> &'static S;`,
  regions/regions-fn-subtyping-return-static-fail.rs): the alias's type keeps no regions. Written in a `let`, it is
  checked.
- **A fn pointer type that binds several regions**: one universal region stands for all of them, so a fn returning
  its first argument's region is accepted as `for<'x, 'y> fn(&'x u8, &'y u8) -> &'y u8`.
- **An argument whose expected type is still an inference variable** (`Other::handle(value)` in a loop where two
  impls may fit, borrowck/mut-borrow-in-loop-2.rs): rustc moves it, zustc reborrows it.
- **`f(x, &*x)`** with `f(&mut i32, &i32)`: without the region check, the first argument's reborrow ends at that
  argument, so the second one's borrow does not conflict with it (E0502 in rustc).
- From part 25 and before: see [part 25](2026-11-24-11-region-check-25.md), section 5.
