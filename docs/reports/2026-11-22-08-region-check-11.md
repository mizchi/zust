# Region (lifetime) checking, part 11: match tails, tail temporaries, closures' bodies, lifetimes written in paths, and trait objects' receivers (issue #1)

Date: 2026-11-22

Part 10 ([2026-11-22-07](2026-11-22-07-region-check-10.md)) was merged with #53. This step takes more of the cases
tests/ui showed accepted. It also makes zustc accept valid code with a turbofish on a struct literal, a struct
pattern, or a constructor used as a function, which it rejected.

## 1. What was added

### Borrow check

- **A match that is the fn's tail returns its arms' values in their scopes.** What an arm returns by naming one of
  its bindings (`S(&mut ref mut r) => r`), or by a constructor of one (`Some(r)`), is returned while the binding is
  in scope. Through a `Drop` value's `&mut` field, that is E0713 (nll/enum-drop-access.rs). A tuple struct's or a
  variant's constructor holds what its arguments do.
- **A variant's pattern moves by type:** `let E::V(n, _) = e;` with n an integer copies, in a closure for an `Fn`
  bound too (from the review of #51).
- **The scrutinee of an `if let` / `match` in a closure comes with the patterns:** `if let E::V(_, s) = e { drop(s) }`
  and `match o { Some(s) => drop(s), .. }` in a closure for an `Fn` bound move the capture out (E0507).
- **A block's tail's temporaries outlive the block's locals** (edition 2021). A temporary a method is called on
  (`D(&_t1).end()`), whose `Drop` may see what it borrows, uses its loans at the end of the enclosing statement. So a
  loan of one of the block's locals is E0597 (nll/issue-54556-*.rs). The body's tail's temporaries go away after its
  locals too. From edition 2024, they go away at the block's end, before its locals.
- **`a;` in a closure moves a**, as `let x = a;` does: a closure made in a loop that does it is E0382 the second
  time (moves/issue-75904-move-closure-loop.rs).
- **A guard sees a `ref mut` binding as shared:** assigning through it is E0594, borrowing it mutably E0596, in a
  closure too (nll/issue-27282-reborrow-ref-mut-in-guard.rs).
- **A `&mut` bound by value by a pattern is moved:** `if let Some(x) = opt` with opt an `Option<&mut T>`, in a loop,
  is E0382 the second time (borrowck/move-in-pattern-mut-in-loop.rs).
- **A receiver written as a borrow stays borrowed during the arguments:** `(&mut x).with(|v| x = ..)` is E0499
  (borrowck/borrowck-autoref-3261.rs).
- **What a returned value borrows is followed through a cast and `Box::new`:** `Box::new(B(&*v)) as Box<dyn X>` is
  E0515. A boxed closure that borrows a local, returned, is E0373 (tests/security/borrow_closure_escapes.rs, a TODO
  before).
- **A `&mut` through a reference a closure captures** (`|| set(&mut *x)` with `x: &mut isize`) borrows `*x` uniquely.
  The capture is a `&mut` one, so through a `&` it is E0596, and two such closures alive at once conflict (rustc's
  E0524; borrowck/borrowck-closures-mut-of-*.rs).
- **A closure's capture held by reference is the place it points to, in the body.** The body borrows and assigns it
  as its own place, so `let p = &this.x; &mut this.x;` in the body is E0502 (borrowck/borrowck-closures-unique-imm.rs).
  What the body moves or writes through such a capture is checked where the closure is made, as before.
- **A trait object's method borrows the receiver,** by `&self` / `&mut self`. A result that borrows from self holds
  the loan, as for a method of a struct. `let y = x.borrowed(); let z = x.mut_borrowed(); y.use_ref();` with x a
  `&mut dyn Foo` is E0502 (borrowck/borrowck-object-lifetime.rs). Before, the call borrowed nothing.

### Regions

- **A constructor's path that writes lifetimes gives the value's type** (nll/user-annotations/adt-*.rs). This holds for
  a tuple variant (`SomeEnum::SomeVariant::<&'static u32>(&c)`), a struct-like variant, a unit variant
  (`SomeOtherVariant::<Cell<&'static u32>>`, related through an invariant `Cell` to the other argument), a tuple
  struct and a struct literal.
- **A path call's type gives the impl's lifetimes:** `A::<'a>::new(&v, 22)` and `<A<'a>>::new(&v, 22)`, with
  `impl<'a> A<'a> { fn new(x: &'a u32, ..) }`, require v to outlive `'a` (nll/user-annotations/method-ufcs-inherent-1.rs,
  -3.rs).
- **A struct pattern's path with lifetimes:** `let Foo::<'static> { field: _z } = foo;` requires what foo borrows to
  be `'static` (pattern_substs_on_*_struct.rs).
- **A trait's const through a qualified path:** `<A<'a> as Tr>::IC`, with `impl Tr for A<'static>`, requires `'a` to
  be `'static`. This was missed (from the review of #53).
- **The gate.** The region check leaves out a fn with fewer than two regions in its signature. Two more cases now
  turn it on there:
  - a statement that writes a lifetime in a path (when the source writes one at all), so a borrow before the path in
    the statement is followed;
  - a value of a struct whose field nests two of its lifetimes (`p: &'a mut &'b i32`). Such a value relates the
    borrows it is built from, as a method may store one through the other. The check is on from the fn's start when
    a local bound before has no tree (nll/capture-ref-in-struct.rs).

### Valid code no longer rejected

- **A struct literal with a turbofish** (`S::<u32> { t: 1 }`) was "cannot find struct". Its instance is the one the
  turbofish writes, in type inference too.
- **A struct pattern with a turbofish** (`let P::<u16>(a, b) = ..`, `S::<String> { t, .. } =>`) was "cannot find
  struct or variant".
- **A tuple struct or variant with a turbofish used as a function** (`let f = P::<u16>;`, `.map(Some::<u32>)`) was
  "unsupported path".
- **An integer literal borrowed for a turbofish's reference** (`let c = 66; P::<&u32>(&c);`) was "expected `&u32`,
  found `&i32`". Type inference now takes a tuple constructor's instance from the turbofish.
- tests/acg/turbofish_ctors.rs runs these and compares the output with rustc's.
- **A blanket impl's method on `()`, and through a reference to a number, `()` or a `Box`** (`r.use_mut()` with
  `impl<T> Fake for T` and `r: &mut ()`) was "no method `use_mut` on type `()`". Self is the referent, and the
  reference is the receiver, as rustc's method lookup matches `&mut self` with it. A `&self` method through a `&mut`
  shares it. For these receivers, the impl's bounds must hold (`impl<T: ?Sized> FutureExt for T where T: Future` is
  not `()`'s). Many borrowck tests use this `Fake` trait.

### Type checks

- **An annotation with holes, of another struct than the value's:** `let x: Foo<_> = Bar::<usize>(..)` is a mismatch
  at the initializer. Before, the holes left the annotation unchecked, and the error was reported later, where x was
  used as a `Foo<usize>`. A hole is shown as `_` in type names.
- **A generic union's instance whose field is neither `Copy` nor `ManuallyDrop`** is E0277:
  `union U<T: Copy> { a: T }` with `U { a: Rc::new(0u32) }` (union/union-generic.rs).

## 4. Review (CodeRabbit, checked against rustc 1.97)

The first round had 11 findings. Ten held as stated, and one held in another form. All are fixed and tested
(`part11_review`, and tests/acg/turbofish_ctors.rs):

- A wrong value at run time: `let P::<u16>(x, _) = P(300, 1);` made x an `i32` (`x.leading_zeros()` was 23, not 7).
  A pattern's turbofish now gives the matched value's instance in type inference.
- Errors missed, now reported:
  - a pattern's turbofish of another instance than the scrutinee's (`S::<u16>(_)` on an `S<u8>`);
  - a struct literal's written arguments against the expected instance (`let _: S<u8, u8> = S::<u16, _> { .. }`);
  - a union's `&mut` field, which is not `Copy`;
  - a method call's turbofish that names a lifetime (`Q.take::<&'static u32>(&c)` in a fn the gate leaves out);
  - a borrow before a turbofish written on several lines, in its statement;
  - a blanket impl's bounds through another blanket impl (`impl<T: Marker> Other for T`).
- `E::<'static>::V::<u8>(&local, 0u8)` is E0109 in rustc: arguments are written on one segment only. zustc now
  rejects it too, rather than following the lifetime.
- Valid code no longer rejected: `r.id()` with `fn id(self) -> Self` and `r: &mut u8`, and a guard's closure whose
  parameter has an arm binding's name.
- A struct was taken for a closure when its id was a closure function's id. The check uses the closure struct map
  now.
- One difference from rustc is left: a pattern's turbofish of another instance than a scrutinee built in place
  (`match S(1u8) { S::<u16>(_) => .. }`) is reported where the scrutinee is built, not at the pattern.
- The second round had 2 findings, and both held. A blanket impl's bound now also holds by an impl for the type
  itself (`impl Other for ()` beside `impl<T: Marker> Other for T`): `().go()` was rejected. A blanket method's
  reference receiver is reborrowed now. A result that borrows from self (`fn get(&mut self) -> &mut Self`,
  `fn id(self) -> Self`) holds the loan, so `*r = 5;` while it is used is E0506 (`part11_review_2`).

## 5. Not covered yet

- **A closure not passed where a bound gives its regions** has no region check of its body's captures:
  `let p: &'static mut usize = &mut self.food;` in such a closure is a missed error
  (regions/regions-addr-of-upvar-self.rs). So is a closure's body that writes a lifetime of the function
  (`|| { SomeStruct::<&'a u32>(&c); }`).
- **A tuple struct with a turbofish used as a function and called later** (`let f = SomeStruct::<&'static u32>; f(&c);`):
  it is made a closure, whose parameter's type is not written.
- **A struct whose field is a generic trait object** (`struct B<'a, T: 'a>(&'a (dyn A<T> + 'a))`). Its type parameter
  is not inferred through the trait object, because a trait object's type is the trait's text. So `B(&*v)` with
  `v: Box<dyn A<u8>>` is "type annotations needed", which rustc accepts. In a generic fn, the error is not reported
  and the body is not checked, so `Box::new(B(&*v)) as Box<dyn X>` returned is a missed E0515
  (regions/regions-close-object-into-object-*.rs).
- **A const whose type names its impl's lifetime** (`impl<'a> Foo<'a> { const C: &'a u32 }`): `<Foo<'a>>::C` returned
  as a `&'static u32` is a missed error (nll/user-annotations/constant-in-expr-*.rs).
- **A blanket impl's `&mut self` method called on a number's place** (`n.use_mut()` with `impl<T> Fake for T`) is
  "expected `&mut u8`, found `&u8`", as on main. The number is passed as a copy.
- **A fn named in uppercase** (`fn AddFlags(..)`) is taken for a constructor, so its result borrowed past the
  statement is a missed E0716 (borrowck/rvalue-borrow-scope-error.rs).
- **A block's value dropped at the end of its statement** (`{ ..; D("other").next(&_t1) };`) does not use its loans
  there (nll/issue-54382-use-span-of-tail-of-block.rs).
- **Two tests passed only through an error zustc no longer makes:**
  - derives/derive-assoc-type-not-impl.rs was "cannot find struct" at `Bar::<NotClone> { x: 1 }.clone()`. The bound
    a derived `Clone` puts on `T` is not checked.
  - suggestions/issue-97704.rs was "cannot infer the return type of this closure" for `async { Ok::<_, i32>(()) }`.
    Now the type is inferred, and `?` applied to a future is not checked.
- **From part 10:** a type with a `Drop` impl of the program's, held by a closure by value, of which the body uses
  only `Copy` parts. See [part 10](2026-11-22-07-region-check-10.md), section 5.
