# Region (lifetime) checking, part 14: `impl Trait` results' captures, closures' `T: 'static`, two-phase borrows through a local, and `ref` rest patterns (issue #1)

Date: 2026-11-23

Part 13 ([2026-11-23-01](2026-11-23-01-region-check-13.md)) was merged with #67. This step checks what an `impl Trait`
result may hold: a hidden type that must be `'static`, and one that captures no lifetime before edition 2024 (E0700). It
also checks a closure's call that requires `T: 'static` of its function's T, a two-phase borrow through a local that
holds a reference, and a `ref` binding of an array's rest.

## 1. What was added

### Regions

- **An `impl Trait + 'static` result's hidden type is `'static`.** `fn foo<T>(x: T) -> impl Any + 'static { x }` was
  accepted (impl-trait/type_parameters_captured.rs, E0310). So was `fn baz<'a>(x: &'a u8) -> impl Any + 'static { x }`
  ("lifetime may not live long enough"). Such a result's tree is now `'static`, and the check is on for the function.
  A closure that captures something is left out. Its tree is of the variables it captures, not of the places it uses:
  `|| drop(&m.a.0)` through a `&'static` field borrows for `'static` in rustc (RFC 2229), and requiring m's region
  would be a false error (closures/2229_closure_analysis/optimization/edge_case_run_pass.rs).
- **Before edition 2024, an `impl Trait` result whose bounds name no lifetime captures none (E0700).** Two programs
  were accepted: `fn s(x: &[u8]) -> impl Iterator<Item = u8> { x.iter().copied() }`, and `fn t(x: &u8) -> impl Display
  { x }`. rustc reports "hidden type ... captures lifetime that does not appear in bounds"
  (impl-trait/precise-capturing/forgot-to-capture-lifetime.rs, feature-gates/feature-gate-lifetime-capture-rules-2024.rs,
  self/arbitrary_self_types_pin_lifetime_impl_trait.rs, its `-async` variant). What such a function returns may not
  borrow through a parameter's reference, nor be one. A `use<>` that lists no lifetime counts as naming none.
  Three cases are left out:
  - generic functions, which capture their type parameters;
  - edition 2024, which captures every lifetime;
  - parameters whose regions are all `'static` (`x: &'static u8`, `'a: 'static`: impl-trait/equal-hidden-lifetimes.rs).

  The check is in the borrow check, because the prelude's iterator types write no lifetimes, so the region check
  sees no region in `Copied<Iter<u8>>`.
- **A closure's call that requires `T: 'static` of its function's T.** `fn test<T>() { || { assert_static::<T>(); }; }`
  was accepted (nll/issue-98693.rs, E0310). The region check of a closure's body has no placeholders for its
  function's type parameters. Such a call is now checked against the function's bounds: `T: 'static`, a where clause,
  or a trait whose `Self` must be `'static`.

### Borrow check

- **A two-phase borrow through a local that holds a reference.** `let w = &v; v.ext(w)` with `fn ext(&mut self, _: &S)`
  was accepted (E0502). A `&mut self` call whose argument is such a local now reserves the receiver, as one whose
  argument names it does. What the local holds is kept until the `&mut` is taken.
- **`ref tail @ ..` of an array borrows the elements between.** The rest binding had no loan, so writing the array
  while tail lived was accepted (borrowck/borrowck-vec-pattern-move-tail.rs, E0506).

## 4. Review (CodeRabbit, checked against rustc 1.97)

CodeRabbit's first review of #69 had 4 findings. Each was checked by running zustc and rustc on a program that shows
it. All held, and are fixed and tested (`part14_review`):

- **A parameter's reference bound to a local.** `let y = x; y.iter().copied()` returned as a no-capture
  `impl Iterator<Item = u8>` was accepted (E0700 in rustc). A local bound once from a parameter's reference (and
  never assigned again) now counts as holding it. A local assigned again is not followed.
- **`'static` through outlives bounds.** `fn f<'a: 'b, 'b: 'static>(x: &'a u8) -> impl Display { x }` was a false
  E0700: only a direct `'a: 'static` made the parameter `'static`. The bounds are now followed.
- **An ADT with no lifetime.** `fn f(x: &'static String) -> impl Display { x }` was a false E0700: the path `String`
  carries a mark for a type written without lifetimes, which was taken for a region. Marks of types that have no
  region are now ignored. A type with a lifetime written without one (`Parser` for `Parser<'a>`) still counts.
- **`T: 'static` implied by a parameter.** `fn f<T>(_: &'static T) { let c = || needs_static::<T>(); }` was a false
  E0310: `&'static T` implies `T: 'static`. A parameter `&'static ..` that names T now gives the bound.

Three findings more came later, all of the closure's `T: 'static` check, and all held (`part14_review2`). The
second round had one, outside the diff; the third had none; the fourth, after main was merged into the branch, had
two:

- `needs_static::<Option<T>>()` in a closure was accepted (E0310 in rustc): a T in the type argument is now checked
  too.
- `T: 'a` with `'a: 'static` was a false E0310: the outlives bounds are now followed from `'a`.
- `T: Derived` with `trait Derived: Base` and `trait Base: 'static` was a false E0310: the supertraits are now followed.

## 5. Not covered yet

- **E0700 through a field.** `fn iter_values_anon(&self) -> impl Iterator<Item = u32> { self.x.iter().map(|a| a.0) }`
  (impl-trait/static-return-lifetime-infered.rs) is accepted: an iterator chain on a field (`self.x.iter()`) does not
  carry the receiver's loan to its result. The same holds for an `impl Iterator + 'static` result.
- **A closure's precise captures in the region check.** A closure's tree is of the variables it captures, so
  `Box<dyn FnMut() + 'static>` of `|| drop(&m.a.0)` with `m.a: &'static Int` is rejected, which rustc accepts. This
  was so before this work, and is why closures are left out of `impl Trait + 'static` above.
- **What a closure's body requires of a local it captures by reference** is still not passed back to its function.
- **A trait object's default `'static` in an impl's header** (nll/issue-54779-anon-static-lifetime.rs) and **a trait
  object with a type parameter** (`dyn A<T>`) are as in part 13.
- **The edition of the closure capture rules is a flag of the process** (`ast_closure::WILD_FAKE_READS`), set by each
  analysis. Two analyses of different editions at once in one process could read each other's. zustc runs one
  analysis at a time per process (its parallel builds fork). The tests' analyses in one process all use editions
  from 2021, which set the flag alike, so this does not happen today.
