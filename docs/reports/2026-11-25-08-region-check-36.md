# Region (lifetime) checking, part 36: `x @ sub` patterns, items in constant initializers, `Fn` parameters boxed as trait objects, lifetime bounds of impl methods (issue #171)

Date: 2026-11-25

Part 35 ([2026-11-25-07](2026-11-25-07-region-check-35.md)) was merged with #172. This step takes items of #171 and
of the failing borrow check tests of tests/ui:

- the borrows and moves of `x @ sub` patterns, and `ref` / `x @ sub` parameters;
- fns written in a `const` / `static` initializer's block;
- generic fns that box an `Fn` parameter into a `Box<dyn Fn..>`, which went unchecked;
- lifetime bounds of an impl's methods and generic associated types against the trait's (E0195, E0276).

## 1. What was added

- **`x @ sub` patterns.**
  - rustc checks each `x @ sub` before its borrow check (its THIR's `check_borrow_conflicts_in_at_patterns`). x moved,
    with a `ref` in sub, is "borrow of moved value". A `ref x` with a move in sub is "cannot move out of value because
    it is borrowed". A `ref mut` on one side and a `ref` or `ref mut` on the other is "cannot borrow value as mutable
    ..." or "as immutable ...".
  - Then its borrow check: sub binds first, so x moved after sub moved a part of it is E0382 ("use of partially moved
    value", `a @ NC(b, c @ NC(d, e))`), or all of it ("use of moved value", `a @ b`).
  - zustc bound sub and then x, and checked neither.
  - The binding of a pattern now gathers, for each `x @ sub`, how each binding of sub binds: by move (a type that is
    not `Copy`), by copy, or by reference. That is checked against how x binds, as rustc does, at the pattern.
  - `Copy` parts, two `ref`s, `ref x @ y` of a `Copy` y, and the default binding modes are accepted, as in rustc.
  - The moves are the borrow check's, which rustc does not give the code after a `return;`: there, only the check of
    the pattern itself holds (pattern/move-ref-patterns/by-move-sub-pat-unreachable.rs).
- **`ref` and `x @ sub` parameters.** `fn f(ref a @ b: U)` and `fn g(ref x: U)` were "unsupported pattern". A
  parameter whose pattern binds by reference or has a subpattern is now bound by a `let`, as one that destructures
  is.
- **Items in a constant's initializer.**
  - `const MOVE: fn(&String) -> String = { fn broken(x: &String) -> String { return *x } broken };` was "nested items
    are not supported", at line 1.
  - A fn written in a top-level `const` / `static` initializer's block is now moved out of it as one written in a fn
    body is, so it is checked: E0507 at `*x`, as in rustc. Also E0596 (span/borrowck-fn-in-const-b.rs), and E0515 on
    the line of rustc's E0713 (borrowck/borrowck-fn-in-const-c.rs). A build runs it.
  - So are the other items of such a block (`const _: () = { impl Tr for S {} };`). A syntax error of a type in a
    hoisted item's signature (`Box<dyn X< : 32 >>`) is reported at the line it was written on, as other errors of
    an item's own syntax are (generic-associated-types/parse/trait-path-*.rs).
- **`Fn` parameters boxed as trait objects.**
  - `zustc check` checks a generic fn nothing calls with a placeholder for each type parameter. A placeholder bounded
    by `FnMut(bool)` boxed into a `Box<dyn FnMut(bool)>` was "not a closure", a type error, so the fn was not
    checked at all.
  - The vtable of such a placeholder has no entry for its call now: the instance is only checked, never run.
  - So `let b: Box<dyn FnMut(bool)> = Box::new(f); drop(f);` is E0382, `fn b<F: FnMut(bool)>(f: F) -> Box<dyn
    FnMut(bool)> { Box::new(f) }` is E0310 (F must outlive `'static`), and the other errors of such fns are found
    (moves/moves-based-on-type-no-recursive-stack-closure.rs).
- **Lifetime bounds of impl methods.**
  - A lifetime of a trait's method that a where clause bounds a type by (`fn foo<'a>(..) where T: 'a`) is
    early-bound. zustc counted only the bounds of lifetimes and of the method's own type parameters, so an impl's
    `fn foo<'a>(..)` with no bound matched it. It is E0195 now, as in rustc
    (trait-bounds/impl-missing-where-clause-lifetimes-from-trait.rs).
  - A type parameter of an impl's method bounded by `'static` where the trait's is not (`F: Debug + 'static` for the
    trait's `F: Debug + 'a`) is E0276 at the `'static`, unless the impl's header gives the trait `'static`
    (typeck/issue-18937.rs). The check of the methods' bounds also reads the impls of a trait with arguments
    (`impl<'a> A<'a> for B`), whose trait it did not find.
  - An outlives between a generic associated type's own lifetimes that the trait's declaration does not imply, by
    their places (`where 'b2: 'a2` for the trait's `where 'a1: 'b1`), is E0276 at the bound
    (generic-associated-types/mismatched-where-clause-regions.rs).

## 4. Review

CodeRabbit's review of #182 made six inline findings. Each was checked with zustc and rustc 1.97:

- **A `'static` the trait's signature implies** (major): `fn f<T: 'static>(x: &'static T)` for the trait's `fn f<T>(x:
  &'static T)` was a false E0276. A trait's signature that names `'static` past its generics may imply it, so the
  check is not made there.
- **A GAT's outlives through the trait's lifetime** (major): the impl's `where 'a: 't, 't: 'b, 'a: 'b` for the
  trait's `where 'a: 't, 't: 'b` was a false E0276. A declaration with an outlives through a lifetime not the GAT's
  own is not compared: the header's arguments that relate the trait's lifetimes to the impl's are not read.
- **A comment in a GAT's bound** (minor): `'a1: /* c */ 'b1` was no bound, so the impl's `'a2: 'b2` was a false
  E0276. Comments are blanked first.
- **A `;` in an array type** (minor): `const _: [(); 1] = { fn bad.. };` ended the item at `[(); 1]`'s `;`, so the fn
  was not hoisted. The `;` of a fn's signature did the same, on main too: `fn foo(a: [u8; 4]) { fn inner() .. }` was
  "nested items are not supported". A `;` in parentheses or brackets ends no item now.
- **A `rest @ ..` in an `x @ sub`** (minor): `ref mut a @ [ref b @ ..]` was accepted. The subslice's binding is one
  of sub's now: "cannot borrow value as immutable because it is also borrowed as mutable", also after a `return;`.
- **The verdict of a method's bounds by its impl's header** (minor): the verdict was kept by the trait and the
  signature's text, so `impl Tr<'static> for A` made `impl<'a> Tr<'a> for B`'s `T: 'static` accepted. It is kept by
  whether the header gives the trait `'static` too.

The review of the fixes (d86322e) made two more findings, both minor, also checked:

- **A `'static` that names another type**: the first fix skipped the check wherever the trait's signature named
  `'static`, so `fn f<T: 'static>(x: &'static u8)` for the trait's `fn f<T>(x: &'static u8)` was accepted, which
  rustc rejects (E0276). The check is skipped now only for a type parameter the trait's parameters and result name
  with a `'static`.
- **`mut rest @ ..` through a reference** (a false error of this PR): `let ref mut a @ [mut b @ ..] = &[1u8];` was
  "cannot borrow value as immutable because it is also borrowed as mutable". Before edition 2024, `mut` binds by
  value where the default binding mode is by reference, as an identifier's binding does; rustc accepts it.

Tests: `part36_review_of_182` and `part36_second_review_of_182` in tests/regionck.rs.

## 5. Not covered yet

- **`it.by_ref().take(n)`** (#171): the fix needs `Take<&mut I>`, an adapter over a reference with `Self = &mut I`.
  zustc's impls for references to a type parameter reach T's methods through the deref (#2), so it is not made yet.
- **Placeholder instances' type errors.** A generic fn nothing calls, checked with placeholders, keeps only its
  borrow and region checks' errors. Many tests of tests/ui expect a type error there, which zustc finds and drops
  (`T: Debug` not given, a method its bounds do not give): #169.
- **Generic fns that call a method of a bound** are not checked with placeholders (their typeck costs +4.9% of the
  traits KPI). In an experiment that checked all of them, 10 more compile-fail tests passed and 5 check-pass tests
  failed.
- **The position of an `x @ sub` parameter's error**: at its fn, not at the pattern, which has no position.
- **E0276 through the impl's header**: a bound of an impl's method on a type the header passes for the trait's
  parameter (`where V: 'a` for the trait's `where T: 'a`, compare-method/region-unrelated.rs), and an outlives
  between the header's lifetimes in a method's where clause (`where 'a: 'b`, compare-method/region-extra.rs). The
  header's trait arguments are not kept.
- From part 35 and before: see #166–#171.
