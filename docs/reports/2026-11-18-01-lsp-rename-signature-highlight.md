# Add rename / signatureHelp / documentHighlight to the LSP (2026-11-18)

Date: 2026-11-18

All three are built on the existing definition / references / signature parts (`prepare_rename` / `rename` /
`signature_help` in `crates/ide/src/navigate.rs`, and the handlers in `crates/analyzer/src/lib.rs`).

- **rename** (with `prepareProvider`):
  - Rewrites the reference locations. For a trait method, it also rewrites the impl methods.
  - Struct shorthand changes shape: renaming a field turns `S { x }` → `S { new: x }`; renaming a local turns
    `S { x }` → `S { x: new }`. It also rewrites inside format captures `"{x}"`.
  - On the B in `use a::B;`, it adds an alias (`use a::B as New;`, plus the B uses in that file). This is the same shape as rust-analyzer.
  - Refused (error `RequestFailed` with a reason): keywords, built-in types, library definitions (except when on a use
    name), file modules (`mod x;`, because the file name would also change), methods generated by derive, and strings that are not valid names.
- **signatureHelp**: the call enclosing the cursor: `f(..)` / `x.m(..)` / `T::f(..)` / `f::<T>(..)` / tuple struct `T(..)`.
  Parameter ranges are in UTF-16 columns. For method calls, self is not counted as a parameter (same as rust-analyzer). Inside an array
  or `vec![..]` within the arguments, it still answers with the outer call. It does not answer inside a declaration `fn f(..)`.
- **documentHighlight**: references within the same file.

Added the comparison against rust-analyzer to `bench/lsp_parity.py` (rename: is the set of edits the same; signatureHelp:
does it contain the name, the parameter count, and the active parameter; documentHighlight: the count):

| Target | Feature | zustc | rust-analyzer |
|---|---|---|---|
| synth | rename | 100% | 100% |
| synth | signatureHelp | 100% (answered 100%) | 100% (answered 95%) |
| synth | documentHighlight | 100% | 100% |
| zustc | rename | 82% (refusals also match, 23/23) | 100% |
| zustc | signatureHelp | 89% (answered 85%) | 100% (answered 95%) |
| zustc | documentHighlight | 85% | 100% |

- Median time (target zustc): rename 1.3 ms (rust-analyzer 0.9), signatureHelp 1.3 ms (rust-analyzer 0.4).
  Time and match for the other features are unchanged (references 14.5 ms, rust-analyzer 26.4 ms).
- Remaining differences:
  - rename and documentHighlight: inside items excluded by cfg, which rust-analyzer counts (same as for references).
    For `Default::default`, rust-analyzer rewrites 1,273 locations, reaching into dependency crates (zustc rewrites the 16 in the workspace).
  - signatureHelp: no answer for std trait methods (`extend`) or for closure calls (`body_hash(..)`).
- The first measurement gave rename 71% and signatureHelp 26%. Fixed after comparing with rust-analyzer:
  self in method calls (parameter count and active parameter were off by 1), rename on a use name (make an alias),
  and refusing rename on `std::sync::Mutex` written as a path.
