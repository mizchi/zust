# Region (lifetime) checking, part 21: fn items coerced to fn pointers, deref coercions through shared references, `ref mut` bindings of annotated lets (issue #1)

Date: 2026-11-24

Part 20 ([2026-11-24-04](2026-11-24-04-region-check-20.md)) was merged with #111. This step adds:

- the well-formedness of a fn item's signature where it is coerced to an annotation's fn pointer type;
- the regions of a deref coercion through a shared reference, which removes false errors that main has too;
- a `ref mut` binding of a place in a `let` with a type written, which makes the place of that type both ways.

## 1. What was added

- **A fn item coerced to an annotation's fn pointer type: its signature's types are well formed.**
  `let f: fn(_, &'a T) -> &'static T = foo;` with `fn foo<'a, 'b, T>(_: &'a &'b (), v: &'b T) -> &'a T` was accepted
  ("lifetime may not live long enough" in rustc): `&'a &'b ()` needs `'b: 'a`, so `'a` had to outlive `'static`
  (implied-bounds/implied-bounds-on-nested-references-plus-variance.rs, -early-bound.rs). For this:
  - the item's signature's types are well formed where it is coerced;
  - a generic item's type arguments are solved from the annotation (its instance's tree was not known before);
  - a fn pointer annotation with holes (`fn(_, &'a T) -> &'static T`) keeps the regions its other parts write: a hole's
    regions are fresh, the rest as written. Before, any hole made the whole annotation fresh.

  Not where the fn pointer type binds a region (`fn(_, &'a T, &())`): rustc accepts that, a known bug (#25860,
  implied-bounds-on-nested-references-plus-variance-2.rs, a check-pass test).
- **A deref coercion through a shared reference holds what the inner reference does.** These were false errors on
  main too (rustc accepts them):
  - `if let [commit, ..] = &parts[..] { Some(commit) }` returned as `Option<&'a str>`, with
    `parts: Vec<&'a str>` a local: E0515;
  - a local `c: &&'a str` returned as `&'a str`: E0515;
  - `fn h<'a, 'b>(x: &'a &'b u32) -> &'b u32 { x }`, and `fn f<'a>(x: &'a mut &'static u32) -> &'static u32 { x }`:
    "lifetime may not live long enough".

  The coercion is the reborrow `&**c`. It lives no longer than the references it goes through, from the inside out,
  and a shared one stops that (NLL's reborrow constraints): of `&'1 &'a str` only `'a`. The region check's flows
  follow that now. The borrow check copies the inner reference out where such a local is returned or passed to a
  constructor whose field takes the inner type, as it does at a `let` or an argument. An element of a `Vec` /
  `VecDeque` is a place of the element type for that. borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs no
  longer has the false error at line 16; its expected error, on a closure's `ref` parameter at line 6, is not
  reported yet.
- **A `ref mut` binding of a place in an annotated `let` is of the annotation's type both ways.**
  `let Foo(ref mut y): Foo<fn(&'static str)> = x;` with `x: Foo<fn(&'a str)>` was accepted ("lifetime may not live
  long enough" in rustc, mir/field-projection-mutating-context2.rs): y is a `&mut` of `x.0`, and a `&mut` is
  invariant, so the place's type must be the annotation's, which needs `'a: 'static`. Where the pattern binds by
  `ref mut` and the initializer is a place, the annotation's tree flows back into the place's. The test's false
  error at `(x.0)(&string)` (a deref coercion) went with the item above.

## 4. Review

CodeRabbit's review of #123 had 2 findings, checked with zustc and rustc 1.97. Both held, were errors this part had
brought in (main reports both), and are fixed and tested (`part21_deref_coercion_copies_inner`,
`part21_fn_item_coerced_wf`):

- **An unsizing to a trait object is no deref coercion.** `x: &'a &'static u32` returned as `&'static dyn Tr`, with
  `impl<'x> Tr for &'x u32`, was accepted ("lifetime may not live long enough" in rustc): the flow took it for a
  deref and related only the inner `'static`. The pointer to the inner reference is what becomes the object, so its
  `'a` is the object's region. A flow whose target's pointee is a trait object, from one that is not, keeps the outer
  reference now.
- **A hole in a fn pointer annotation whose result elides a region.** `let f: fn(&u32, _) -> &u32 = first::<u8>;
  f(x, 0)` returned as `&'static u32` was accepted: the parts taken one by one gave the result's elided region a late
  bound of its own, not the parameter's, so a call's result was tied to nothing. Such an annotation is fresh as a
  whole again, as before this part; only one whose result elides no region is taken part by part.

## 5. Not covered yet

- **A projection's normalized type as a parameter's or an annotation's** (`_wf: <&'a u8 as Tr>::Ty` implying
  `'a: 'static` with `type Ty = &'static T`, implied-bounds/assoc-ty-wf-used-to-get-assoc-ty.rs, a false error at line
  16 here; `let _: <() as Foo>::Out = &a;`, nll/user-annotations/normalization.rs). The summaries keep no codes of an
  impl's associated types.
- **A closure stored in a local and cast to a fn pointer type** (`let c = |_: &'static u32| {}; c as fn(&u32)`,
  E0308 in rustc): the cast does not see the closure's parameters (part 20, section 4).
- **A closure's `ref` parameter borrowed for a region its result escapes with** (`.filter_map(|ref line|
  self.make_entry(line))`, borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs line 6).
- **A fn item passed through a type alias** of a fn pointer type that fixes a lifetime: `want_G(baz)` with
  `type G = for<'cx> fn(&'cx S) -> &'static S;` (regions/regions-fn-subtyping-return-static-fail.rs). The summaries
  keep no lifetimes of an alias's definition, and a fn's summary does not see its module's aliases.
- **A fn pointer type's distinct bound lifetimes** (`for<'a, 'b> fn(&'a u32, &'b u32) -> &'a u32`) are one
  placeholder where a fn item is passed: the region codes keep no binder (part 19, section 4).
- **A closure made in the function and called in another closure's body**
  (adt-tuple-struct-calls.rs's `annot_reference_named_lifetime_across_closure`). The inner body is checked on its
  own, without the outer closure's signature.
- **What the calls of a closure through a struct's field, or in another closure's body, borrow**
  (closures/issue-113087.rs). Only a closure called by a local's name holds it.
- **A constant's initializer that nothing uses** (`const z: &'static isize = { let p = 3; &p };` in main,
  static/issue-18118.rs), and a fn item in a block of a constant's initializer (borrowck/borrowck-fn-in-const-c.rs).
  A constant is expanded and checked where it is used.
- **A trait's constant whose type names the trait's lifetimes** (`<T as Foo<'a>>::C`, `T::C` with `T: Foo<'a>`,
  nll/user-annotations/constant-in-expr-trait-item-2.rs, -3.rs). A generic fn that nothing calls does not reach the
  constant's use.
- **An implicit reborrow of a `&mut` read through a guard temporary** (`let val: &_ = x.borrow().0;` used after,
  borrowck/issue-36082.rs).
- **`Cow<'_, T>` of a type that is not a slice or `str`**, and `use std::option::Option::Some as S;` in a fn
  (lifetimes/temporary-lifetime-extension-tuple-ctor.rs).
- **A `&mut` moved by value elsewhere than a `let`'s initializer**: `f(a[0])` with a generic f, `vec![a[0]]` (E0508).
- From part 17:
  - two derefs of the program's written in one place (`(&mut **w).bump()`);
  - a trait whose impls for a type are ambiguous (borrowck/mut-borrow-in-loop-2.rs).
- From part 16:
  - a generic fn's `dyn Tr<T>`;
  - `&*vec![1].iter().next().unwrap()`;
  - the opaque type's member constraints (E0700);
  - `&mut` in a tuple's inference;
  - per-field regions;
  - the borrow check of a `static` closure.
