# Region (lifetime) checking, part 25: placeholders' associated types, a path's type arguments referring to a placeholder, a callee's bound met by the caller's where clause, an impl's associated type against its trait's bound (issue #1)

Date: 2026-11-24

Part 24 ([2026-11-24-10](2026-11-24-10-region-check-24.md)) was merged with #130. This step adds:

- a placeholder's associated type (`<T# as MyTrait<'a>>::Output`), with what it outlives;
- the well-formedness of a path's type argument that is a reference to a placeholder's type;
- a callee's trait bound that only the caller's where clause on a type meets, whose regions it takes;
- an impl's associated type's value against the lifetime bound its trait's declaration gives it (E0477).

## 1. What was added

- **A placeholder's associated type.** `bar::<T::Output>()` with `fn bar<'a, T>() where T: 'a` in `fn foo<'a, T>() ->
  &'a () where T: MyTrait<'a>` was accepted (E0309 in rustc, nll/ty-outlives/projection-where-clause-none.rs and
  -env-wrong-bound.rs). A generic fn that nothing calls is checked with a placeholder for each type parameter
  (`T#`). `<T# as MyTrait<'a>>::Output` was not found, so the fn was not checked at all.
  - Such an associated type is a placeholder of its own now, where a bound's trait declares it and the bound does
    not bind it (`Iterator<Item = u32>`). It is bounded as the trait declares it (Program::assoc_placeholder).
  - Its region is a universal one, the same wherever the type is, a parameter's `&'x T::Foo` too. It outlives:
    - what the trait's declaration bounds it by (`type Output: 'a`). The summaries keep an associated type's
      lifetime bounds with its other bounds, as `'static` or the trait's lifetime by its place;
    - what the function's where clauses say (`T::Output: 'b`, `<T as MyTrait<'a>>::Output: 'b`, kept as `T::Output`;
      the trait's arguments are not compared);
    - what its placeholder and the bound's lifetimes all outlive, as rustc's rule for a projection's components.
  - It is made only where typeck finds the associated type to be that placeholder: with `impl<T> Trait for T { type
    Assoc = T; }` typeck takes `T::Assoc` for T, and so does the region check.
  - It is not made for a bound with type arguments, or with a lifetime the function does not name (the bound's own
    `for<'x>`). Nor is it made where a where clause bounds a type the summaries do not read by a lifetime
    (`StrategyFor<A>: 'static` of a type alias of a projection, nll/ty-outlives/issue-53789-*.rs): what it outlives
    is not all known there.
  - The borrow check takes such a type for Copy. What makes it Copy may be a where clause of its trait (`trait Op
    where Self::Output: Copy`) or of the fn, which are not read
    (associated-type-bounds/assoc-type-bound-through-where-clause.rs).
  - The message names the associated type, as rustc's does: "the associated type `<T as MyTrait<'a>>::Output` may
    not live long enough". The region check's messages no longer show a placeholder's `#` mark.
- **A path's type argument that is a reference to a placeholder's type.** `wf::<&'x T>()` in `fn func<'x, T:
  Trait1<'x>>(t: &'x T::Foo)` was accepted (E0309 in rustc, regions/regions-implied-bounds-projection-gap-1.rs). T
  must outlive `'x`, which `&'x T::Foo` does not imply. Part 24 checked a path's type arguments only for types with a
  struct that bounds a parameter by `'static`. Now a reference to a placeholder's type is checked too, where every
  parameter's and the result's type is followed. Otherwise what they imply is not all known
  (implied-bounds/normalization.rs).
- **A callee's bound met only by the caller's where clause.** `impls_get::<&'min G>()` with `fn impls_get<G>() where
  G: Get` in a fn with `where 'max: 'min, &'max G: Get` was accepted ("lifetime may not live long enough" in rustc,
  variance/variance-{co,contra,in}variant-self-trait-match.rs).
  - In zustc check's last round, a type with a placeholder in it (`&G#`) whose bound is not known to hold is taken to
    meet it: a where clause of the generic fn may. Before, the fn was not checked.
  - The fn's where clauses on a type that is no type parameter keep their trees as written. A callee's bound that
    only such a clause meets (no impl of the trait fits the type) makes the type the clause's. A trait's `Self` is
    invariant, so `'min` and `'max` must be the same.
  - Where an impl fits the type too (`impl<'x, T> Get for &'x T`), this is not done. rustc still takes the where
    clause first there, so such a program is accepted where rustc rejects it (section 5).
- **An impl's associated type against its trait's bound (E0477).** `impl<'a> Foo<'static> for &'a i32 { type Value =
  &'a i32; }` with `trait Foo<'a> { type Value: 'a; }` was accepted ("the type `&'a i32` does not fulfill the
  required lifetime" in rustc, regions/regions-assoc-type-region-bound-in-trait-not-met.rs,
  -static-bound-in-trait-not-met.rs). Once the program's traits are known, each impl's associated type whose trait's
  declaration bounds it by a lifetime is read again. The impl's lifetimes its value names must outlive the bound:
  `'static`, or the trait's lifetime that the impl's trait path writes at its place. The header's bounds and the
  ones its self type implies are what is known. A lifetime that a `for<..>` in the value binds is the value's own.

## 4. Review

CodeRabbit's review had 3 findings, each checked with zustc and rustc 1.97. All 3 held, and all are fixed in the
commit that follows the merge of main (25c18d6). Two were false errors this part brought in; rustc and main accept
the programs:

- **A callee's projection read by the caller's parameter at its place.** With `fn take<V: Tr>(_: &V::Out)`,
  `take::<U>(x)` in `fn f<'a, T: Tr, U: Tr>(x: &'a U::Out)` gave "the associated type `<U as Tr>::Out` may not live
  long enough (it must outlive `<T as Tr>::Out`)". A placeholder's associated type's region was found by the type
  parameter's place, which in a callee's signature is the callee's. It is found by the placeholder's region now, the
  one the type arguments' trees give the parameter: the caller's `U` for the callee's `V`. A real requirement
  through it (`take::<U>(x)` returned as `&'static U::Out`) is still reported.
- **A type alias in an associated type's value.** `type Value = Erased<'a>;` with `type Erased<'a> = ();` gave a
  false E0477: the alias names `'a`, its body does not use it. A value that writes one of the program's type
  aliases is not checked for E0477 now.

The third was a line: an impl in a fn body, which is hoisted, had its E0477 at the hoisted line. It is at the line
it is written on now.

tests/regionck.rs checks the cases (`part25_review`).

## 5. Not covered yet

- **A where clause taken first where an impl fits too** (`impls2::<&'min G>()` with `&'max G: Get2` and `impl<'x,
  T> Get2 for &'x T`): rustc selects the where clause, zustc leaves the bound to the impl.
- **A projection with other trait arguments than its where clause's** (`<T as MyTrait<'a>>::Output` against
  `<T as MyTrait<'b>>::Output: 'a`, nll/ty-outlives/projection-where-clause-env-wrong-lifetime.rs): the where
  clauses are kept by `T::Output`, the trait's arguments aside.
- **A placeholder's associated type of a bound with type arguments**, or of a supertrait (`T: DoubleEndedIterator`'s
  `Item`), and a placeholder's associated type's own associated types (`T::Output::Inner`).
- **A struct's type arguments inferred through a trait object** (`B(&*v)` with `struct B<'a, T>(&'a (dyn A<T> +
  'a))`, regions/regions-close-object-into-object-*.rs): a false "type annotations needed".
- **`err.is::<T>()` of a `&dyn Error`** (the method is of `dyn Error + 'static`,
  regions/regions-static-bound-on-type-param.rs).
- **An impl's method against its trait's signature with the impl's implied bounds** (`fn listeners<'b>(&'b self) ->
  &'a MessageListeners<'b>`, implied-bounds/impl-implied-bounds-compatibility.rs, E0491).
- From part 24 and before: see [part 24](2026-11-24-10-region-check-24.md), section 5.
