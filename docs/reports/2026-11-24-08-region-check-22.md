# Region (lifetime) checking, part 22: projections' associated types in annotations and parameters, closures cast from a local (issue #1)

Date: 2026-11-24

Part 21 ([2026-11-24-05](2026-11-24-05-region-check-21.md)) was merged with #123. This step adds:

- the regions of a projection written as a `let`'s type, taken from its impl's associated type's value;
- the implied bounds of a parameter whose type is such a projection, which removes a false error main has too;
- a closure held by a local and cast to a fn pointer type, against its annotated parameters.

## 1. What was added

- **A projection written as a `let`'s type is of the regions its associated type's value writes.**
  `let _: <() as Foo>::Out = &a;` with `impl Foo for () { type Out = &'static u32; }` was accepted (E0597 in rustc),
  and so was `let _: <&'static () as Foo>::Out = &a;` with `impl<'a> Foo for &'a () { type Out = &'a u32; }`
  (nll/user-annotations/normalization.rs). The summaries keep the codes of an impl's associated type whose value names
  a lifetime, against the impl's lifetimes (`Summary::assoc_regions`, `Program::assoc_regions`), as part 19 did for an
  impl's constants. A projection in a `let`'s annotation takes them where one impl's associated type of the name fits
  its self type: the impl's lifetimes are those the self type writes there (`<&'_ () as Foo>::Out` a fresh one), a
  blanket impl's type argument the self type as written. Such an annotation starts the function's region check.
- **A parameter whose type is such a projection has the bounds its value implies.** `fn test<'a>(x: &'a u8, _wf:
  <&'a u8 as Tr>::Ty) -> &'static u8 { x }` with `impl<T: 'static> Tr for T { type Ty = &'static T; }` was a false
  "lifetime may not live long enough" (main too; rustc accepts it): `_wf`'s type is `&'static &'a u8`, which implies
  `'a: 'static`. The summary does not follow a parameter whose type is a projection; the fn's region check takes the
  value's tree for it now, and its implied bounds are known (implied-bounds/assoc-ty-wf-used-to-get-assoc-ty.rs no
  longer has the false error at line 16).
- **A closure held by a local and cast to a fn pointer type.** `let c = |_: &'static u32| {}; let f = c as
  fn(&u32);` was accepted (E0308 in rustc): only a closure written at the cast was checked against the type (part 20).
  The closures made with a parameter annotated with a lifetime are kept by struct, and a cast of a local holding one
  checks its parameters the same way, reported at the cast.

## 4. Review

CodeRabbit's review had 6 findings, each checked with zustc and rustc 1.97. All 6 held. Five are about the region check, and main accepted each of their programs too: they are gaps in what this part added, or in part 20. The sixth, about the build cache, was a bug:

- **The build cache** (fixed in b874b80f). When an associated type's value changed, the functions that write its
  projection kept their cached results. `type Out = &'a u32` changed to `&'static u32` kept a cached build of
  `let x: <&'b () as Foo>::Out = r;`, which is an error now. `type Out = u32` changed to `u64` kept `size_of_val` at 4;
  main has that one too. A function's key now holds the definitions of the program's associated types: the texts of
  their impl members. For a dependency crate's function, it holds those of the crates it sees.
  tests/driver2_cache.rs checks it (`associated_type_invalidates`).
- **A `let` with no initializer** (1643b40f). `let x: <() as Foo>::Out; x = r;` with `type Out = &'static u32` was
  accepted. x now has the projection's tree, and the assignment flows into it.
- **An impl's type arguments and lifetimes in its self type** (1643b40f). Two programs were accepted:
  - with `impl<T> Foo for W<T> { type Out = (&'static u32, T); }`, `<W<&'static u32> as Foo>::Out` gave `T` fresh
    regions;
  - with `impl<'a, T> Foo for W<'a, T>`, `<W<'static, &'static u32> as Foo>::Out` lost `'a`, because the written type
    has more regions than the impl's self type.

  The impl's self type is now matched part by part against the written type's tree. Its lifetimes and type
  parameters take the parts at their positions.
- **A fn pointer type that names a lifetime** (1643b40f). `|_: &'static u32| {}` coerced to `fn(&'a u32)` was
  accepted in four places, where rustc reports "lifetime may not live long enough":
  - a cast of a local;
  - a `let`;
  - a cast;
  - a call (`want(x, ..)` with `fn want<'a>(_: &'a u32, _f: fn(&'a u32))`).

  The closure takes what the type gives, so the type's region must outlive the annotation's region: here
  `'a: 'static`. With `where 'a: 'b`, `|_: &'b u32|` as `fn(&'a u32)` is accepted, as in rustc. Part 20 left these
  regions aside.
- **A cast to a type alias of a fn pointer type** (`c as F` with `type F = fn(&u32);`) is not fixed. The summaries
  keep no lifetimes of an alias's definition, so `fn(&u32)` and `fn(&'static u32)` look the same there. Section 5
  records it.

tests/regionck.rs checks the cases (`part22_projection_review`, `part22_closure_fnptr_named`). With the fixes and main
(014c605) merged in, tests/ui shows no regression: compile-fail
4639 → 4640 against main, run-pass 1857 and check-pass 1524 unchanged. No passing run-pass test is rejected that main
accepts. The KPI workflow measures the pushed head against main.

## 5. Not covered yet

- **A projection's normalized type at a call** (`test(&x, &&3)` with `fn test<'a>(x: &'a u8, _wf: <&'a u8 as Tr>::Ty)`,
  implied-bounds/assoc-ty-wf-used-to-get-assoc-ty.rs line 24): the callee's summary keeps no codes of a parameter
  whose type is a projection, so the call does not follow it. Inside the fn, and in a `let`'s annotation, it is
  followed now.
- **A cast to a type alias of a fn pointer type** (`c as F` with `type F = fn(&u32);`): the summaries keep no
  lifetimes of an alias's definition (section 4).
- **A closure's `ref` parameter borrowed for a region its result escapes with** (`.filter_map(|ref line|
  self.make_entry(line))`, borrowck/cannot-return-ref-to-fn-param-in-filter-map.rs line 6).
- **A fn item passed through a type alias** of a fn pointer type that fixes a lifetime: `want_G(baz)` with
  `type G = for<'cx> fn(&'cx S) -> &'static S;` (regions/regions-fn-subtyping-return-static-fail.rs). The summaries
  keep no lifetimes of an alias's definition, and a fn's summary does not see its module's aliases.
- **A fn pointer type's distinct bound lifetimes** (`for<'a, 'b> fn(&'a u32, &'b u32) -> &'a u32`) are one
  placeholder where a fn item is passed: the region codes keep no binder (part 19, section 4).
- **A closure made in the function and called in another closure's body**
  (adt-tuple-struct-calls.rs's `annot_reference_named_lifetime_across_closure`). The inner body is checked on its
  own, without the outer closure's signature.
- **What the calls of a closure through a struct's field, or in another closure's body, borrow**
  (closures/issue-113087.rs). Only a closure called by a local's name holds it.
- **A constant's initializer that nothing uses** (`const z: &'static isize = { let p = 3; &p };` in main,
  static/issue-18118.rs), and a fn item in a block of a constant's initializer (borrowck/borrowck-fn-in-const-c.rs).
  A constant is expanded and checked where it is used.
- **A trait's constant whose type names the trait's lifetimes** (`<T as Foo<'a>>::C`, `T::C` with `T: Foo<'a>`,
  nll/user-annotations/constant-in-expr-trait-item-2.rs, -3.rs). A generic fn that nothing calls does not reach the
  constant's use.
- **An implicit reborrow of a `&mut` read through a guard temporary** (`let val: &_ = x.borrow().0;` used after,
  borrowck/issue-36082.rs).
- **`Cow<'_, T>` of a type that is not a slice or `str`**, and `use std::option::Option::Some as S;` in a fn
  (lifetimes/temporary-lifetime-extension-tuple-ctor.rs).
- **A `&mut` moved by value elsewhere than a `let`'s initializer**: `f(a[0])` with a generic f, `vec![a[0]]` (E0508).
- From part 17:
  - two derefs of the program's written in one place (`(&mut **w).bump()`);
  - a trait whose impls for a type are ambiguous (borrowck/mut-borrow-in-loop-2.rs).
- From part 16:
  - a generic fn's `dyn Tr<T>`;
  - `&*vec![1].iter().next().unwrap()`;
  - the opaque type's member constraints (E0700);
  - `&mut` in a tuple's inference;
  - per-field regions;
  - the borrow check of a `static` closure.
