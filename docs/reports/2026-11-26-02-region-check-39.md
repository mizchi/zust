# Region (lifetime) checking, part 39: dyn Error's `is`, lets assigned through a deref, closures held as fn pointers, and trait methods' elided results (issue #169)

Date: 2026-11-26

Part 38 ([2026-11-26-01](2026-11-26-01-region-check-38.md)) was merged with #237. This part takes more of #169's type
check gaps that stop lifetime tests before the borrow check, and a gap part 38 left: a trait method's elided result.

## 1. What was added

- **`<dyn Error + 'static>::is`.** The prelude's `Error` has a default method that gives the implementing type's
  `TypeId` (each impl's instance of the default), and `impl dyn Error + 'static { fn is<T: Error + 'static>(&self) ->
  bool }` compares it with `T`'s, through the object's vtable. Its header writes `'static`, so a call through an object
  of a shorter lifetime is rustc's E0521 at the call, as part 38 checks for an `impl dyn Tr`
  (regions/regions-static-bound-on-type-param.rs: `err.is::<T>()` with `err: &dyn Error`). `is` was not found before.
- **A `let` assigned later through a deref.** The type inference of `*x` follows the target of a Deref impl (RefCell's
  `Ref`, `Rc`, a user's `impl Deref for W`), and the derefs the compiler knows of String (`str`) and Vec (`[T]`). So
  `let p; { let b = m.borrow(); p = &*b; }` knows p's type, and the borrow check finds b dropped while borrowed (E0597,
  span/mut-ptr-cant-outlive-ref.rs). It was "cannot infer the type of this `let`", and `let d; d = *r;` with `r:
  Rc<u32>` was a false "mismatched types".
- **A closure held as a fn pointer with holes.**
  - In `let g: fn(_, _) -> _ = |_x, y| y;` the closure is not linked to the annotation's type: that type has holes,
    and linked, the closure was that type, so its parameters never learned what a later use gives (`g` returned as
    `fn(&'a u32, &'b u32) -> &'a u32`). They were "cannot infer the type of this closure parameter".
  - The region check: a closure whose value is one of its parameters flows that parameter into the pointer's result.
    Returned as `fn(&'a u32, &'b u32) -> &'a u32`, `|_x, y| y` needs `'b: 'a`: "lifetime may not live long enough" on
    rustc's line (nll/mir_check_cast_closure.rs). Only a body that is the parameter itself is followed; what another
    body returns, the check does not know.
- **A trait method's elided result.** The `&self` of a trait's declaration ties the method's elided result to the
  receiver's borrow, as Rust's elision does:
  - through the vtable: `b.get()` of a local `Box<dyn Tr>` returned, with `fn get(&self) -> &u8` declared in the trait,
    is E0515;
  - as a default through `impl Ext for dyn Tr {}`: `x.get()` of `x: &(dyn Tr + 'static)` returned as `&'static u8` is
    "lifetime may not live long enough".

  Before, the result's regions were fresh, so both were accepted (part 38's report listed them).
- **The review's fix (#263).** A Deref impl's target that is one of its parameters is looked up among the self type's
  arguments: `impl<B, A> Deref for Wrap<A, B> { type Target = A }` gives Wrap's first argument, for `*x` and for a
  field through the deref. `let x; x = *w;` of `Wrap(1u8, "s")` was "expected `&str`, found `u8`".

## 4. Not covered yet

- **`is` on a `Box<dyn Error>`**: the boxed form is the prelude's `__DynError`, which keeps only the error's display
  and debug strings, so `e.is::<A>()` of `e: Box<dyn Error>` finds no method (on main too). Its type identity would
  have to be kept at the conversion.
- **A generic fn nothing calls** (`fn f<T: Tr>(t: &T) -> &'static u8 { t.get() }`): its body is not region-checked
  here, so a placeholder's method result returned as `'static` is not reported.
- **What other closure bodies return**: a closure held as a fn pointer whose body is not one of its parameters gives
  its pointer's result no region of its parameters (`|x, y| if c { x } else { y }`).
- **A self type with an elided lifetime in a method's receiver** (`self: &Pair<&str, isize>` in `impl Pair<&str,
  isize>`): rustc's E0308 (lifetimes/elided-lifetime-mismatch-in-self-type.rs). The existing check compares only
  lifetime arguments the receiver writes.
- **Implied bounds of a signature for a projection in its result** (`fn mk<'a, T>(r: &'a T) -> D<fn(&'a T)>` with
  `<fn(&'a T) as HasArg>::Arg = &'a T`): a false E0309 (borrowck/alias-liveness/drop-liveness-invariance-issue-160670.rs),
  #168's.
- From part 38 and before: see #166–#171.
