# Region (lifetime) checking, part 35: the drop of a type that holds no reference (issue #1)

Date: 2026-11-25

Part 34 ([2026-11-25-06](2026-11-25-06-region-check-34.md)) was merged with #161. #1 is closed now, and its
remaining work is in #166–#171. This step fixes the drop check of a `Drop` type that holds no reference, the minor
finding of #161's last review.

## 1. What was changed

- **The drop of a type that holds no reference.**
  - The drop check took every type with a `Drop` impl for a drop that may see what its value borrows.
  - So `let mut d = (None, Token); { let x = 1; d.0 = Some(&x); }` was E0597 on main, with `Token` a `Drop` type with
    no fields.
  - Part 34's check of a value that holds a loan of itself used the same gate, so
    `let d = (Cell::new(None), 1, Token); d.0.set(Some(&d.1));` was E0597 too.
  - rustc accepts both: its drop check requires only what a `Drop` type's parameters hold to be alive.
  - A `Drop` impl now counts only for a type that may hold a reference. A `Drop` type that holds the borrow
    (`struct D<'a>(Option<&'a i32>)`) is still E0597, as in rustc.
- **E0726 came with #138.**
  - This part first checked E0726 in impl headers and `async fn` parameters, from the items' syntax trees.
  - #138, merged into main meanwhile, checks the same error from the items' text, and makes the same six tests pass.
  - To keep one check of it, this part leaves E0726 to #138's.
  - The cases #138's check does not cover are in #171: a path inside the self type (`impl Tr for Vec<Foo>`), and
    rustc's column instead of column 1.
  - The tests of this part's E0726 cases are kept (`part35_elided_lifetimes_in_impl_headers_and_async_fns`), and pass
    with #138's check.

## 4. Review

CodeRabbit's first review (of c4a0361) made three findings and a nitpick, all of the E0726 check that this part then
dropped in favour of #138's (92800f9):

- a trait's type argument (`impl Tr<Foo> for S`) not checked;
- an impl's type parameter named like a struct (`impl<Foo> S<Foo> { async fn f(x: Foo) {} }`) taken for the struct;
- the line of a hoisted impl.

Checked with rustc 1.97, #138's check on main has the same three: it accepts the first, reports a false E0726 for the
second, and reports the third at the hoisted item's line. They are listed in #171. The review of 92800f9 made no
finding.
