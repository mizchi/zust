# Region (lifetime) checking, part 35: elided lifetimes in impl headers and `async fn` parameters (E0726), the drop of a type that holds no reference (issue #1)

Date: 2026-11-25

Part 34 ([2026-11-25-06](2026-11-25-06-region-check-34.md)) was merged with #161. This step adds:

- E0726 for an impl header that names a struct, an enum or a trait of the program with lifetime parameters and
  writes none of them;
- E0726 for an `async fn`'s parameter of such a type;
- the drop check of a `Drop` type that holds no reference, the minor finding of #161's last review.

## 1. What was added

- **E0726 in impl headers.**
  - Take `impl MyTrait for Foo` with `struct Foo<'a>`, or `impl MyTrait for u32` with `trait MyTrait<'a>`. rustc
    reports "implicit elided lifetime not allowed here" (E0726) at the path. An impl header does not elide a path's
    lifetimes; `Foo<'_>` names one.
  - zustc accepted these. Once all items are summarized, the program's structs, enums and traits with lifetime
    parameters are known. An impl header whose summary names one is read again, and E0726 is reported at the first
    path that writes none of its lifetimes.
  - The trait is checked first, then the self type, also inside it (`impl Tr for Vec<Foo>`).
  - These are accepted: a path with `'_` or the impl's own lifetimes, a reference's elided lifetime (`impl Tr for
    &Foo<'_>`), and a type parameter of the impl named like a struct.
  - impl-header-lifetime-elision/path-elided.rs, trait-elided.rs, coherence/skip-reporting-if-references-err.rs and
    wf/wf-in-foreign-fn-decls-issue-80468.rs pass.
- **E0726 in `async fn` parameters.**
  - `async fn f(m: Msg)` with `struct Msg<'a>` is E0726 at `Msg`: the future the fn returns captures the parameter's
    lifetimes, which must be named. A fn that is not async elides them, as before.
  - An item's names before its `fn` tell whether it is async; only such an item, whose summary's parameters name such
    a type, is read again (async-await/async-fn-path-elision.rs, lifetimes/issue-69314.rs).
- **The drop of a type that holds no reference.**
  - The drop check took every type with a `Drop` impl for a drop that may see what its value borrows. So
    `let mut d = (None, Token); { let x = 1; d.0 = Some(&x); }`, with `Token` a `Drop` type with no fields, was E0597,
    on main too. Part 34's check of a value that holds a loan of itself used the same gate:
    `let d = (Cell::new(None), 1, Token); d.0.set(Some(&d.1));` was E0597. rustc accepts both, as its drop check
    requires only what a `Drop` type's parameters hold to be alive.
  - A `Drop` impl now counts only for a type that may hold a reference. A `Drop` type that holds the borrow
    (`struct D<'a>(Option<&'a i32>)`) is still E0597, as in rustc.
