# Region (lifetime) checking, part 28: the type arguments of generic trait objects, bare trait objects before 2021, E0223 (issue #1)

Date: 2026-11-24

Part 27 ([2026-11-24-13](2026-11-24-13-region-check-27.md)) was merged with #151. This step adds:

- the type arguments of a trait object that name a type parameter (`Box<dyn Fn(U) -> U>` in `struct S<U>`,
  `&dyn A<T>` in a generic fn), given where the generic type or fn is used, and inferred from;
- the region check of such trait objects, which a type error hid (regions/regions-close-object-into-object-*.rs);
- a trait's name behind a pointer before the 2021 edition, as its trait object;
- E0223 for an associated type of a trait object named without its trait.

## 1. What was added

- **The type arguments of generic trait objects.** zustc keeps a `dyn` type as its text (`A < T >`). A type
  parameter that the text named was looked up by its name where the type was used, not where it was written. main
  gave false errors:
  - `struct S<U> { f: Box<dyn Fn(U) -> U> }` with `(s.f)(x)` in `fn app<T>(s: &S<T>, x: T)`: "cannot find type
    `U`";
  - `fn repeat<T: Clone>(t: T) -> Box<dyn FnMut() -> T>`: the caller's `f()` gave "cannot find type `T`";
  - `fn unbox<X>(v: Box<dyn A<X>>) -> X` called with a `Box<dyn A<String>>`: "mismatched types";
  - `B(v)` with `struct B<'a, T: 'a>(&'a (dyn A<T> + 'a))` and `v: &dyn A<i32>`: "type annotations needed".
  - Where the type is resolved, a type parameter in its text is now marked with its index. A type that a parameter
    stands for in an instance is written out.
  - Substitution writes each parameter's argument in. The type arguments of two trait objects are matched to infer
    a call's or a constructor's type parameters.
  - Where a call's parameter is not known yet, the expected type has the parameter's name, as before. That is a
    closure passed for `Box<dyn Fn(T) -> T>` before `T` is known. The closure is coerced to it, and its own types
    decide `T`.
- **The region check of such trait objects.** regions/regions-close-object-into-object-2.rs returns
  `Box::new(B(&*v))` with `v: Box<dyn A<T> + 'a>`. zustc reports E0515, as rustc does. Before, typeck failed on
  `B(&*v)` ("type annotations needed"), and the fn was not checked.
- **Bare trait objects before 2021.** In the 2015 and 2018 editions, a trait's name is a type: its trait object
  (`Box<X>` is `Box<dyn X>`).
  - zustc read `X + 'a` so, but not `X` alone: `as Box<X>` gave "cannot find type `X`".
  - Now a top-level trait's name behind a pointer (`&`, `*const`, `*mut`, `Box`) is its trait object.
  - A trait's name elsewhere is not, as in `Trait::method()`: this work's first cycle read every one so, and 14
    tests that passed failed.
  - A module's trait is not either. zustc does not check its privacy there, and a private one named through a glob
    import is an error (privacy/privacy-ns1.rs).
- **E0223.** `<dyn Trait<i32>>::Ty` names an associated type of a trait object without its trait, and is E0223
  (associated-item/ambiguous-associated-type-with-generics.rs).
  - main rejected the program for another reason: it found no `Ty` for `dyn Trait<i32>`.
  - With the type arguments matched, `impl<A> Assoc for dyn Trait<A>` gives it now. `<dyn Trait<i32> as
    Assoc>::Ty` is `i32`.

## 4. Review

CodeRabbit reviewed #154 at 552ed3a and made five findings. Each was checked with zustc and rustc 1.97:

- **The edition of the signatures and the fields.** The program was built in the 2021 edition, and the crate's
  edition was set after. So a bare trait object in a 2015 signature (`fn take(x: &X)`) or struct field (`x: &'a X`)
  was not read as one: "cannot find type `X`", as on main.
  - The program is now built in the crate's edition.
  - The traits' names are known before the fields are resolved.
  - With that, dyn-keyword/dyn-2018-edition-lint.rs was accepted, a test that passed: it denies the
    `bare_trait_objects` lint. Such an object is an error now where the lint is denied, at the line that names it.
- **A closure for `Box<dyn Fn(T) -> U>` where T is known and U is not.** Take `f(1i32, Box::new(|x: i32| x), 2i32)`
  with `fn f<T, U>(a: T, cb: Box<dyn Fn(T) -> U>, b: U)`. main accepted it; this work gave "mismatched types". The
  closure was coerced to `Box<dyn Fn(i32) -> U>`, which matched neither the parameter's names nor its arguments.
  - Such a type now matches where it is the parameter's text with some of the known parameters given.
  - The argument takes the instance's type at the call.
- **A program's own type named like a mark** (`struct __S0`). It resolved to the struct the mark names; a type of
  the program's own is that type now.
- **Two punctuations joined by the rewrite.** A `dyn` type's text is joined again after its marks are replaced.
  Two punctuations that the text keeps apart (`/ *`) could be joined. They stay apart now.
- **A struct literal whose closure field comes before the field that gives its parameter.** Take
  `S { cb: Box::new(|x: i32| x), value: 1i32 }` with `struct S<T> { cb: Box<dyn Fn(T) -> T>, value: T }`. The finding
  said it fails, depending on the fields' order. It was not reproduced: both orders build and run as with rustc.
- tests/regionck.rs checks the first three (`part28_review`).
- After the fixes: tests/ui has no regression, the run-pass check rejects nothing main accepts, and `cargo test`
  passes. Against main (becb570), measured here, no KPI grows by more than +0.35% (traits check), except patterns
  edit.
  - kpi_track's run measured patterns edit at 283.955 → 285.858 M (+0.67%).
  - Measured on its own, three times for each binary, it is 285.609 → 286.000 M (+0.14%), the same in each run.
    kpi_track's run measures it after the other KPIs.
  - The first version of the fixes measured +0.84% for traits check. The check of each argument against the
    instance's parameter type was no longer lazy; it is again.
- CodeRabbit's second review, at 5297119, made four findings:
  - **A trait object's other bounds** (`dyn A<T> + Send` against `dyn A<i32>`). This is not this work's: a `dyn`
    type's text keeps no auto trait, on main too, so the two are one type there.
  - **A trait whose name begins like a mark** (`__Pretty`, and the prelude's `__PathExt`) was read as a type with
    parameters. The marks are `__zp{i}_{name}` and `__zs{id}` now, and only a well-formed mark counts.
  - **A generic parameter or an undeclared name that looks like a mark** (`fn f<T, __zp0_U>`, `let x: __zs0`). The
    generic parameters' names are looked up first now. A struct's mark is read only for a placeholder or a closure,
    the structs that dyn_src writes so.
  - **A crate's `allow(bare_trait_objects)` after its `deny`.** It allows bare trait objects now. An item's `#[deny]`
    is still taken for the crate.
  - tests/regionck.rs checks the last three (`part28_review`).
- CodeRabbit's third review, at ab3d20d, made two findings, both fixed:
  - **An item's `#[deny(..)]` that names bare_trait_objects after another lint** (`#[deny(unused,
    bare_trait_objects)]`): it is read from the whole list now.
  - **References' mutabilities in a trait object's arguments.** `dyn A<&T>` matched `dyn A<&mut i32>`, as a
    coercion of an argument does. A trait object's arguments are no coercion site, so the mutabilities agree now:
    passing a `&dyn A<&mut i32>` for `&dyn A<&T>` is "mismatched types", as in rustc (E0308) and on main.
  - tests/regionck.rs checks both (`part28_review`).
- CodeRabbit then found a generic parameter named like a mark inside a `dyn` type (`&dyn A<__zp0_U>`), which was
  taken for the mark. The names a type's env gives are looked up first there too now. An undeclared name that is a
  mark (`__zp0_U`) is still read as one: names of `__z` are the compiler's, as the prelude's `__core_*` are.

## 5. Not covered yet

- **A coercion to a generic trait object that infers its type arguments from an impl.** Take `B(&9)` with
  `impl A<i32> for i32`, or `use_a(&5)` with `fn use_a<T>(a: &dyn A<T>) -> T`. rustc infers `T = i32`; zustc does
  not ("type annotations needed", "cannot infer type parameter `T`").
- **The E0310 of regions/regions-close-object-into-object-4.rs and -5.rs.** Take `Box<dyn A<U> + 'a>` closed
  into a `Box<dyn X + 'static>`: zustc reports the E0515, not that `U` may not live long enough.
- **A trait object's type argument written with a module's path** (`dyn A<m::S>`). The same type written out for
  a parameter is `S`, so the two texts differ: "mismatched types", as on main.
- **A `dyn Fn` result's parameter that only the closure's result gives** (`g(Box::new(|x: i32| x as i64), 7)` with
  `fn g<T, U>(cb: Box<dyn Fn(T) -> U>, a: T) -> U`): "cannot infer type parameter `U`", as on main.
- From part 27 and before: see [part 27](2026-11-24-13-region-check-27.md), section 5.
