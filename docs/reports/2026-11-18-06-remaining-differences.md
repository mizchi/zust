# Closing the remaining differences from rust-analyzer in TODO.md

Date: 2026-11-18

Work on the items left in TODO.md: zust-analyzer answers that differed from rust-analyzer, the fixture remainder, and
reference speed. Each item was reproduced in a small crate and compared with rust-analyzer's answer, then checked on
the fixture workspace (`bench/ide_golden_ra.py`) and on zustc's own sources (`bench/lsp_parity.py`).

## Type inference

- **Prefix operators.** `&*p` on a raw pointer `*const T` is `&T`; `*b` on `&T` / `Box<T>` is `T`. Leading `&` /
  `&mut` / `*` are applied to the type of the operand (only when no binary operator follows). Raw pointer annotations
  (`p: *const T`) are accepted. `unsafe { .. }` blocks are looked into like plain blocks.
- **Associated consts of primitive types.** `u32::MAX` was `char` and `i64::MIN` was `f32`: a lowercase qualifier was
  read as a module, which found the deprecated module constants `core::char::MAX` / `core::f32::MIN`. Primitive type
  names are now types, so `u32::MAX` is `u32` and `usize::BITS` is `u32` (definitions match rust-analyzer).
- **Aliases with the same head name.** `std::io::Result<T>` (= `Result<T, Error>`) was never expanded, because an alias
  whose right-hand side has the same name was skipped to avoid loops. It is now expanded when the number of type
  arguments differs, and method lookup expands the receiver until it matches the impl's arity. The `e` in
  `fs::write(..).map_err(|e| e.to_string())` is `io::Error`. Among several aliases of one name, the one in the same file,
  then the same crate, then the workspace is preferred.
- **Range loop variables.** `for k in 0..n` (without parentheses) gives `k` the type of `n`; `for k in 0..3` gives
  `i32` (rust-analyzer's default). `a..` is `RangeFrom<T>`.
- **Array values.** `["a", "b"].into_iter()` was `[&str; 2]::IntoIter`: the projection was cut at the space inside
  `[&str; 2]`. It is now `IntoIter<&str>`, and `find(|k| ..)` gives `k: &&str` (so `k.len()` is `str::len`, as in
  rust-analyzer).
- **Match arms with tuple patterns.** In `(TokenTree::Literal(x), TokenTree::Literal(y)) => ..`, the walk back from `x`
  went through the previous arm's body and stopped at its `==`. The arm's pattern span is now found first.
- **Iterators of dependencies.** serde_json's `Map::iter()` returns `map::Iter` (no type arguments). It was mixed up with
  `option::Iter<'a, A>` and then with `std::path::Iter`. A type with no type arguments returned by a method is now
  qualified with its module when the name is ambiguous, and associated types are looked up only in that module. The
  impl itself is generated by a macro, so the item type is now unknown rather than wrong (TODO.md).
- **`zustc/typeAt` at bindings.** The debug request now answers at a binding itself (patterns, parameters, closure
  parameters), not only at its uses.

## Definitions and references

- **`name!(..)` resolves to macros only.** `vec!` went to `pub mod vec`, `format!` to nothing (it collided with
  `fn fmt::format`). `format!` now has 3 references, like rust-analyzer.
- **str pattern iterators.** `s.split(',').next()` went to slice `Split::next`. The methods inside core's
  `generate_pattern_iterators!` are indexed as `__str_pat_iter` (like `uint_impl!`), and impls whose number of type
  arguments does not match the receiver are dropped.
- **Crate names.** The server tells zust-analyzer which file is each crate's root (workspace crates, std / core / alloc,
  and dependencies). `std` and `fixture` now go to the crate root, `std::collections` to `collections/mod.rs`, and the
  references of a workspace crate include `crate::`, `pub(crate)` and `super` that mean its root, as in
  rust-analyzer (7/7 for `fixture`). Library crates get their own crate number so that `mod x;` is resolved within the
  same crate.
- **`cfg(miri)`.** rust-analyzer's `cargo.cfgs` defaults to `["debug_assertions", "miri"]`, so `#[cfg(miri)]` items are
  active. zust-analyzer now does the same.
- **Names inside cfg predicates.** `test` in `#[cfg(test)]` was counted as a reference of the `#[test]` attribute
  macro. Names inside `#[cfg(..)]`, the predicate of `#[cfg_attr(..)]` and `cfg!(..)` no longer resolve.
- **Golden harness.** The ide golden test now registers crate roots and gives library files their crate numbers, as
  the server does. The fixture's small std gained the macros and attributes the fixture uses (`assert!`, `assert_eq!`,
  `vec!`, `format!`, `test`, `derive`, `Copy`), so `bench/ide_golden_ra.py` compares like with like.

## Speed

References scan each file independently. Slim files are reloaded first on the main thread; then the files are scanned
on up to 8 threads (when there are 8 or more files). On 4 cores the slow queries on zustc's own sources (methods with
common names) went from 110–230 ms to 55–205 ms.
