# Region (lifetime) checking, part 38: methods of impls for trait objects, and the `'static` they require (issue #169)

Date: 2026-11-26

Part 37 ([2026-11-25-10](2026-11-25-10-region-check-37.md)) was merged with #221. This part starts on #169, the type
check's gaps that stop lifetime tests before the borrow check, with the one listed there that also holds lifetime
errors behind it: the methods of `impl dyn Trait`. They were not found, so every test that calls one stopped at "no
method named .. found for `dyn Tr`" or at the type of an `impl Trait` result.

## 1. What was added

- **Methods of `impl dyn Tr` and of a trait's impl for the object.**
  - A method that the object's vtable does not have is now looked up, in order, as:
    - one of `impl dyn Tr { .. }` or `impl X for dyn Tr { .. }`, which the program keeps as `__dyn_Tr::m`;
    - else a default method of a trait the object implements (`impl MyTrait for dyn Tr {}`).
  - The method is called with the object's pair as its `&self`. A generic impl, `impl<T> MyTrait<T> for dyn
    ObjectTrait<T>`, takes its parameters from the receiver's object (`dyn ObjectTrait<u8>`), and a method's own
    turbofish is passed on.
  - `MyTrait::use_self(val)` with val a trait object is that method call with the trait named. In a module, where the
    path names the trait's default itself, it was called directly with `Self` the object, and the impl for the object
    was never chosen.
  - Two traits whose defaults of the name the object implements are ambiguous, as in rustc (E0034).
  - The type inference of an `-> impl Trait` body follows these methods too: `val.use_self()` as the result of `fn
    use_it<'a>(val: &'a dyn ObjectTrait) -> impl OtherTrait<'a> + 'a` was "cannot infer the `impl Trait` return type".
    The object's trait was looked up with the spaces of its text (`ObjectTrait < u8 >`), which found no method of a
    generic one.
- **The `'static` an impl for a trait object requires.**
  - A trait object in an impl header's self type that is not behind a reference, `impl dyn Tr` or `impl X for dyn
    Tr`, is `dyn Tr + 'static`. Its default is the header's, not the one of the `&self` that later holds `Self`.
  - A call through such an impl needs the receiver's object lifetime to be `'static`. With `val: &'a dyn
    ObjectTrait` that is rustc's E0521 ("borrowed data escapes outside of function") at the call. zustc reports it at
    the same line as "lifetime may not live long enough (`'a` must outlive `'static`)".
  - An impl whose object writes a lifetime (`impl MyTrait for dyn ObjectTrait + '_`) asks nothing of it.
  - For a default method through `impl MyTrait for dyn Tr {}`, whose signature names no object, the requirement is
    an edge from the receiver's object region to `'static`. The region check is turned on for such a call, as for
    any callee that requires `'static`.

- **The review's fixes (#237).** A call through these impls is checked as a call through the vtable is:
  - an unsafe method outside `unsafe` (E0133);
  - a `&mut self` method through a shared reference (E0596);
  - the receiver's borrow, for the borrow check (`b.get()` and `(*b).get()` of a local `Box<dyn Tr>` returned are
    E0515). An explicit deref's receiver (`(*b).get()`) borrowed no place of b, through the vtable too: it is now
    borrowed as `&*b` is, a loan of what the function owns and a reborrow through the references it is reached
    through (`(*b).get()` of `b: &Box<dyn Tr>` is not a loan);
  - the result's tree, for the expression;
  - a `&self` result tied to the receiver's borrow, not only to its object (`fn leak(x: &(dyn Tr + 'static)) ->
    &'static u8 { x.get() }`).

  The object of an impl whose trait takes a lifetime (`impl<'a> dyn Obj<'a>`) is not given `'static`: the trait's own
  bound (`trait Obj<'a>: 'a`) may be its default. An impl for `dyn Obj<u8> + '_` is found by the object's arguments.
  `Ext::pick(x)` beside the object's own `pick` calls Ext's, not the vtable's.

  The second review's:
  - An object among a user type's arguments (`impl<'a> W<'a, dyn Obj>` with `struct W<'a, T: ?Sized + 'a>`) is not
    given `'static`. That type's bound may be its default, and the header does not see it. Only std types whose
    parameters take no lifetime bound (`Box`, `Vec`, `Rc`, ..) give `'static` to their objects. `w.get()` of `W<'a,
    dyn Obj + 'a>` was a false error.
  - `E3::pick(x)` calls E3's default, not an inherent `pick` of `impl dyn O3`. It printed 3 where rustc prints 2.
  - The type expected of the result reaches the method (`let v: u8 = x.make()` with `fn make<T: Default>(&self) ->
    T`).
  - The type inference of an `impl Trait` body solves the impl's parameters from the object's arguments (`impl<T>
    Get<T> for dyn O<T>` through `dyn O<u8>`).
  - tests/probe/dyn_impl_methods.rs runs these programs against rustc's output.

## 4. Not covered yet

- **An impl for `Box<dyn Tr>`** (`impl MyTrait for Box<dyn ObjectTrait>`): its method is found, but the call's
  receiver has no region tree (rg_recv follows a struct's receiver only), so the `'static` its object needs is not
  checked. The other test of the pair,
  suggestions/impl-on-dyn-trait-with-implicit-static-bound-needing-more-suggestions.rs, is made of such impls.
- **A trait method's elided result**: the result of `fn get(&self) -> &u8` is not tied to the receiver's borrow when
  the method is called through the vtable (declared in the trait) or is a trait's default called through `impl Ext
  for dyn Tr {}`. So two errors are missed:
  - `b.get()` of a local `Box<dyn Tr>` returned (E0515);
  - `x.get()` of `x: &(dyn Tr + 'static)` returned as `&'static u8`.

  The result is tied when the lifetime is written (`fn get<'a>(&'a self) -> &'a u8`). The vtable's case is on main
  too.
- **The lifetime bounds a trait declares**: the object of `impl<'a> dyn Obj<'a>` is not given `'static` even when
  `trait Obj<'a>` declares no bound, so the call's E0521 is missed. The header sees no trait declaration.
- **An impl for the object found by its trait's name only**: a generic impl is taken for any `dyn Obj<..>` (E0599
  missed). This covers `impl<T> Ext for dyn Obj<Vec<T>>` through `dyn Obj<u8>`, and an impl whose bound the object's
  arguments do not meet (`impl<T: Copy> Ext for dyn O<T>` through `dyn O<String>`).
- **E0521's own message**: the error is "lifetime may not live long enough" at rustc's line.
- **The rest of #169**: a `let` assigned later through a deref, a closure's parameters from a fn pointer annotation
  (`let g: fn(_, _) -> _ = |_x, y| y;`), `std::cell::OnceCell`, the default methods of an impl for `&T`, `dyn Error`'s
  `is`, and the trait bounds listed there.
- From part 37 and before: see #166–#171.
