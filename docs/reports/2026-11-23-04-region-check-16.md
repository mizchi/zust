# Region (lifetime) checking, part 16: deref coercions, block values and guards that outlive a block's locals, `&mut` arguments, and temporaries' places (issue #1)

Date: 2026-11-23

Part 15 ([2026-11-23-03](2026-11-23-03-region-check-15.md)) was merged with #71. This step fixes a false error of a
common shape, `&a` of a reference `a: &T` where a `&T` is expected (a deref coercion). It also follows what more values
borrow: a call's `&mut` argument, a closure bound's result, a result that may hold an argument of a type parameter, a
str's views, an unsized box's contents, a `let ref`'s temporary, a place in a temporary (`&f().0`), and the values and
guards of a block that outlive the block's locals.

## 1. What was added

### False errors fixed

- **`&a` of a reference where a `&T` is expected is a deref coercion.** `fn f(a: &i32) -> &i32 { &a }` (also in an
  `if`'s branches) was "mismatched types: expected `&i32`, found `&&i32`". Through a `let` or an argument
  (`let r: &i32 = &a; r`, `g(&a)`) the borrow of the local a was returned (a false E0515). It is now the pointer a holds,
  after as many derefs as it takes: a reborrow of `*a` in the borrow check, a's tree in the region check. What a holds
  is still followed: `let a = &x; let b = &a; &b` returned is E0515 of x. `&mut a` stays a mutable borrow of the local
  a, which needs it `mut` (E0596, did_you_mean/issue-37139.rs). What is reborrowed through it lives no longer than that
  borrow.
- **`let ref x = e;` binds a reference.** The type inference bound it as `let x = e;`, so `[x]` of
  `let ref init = 0i32;` was a mismatch. nll/return-ref-mut-issue-46557.rs passed through such a mismatch before. It now
  passes for the error it tests (below).

### Borrow check

- **`&*b` of a `Box<dyn Tr>` / `Box<[T]>` / `Box<str>` borrows what the box owns.** The reborrow was the box's pointer
  itself, with no loan. `let r = &*v; drop(v); r` is now E0505, and `Box::new(B(&*v))` returned as a `Box<dyn X>` is
  E0515. A method's auto-ref through it needs the box mutable: `b.iter_mut()` of a `b: Box<[u8]>` not declared `mut`,
  and `self.0.sort()` through `&self`, are E0596, reported at the receiver.
- **A `let ref` of a temporary.** The temporary of `let ref mut x = 1234543;` (or of a `let ref` of a call's value)
  is borrowed and goes away with the block's locals: returning x is E0515
  (nll/return-ref-mut-issue-46557.rs), and a reference to it kept past an inner block is E0716. A constant one
  (`let ref x = 5;`) is not, as `let x = &5;` is not.
- **A call's `&mut` argument stores what the others borrow, by the signature.** `push(&x, &mut v)` of
  `fn push<'a>(r: &'a i32, v: &mut Vec<&'a i32>)` (or `fn put<T>(a: T, v: &mut Vec<T>)`) held no loan of x in v, so
  `x = 2;` while v is used was accepted (borrowck/cannot-assign-borrowed-ref-in-slice.rs, E0506). The sources of the
  arguments that share a named lifetime or a type parameter with a `&mut place` argument's referent now flow into it.
  - The argument itself flows when the shared lifetime is its reference's own (`r: &'a i32`) or the type parameter is
    its type (`a: T`).
  - Behind its reference (`b: &mut T`), what the referent holds flows: `swap(&mut values, &mut x.values)` stores no loan
    of values in x (borrowck/borrowck-mut-uniq.rs, a run-pass test, is still accepted).
  - A referent whose type holds no reference takes nothing. An elided lifetime, or another one, does not flow.
- **A call through a closure bound holds what its result borrows by the bound's lifetimes.**
  `let y = f(&x); x = 5; drop(y);` with `F: Fn(&isize) -> &isize` is E0506. The result holds the loans of the arguments
  whose types name a lifetime its result names, or of the only one with a reference when its result's is elided. Not a
  result of no reference, nor a `'static` one.
- **A view of a str / slice holds what the receiver does.** `v0.chars()` of a `v0: &str` held nothing, as only the
  prelude's types passed what their receiver holds on to their results. Returned as an `impl Iterator<Item = char>`
  that captures no lifetime it is now E0700 (lifetimes/issue-105227.rs). `t.chars()` of `t: &str = &s`, kept while
  `s.push('c')`, is E0502.
- **Before edition 2024, a block's tail outlives the block's locals in two more ways.**
  - A block's value that a statement discards is dropped at the statement's end:
    `{ let t1 = D(1); D("other").next(&t1) };` is E0597 when D's `Drop` may see the borrow of t1, also through an inner
    block (nll/issue-54382-use-span-of-tail-of-block.rs).
  - A guard of the prelude (`Ref`, `RefMut`, `MutexGuard`) is dropck: its `Drop` releases the borrow of what it guards.
    One made in a block's tail (`y.borrow().clone()`, `*a.borrow() + 1`) makes the local it borrows not live long enough
    (E0597, span/issue-23338-locals-die-before-temps-of-body.rs, span/destructor-restrictions.rs). The tail's
    temporaries are found through operators too, and what one holds is found also when the lowering copies the call
    (a method of what the guard derefs to). A fn body's tail is such a block too: `c.borrow().len()` as the tail of a
    fn that owns c is E0597 (feature-gates/feature-gate-shorter_tail_lifetimes.rs).
- **A block's value that holds what one of the block's locals holds is checked after the block.**
  `let v = { let x = 1; let y = &x; y };` with v used after is E0597, as is a call's result through a local
  (`f(a, b)` of `let f = &shorten_lifetime;`, nll/promoted-bounds.rs). Only a tail that borrowed directly
  (`{ let x = 1; &x }`) was checked, as the block's names are gone after it. The value is read where it is used after the
  block, also as a match's scrutinee or a call's argument (span/issue-40157.rs). A value that holds nothing of the
  block's (`{ let y = &outer; y }`) is fine. tests/security/region_block_tail_escapes.rs, a TODO case, is caught now
  (also through a guard and `Some(&v).unwrap()`), and its TODO entry is removed.
- **A result may hold an argument of a type parameter that outlives a lifetime the result names.**
  `scoped(|| { let _z = y; })` of `fn scoped<'a, F: Fn() + Send + 'a>(f: F) -> Guard<'a>` holds what the closure holds:
  used after the block that owns what the closure borrows, it is E0597 (span/send-is-not-static-ensures-scoping.rs,
  span/regions-close-over-type-parameter-2.rs). The bound `T: 'r` with `'r` in the result is what tells it.
- **A borrow of a place in a temporary is a borrow of the temporary.** `v = &mk().1;`, `id(&x.borrow().1)`,
  `&v.clone()[0].1`, `&Box::new((0, 1)).1` and `&mk().0[..]` kept past the statement are E0716: the place is reached
  through the fields, indexes and owning derefs (a `Box`, a guard's or an `Rc`'s `Deref`) of a temporary a call makes.
  A `let` extends it as before (`let v = &x.borrow().1;` is fine), and a place reached through a reference the
  temporary is (`&v.iter().next().unwrap().1`) is not the temporary's. A `&mut` field read through a guard where a
  `&mut` is annotated (`let v: &mut i32 = x.borrow_mut().0;`) is a reborrow through the temporary too.

### Diagnostics

- **A returned `match`'s arm after the first is reported at the match**, as rustc's blame does: its value is coerced
  to the match's type, and the return of the match's value is the constraint rustc names
  (regions/regions-free-region-ordering-incorrect.rs). The first arm, an `if`'s branches, and an arm that makes its
  value (a block, an `if`, a constructor's call) are reported where they are, as in rustc.

## 4. Review (CodeRabbit, checked against rustc 1.97)

CodeRabbit's first review of #88 had 6 findings. Each was checked by running zustc and rustc on a program that shows
it. Five held, and are fixed and tested (`part16_review`):

- **Nested tail watches (a crash).** A block in an argument of a block tail's watched call
  (`c.borrow().get({ let e = RefCell::new(1usize); *e.borrow() }).copied()` as a block's tail) removed the outer tail's
  position watches when it ended, and the outer call then indexed past them: zustc panicked. Each tail now removes only
  the watches it added. The program is E0597 of e, at rustc's line.
- **A discarded block value in edition 2024.** `{ let x = 0; D(&x) };` with D's `Drop` reading the reference was
  accepted in edition 2024 (E0597 in rustc). The 2024 rule changes when a tail's temporaries go, not when the block's
  value goes: it is drop-checked at the statement's end in every edition.
- **A `dyn Fn` call's result.** `let r = f(&x); x = 2;` with `f: &dyn Fn(&i32) -> &i32` and r used after was accepted
  (E0506): only a generic bound's call held the arguments' loans in its result. A `dyn Fn` call now does too.
- **A coerced `&x` through a `&mut`.** `&x` of `x: &'short mut &'long mut i32` returned as `&'long i32` was accepted
  (rustc: lifetime may not live long enough). The coerced reborrow (`&**x`) is now bounded by the `&mut` links it goes
  through, as an explicit one; a shared link stops the bounds there.
- **A local passed, then assigned by a later argument.** `put(r, { r = &x; }, &mut v)` stored only x's loan in v, so
  `k = 3;` (r was `&k` when passed) was accepted. rustc's region of r holds both loans and reports both writes (E0506).
  When an argument assigns, what the locals passed hold before the arguments flows too.

The sixth, that `F: Fn(&'a i32, &'a i32) -> &i32` should give its result the one lifetime its parameters share, does
not apply: rustc rejects that bound (E0106, missing lifetime specifier), so it cannot be written.

The second round had one finding in the diff and one outside it. Both held, and are fixed and tested
(`part16_review`):

- **A `let ref` temporary below a block value's holder.** `let r = { let ref x = make(); x };` with r used after was
  accepted (E0716 in rustc): the end of the block's scope stopped at the holder of the enclosing block's value, pushed
  after the temporary. Every temporary of the scope that ends now goes with it.
- **A coerced `&x`'s region.** `let r: &'a i32 = &x; *x = 2;` with `x: &'a mut i32` was accepted (E0506 in rustc): the
  coerced reborrow had no region of its own for the borrow check's loan to follow, as an explicit `&*x` has. It now
  does. Checking this also showed that `&x` of `x: &'a mut i32` returned as `&'a i32` was accepted: through `&mut`
  links only, the reborrow goes through the borrow of x the coercion takes, so it is E0515 in rustc, and now here.

The third round had one, and it held: that last bound applied to any place, so `&s.f` of `s: &mut S`, `&s.r` of `s: &'a S<'a>`
and `&*x`, returned, were a false E0515 (rustc accepts them). Only a place the function owns is bounded by the coercion's borrow of
it now; one reached through a reference is a reborrow through that reference, as the explicit path's. Tested in
`part16_review`, with `&s.f` of an owned `s: S` still E0515.

## 5. Not covered yet

- **A generic struct's `dyn Tr<T>` field, and a generic fn's `&dyn Tr<T>` parameter**, are not instantiated with T:
  `B(&*v)` of `struct B<'a, T>(&'a (dyn A<T> + 'a))` is "type annotations needed", and the generic function is not
  checked (regions/regions-close-object-into-object-*.rs). A trait object's type is kept as text.
- **A higher-ranked bound an impl is not general enough for** (`T: for<'a> Foo<&'a isize>` with only
  `impl Foo<&'static isize>`), and a fn item passed as a higher-ranked fn pointer whose result must be `'static`
  (regions/regions-fn-subtyping-return-static-fail.rs): bound regions are variables in the region check, not
  placeholders.
- **A trait bound's method with lifetimes tied by a higher-ranked bound** (`F: for<'a> FnLike<&'a isize, &'a isize>`,
  higher-ranked/trait-bounds/hrtb-identity-fn-borrows.rs): a fn whose body calls such a method is not checked with a
  placeholder instance.
- **Indexing through a `Deref` to a slice** (`self[0]` with `type Target = [()]`, borrowck/issue-81365-6.rs) is
  "cannot index into a value", and a str's (`&s[1..3]` with `type Target = str`) too.
- **A tuple's `&mut` element coerced to `&T` when the tuple is made** (`RefCell::new((&mut r, s))` then
  `let v: &_ = x.borrow().0;`, borrowck/issue-36082.rs): the type inference takes the element as `&i32`, so the read
  is a copy, not a reborrow through the guard.
- **A blanket impl's method for a reference in a trait object** (`impl<A> Foo for A`, `Box::new(v) as Box<dyn Foo>`
  with `v: &i32`) is a false "`Foo::get` has no implementation for `&i32`" (on main too). In
  span/regions-close-over-type-parameter-2.rs it is reported beside the E0597 the test is about.
- **A move out of a raw pointer's referent** (`let y = *x;` with `x: *const Box<isize>`,
  borrowck/borrowck-move-from-unsafe-ptr.rs) is not E0507: a raw pointer's deref is not a place of the borrow check.
- **`let it = v.iter();` without `mut`** outside a `for` loop is not supported yet.
